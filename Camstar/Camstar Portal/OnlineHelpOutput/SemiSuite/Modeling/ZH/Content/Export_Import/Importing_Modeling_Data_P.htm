导入建模数据

通过 Opcenter EX SM Portal，可以将从一个 Manufacturing 系统导出的建模对象实例上传和导入到另一个系统。无需选择整个导出文件用于导入，而只需指定不希望包含在导入中的所选实例，即可执行部分导入。

注释: Microsoft HTTP 类的默认设置可能不足以用于文件导入。建议文件导入的最大值为 6 MB。可以导入大于 6 MB 的文件，但性能可能会受到影响。有关导入大于 6 MB 的文件的信息，请参考《Opcenter Execution Core 系统管理指南》。

导入建模数据

应用程序按名称导入建模对象实例。当导入文件包含与现有实例同名的实例时，导入流程可以覆盖应用程序中的现有实例。可以在开始导入流程之前启用替代模式，以防止实例被覆盖。

导入会一直运行直到导入流程完成。可以修改 Portal Studio 中的门户设置以启用超时，即可在达到时间限制时中止导入流程。有关设置超时的信息，请参考《Opcenter Execution Core Portal Studio 用户指南》。

通过使用“执行控制台”页上的应用程序替代模式设置，可以指定应用程序中的建模对象实例是否会被指定导入文件中的建模对象实例覆盖以及如何覆盖。导入流程为导入提供了三个替代选项：

• 中止 – 当导入流程在应用程序中检测到与导入文件中的建模对象实例同名的建模对象实例时，导入流程将中止。
• 覆盖 – 导入流程从导入文件导入建模对象实例，并覆盖应用程序中同名的任何实例。
• 跳过 – 导入流程从输入文件导入建模对象实例，但跳过与应用程序中的现有实例同名的导入实例。
注释: 如果不选择替代方法，则默认情况下应用程序将使用跳过替代方法。

应用程序会在“实例选择”页面的“所选实例”表格中显示所有可从指定 XML 文件导入的建模对象实例。可以删除不希望导入的实例。选择“所选实例”表格中的实例，然后单击“删除所选行”按钮。

导入建模对象定义而不首先导入它们所依赖的建模对象定义时将发生错误。例如，如果一个对象定义了填充另一个对象页面上的必需字段的实例，则对象可能依赖于另一个对象。必须首先导入其他对象所依赖的建模对象，然后在单独的导入中导入从属对象。

例如，在导入“审批模板”和“审批决定列表”的实例时，应首先导入“审批决定列表”的实例，因为“审批模板”的实例期望“审批决定列表”实例在导入流程中出现在系统中。然后，应在单独的导入流程中导入“审批模板”实例。

可以使用 Portal Studio 自定义在导入页上显示的标签。有关信息，请参考《Opcenter Execution Core Portal Studio 用户指南》。

导入失败

完成消息将指示失败的任何实例导入。如果实例在应用程序中已存在并且在导入过程中阻止覆盖，则导入该实例将失败。

用于手动导入建模数据的页面流

手动导入建模数据的页面流包括 4 页：

• 数据传输类型，在其中选择手动导入
• 实例选择，在其中选择要导入的 xml 文件以及要导入的特定建模对象实例
• 执行控制台，在其中指定替代模式（如有），然后开始导入
• 执行汇总，在其中可以查看导入的摘要和错误信息

如何手动导入建模数据

按照以下步骤手动导入建模数据：

1. 从导出/导入菜单中打开导出/导入页。将显示“导出/导入数据传输类型”页。
2. 使用以下过程完成页面流上的必需字段：
• “如何选择数据传输类型”
• “如何选择要导入的建模对象实例”
• “如何开始导入”
3. 单击完成以完成导入流程。应用程序关闭“导出/导入”页，并显示“执行汇总”页，可以在其中查看导入的汇总以及发生的任何错误。
