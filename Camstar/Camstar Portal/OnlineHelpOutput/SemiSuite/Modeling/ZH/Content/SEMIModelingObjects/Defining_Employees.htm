定义员工

“员工”是在应用程序中执行活动（例如维护建模定义、进行查询、管理安全管理功能和执行车间事务）的用户。系统管理员使用安全管理功能向员工授予特权，使其能够访问这些活动。

每个员工必须具有有效登录帐户，并且员工姓名必须与登录帐户 ID 匹配。 有关用户名的确切语法，请与系统管理员联系。

可以定义不具有帐户的员工，但这些员工无法登录。可以将它们作为执行容器事务或资源事务的员工加以输入。例如，具有有效登录帐户（和相应权限）的主管可以登录到应用程序并访问“开始”页面。记录在“开始”页面上的员工姓名可以是主管或其他员工（实际执行启动容器这一工作的任何人）。此员工不一定具有帐户。

为每个员工设置会话值可以对执行事务的人员限制查看。员工只能查看他或她被允许查看的内容，并具有一个用于搜索的较短值列表。这就限制了搜索时间并减少了犯错的机会。

安全模型

应用程序的安全模型基于角色访问控制模型。系统管理员为员工指派角色成员资格，以控制员工对整个应用程序或应用程序某些部分的访问权。为员工指定主要组织和角色成员资格时，需要为该员工设置安全权限。要执行任何操作，用户必须通过角色传播直接或间接地在组织中获取角色。

角色在“角色”页上定义。可以在“员工”页或“角色”页上指派角色成员资格。但是，只能在“角色”页上为该角色指派权限。

《Opcenter Execution Core Security 指南》包含有关安全管理的章节。它讨论了权限类型和模式、身份验证和授权流程如何进行以及如何验证用户权限。

默认员工

默认情况下，应用程序提供以下员工定义：

• Administrator
• CamstarAdmin
• InSiteAdmin
• 系统

首次登录到应用程序时，使用以上任意一个员工名。

首次实施 Opcenter Execution Core 时或者转换或更新为新版本并升级默认实例数据时，默认门户菜单会自动指派给管理员、CamstarAdmin、InSiteAdmin 和 System 员工。在“员工”页上使用“门户菜单定义”字段为其他员工指派门户菜单。

默认角色

Siemens 还为默认公司组织提供了若干个预定义的角色。系统为默认员工指派全部或部分默认角色中的成员资格。还为具有 Change Management 许可的用户提供其他默认角色。

定义员工

至少有一个默认员工必须是有效的 Active Directory 用户，才能首次成功登录到门户。

如果是首次定义员工，确保您自己以管理员身份创建员工定义。可以使用 Windows 登录名作为员工姓名。如果要为其他员工创建定义，可以使用该员工的 Windows 登录名。

应用程序中使用的员工定义如下所示：

• 作为已登录到 Portal 的员工，默认组织是您的主要组织。只有具有直接角色或可传播角色的组织才可供在门户页面上选择。
• 在应用程序中执行记录搜索时，可以输入所有者作为搜索准则的一部分。所有者是与要搜索的质量记录关联的员工。

注意以下事项：

• “员工”包含以下可选建模定义：“组织”、“字典”、“电子签名角色组”、“工厂”、“培训计划”、“作业”和“工作中心”。
• “员工”是所有容器事务和所有资源事务中的可选字段。

定义上报收件人

上报收件人是当员工有即将进行、到期或逾期的工作时会收到电子邮件通知的人员。例如，如果工作到期，可以向员工的经理发送电子邮件通知。使用“上报收件人”表格中的“员工”字段定义上报收件人。

“更改管理设置”建模对象用于在审批者或协同者有未完成任务时设置提醒通知以发送给上报收件人。如果选择此类提醒通知，应用程序会将提醒发送给为员工指定的上报收件人。有关信息，请参考《Opcenter Execution Core Modeling 用户指南》。

如果在“上报收件人”表格中未选择上报收件人，应用程序将不会发送电子邮件通知。确保在每个上报收件人的“员工”建模对象实例中已完成“电子邮件地址”字段，否则收件人将无法收到电子邮件通知。

如何定义员工

按照以下步骤定义“员工”：

1. 打开员工页。随即“建模”页中将显示“员工”页。
2. 单击新建。显示用于定义新实例的空白字段。
3. 在员工字段中输入员工姓名。
4. 在访问权限级别字段中输入员工的访问权限级别。
5. 根据您的业务需求输入可选信息。有关可选字段的信息，请参考字段定义表。
6. 单击保存。应用程序保存建模对象并显示成功消息。
