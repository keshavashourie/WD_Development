Defining Numbering Rules

A Numbering Rule is a configurable numbering scheme that automatically assigns unique tracking numbers to matrix objects, quality records, and lots. Typically, an organization defines and assigns a numbering scheme to these entities. The application applies the appropriate numbering scheme and assigns the next available ID or number to the appropriate matrix object, quality record, or container. Refer to the Opcenter Execution Core Modeling User Guide for additional information on numbering rules.

When Defining Numbering Rules for Containers and Lots

The application uses the numbering rules specified on these modeling objects to generate container and lot names automatically:

• Product
• Product Family
• Service Setup

Numbering Rule is an optional field in these modeling definitions.

Shop floor users have the option to generate container names automatically when starting parent and child containers and lots, splitting containers and lots, and splitting quantities. Refer to the Opcenter Execution Core Shop Floor User Guide for information on generating container names automatically.

The application uses this order of precedence to determine the numbering rule to use when a numbering rule has been specified on multiple modeling objects:

1. Product
2. Product Family
3. Service Setup

Field Entry Format Requirements

Numbers must be 30 characters or less, including any prefix or suffix and the sequence number. The number generated is calculated as follows:

Number = Prefix (if any) + Sequence Number (Required) + Suffix (if any)

For example: EVENT-ORG15-00000001-2014

The Prefix and Suffix fields can be used for either literal or unified expression syntax entries.

Both require very specific formats, for example:

• A literal prefix may be defined as "ABCCorp_" or "_Smith." Double quotes around the entry are required.
• Unified expression syntax might be used to create a dynamic prefix or suffix, such as:
• Prefix = "(<Organization.Name>"
• Suffix ="_"+StrSubstring(String(TruncateTime(GMTToLocal(SetSystemDateGMT()))),(StrLength(String(TruncateTime(GMTToLocal(SetSystemDateGMT()))))-4),4)

Refer to the Opcenter Execution Core Designer User Guide for information on unified expression syntax.

Numbering Rule Page Field Definitions

This table defines the fields unique to the Numbering Rule page.

Numbering Rule Type

List containing the numbering rule types for selection. Possible values include:

• High Volume/Skip
• Low Volume/No Skip

Prefix (Dynamic Expression)

You may define a prefix to append to the sequence number. The prefix can support both static string text and unified expression syntax to generate dynamic text. An example of a static string text prefix is "PE-ORG15." You must include double quotes around your entry as shown in the example.

Optional

Suffix (Dynamic Expression)

You may define a suffix to append to the sequence number. The suffix can support both static string text and unified expression syntax to generate dynamic text. An example of a static string text suffix is a four-digit year "2014" or a product name "BPMON." You must include double quotes around your entry as shown in the examples.

Optional

Use Prefix Based Last Assignment Sequence

Indicates whether to override rule-based sequencing with prefix-based sequencing.

Note: Prefix-based sequencing makes sense for numbering rules configured with unified expressions that dynamically generate prefixes. The application assigns a starting sequence value each time a numbering rule generates a unique prefix for the first time. If a numbering rule subsequently generates the same prefix, the application increments the last assigned sequence for that prefix when generating the container name.

Refer to the Opcenter Execution Core Modeling User Guide for information.

Optional

Use Hexadecimal Value

Indicates whether to use hexadecimal value instead of integer value.

Optional

Use AlphaNumeric Value

Check box indicating whether to use alphanumeric numbering for the sequence.

Note: This option works with both rule-based and prefix-based sequencing.

Optional

Numbering Rule Options

Setting that controls numbering rule behavior when the maximum sequence value is reached. Numbering rule options include the following:

• Rollover - The sequence restarts after reaching a predefined limit. When the maximum sequence value is reached, the numbering rule starts to generate ascending values from the value, indicated in the Last Assigned Value field.

Note: If Rollover is selected, an error will occur if a duplicated container name is detected.

• Stop - The sequence stops at a predefined limit. The numbering rule cannot generate more values after reaching the maximum value.
• Continue - The sequence increments without bound. The numbering rule continues to generate values after reaching the maximum value.

Note: This field is enabled when the Use AlphaNumeric Value check box is selected.

Optional

Max Value

You may define a maximum value to be generated. This value should accept an integer value if the numbering rule does not use hexadecimal values and support a hexadecimal value if it does. An error message will be displayed if numbering rule generates a value that exceeds the defined maximum value.

Optional

Use Values

Indicates whether to use the values list to get the next sequence instead of the sequence length.

Optional

Reset Values When Prefix Change

Indicates whether the index used in values is reset to the first value when the dynamic value of Prefix changes during generation.

Note: You must check the "Use Values field" in order to use this field.

Optional

Reset Values When Suffix Change

Indicates whether the index used in Values is reset to the first value when the dynamic value of Suffix changes during generation.

Note: You must check the "Use Values field" in order to use this field.

Optional

Last Assigned Sequence

Last sequence number assigned to a quality record. The application calculates the next sequence number to assign by incrementing this number by one. The default value is 0.

Required

Sequence Length

Desired length of the sequence number. The maximum length of a calculated sequence number is 30 characters, assuming the prefix and suffix are not used.

Required

Txn Data Key (Dynamic Expression)

Field used when Values list is used to generate the next sequence. The Txn Key's resolved value will be stored in the TxnData list to allow multiple sequences per setup. For example, one Numbering Rule setup can be used by multiple Equipment to generate a run number. So to ensure each Equipment has its own sequence, the Txn Key should be configured as the Equipment name.

Optional

Sequence Values grid

List that specifies an ordered sequence of values to use to generate the sequence instead of using a sequence number. The order in which the value is set up is important since the logic chooses the next index each time a sequence is required.

Optional

Value

Value for the sequence.

Optional

Txn Data grid

Used when the Values list is used to generate the next sequence. Each TxnDataKey's resolved value is used to track different sequences with one Numbering Rule setup.

Optional

Key Value

Key used to generate the sequence using the Values list.

Required

Last Value String

Last value string used in the parent Values list to generate the sequence.

Optional

Last Prefix Value

Last resolved value of the prefix. This is used to compare against the generated Prefix to determine whether to reset the values if there is a change.

Optional

Last Suffix Value

Last resolved value of the suffix. The application compares this value to the generated suffix to determine whether to reset the values if there is a change.

Optional

How to Define a Numbering Rule

Follow these steps to define a Numbering Rule:

1. Open the Numbering Rule page. The Numbering Rule page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter a name for the numbering rule in the Numbering Rule field.
4. Select a Numbering Rule Type.
5. Enter a value in the Last Assigned Sequence field.
6. Enter a value in the Sequence Length field.
7. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
8. Click Save. The application saves the modeling object and displays a success message.
