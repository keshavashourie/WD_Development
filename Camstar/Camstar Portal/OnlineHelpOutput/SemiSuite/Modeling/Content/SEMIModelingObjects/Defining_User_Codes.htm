Defining User Codes

User codes fall under the category of Named Data Objects (NDOs). They are uniquely identified by name within type. Examples of user code types include job repair codes, failure types, bonus reasons, and rework reasons.

Opcenter EX CR and Opcenter Execution Semiconductor provide default user codes. You can easily add user codes using the modeling page for the type of user code to be added. For example, to add a bonus reason, use the Bonus Reason page in Modeling.

Note: Refer to the Opcenter Execution Core Modeling User Guide for additional information about user codes and a list of Opcenter EX CR user code defaults.

Default Opcenter Execution Semiconductor User Code Types

This table defines the default user code types provided with Opcenter Execution Semiconductor.

Additional information that can be assigned to a schedule during Lot Schedule Request.

• LOCAL: Attributes of this type are displayed for the Lot Modify Attrs transaction.
• MATERIAL: Attributes of this type are displayed for the Lot Modify Materials transaction if Service Attrs Details is implemented for attribute modification.

Reason for a carrier's current status. For example, the reason for a carrier being in a DOWN status might be MAINTENANCE.

SPC Annotation Category

SPC Exclude Reason

Surveillance Reason

used for reporting purpose.

Tool Family

Track Label

Code used by the Track Label feature.

Un-Terminate Reason

UTA Reason

Variance Reason

Represents a reason for a count variance.

WIP Data Display Filter

How to Define a User Code

Note: These instructions are for adding a user code to an existing user code type. Refer to the Opcenter Execution Core Modeling User Guide to learn how to create new user code types.

Follow these steps to define a user code:

1. Open the modeling page for the type of user code that you want to define (add).
2. Click New. Blank fields appear for you to define a new instance.
3. Enter a name for the user code in the User Code field.
4. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
5. Click Save. The application saves the modeling object and displays a success message.
