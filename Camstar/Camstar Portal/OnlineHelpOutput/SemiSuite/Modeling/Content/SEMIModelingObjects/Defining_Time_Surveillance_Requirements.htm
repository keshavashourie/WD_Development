Defining Time Surveillance Requirements

Time Surveillance requirements enforce data collection for resources, resource groups, operations, and work centers at specified time intervals. These requirements can be configured with options to set tolerance and warning allowances (in days), and e-mail distribution lists for pending, due, and past due notifications.

Surveillance requirements are activated for resources, resource groups, operations, and work centers using the Surveillance Activation shop floor page.

Before Defining Time Surveillance Requirements

Surveillance Reason is a required field on the Time Surveillance page. Make sure that the necessary surveillance reason has been added to the application before defining a time surveillance requirement.

When Defining Time Surveillance Requirements

These are the available recurring date patterns:

• Hourly - Schedules have a fixed number of hours between each execution.
• Daily - Schedules have a fixed number of days between each execution.
• Weekly - Schedules have a specific day of the week.
• Monthly - Schedules have a specific day of the month.
• Yearly - Schedules have a month and a day during the month.

All of these intervals support a frequency, which identifies a pattern for how often the requirement repeats. The number 1 indicates that the application executes the surveillance event on every scheduled recurrence. The number 2 indicates every other scheduled recurrence, and so forth.

How to Define a Time Surveillance Requirement

Follow these steps to define a Time Surveillance requirement:

1. Open the Time Surveillance page. The Time Surveillance page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter a name for this requirement in the Time Surveillance field, and enter the revision identifier for this definition in the Revision field.
4. Expand the Scheduling Details section if it is not already expanded.
5. Select the Surveillance Reason.
6. Select the required data collection from the Data Collection Def field.
7. Select a date pattern from the Recurring Date Pattern field list.
8. Enter a number in the Frequency field.
9. Did you select Monthly, Weekly, or Yearly for Recurring Date Pattern?

Yearly

b. Select a Month of Year.

11. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
12. Click Save. The application saves the modeling object and displays a success message.

How to Add a Notification to a Time Surveillance Requirement

Follow these steps to add a notification to a Time Surveillance requirement:

1. Perform the "How to Define a Time Surveillance Requirement" procedure.

Or

Select an existing Time Surveillance instance.

2. Expand the Notifications section.
3. Click Add new row in the Pending E-mail Target, Due E-mail Target, or Past Due E-mail Target grid. A new row appears.
4. Enter an e-mail notification in the newly added row. The notification is added to the grid.
5. Enter the text for the e-mail in the corresponding Pending E-mail Text, Due E-mail Text, or Past Due E-mail Text field. You also have the option to use text variables.
6. Repeat steps 3-5 to set up notifications for additional recipients.
7. Click Save. The application saves the modeling object and displays a success message.
