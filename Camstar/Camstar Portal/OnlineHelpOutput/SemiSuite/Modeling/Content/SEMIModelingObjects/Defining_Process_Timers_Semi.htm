Defining Process Timers in Opcenter Execution Semiconductor

Process Timers control and monitor the manufacturing process by defining actions to take if processing is initiated on a container before a minimum time is met or after the maximum allowable time for the process to execute has passed. Opcenter Execution Semiconductor uses the Opcenter Execution Core (Opcenter EX CR) process timer object with minor modifications.

Note: Remember the intended application when configuring process timers with Rework or Move Non-Std dispositions. Both of these transactions contain standard validations which prevent execution under certain circumstances such as while the lot is tracked into the equipment.

When Defining a Process Timer

A process timer starts at a specified transaction, ends at a specified transaction, or does both. The process timer may specify one of these Disposition Details to automatically execute when a timer ends:

• Do NOT allow End Txn to execute and do NOT execute Disposition Actions—The application does not complete the transaction at which the timer ended and does not perform disposition actions.
• Allow End Txn to execute and also execute all defined Disposition Actions—The application completes the transaction at which the timer ended along with any disposition details. Refer to "End Transaction Disposition Exception."
• Allow End Txn to execute with Electronic Signature and do NOT execute Disposition Actions—The application completes the transaction at which the timer ended but does not perform disposition actions.

The process timer may also have one of these Disposition Actions selected:

• Business Rule
• Production Event
• Rework
• Move Non-Std
• Future Hold

End Transaction Disposition Exception

It is critical to remember the normal execution of Opcenter Execution Semiconductor when configuring process timers. One of the configurable options within Process Timers is "Allow End Txn to execute and also execute all defined Disposition Actions." You can select this option and also select Rework and Move Non-Std as a disposition action. You can then assign the process timer to use Track In as the “End Txn.”

The application is designed to bypass the Track In under this scenario to avoid violating the Opcenter Execution Semiconductor rule that does not permit Rework or Move Non-Std to be performed for a lot while it is tracked in to an equipment resource. In this scenario, Track In is bypassed for the end transaction, the disposition actions are performed, and the status message indicates the completed execution.

How to Define a Process Timer

Follow these steps to define a Process Timer Type:

1. Open the Process Timer page. The Process Timer page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter a name for the process timer type in the Process Timer field.
4. Select the radio button under Timer. The default selection is Min only.
5. Enter the desired times under Timer Format ([d.]hh:mm:ss).
Note: The fields will be marked as required or disabled based on your selection under Timer.
6. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
7. Click Save. The application saves the modeling object and displays a success message.
