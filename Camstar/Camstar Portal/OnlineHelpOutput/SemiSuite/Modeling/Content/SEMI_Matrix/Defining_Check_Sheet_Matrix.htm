Defining a Check Sheet Matrix

The Check Sheet matrix object is used to resolve the check sheet (also called electronic procedures) for a transaction. Check sheets enable you to assign a collection of tasks to a specification. For example, a check sheet might require the operator to clean the workstation, measure a wafer, place a wafer in a bath of cleaner, and finally remove and remeasure the wafer.

The check sheet matrix enables the support of multiple check sheets in a single spec. You can configure up to three different check sheets per spec: one for the Track In transaction, one for the Track Out transaction, and one for the Move Out transaction.

Note: Because the application does not support electronic procedures prior to the Move In transaction on the container, you cannot configure check sheets for use by Move In transactions.

When Defining Check Sheet Matrix Objects

Remember the following points when the matrix object uses WIP Step Workflow to define a step in the workflow as one of the criteria:

• Deleting a step from the workflow referenced in the matrix object will render that particular matrix entry invalid.
• Editing a step in the workflow referenced in the matrix object does not render that particular matrix entry as invalid unless the step is removed and then re-entered.

How to Define a Check Sheet Matrix

Follow these steps to define a Check Sheet Matrix:

1. Open the Check Sheet Matrix page. The application displays the Check Sheet Matrix page.
2. Perform one of the procedures as indicated in the following table:

To define . . .

Perform the following . . .

A new instance

Specify settings in the Criteria area. Refer to the field definitions table for information on the available fields.

An instance using an existing instance

Select and edit and existing instance. Refer to "How to Save an Edited Instance as a New Instance" for instructions.
3. Enter a name for the check sheet matrix instance in the Check Sheet Matrix Name field.
4. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
5. Click Save. The application saves the modeling object and displays a success message.
