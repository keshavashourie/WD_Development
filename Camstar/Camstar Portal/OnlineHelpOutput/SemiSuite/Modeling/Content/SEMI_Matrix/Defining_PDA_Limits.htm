Defining a PDA Limits Matrix

PDA Limits are used to specify the percentage defective aggregate yield calculations.

Bins required are taken from the last bin collection. Rejects required can be set to a Loss Reason Reference Spec (example, a previous step) or the current step. The sum of the required bins and rejects will be used to verify against the PDA Limits in units, percentage, or both. A Reference Spec is used to determine the Move In Qty used to verify the Limit In Percentage.

Each set of limits are based on the number of times the lot has been through the step. This will allow a more stringent limit if the lot was reworked and passed through the same step again. The Spec Pass Count (example, Step Count) will be used to indicate the number of times the lot has passed through the step.

When Defining a PDA Limits Matrix

You can define a Numbering Rule object to automatically name the matrix object. The application will then populate the Name field automatically when you save the instance. Refer to "Using Numbering Rules to Name Instances Automatically" for information on using numbering rules to name matrix object instances.

How to Define a PDA Limits Matrix

Follow these steps to define a PDA Limits Matrix:

1. Open the PDA Limits page. The application displays the PDA Limits page.
2. Perform one of the procedures as indicated in the following table:

To define . . .

Perform the following . . .

A new instance

Specify settings in the Criteria area. Refer to the field definitions table for information on the available fields.

An instance using an existing instance

Select and edit and existing instance. Refer to "How to Save an Edited Instance as a New Instance" for instructions.
3. Enter a name for the PDA Limits matrix instance in the PDA Limits Name field. If you do not specify a name and there is a numbering rule object modeled for this matrix object, the application populates this field automatically when you save the instance.
4. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
5. Click Save. The application saves the modeling object and displays a success message.
