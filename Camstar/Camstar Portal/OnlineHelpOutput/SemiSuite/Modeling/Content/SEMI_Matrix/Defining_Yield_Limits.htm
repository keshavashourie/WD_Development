Defining a Yield Limits Matrix

Yield Limit matrix objects are used to specify limits used by the yield handler calculations.

When Defining Yield Limit Matrix Objects

Remember the following points when the matrix object uses WIP Step Workflow to define a step in the workflow as one of the criteria:

• Deleting a step from the workflow referenced in the matrix object will render that particular matrix entry invalid.
• Editing a step in the workflow referenced in the matrix object does not render that particular matrix entry as invalid unless the step is removed and then re-entered.

You can define a Numbering Rule object to automatically name the matrix object. The application will then populate the Name field automatically when you save the instance. Refer to "Using Numbering Rules to Name Instances Automatically" for information on using numbering rules to name matrix object instances.

Upper Yield Failure Action

Specifies the action to take in the case of an upper yield failure. Options are:

• HOLD – The lot will be put on hold if any failures are detected. The application will not process any transactions on the lot. You must specify a value for the Upper Yield Failure Hold Reason field if you select HOLD.
• HOLDALL – The lot and other lots in its schedule will be put on hold if any failures are detected. The application will not process any transactions on any of the lots. You must specify a value for the Upper Yield Failure Hold Reason field if you select HOLDALL.
• WAIVE – The lot is not placed on hold even if failures are detected. The application will continue processing transactions on the lot.
• FUTUREHOLD – The lot is placed on hold in a future step. The application will continue to process transactions until the lot arrives at the future step. You must specify a value for the Upper Yield Failure Future Hold Setup field if you select FUTUREHOLD.

How to Define a Yield Limits Matrix

Follow these steps to define a Yield Limits matrix:

1. Open the Yield Limits page. The application displays the Yield Limits page.
2. Perform one of the procedures as indicated in the following table:

To define . . .

Perform the following . . .

A new instance

Specify settings in the Criteria section. Refer to the field definitions table for information on the available fields.

An instance using an existing instance

Select and edit an existing instance. Refer to "How to Save an Edited Instance as a New Instance" for instructions.
3. Enter a name for the matrix instance in the Yield Limits Name field. If you do not specify a name and there is a numbering rule object modeled for this matrix object, the application populates this field automatically when you save the instance.
4. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
5. Click Save. The application saves the modeling object and displays a success message.
