Matrix Modeling Pages

All matrix pages consist of sections that enable you to search and define criteria to determine the behavior of lots as they move through the manufacturing process. You can use the matrix modeling pages to view, edit, delete or to add new instances . Matrix pages consist mainly of the following sections:

• Search and Selection Area
• Criteria Area
• Details Area

These six matrix pages have a different page layout based on the latest user interface enhancement:

• Blanket Experiment Matrix
• Equipment Matrix
• Parameter Matrix
• Recipe Matrix
• Tool Plan Matrix
• WIP Data Setup Matrix

The page layout for these pages includes the following sections:

• Filter and Selection Area
• Criteria Area (appears as pop-up)
• Details Area (appears as pop-up)

The rest of the matrix pages will remain with the previous matrix user interface until future enhancement.

Note: The descriptions and procedures described in this section are common to all matrix modeling objects. Refer to the each of the matrix pages for the specific description and definitions.

Search and Selection Area

The search and selection area enables you to search for matrix instances that match the criteria you define. Each matrix instance uses its own set of search criteria.

Click Refresh button under the grid to execute your search. The results will be displayed in the grid.

For the new enhanced matrix pages, the search area has been replaced with a filter section. The filter section appears as a slide-out panel on the left-side of the matrix pages. This area helps you to search for matrix instances that match the criteria you define. Click the Apply button under the filter section to execute your search. The results will be displayed in the grid.

When you first navigate to the new matrix page, the right-command bar disables some of the buttons including Edit, Delete, View Details and Audit Trail. You must select an instance row in the grid to enable those buttons.

Note: Each matrix pages and instance might have different set of search criteria field based on their own functionality.

You can search for a matrix based on specific fields having specific values. For example, you enter PA-004 in a Product search field to find a matrix with a product criteria of PA-004. You can leave all search fields blank when you want to see all matrices.

Highest Matching Algorithm

When you specify filter criteria for a matrix modeling object, the application uses the highest matching algorithm during run time to search the database for the best records to return. The algorithm assigns a binary value to each specified criterion according to the importance of each.

The matrix modeling pages have different sets of filter criteria. The order of the criteria fields on the page indicates the importance of each criterion. The fields are ordered according to binary weight. The first criterion has the highest value, the one listed next has a smaller value, and so on.

On the Equipment Matrix page, the binary value assigned to Product is higher than that of Process Spec. Process Spec is assigned a higher value than Product Line, and so on, with Spec having the lowest value. For example, the binary values for Product = 16, Process Spec = 8, Product Line = 4, Owner = 2 and Spec = 1. If multiple entries are returned, the first listed record in the grid is the one used most. The first listed record is the one with highest total binary value.

You can specify one or more filter criteria as required to define the parameters of the modeling object. When you specify more than one search criteria, the application will return results based on the "or NULL" condition where it will return both individual and matching records. For example, if you specified PN criteria and Process Spec criteria, the application will return records matching:

• Both the PN and the Process Spec
• Only the PN, and
• Only the Process Spec

How to Use the Search and Selection Area to Find Instances

Follow these steps to search for and select instances of a matrix object:

1. Open the matrix modeling page. For example, Equipment Matrix. The matrix modeling object page appears.
2. Enter the criteria in the fields provided, and click the Refresh button under the Selection grid. The application displays the instances that match the specified criteria.
3. In the Selection grid, click in the row that contains the record. The application populates the matrix object page with the specific information from that instance.

How to Use the Filter and Selection Area to Find Instances

Follow these steps to search for and select instances of a matrix object:

1. Open the matrix modeling page from the Modeling > Matrix. The application displays the selected matrix page.
2. In the Filter slide-out panel, enter the criteria in the fields provided. Click Apply. The application displays the instances that match the specified criteria in the Selection grid.
3. Select the row containing the instance you want to view, edit, or delete. Click the button on the Command bar to display the pop-up for the action you want to complete.

Criteria Area

In the Criteria area, you can select criteria to define a new instance or add additional criteria to the instance you specified in the search and selection area.

Details Area

In the Details area, you further define the instance by naming the matrix object and adding other required and optional information as needed for the specific matrix object type.

Note: If you do not specify a name and there is a numbering rule object modeled for this matrix object, the application populates this field automatically when you save the instance. Refer to "Using Numbering Rules to Name Instances Automatically" for information on using numbering rules to name matrix object instances.

Using Numbering Rules to Name Instances Automatically

If you do not specify a name for the instance and there is a numbering rule object modeled for this matrix object, the application populates this field automatically when you save the instance. To use this feature, you must create a Numbering Rule object with the following naming pattern:

matrixNameChanges

Where matrixName is the name of the matrix object.

For example, to create a numbering rule for equipment matrix objects, you would create a Numbering Rule object named “EquipmentMatrixChanges”. Then, when you create new equipment matrix object instances for which you do not specify a name, the application generates a unique name for each instance as specified by the Numbering Rule object. Refer to the Opcenter Execution Core Modeling User Guide for information about Numbering Rule objects.
