Defining Switching Rules

The Switching Rule page enables you to define the rules used to move a sampling plan from one inspection level to another. Switching rules enable a sampling plan to change to a reduced or tightened inspection plan based on the number of passed or failed lots in a sequence of lots. A sampling plan enables defining switching rules, which are evaluated based on the number of passes for a defined number of lots or on an expression. When the switching rule criteria is met, the application can change the switching rule inspection plan automatically, send an e-mail notification to a decision maker for a manual intervention, or both.

Similar to sampling rates, switching rules can have a maximum duration. As part of the sample rate, a maximum duration can be defined for the switching rule. Therefore, only lots processed within the maximum duration time frame (set by the Switching Rule Max Duration field in the Sampling Plan) are included when evaluating switching rules. The application initiates the Switching Rule evaluation process only if either of the following is true:

• The Switching Rule Max Duration field in the Sampling Plan is set to 0.
• The number of days since the current Sampling Status record was updated is less than the value set by the Switching Rule Max Duration field in the Sampling Plan.

Refer to "Defining Sampling Plans" for information on the Switching Rule Max Duration field.

Switching Rule Add Pop-Up Field Definitions

This table defines the fields on the Add pop-up.

Field

Definition

Type

From Inspection Level

Starting inspection level for this switching rule, which may be enacted if the current inspection level is equal to this value.

Required

To Inspection Level

Resulting inspection level, which is the new inspection level if switching rule criteria are met.

Required

Pass (or Fail) Container Count

Number of lots that passed or failed inspection. Whether the number represents lots that passed or failed depends on the value of the Passed/Failed field. This field is always an integer.

The application determines whether to change inspection plan if the following expression is true:

X out of Y

Where:

• X is the Pass (or Fail) Container Count (this field).
• Y is the number of lots in the last set (Last Container Set Count field).

For example, Passed/Failed is set to Passed, Pass (or Fail) Container Count is set to 3, and Last Container Set Count is set to 4. If 3 of the last 4 (3 out of 4) lots pass inspection, then the application will change the inspection plan.

Note: The Allow Automatic Switching field must be set for the application to change the inspection plan.

Optional

Last Container Set Count

Number of lots in the last set used to determine the pass or fail. Whether the number represents lots that passed or failed depends on the value of the Passed/Failed field. This field is always an integer.

The application determines whether to change inspection plan if the following expression is true:

X out of Y

Where:

• X is the Pass (or Fail) Container Count.
• Y is the Last Container Set Count (this field).

For example, Passed/Failed is set to Passed, Pass (or Fail) Container Count is set to 3, and Last Container Set Count is set to 4. If 3 of the last 4 (3 out of 4) lots pass inspection, then the application will change the inspection plan.

Note: The Allow Automatic Switching field must be set for the application to change the inspection plan.

Optional

Passed/Failed

Indicates whether the Pass (or Fail) Container Count field is the count of passed or failed sample tests.

Optional

Expression

This unified expression can be used in place of the Pass (or Fail) Container Count and Last Container Set Count fields to determine if the switching rule is triggered. The expression must result in a Boolean (true/false). Refer to the Opcenter Execution Core Designer User Guide for information on unified expressions.

Note: Either the Pass (or Fail) Container Count, Last Container Set Count, and Passed/Failed fields OR the Expression field will be populated.

Optional

Allow Automatic Switching

Indicates whether the Inspection Level automatically updates to the To Inspection Level when the switching rule criteria are met.

Optional

Require Notification

Email notification is sent when the Switching Rule criteria are met.

Optional

E-Mail Distribution

Email distribution list for the individual Switching Rule if different from the default one in the Processing section.

Optional

How to Define a Switching Rule

Follow these steps to define a Switching Rule:

1. Open the Switching Rule page. The Switching Rule page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter a name for the Switching Rule instance in the Switching Rule field.
4. Enter the revision, or version, of the instance in the Revision field. The application uses both the name and revision to identify the definition.
5. Enter the switching rule parameters in the Switching Rule Details grid as follows:
a. Click Add new row. The application adds a blank row to the grid.
b. Enter the beginning inspection level for the switching rule in the From Inspection Level field. The From Inspection Level can be enacted if the current inspection level is equal to this value.
c. Enter the resulting Inspection Level for the Switching Rule in the To Inspection Level field. This value becomes the new inspection level if the switching rule criteria are met.
d. Enter optional information according to your business requirements. Refer to "Switching Rule Add Pop-Up Field Definitions" for information on the optional fields.
e. Repeat steps a-d for each switching rule parameter you want to add.
6. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
7. Click Save. The application saves the modeling object and displays a success message.
