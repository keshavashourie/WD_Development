Main Modeling Objects

Main modeling objects define the physical and process models for your factory. Main modeling objects fall into one of two categories:

• Modeling objects in the physical model describe the physical elements of your factory. These elements define the equipment and other resources that are used in the manufacturing process, as well as divisions, locations, and areas of the factory. For example, the Location modeling object defines a physical location within a factory, such as an aisle or rack space within a warehouse.
• Modeling objects in the process model describe the control portion of your factory model, including manufacturing workflow process flows and specifications. For example, Workflow modeling objects define the steps used to manufacture a product.

These modeling objects are static, meaning that you can define the modeling objects one time and use them to control product processing activities in Opcenter Execution Semiconductor .

Note: Main modeling objects were referred to as Setup A objects in Semiconductor Suite Version 6 SU1 and earlier.

Named Data Objects

A named data object (NDO) is a class of main modeling objects that is identified by a unique name. NDO instances are persistent; that is, information on them is written to the database. Because NDOs are designated only by a name, named modeling objects of the same type must have unique names. For example, if you have an Operation modeling object named "Assembly," you cannot create another Operation that is also named "Assembly."

Revisioned Objects

A revisioned object (RO) is an object that requires both a name and a revision. Revisions enable you to maintain multiple versions of the same modeling entity. As modifications are made to a revisioned modeling object, you can define new versions without assigning a new object name. Like NDOs, ROs are persistent, so you can maintain multiple versions of the same modeling objects and reference any existing revision of the RO as needed.

Revisioned objects allow you to:

• Provide revisions for modeling objects such as Products (PNs), Workflows, and Process Specs. This is helpful when you want to create different versions of the ROs for different uses. For example, you could clone an existing revision to create a new revision while maintaining the model. Since the Opcenter EX SM Portal enables you to maintain several ROs in your modeling data, you can then modify an existing RO without breaking your factory dependencies that exist on that RO.
• Reference a specific revision or the revision of record. For example, when referencing a Spec, you must select either a specific revision or the revision of record. If you reference a specific revision, the workflow always uses that revision even if new revisions are created. If you reference the revision of record, the workflow always uses the revision of record, regardless of the actual revision number.
• Clone existing revisions to create a new revision while maintaining the model. Since Opcenter EX SM Portal enables you to maintain several ROs in your modeling data, you can modify an existing RO without breaking your factory dependencies that exist on that RO.

Filtering the List of Instances

The Filter field can be used to narrow down a large number of modeling instances that appear in the Instances list. You can use the filtering list for either revisioned or named data objects.

Type a fragment of a string and click Refresh to display a list of instances with names beginning with that string fragment. Click Refresh with the Filter field blank to return all instances.

A list control appears below the filter if the number of defined instances is greater than 100.

Revision of Record

The revision of record is the revision currently designated as the default to use in the factory model and on the shop floor, even if other revisions are active and available for use. The revision of record feature reduces model maintenance and ensures the use of correct revisions on the shop floor.

The revision of record is not necessarily the most recent revision of the object. You can specify only one revision as the revision of record, but you can change that designation at any time and make another revision the revision of record.

The advantage of using the revision of record is that when you reference the revision of record, you do not need to update the workflows that use that object every time a new revision of the object is approved for use. For example, when you create a Workflow, you create steps by referencing Spec objects or other Workflow objects. When you reference a Spec, you must select either a specific revision or the revision of record. If you reference a specific revision, the Workflow always uses that revision even if new revisions are created. However, if you reference the revision of record, the Workflow always uses the revision of record, regardless of the actual revision number.

Revisioned Objects in the Instance Selection List

The instance selection list displays in expanded view so that you can see the instances and their associated revisions. The application indicates the revision of record by listing the revision of record after the name of the instance along with a check box after the name of the specific revision.

Clicking an instance name displays the maintenance page for the revision of record of that instance. Clicking the name of a specific revision displays the maintenance page for that revision.

The first instance of a revisioned object you create is the revision of record by default.

You can define a revision of an existing revisioned object instance by using any of the following methods:

• Click New Rev to create a copy of the revision with all fields blank except the name field. You might do this when most attributes will be unique to the new revision.
• Click Copy to create a copy of the revision with all the information from the original revision. You might do this when you want to use an existing revision as the basis for a brand new revision.
• Click Copy Rev to create a copy of the revision with all the information from the original revision except the revision number.

How to Delete an Instance or Revision

Follow these steps to delete an instance or revision:

1. Select Main from the Modeling menu. The application displays the Object selection panel.
2. Click the object type on the Objects list that matches the object type of the instance or revision you want to copy. The instance selection list appears.
3. Click the instance or revision that you want to delete. If you click the instance name instead of a specific revision, the application selects the revision of record by default.
4. Perform one of the following:
