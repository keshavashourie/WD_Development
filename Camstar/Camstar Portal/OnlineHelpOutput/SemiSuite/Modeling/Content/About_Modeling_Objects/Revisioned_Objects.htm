Revisioned Objects

A revisioned object (RO) is an object that requires both a name and a revision. Revisions enable you to maintain multiple versions of the same modeling entity. As modifications are made to a revisioned modeling object, you can define new versions without assigning a new object name. Like NDOs, ROs are persistent, so you can maintain multiple versions of the same modeling objects and reference any existing revision of the RO as needed.

Revisioned objects allow you to:

• Provide revisions for modeling objects such as Products (PNs), Workflows, and Process Specs. This is helpful when you want to create different versions of the ROs for different uses. For example, you could clone an existing revision to create a new revision while maintaining the model. Since Semiconductor Shop Floor enables you to maintain several ROs in your modeling data, you can then modify an existing RO without breaking your factory dependencies that exist on that RO.
• Reference a specific revision or the revision of record. For example, when referencing a Spec, you must select either a specific revision or the revision of record. If you reference a specific revision, the workflow always uses that revision even if new revisions are created. If you reference the revision of record, the workflow always uses the revision of record, regardless of the actual revision number.
