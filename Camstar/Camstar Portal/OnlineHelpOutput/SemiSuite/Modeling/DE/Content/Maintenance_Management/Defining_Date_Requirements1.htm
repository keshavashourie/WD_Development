Definieren von Datumsanforderungen

Eine Datumsanforderung (Terminanforderung) definiert den Wartungsplan einer Ressource auf Grundlage eines einzelnen Kalenderdatums. Die Anforderungsdefinition enthält auch die Toleranz- und Warnbereiche (in Tagen) und die entsprechenden E-Mail-Verteilerlisten für E-Mail-Benachrichtigungen zu ausstehenden, fälligen und überfälligen Wartungsereignissen. Sie haben auch die Möglichkeit, einen Dokumentsatz und eine Datensammlungsdefinition mit der Anforderung zu verbinden.

Hinweis: Sie können Geschäftsregeln so konfigurieren, dass automatisch E-Mail-Benachrichtigungen gesendet und konfigurierte Wartungsjobs erstellt werden, wenn eine Datumsanforderung innerhalb eines definierten Warnzeitraums überfällig oder fällig wird. Weitere Informationen finden Sie unter "Verwenden von Geschäftsregeln, um Wartungs-E-Mails und Joberstellung zu automatisieren".

Optional

Dieser Anforderung zugeordneter Grund.

Dieser Anforderung zugeordneter Dokumentsatz.

Die Datensammlungsdefinition, die mit dieser Anforderung verknüpft ist.

Der Zeitpunkt (Datum und Uhrzeit), zu dem die Anforderung fällig wird. Dies setzt eine Aktivierung der Anforderung für die Ressource oder die Wartungsklasse voraus. Die Uhrzeit wird standardmäßig auf Mitternacht gesetzt, wenn keine andere Uhrzeit angegeben wird.

Löst die "Fällig"-E-Mail aus.

Erforderlich

Warnungsfrist

Gibt an, ab dem wievielten Tag vor dem geplanten Datum die Wartungsanforderung als ausstehend für die entsprechende Ressource gilt.

Löst die "Ausstehend"-E-Mail aus.

Die "Ausstehend"-E-Mail wird nicht versandt, wenn der Standartwert 0 für das Feld zulässig ist.

Optional

Toleranzfrist

Gibt an, ab dem wievielten Tag vor dem geplanten Datum die Wartungsanforderung als ausstehend für die entsprechende Ressource gilt.

Versendet die "Überfällig"-E-Mail und die Ressource steht für die weitere Bearbeitung nicht mehr zur Verfügung.

Wenn der Standardwert 0 zulässig ist, wird die "Überfällig"- E-Mail am geplanten Datum versandt. Die Ressource ist ab sofort nicht mehr für die weitere Verarbeitung verfügbar.

Optional

Verzicht möglich

Gibt an, ob diese Wartungsanforderung für eine Ressource aufgehoben werden kann.

Optional

Elektronische Unterschrift erforderlich für Verwaltung von Verzicht/Verzögerung

Vordefinierte Anforderung hinsichtlich einer elektronischen Unterschrift. Falls diese hier festgelegt wird, muss die elektronische Unterschrift bereitgestellt werden, wenn diese Wartungsanforderung für eine Ressource aufgehoben oder verschoben werden soll.

Optional

Anforderung zur elektronischen Unterschrift

Vordefinierte Anforderungen zur elektronischen Unterschrift. Falls diese hier festgelegt wird, können Sie die Transaktion erst durchführen, wenn alle Unterschriften vorliegen.

Optional

Verzögerung möglich

Gibt an, ob diese Wartungsanforderung für eine Ressource verschoben werden kann.

Optional

Max. Verzögerungsdauer

Maximale Anzahl von Verzögerungen, die auftreten können, bevor eine Wartung durchgeführt werden muss.

Optional

Tabelle "Checkliste"

Optional

Checklisten-ID

Eindeutiger Checklistenname zur Identifizierung der Checkliste.

Erforderlich

Anweisung

Unformatierter Text, der während einer Checklistenkonfiguration hinzugefügt wird und den Benutzer bei der Verwendung der Checkliste unterstützen soll.

Erforderlich

Mitarbeitergruppe

Gruppe von Mitarbeitern, die die Checkliste ausführen dürfen.

Optional

Nur einzeln

Kontrollkästchen, das steuert, ob diese Checkliste zusammen mit anderen Checklisten ausgewählt werden kann.

Optional

Datensammlungsdefinition

Definiert Daten, die bei der Verwendung der Checkliste gesammelt werden.

Optional

Beschreibung

Unformatierter Text, um aussagekräftige Informationen über die Checkliste hinzuzufügen.

Optional

Hinweise

Relevante Kommentare. Sie können maximal 2000 Zeichen eingeben.

Optional

Checklistenreihenfolge erzwingen

Gibt an, ob die Anwendung die Reihenfolge der Checklistenelemente durchsetzen soll.

Optional

Tabelle "PM-Überschreibungen"

Tabelle mit verknüpften Anforderungen, die als abgeschlossen markiert werden, sobald diese Basisanforderung als abgeschlossen markiert ist.

Optional

Datumsanforderung

Name der verknüpften Datumsanforderung, die automatisch als abgeschlossen markiert wird, sobald diese Eltern-Anforderung als abgeschlossen markiert wird.

Optional

Benachrichtigungen

Tabelle "Ausstehend - E-Mail-Empfänger"

In dieser Tabelle werden die Empfänger angegeben, die eine E-Mail-Benachrichtigung über eine ausstehende Wartung erhalten.

Optional

Ausstehend - E-Mail-Text

Der Text der E-Mail, die versandt wird, wenn die Wartung ausstehend ist. Sie müssen einen Text eingeben, wenn Sie im Feld "Ausstehend - E-Mail-Empfänger" eine Angabe machen. Es können Textvariablen verwendet werden.

Optional

Tabelle "Fällig - E-Mail-Empfänger"

In dieser Tabelle werden die Empfänger angegeben, die eine E-Mail-Benachrichtigung erhalten, wenn die Wartung fällig ist.

Optional

Fällig - E-Mail-Text

Der Text der E-Mail, die versandt wird, wenn die Wartung fällig ist (aber noch in der Toleranzfrist liegt). Sie müssen einen Text eingeben, wenn Sie im Feld "Fällig - E-Mail-Empfänger" eine Angabe machen. Es können Textvariablen verwendet werden.

Optional

Tabelle "Überfällig - E-Mail-Empfänger"

In dieser Tabelle werden die Empfänger angegeben, die eine E-Mail-Benachrichtigung erhalten, wenn die Wartung überfällig ist.

Optional

Überfällig - E-Mail-Text

Der Text der E-Mail, die versandt wird, wenn die Wartung überfällig ist. Sie müssen Text eingeben, wenn Sie im Feld "Überfällig - E-Mail-Empfänger" eine Angabe machen. Es können Textvariablen verwendet werden.

Optional

Zusätzliche Felder

Stückliste

Ressourcenstückliste für die Wartungsanforderung, die mögliche, während der Ausführung der Wartung verfügbare Ausrüstungskomponenten (Teile) enthält.

Optional

Geschätzte Dauer (Stunden)

Geschätzte Anzahl von Stunden für die Reparatur. Wird im Berichtswesen verwendet.

Optional

Jobmodell

Das Jobmodell, das von der Anwendung verwendet, um einen Wartungsjob zu erstellen, wenn das konfigurierte Wartungsfälligkeitsdatum abgelaufen ist.

Vorgehensweise zum Definieren einer Datumsanforderung

Gehen Sie folgendermaßen vor, um eine Datumsanforderung zu definieren:

1. Öffnen Sie die Seite Datumsanforderung. Die Seite "Datumsanforderung" wird innerhalb der Seite "Modellierung" angezeigt.
2. Klicken Sie auf Neu. Es werden leere Felder zum Definieren einer neuen Instanz angezeigt.
3. Geben Sie einen Namen für diese Anforderung in das Feld Datumsanforderung ein und geben Sie den Revisionsidentifikator für diese Definition in das Feld Revision ein.
4. Erweitern Sie den Abschnitt Ablaufplanungsdetails.
5. Wählen Sie den Grund, der mit dieser Anforderung verknüpft ist, im Feld Wartungsgrund aus.
6. Geben Sie das Wartungsdatum für diese Anforderung in das Feld Geplantes Datum ein.
7. Geben Sie entsprechend Ihren Geschäftsanforderungen optionale Informationen ein. In der Felddefinitionstabelle finden Sie Informationen zu den optionalen Feldern.
8. Klicken Sie auf Speichern. Die Anwendung speichert das Modellierungsobjekt und zeigt eine Erfolgsmeldung an.

Vorgehensweise zum hinzufügen Datumsanforderungs-Benachrichtigungen

Gehen Sie folgendermaßen vor, um eine Datumsanforderungs-Benachrichtigung hinzuzufügen:

1. Führen Sie die Schritte unter "Vorgehensweise zum Definieren einer Datumsanforderung" aus.

Oder

Wählen Sie eine vorhandene Instanz einer Datumsanforderung aus.

2. Erweitern Sie den Abschnitt "Benachrichtigungen".
3. Klicken Sie in der Tabelle "Ausstehend - E-Mail-Empfänger", "Fällig - E-Mail-Empfänger" oder "Überfällig - E-Mail-Empfänger" auf Neue Zeile hinzufügen. Eine neue Zeile wird angezeigt.
4. Geben Sie eine E-Mail-Benachrichtigung in die neu hinzugefügte Zeile ein. Die Benachrichtigung wird der Tabelle hinzugefügt.
5. Geben Sie den Text der E-Mail in das entsprechende Feld ein: Ausstehend - E-Mail-Text, Fällig - E-Mail-Text oder Überfällig - E-Mail-Text. Sie haben auch die Möglichkeit, Textvariablen zu verwenden.
6. Wiederholen Sie die Schritte 3 bis 5, um die Benachrichtigungen für weitere Empfänger einzurichten.
7. Klicken Sie auf Speichern. Die Anwendung speichert das Modellierungsobjekt und zeigt eine Erfolgsmeldung an.

Vorgehensweise zum Hinzufügen von PM-Überschreibungen zu einer Datumsanforderung

Gehen Sie folgendermaßen vor, um PM-Überschreibungen hinzuzufügen:

1. Führen Sie die Schritte unter "Vorgehensweise zum Definieren einer Datumsanforderung" aus.

Oder

Wählen Sie eine vorhandene Instanz einer Datumsanforderung aus.

2. Erweitern Sie alle Abschnitte.
3. Klicken Sie in der Tabelle "PM-Überschreibungen" auf Neue Zeile hinzufügen. Eine neue Zeile wird angezeigt.
4. Wählen Sie eine Datumsanforderung aus, die in den Überschreibungsprozess aufgenommen werden soll.
5. Wiederholen Sie die Schritte 3 und 4 für jede weitere hinzuzufügende PM-Überschreibung.
6. Klicken Sie auf Speichern. Die Anwendung speichert das Modellierungsobjekt und zeigt eine Erfolgsmeldung an.
