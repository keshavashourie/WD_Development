Definieren von Nutzercodes

Nutzercodes fallen unter die Kategorie "Named Data Objects" (NDOs). Sie werden durch Namen innerhalb des Typs eindeutig identifiziert. Beispiele für Typen von Nutzercodes sind Jobreparaturcodes, Fehlertypen, Bonusgründe und Nacharbeitsgründe.

Opcenter EX CR und Opcenter Execution Semiconductor umfassen Standardnutzercodes. Sie können über die Modellierungsseite problemlos Nutzercodes für den Typ von Nutzercode hinzufügen, der hinzugefügt werden soll. Beispiel: Um einen Bonusgrund hinzuzufügen, verwenden Sie in der Modellierung die Seite "Bonusgrund".

Hinweis: Weitere Informationen zu Nutzercodes und eine Liste der Standardnutzercodes von Opcenter EX CR finden Sie im Opcenter Execution Core Modeling-Benutzerhandbuch.

Standardnutzercodetypen in Opcenter Execution Semiconductor

Diese Tabelle definiert die standardmäßigen Nutzercodetypen, die mit Opcenter Execution Semiconductor zur Verfügung gestellt werden.

Nutzercode

Beschreibung

Bereichsgruppe

Zusätzliche Informationen, die während einer Loszeitplananforderung einem Zeitplan zugewiesen werden können.

Attributtyp

Kategorisiert die Felder "Containerattribute", "Losattribute" und "Ext. Losattribute", die über die Transaktion "Attribute ändern" geändert werden dürfen. Dies folgenden beiden Typen sind standardmäßige Attributtypen:

• LOCAL: Attribute dieses Typs werden für die Transaktion "Los: Attribute ändern" angezeigt.
• MATERIAL: Attribute dieses Typs werden für die Transaktion "Los: Materialien ändern" angezeigt, wenn "Serviceattribute: Details" zur Attributänderung implementiert ist.

Behälterstatusgrund

Grund für den aktuellen Status eines Behälters. Beispiel: Der Grund für einen Behälter, der sich im Status DOWN befindet, kann MAINTENANCE sein.

Externer Ort: Typ

Optionales Feld, das in der Definition einer Operation verwendet werden kann.

Feederslot

Physischer Ort oder Ort in einer Maschine oder eine Feederbank, in die ein Feeder geladen werden kann.

Anhalteposition

Physischer Raum in Einrichtung, in dem ein Container oder Los aufbewahrt werden kann.

Aufbewahrungstyp

Allgemeiner Grund für das Verschieben eines Loses aus der Ablaufplanung. Beispiel: Der Aufbewahrungstyp AGING kann für gealterte aufbewahrte Lose erstellt werden.

Einsetzungsgrund

Grund für den Austausch eines ungeplanten Loses durch Umlaufbestandsverarbeitung. Ein typisches Beispiel wäre erneutes Testen.

Jobursachencode

Grund für die Erstellung eines Ausrüstungsreparatur- oder Wartungsjobs.

Jobreparaturcode

Aktion zum Reparieren von Ausrüstung.

Jobstufe

Name eines Schritts innerhalb eines Jobmodells.

Jobsymptomcode

Verhalten oder Erscheinungsbild der Ausrüstung, das die Notwendigkeit signalisiert, einen Reparatur- oder Wartungsauftrag zu erstellen.

Beschriftungstyp

Kategorie der Beschriftung, die den Beschriftungszweck angibt, z. B. BOX oder REEL.

Maschinengruppe

Wird zum Gruppieren von Maschinen verwendet.

Maskenebene

Oberflächenebene (in Bezug auf Tiefe), die in der Waferverarbeitung verwendet wird.

Material Kategorie

Wird zum Gruppieren von Materialien verwendet.

Fertigungslinie

Gruppieren (möglicherweise in einer physischen Reihenfolge) von Ausrüstung, die zum Verarbeiten von Losen verwendet wird. Dieses Feld wird zunächst mit der Fertigungslinie gefüllt, die im Arbeitsauftrag angegeben ist.

Attribute ändern: Grund (Änderungsgrund)

Grund für Aktualisierung oder Anpassung eines Losattributs.

Operationsgruppe

Wird zum Gruppieren von Verarbeitungsoperationen verwendet.

Teilefamilie

Wird zum Gruppieren von Teilen verwendet.

Physische Position

Position innerhalb eines physischen Orts

Drucktyp

Definiert den Druckzieltyp, z. B. LABEL, REPORT und TEXTFILE.

Prozessbereich

Zusätzliche Informationen, die während einer Anforderung des Loszeitplans einem Zeitplan zugewiesen werden können.

Prozesstyp

Gibt den Zweck eines Herstellungsprozessschritts an. Beispiele können Folgendes sein: MNT, ETCH, FINAL_CLEANING und BOX_INSPECT.

Produktzweig

Wird zum Gruppieren von Produkten verwendet.

Ablehnungskategorie

Typ des Grunds für die Ablehnung eines Teils oder des gesamten Loses.

Notizcode für Umsortierung

Code, der verwendet wird, um bei einer Umsortierung weitere Anweisungen zu Verfügung zu stellen.

Einrichtungszugriff

Wird von der Anwendung verwendet, um Zugriff auf ein Modellierungsobjekt zu gewähren. Die Anwendung gewährt Zugriff, wenn der Benutzer eine Rolle mit dem gleichen Einrichtungszugriff wie das Objekt aufweist.

Hinweis: Die Anwendung gewährt standardmäßig Zugriff, wenn einem Objekt kein Einrichtungszugriff zugewiesen ist.

Schicht

Gibt einen Zeitrahmen an, in dem eine Gruppe von Mitarbeitern ihren Job zu einem bestimmten Zeitpunkt startet und zu einem bestimmten Zeitpunkt beendet. Wird in Produktions- kalender verwendet.

Versandfabrikcode

Code, der eine konfigurierte Empfängerfabrik angibt. Wird verwendet, um die Dokumentnummer während der Transaktion "Losversand" zu generieren.

Versandwerkscode

Ähnelt dem Versandfabrikcode. Wird in der Regel verwendet, um einen alternativen Namen für die Fabrik bereitzustellen. Er kann zum Generieren einer Reihenfolge verwendet werden. Ein Beispiel wäre die Generierung der Dokumentnummernreihenfolge während eines Losversands.

Empfängerprozess

Prozessbereich in der Zielfabrik, an den das Produkt gesendet werden soll.

IQC-Sortierung: Los: Prüfung

Fehlergrund für IQC-Sortierung. Grund, aus dem ein Los bei der Transaktion "IQC-Sortierung" fehlgeschlagen ist, die zur Prüfung eines Loses durchgeführt wurde, das den Umlaufbestand erreicht.

Hinweis: IQC-Sortierung erfolgt in der Regel im ersten Schritt des Umlaufbestands.

IQC-Sortierung: Wafer: Prüfung

Fehlergrund für IQC-Sortierung. Grund, aus dem ein Wafer bei der Transaktion "IQC-Sortierung" fehlgeschlagen ist, die zur Prüfung von Wafer (Elementen) eines Loses durchgeführt wurde, das den Umlaufbestand erreicht.

Notizcode für Sortierung

Code, der verwendet wird, um bei der ersten Sortierung weitere Anweisungen zu Verfügung zu stellen.

SQA-Sortierung: Fehler

Fehlergrund für SQA-Sortierung.

Hinweis: SQA-Sortierung wird verwendet, um ausgehende Wafer (Elemente) eines Loses im Umlaufbestand zu prüfen. Dies erfolgt in der Regel, bevor das Los den Umlaufbestand durchlaufen hat.

SPC-Anmerkungskategorie

Typ der Anmerkung, die auf einen SPC-Datenpunkt angewendet wird.

SPC-Ausschlussgrund

Gibt den Grund für einen Datenpunkt an, der aus zukünftigen Berechnungen ausgeschlossen wird.

Überwachungsgrund

Der mit der Überwachungsanforderung verknüpfte Grund.

Abbruchkonto

Gibt ein Konto an, dem eine Losbeendigung zugerechnet wird. Dies wird

für Berichterstellungszwecke verwendet.

Werkzeugfamilie

Kategorisiert Werkzeuge auf der Basis der Geschäftsanforderung der Fabrik.

Nachverfolgungsbeschriftung

Code, der von der Funktion "Nachverfolgungsbeschriftung" verwendet wird.

Grund für Abbruchaufhebung

Grund, der mit dem Entfernen einer Losbeendigung verbunden ist.

UTA-Grund

Stellt einen Grund für die Berechtigung eines Einheitentransfers dar.

Abweichungsgrund

Stellt einen Grund für eine Zahlenabweichung dar.

Umlaufbestandsdaten: Anzeigefilter

Anzeigefilter für Umlaufbestandsdatenname.

Vorgehensweise zum Definieren eines Nutzercodes

Hinweis: Diese Anweisungen gelten beim Hinzufügen eines Nutzercodes zu einem vorhandenen Nutzercodetyp. Informationen zur Vorgehensweise beim Erstellen neuer Nutzercodetypen finden Sie im Opcenter Execution Core Modeling-Benutzerhandbuch.

Gehen Sie folgendermaßen vor, um einen Nutzercode zu definieren:

1. Öffnen Sie die Modellierungsseite für den Typ von Nutzercode, den Sie definieren (hinzufügen) möchten.
2. Klicken Sie auf Neu. Es werden leere Felder zum Definieren einer neuen Instanz angezeigt.
3. Geben Sie im Feld "Nutzercode" einen Namen für den Nutzercode ein.
4. Geben Sie entsprechend Ihren Geschäftsanforderungen optionale Informationen ein. In der Felddefinitionstabelle finden Sie Informationen zu den optionalen Feldern.
5. Klicken Sie auf Speichern. Die Anwendung speichert das Modellierungsobjekt und zeigt eine Erfolgsmeldung an.
