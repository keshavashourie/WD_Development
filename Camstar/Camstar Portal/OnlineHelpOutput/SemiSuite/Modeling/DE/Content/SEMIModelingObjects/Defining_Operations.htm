Definieren von Operationen

Eine Operation ist ein Produktions- oder Bearbeitungspunkt, an dem Lager- und Produktionsaktivitäten verfolgt werden. In der Operationsdefinition werden Elemente wie Ursachencodes, Bearbeitungsregeln und die erlaubten Transaktionen für den Transport des Materials im Verlauf der Operation beschrieben. Im Gegensatz werden in Spezifikationen die Verarbeitungsschritte definiert, die bei einer Operation durchgeführt werden.

Hier einige Beispiele für Operationsinformationen:

• Referenzen auf Nutzercodes für die Aufzeichnung von Verlust-, Bonus-, Nacharbeits- und Versandinformationen
• Optionale Kennzeichnung der Operation als "Bestand", "Unterwegs" oder "Externer Servicepunkt"
• Ausweisung zulässiger und unzulässiger Transaktionen
• Angabe, ob der Status "In Warteschlange" verwendet wird und daher eine Anmeldung erforderlich ist

Sie können beim Erstellen eines Ereignisses eine Operation angeben, um den Produktions- oder Bearbeitungspunkt anzugeben, an dem das Ereignis festgestellt wurde.

Typen von Operationen

Semiconductor Shop Floor stellt verschiedene Typen von Operationen bereit, von denen jeder einer bestimmten Transaktion entspricht: geplante Operationen, Umlaufbestandsoperationen, Unterwegs-Operationen und Lagerbestandsoperationen. Die folgende Tabelle beschreibt die Operationstypen:

Operationstyp

Beschreibung

Geplante Operation

Geplante Operationen sind erforderlich, um die Lagerbestands- und Produktionsaktivitäten für geplante Spezifikationen nachzuverfolgen. Jede geplante Operation entspricht der geplanten Spezifikation gemäß der Fertigungsoperation, die sie nachverfolgt. Zum Beispiel entspricht die Operation "Zusammenbau: Geplante Operation" der Spezifikation "Zusammenbau: Geplante Spez.". Wenn Ihr Arbeitsplan über eine geplante Spezifikation auf eine geplante Operation verweist, müssen Sie "Loszeitplan freigeben" ausführen, um das Los für den Umlaufbestand anzumelden.

Die Anwendung stellt die folgenden geplanten Operationen bereit:

• Zusammenbau: Geplante Operation
• Backgrind: Geplante Operation
• Test: Geplante Operation
• Wafer: Geplante Operation
• Wafersortierung: Geplante Operation

Umlaufbestandsoperation

Umlaufbestandsoperationen sind erforderlich, um die Lagerbestands- und Produktionsaktivitäten für Umlaufbestandsspezifikationen nachzuverfolgen, die wiederum Umlaufbestandsschritte definieren. Jede Umlaufbestandsoperation entspricht der Umlaufbestandsspezifikation gemäß der Fertigungsoperation, die sie nachverfolgt. Zum Beispiel entspricht die Operation "Zusammenbau: Umlaufbestandsoperation" der Spezifikation "Zusammenbau: Umlaufbestandsspez.".

Semiconductor Shop Floor umfasst die folgende Umlaufbestandsoperation:

• Zusammenbau: Umlaufbestandsoperation
• Backgrind: Umlaufbestandsoperation
• Test: Umlaufbestandsoperation
• Wafersortierung: Umlaufbestandsoperation
• Wafer: Umlaufbestandsoperation

Unterwegs-Operation

Unterwegs-Operationen sind erforderlich, um die Lagerbestands- und Produktionsaktivitäten für Unterwegs-Spezifikationen nachzuverfolgen. Jede Unterwegs-Operation entspricht der Unterwegs-Spezifikation gemäß der Fertigungsoperation, die sie nachverfolgt. Zum Beispiel entspricht die Operation "Die-Bank: Unterwegs-Operation" der Spezifikation "Die-Bank: Unterwegs-Spez.". Semiconductor Shop Floor umfasst die folgenden Unterwegs-Operationen:

• Die-Bank: Unterwegs-Operation
• Testspeicher: Unterwegs-Operation
• Wafer: Unterwegs-Operation
• Wafersortierung: Unterwegs-Operation

Lagerbestandsoperation

Lagerbestandsoperationen sind erforderlich, um die Lagerbestands- und Produktionsaktivitäten für Lagerbestandsspezifikationen nachzuverfolgen, die Arbeitspläne beginnen und beenden. Jede Lagerbestandsoperation entspricht der Lagerbestandsspezifikation gemäß der Fertigungsoperation, die sie nachverfolgt. Zum Beispiel entspricht die Operation "Die-Bank: Lagerbestandsoperation" der Spezifikation "Die-Bank: Lagerbestandsspez.". Semiconductor Shop Floor umfasst die folgenden Lagerbestandsoperationen:

• Die-Bank: Lagerbestandsoperation
• Testspeicher-Lagerbestandsoperation
• Wafer-Lagerbestandsoperation
• Wafersortierung: Lagerbestandsoperation

Felddefinitionen der Seite "Operation"

Diese Tabelle definiert die Felder auf der Seite "Operation" für jeden Operationstyp.

Feld

Definition

Typ

Typ-Operation

Eindeutiger Name für diese Operation, wobei Typ der Typ der Operation ist. Für eine "Zusammenbau: Umlaufbestandsoperation" lautet das Feld z. B. "Zusammenbau: Umlaufbestandsoperation".

Erforderlich

Allgemein

Arbeitsbereich

Bereich der Fertigung, in dem ähnliche Arbeiten durchgeführt werden. Z. B. könnte ein Bereich, in dem verschiedene Aktivitäten zur Verpackung von Produkten durchgeführt werden, als ein Arbeitsbereich definiert werden.

Optional

Bereitstellungsdetails

Mengenänderung

Verlustgründe

Name der Nutzercodegruppe, in der die Gründe für Verluste bei der Operation definiert sind. Als Verluste werden während der Bearbeitung verloren gegangene Containereinheiten bezeichnet.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Verlustgrundgruppe" verwenden oder eine neue Gruppe für operationsspezifische Verlustgründe erstellen.

Optional

Verkaufsgrund

Name der Nutzercodegruppe, in der die Verkaufsgründe für die Operation definiert sind. Ein Verkauf ist eine Verringerung der Menge eines Containers. Er wird in der Regel einer Buchungseinheit zugerechnet und durch eine Kontonummer identifiziert.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Verkaufsgrundgruppe" verwenden oder eine neue Gruppe für operationsspezifische Verkaufsgründe erstellen.

Optional

Mengenanpassungsgrund

Name der Nutzercodegruppe, in der die Gründe für die Änderung der Menge eines Containers bei der Operation definiert sind. Mengenanpassungsgründe werden in der Regel zur Beschreibung von Anpassungen nach oben oder unten verwendet, die nicht mit den Bearbeitungsaktivitäten im Zusammenhang stehen. Sie können die Menge eines Containers z. B. nach Beendigung der jährlichen Inventur anpassen.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Mengenanpassungsgrundgruppe" verwenden oder eine neue Gruppe für operationsspezifische Mengenanpassungsgründe erstellen.

Optional

Bonusgrund

Name der Nutzercodegruppe, in der die Bonusgründe für die Operation definiert sind. Ein Bonus ist eine Erhöhung der Menge eines Containers.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Bonusgrundgruppe" verwenden oder eine neue Gruppe für operationsspezifische Bonusgründe erstellen.

Optional

Kaufgrund

Name der Nutzercodegruppe, in der die Kaufgründe für die Operation definiert sind. Ein Kauf bedeutet eine Erhöhung der Menge eines Containers, die in der Regel einer Buchungseinheit, wie etwa der Entwicklungsabteilung zugerechnet wird.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Kaufgrundgruppe" verwenden oder eine neue Gruppe für operationsspezifische Kaufgründe erstellen.

Optional

Standardrollupgrund

Name der Nutzercodegruppe, in der die Rollupgründe für die Operation definiert sind. Änderungen der Containermenge werden auf dem untersten Containerlevel (Kind-Container) erfasst und können mehrere Ursachencodes aufweisen. Die Mengen werden dann auf dem mittleren und obersten Eltern-Containerlevel zusammengefasst. Bei dieser Zusammenfassung wird den Eltern-Containern nur ein Ursachencode zugewiesen. Die Anwendung verwendet den in der Operation referenzierten Rollupgrund, es sei denn, dieser wird vom Benutzer bei der Mengentransaktion überschrieben.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Rollupgrundgruppe" verwenden oder eine neue Gruppe für operationsspezifische Rollupgründe erstellen.

Optional

Defektgründe

Komponentendefektgrund

Name der Nutzercodegruppe, in der die Komponentendefektgründe für die Operation definiert sind. Ein Komponentendefekt bezieht sich auf eine defekte Stücklistenkomponente, die nicht als Verlust in Bezug auf die Menge des betreffenden Containers gewertet wird.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Komponentendefektgrundgruppe" verwenden oder eine neue Gruppe für die operationsspezifischen Komponentendefektgründe erstellen.

Optional

Containerdefektgrund

Name der Nutzercodegruppe, in der die Containerdefektgründe für die Operation definiert sind. Ein Containerdefekt ist eine Containereinheit, die defekt ist, aber nicht als Verlust gezählt wird.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Containerdefektgrundgruppe" verwenden oder eine neue Gruppe für die operationsspezifischen Defektgründe erstellen.

Optional

Nacharbeitsgrund

Name der Nutzercodegruppe, in der die Nacharbeitsgründe für die Operation definiert sind.

Sie können die von der Anwendung bereitgestellte Nutzercodegruppe "Nacharbeitsgrundgruppe" verwenden oder eine neue Gruppe für die operationsspezifischen Nacharbeitsgründe erstellen.

Optional

Details

Versandziel

Named Object Group, die eine Gruppe von Versandzielen darstellt. Ein Versandziel ist ein Named Data Object, das die Fabrik oder den Kunden angibt, an die bzw. den der Container versendet wird. Das Versandziel wird verwendet, um ein bestimmtes Versandziel für die Operation anzugeben. Zum Beispiel muss die Unterzusammenbau-Operation in einer Fabrik ihre Produkte an ein bestimmtes Subunternehmen schicken, oder eine Endmontage-Operation schickt ihre Fertigwaren an ihren Kunden (das Versandziel).

Optional

Erledigungsregel

Liste von Erledigungsregelinstanzen. Verwenden Sie dieses Feld, um eine bestimmte Erledigungsregel für den Arbeitsbereich zu referenzieren.

Optional

Trainingsanforderungsgruppe

Trainingsgruppe, die zur Autorisierung eines Benutzers für die Durchführung einer angegebenen Aufgabe erforderlich ist.

Optional

Druck-Warteschlange

Name des Netzwerkdruckers, der zum Ausdrucken von Containeretiketten im Zusammenhang mit der Operation verwendet wird.

Optional

Attribut

Unterwegs

Bei Aktivierung dieses Attributs wird angenommen, dass die Container an der Operation in Bezug auf die Anmeldung und die Verfolgung zwischen Fabriken und Subunternehmern den Status "Unterwegs" haben. Wenn dieses Attribut aktiviert ist, haben die Container den Status "Unterwegs".

Optional

Lagerort

Wenn dieses Attribut aktiviert ist, ist die Operation ein Lagerort. Wenn aktiviert, ist die Operation ein Lagerort. Eine Lagerbestandsoperation kann ein Schritt eines Arbeitsplans oder eine eigenständige Operation sein.

Optional

Externer Servicepunkt

Wenn dieses Attribut aktiviert ist, handelt es sich bei der Operation um einen externen Servicepunkt, z. B. ein Subunternehmen. Wenn aktiviert, ist die Operation ein externer Servicepunkt. Diese Informationen werden zum Sortieren operationsbezogener Informationen und zur Erstellung entsprechender Berichte verwendet.

Optional

In Verarbeitung

Warteschlange verwenden (deaktiviert)

Gibt an, ob die Operation einen Warteschlangenstatus verwendet, um die Container nachzuverfolgen, die darauf warten (in der Warteschlange), verarbeitet zu werden. Wenn aktiviert, verwendet die Operation einen Warteschlangenstatus. Bei Verwendung einer Warteschlange wird vor der Bearbeitung des Containers eine "Anmelden"-Transaktion ausgeführt, um den Status von "In Warteschlange" in "In Bearbeitung" zu ändern.

Optional

Durchsatzzusammenfassung

Wenn diese Option aktiviert ist, werden die Durchsatzinformationen auf dem obersten Containerlevel erfasst. Der Eintrag im Feld "Durchsatzberichtsebene" bleibt dabei unberücksichtigt.

Optional

Eingehenden abweichenden Container ablehnen

Gibt an, ob Container mit einer oder mehreren offenen Abweichungen nicht für Schritte dieser Operation angemeldet werden können. Dieses Feld ist nur als Bestandteil des separat lizenzierten Moduls "Nonconformance Management" verfügbar.

Optional

Durchsatzberichtsebene

Containerlevel, das von der Anwendung zur Berechnung und Erstellung von Berichten zum Durchsatz bei dieser Operation verwendet wird. Weitere Informationen finden Sie in der Beschreibung von "Durchsatzzusammenfassung".

Erforderlich

Tabelle "Unzulässige Transaktion(en)"

Tabelle mit den Transaktionen, die für diese Operation nicht erlaubt sind.

Optional

Transaktionstyp

Name der Transaktion. Die Liste wird mit den Transaktionen gefüllt, deren Ausführung für die betreffende Operation abgelehnt werden kann, weil sie nicht erlaubt sind.

Optional

Nutzerfelder

Externer Ort

Ort der externen Systems.

Optional

Externer Ort: Typ

Typ des externen Orts.

Optional

Aufbewahrungsalter (Monate)

(Nur Lagerbestandsoperationen.) Die Zeitspanne (in Monaten), die das Los in der "Losaufbewahrung"-Transaktion verbleiben kann.

Optional

Aufbewahrungstyp

(Nur Lagerbestandsoperationen.) Das standardmäßige Datumscodealter, das während der "Losaufbewahrung"-Transaktion verwendet werden soll.

Operationsgruppe

Operationsgruppe, zu der diese Operation gehört.

Integration überspringen

Gibt an, ob die Anwendung alle Transaktionen aus der Integration überspringen soll.

Vorgehensweise zum Definieren einer Operation

Gehen Sie folgendermaßen vor, um eine Operation zu definieren:

1. Wählen Sie Haupt im Menü Modellierung aus. Die Anwendung zeigt die Seite "Modellierung" an.
2. Klicken Sie auf Typ-Operation. Dabei ist "Typ" der Operationstyp (z. B. "Zusammenbau: Geplante Operation"). Die Anwendung zeigt die Seite für die ausgewählte Operation innerhalb der Seite "Modellierung".
3. Klicken Sie auf Neu. Es werden leere Felder zum Definieren einer neuen Instanz angezeigt.
4. Geben Sie einen Namen für die Operation in das Feld Typ-Operation ein. Dabei ist "Typ" der Operationstyp (z. B. "Zusammenbau: Geplante Operation").
5. Geben Sie eine Durchsatzberichtsebene ein.
6. Geben Sie entsprechend Ihren Geschäftsanforderungen optionale Informationen ein. In der Felddefinitionstabelle finden Sie Informationen zu den optionalen Feldern.
7. Klicken Sie auf Speichern. Die Anwendung speichert das Modellierungsobjekt und zeigt eine Erfolgsmeldung an.

Vorgehensweise zum Angegeben eine Transaktion, die für diese Operation nicht zulässig ist

Gehen Sie folgendermaßen vor, um eine Transaktion anzugeben, die für diese Operation nicht erlaubt ist:

1. Führen Sie die Schritte unter "Vorgehensweise zum Definieren einer Operation" aus.

Oder

Wählen Sie eine vorhandene Operationsinstanz aus.

2. Erweitern Sie den Abschnitt Details.
3. Klicken Sie in der Tabelle "Unzulässige Transaktion(en)" auf Neue Zeile hinzufügen. Die Anwendung fügt der Tabelle eine leere Zeile hinzu.
4. Wählen Sie im Feld Transaktionstyp eine Transaktion zur Eingabe aus.
5. Wiederholen Sie ggf. die Schritte 3 und 4, um eine weitere unzulässige Transaktion hinzuzufügen.
6. Klicken Sie auf Speichern. Die Anwendung speichert das Modellierungsobjekt und zeigt eine Erfolgsmeldung an.
