Definieren von Mitarbeitern

Ein Mitarbeiter ist ein Benutzer, der Aktivitäten in der Anwendung ausführt, z. B. die Verwaltung von Modellierungsdefinitionen, das Durchführen von Anfragen, die Verwaltung der Sicherheitsadministration und die Ausführung von Fertigungstransaktionen. Ein Systemadministrator verwendet die Sicherheitsadministrationsfunktionen, um Mitarbeitern Berechtigungen zu erteilen, damit sie auf diese Aktionen zugreifen können.

Jeder Mitarbeiter muss über ein gültiges Anmeldekonto verfügen, und der Name des Mitarbeiters muss mit der ID des Anmeldekontos übereinstimmen. Wenden Sie sich an den Systemadministrator, um die genaue Syntax von Benutzernamen zu erfragen.

Mitarbeiter können auch ohne Benutzerkonto definiert werden. Diese Mitarbeiter können sich jedoch nicht anmelden. Sie können z. B. als der Mitarbeiter eingegeben werden, der eine Container- oder Ressourcentransaktion ausgeführt hat. Beispielsweise kann sich ein Vorarbeiter, der ein gültiges Anmeldekonto (und die entsprechenden Berechtigungen) hat, bei der Anwendung anmelden und auf die Startseite zugreifen. Der Mitarbeitername, der auf der Startseite erfasst wurde, kann der des Vorarbeiters oder der eines anderen Mitarbeiters sein, je nachdem, wer den Container gestartet hat. Dieser Mitarbeiter kann ein Konto haben, dies ist aber nicht zwingend.

Sitzungswerte können für jeden Mitarbeiter eingestellt werden, um die Anzeige für jemanden zu beschränken, der Transaktionen ausführt. Der Mitarbeiter sieht nur, was er sehen soll, und hat eine kürzere Liste von Werten, die er durchsuchen kann. Dies verringert die Suchzeit und bietet weniger Gelegenheiten für Fehler.

Sicherheitsmodell

Das Sicherheitsmodell für die Anwendung basiert auf einem rollenbasierten Zugriffssteuerungsmodell. Der Systemadministrator weist einem Mitarbeiter eine Rollenmitgliedschaft zu, um dessen Zugriff auf die ganze Anwendung oder Teile der Anwendung zu steuern. Wenn Sie eine primäre Organisation und Rollenmitgliedschaften für einen Mitarbeiter angeben, stellen Sie die Sicherheitsrechte für diesen Mitarbeiter ein. Ein Benutzer muss zum Ausführen einer beliebigen Aktion eine Rolle in der Organisation haben, entweder direkt oder indirekt durch Rollenweitergabe.

Rollen werden auf der Seite "Rolle" definiert. Sie können Rollenmitgliedschaften auf der Seite "Mitarbeiter" oder "Rolle" zuweisen. Allerdings können Sie auf der Seite "Rolle" nur Berechtigungen für diese Rolle zuweisen.

Die Opcenter Execution Core-Sicherheitsrichtlinien enthalten ein Kapitel zur Sicherheitsverwaltung. Darin werden die Berechtigungstypen und -modi besprochen und wird besprochen, wie der Authentifizierungs- und der Autorisierungsprozess funktioniert und wie Nutzerberechtigungen überprüft werden.

Standardmitarbeiter

Die Anwendung stellt standardmäßig die folgenden Mitarbeiterdefinitionen zur Verfügung:

• Administrator
• CamstarAdmin
• InSiteAdmin
• System

Verwenden Sie einen dieser Mitarbeiternamen für Ihre erste Anmeldung bei der Anwendung.

Das Standard-Portalmenü wird den Administrator-, CamstarAdmin-, InSiteAdmin- und Systemmitarbeitern in folgenden Situationen automatisch zugewiesen: bei der ersten Implementierung von Opcenter Execution Core oder wenn zu einer neuen Version konvertiert oder aktualisiert wird und Standardinstanzdaten aktualisiert werden. Verwenden Sie das Feld "Portalmenüdefinition" auf der Seite "Mitarbeiter", um anderen Mitarbeitern Portalmenüs zuzuweisen.

Standardrollen

Siemens bietet mehrere vordefinierte Rollen für die Standardorganisation "Corporate". Den Standardmitarbeitern werden Mitgliedschaften in allen oder einigen der Standardrollen zugewiesen. Weitere Standardrollen stehen Benutzern zur Verfügung, die über eine Lizenz für die Änderungsverwaltung verfügen.

Beim Definieren eines Mitarbeiters

Mindestens einer der Standardmitarbeiter muss ein gültiger Active Directory-Benutzer sein, um sich erstmalig im Portal anmelden zu können.

Falls Sie zum ersten Mal Mitarbeiter definieren, erstellen Sie die Mitarbeiterdefinition für sich selbst als "Administrator". Verwenden Sie Ihren Windows-Benutzernamen als Ihren Mitarbeiternamen. Wenn Sie eine Definition für einen anderen Mitarbeiter erstellen, verwenden Sie den Windows-Benutzernamen dieses Mitarbeiters.

Mitarbeiterdefinitionen in der Anwendung werden wie folgt verwendet:

• Als bei Portal angemeldeter Mitarbeiter ist Ihre primäre Organisation die Standardorganisation für Sie. Nur die Organisationen, in denen Sie eine direkte Rolle haben oder über die Rollenweitergabe eine Rolle zugewiesen bekommen haben, sind auf den Portal-Seiten zur Auswahl verfügbar.
• Beim Ausführen einer Datensatzsuche in der Anwendung können Sie den Eigentümer als Teil der Suchkriterien eingeben. Der Eigentümer ist der Mitarbeiter, der mit den zu durchsuchenden Qualitätsdatensätzen verknüpft ist.

Beachten Sie Folgendes:

• "Mitarbeiter" enthält die folgenden optionalen Modellierungsdefinitionen: "Organisation", "Wörterbuch", "Elektr. Unterschrift: Rollengruppe", "Fabrik", "Trainingsplan", "Operation" und "Arbeitsbereich".
• "Mitarbeiter" ist ein optionales Feld in allen Container- und Ressourcentransaktionen.

Beim Definieren von Eskalationsempfängern

Ein Eskalationsempfänger ist diejenige Person, die eine E-Mail-Benachrichtigung erhält, wenn für einen Mitarbeiter in Kürze fällige, fällige oder überfällige Arbeit vorliegt. Sie können z. B. eine E-Mail-Benachrichtigung an den Vorgesetzten eines Mitarbeiters senden, wenn eine Arbeit fällig ist. Sie können Eskalationsempfänger über das Feld "Mitarbeiter" in der Tabelle "Eskalationsempfänger" definieren.

Mit dem Modellierungsobjekt "Änderungsmanagementeinstellungen" können Sie Erinnerungsbenachrichtigungen einrichten, die an Eskalationsempfänger gesendet werden, wenn für einen Genehmiger oder Projektmitarbeiter eine unvollständige Aufgabe vorliegt. Die Anwendung sendet die Erinnerung an den festgelegten Eskalationsempfänger für diesen Mitarbeiter, wenn Sie diesen Erinnerungsbenachrichtigungstyp auswählen. Weitere Informationen finden Sie im Opcenter Execution Core Modeling-Benutzerhandbuch.

Die Anwendung sendet keine E-Mail-Benachrichtigungen, wenn Sie keine Eskalationsempfänger in der Tabelle "Eskalationsempfänger" auswählen. Gewährleisten Sie, dass das Feld "E-Mail-Adresse" in der Instanz des "Mitarbeiter"-Modellierungsobjekts jedes Eskalationsempfängers vollständig ist. Andernfalls erhalten die Empfänger keine E-Mail-Benachrichtigungen.

Vorgehensweise zum Definieren eines Mitarbeiters

Gehen Sie folgendermaßen vor, um einen Mitarbeiter zu definieren:

1. Öffnen Sie die Seite Mitarbeiter. Die Seite "Mitarbeiter" wird innerhalb der Seite "Modellierung" angezeigt.
2. Klicken Sie auf Neu. Es werden leere Felder zum Definieren einer neuen Instanz angezeigt.
3. Geben Sie in das Feld Mitarbeiter den Namen des Mitarbeiters ein.
4. Geben Sie in das Feld Zugriffsebene die Zugriffsebene für den Mitarbeiter ein.
5. Geben Sie entsprechend Ihren Geschäftsanforderungen optionale Informationen ein. In der Felddefinitionstabelle finden Sie Informationen zu den optionalen Feldern.
6. Klicken Sie auf Speichern. Die Anwendung speichert das Modellierungsobjekt und zeigt eine Erfolgsmeldung an.
