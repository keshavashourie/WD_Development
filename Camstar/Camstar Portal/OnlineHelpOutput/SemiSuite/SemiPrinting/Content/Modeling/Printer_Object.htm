Defining Printers

The Printer object defines physical printers available to the system. Printer instance names must match the name of the physical printer exactly. If the name does not match, the printing system cannot connect to the physical printer.

Note: If the physical printer is on a network print server, the instance name need not contain the print server name. The print server name is defined in the Print Server Name field of the modeled Printer.

Printer Page Field Definitions

This table defines the fields on the Printer page.

Field

Definition

Type

Printer

Name for this printer. Must match the name of the physical printer.

Required

Description

Short description of the modeling object. You can enter a maximum of 255 characters.

Optional

Notes

Relevant comments about the modeling object. You can enter a maximum of 2000 characters.

Optional

Details

Setup Access

Sets the employee's access to this modeling object.

Optional

User Fields

In Use Timeout (Minutes)

Allotted time for a print request to complete before the printer is released to process the next print request. Value of 0 or less means no timeout. The default value is set to 5 minutes.

Optional

Last Printing Timestamp

Displays the timestamp of the last printing.

Display Only

Printer Type

Defines the print target type, for example: LABEL, REPORT, and TEXTFILE.

Required

Printing Interval

Interval to ensure that the printer is not used within a time period after it last printed. Value of 0 or less means no waiting time is required. For Printing Automation, this value will be ignored.

Optional

Print Server Name

Name of a print server if the physical printer is connected to one.

Optional

How to Define a Printer

Follow these steps to define a Printer:

1. Open the Printer page. The Printer page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter a name for the new printer instance in the Printer field.
4. Select the Printer Type.
5. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
6. Click Save. The application saves the modeling object and displays a success message.
