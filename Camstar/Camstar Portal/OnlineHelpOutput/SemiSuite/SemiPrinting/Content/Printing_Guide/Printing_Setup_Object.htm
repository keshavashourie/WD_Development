Defining Printing Setups

The Printing Setup object enables you to specify output format, queries, and other key print request processing factors.

Printing Setup Page Field Definitions

This table defines the fields on the Printing Setup page.

Field

Definition

Type

Printing Setup

Name of this instance of the Printing Setup object.

Required

Description

Short description of the modeling object. You can enter a maximum of 255 characters.

Optional

Notes

Relevant comments about the modeling object. You can enter a maximum of 2000 characters.

Optional

Details

Setup Access

Sets the employee's access to this modeling object.

Optional

Printing Type

Defines the print target type, for example: LABEL, REPORT, and TEXTFILE. This value affects the choice of available printers during a print transaction.

Required

Printing Connection

Link to a printing connection instance. This is only necessary if printing type has a value of "REPORT."

The printing system will pass the printing connection field values into the report template to enable it to log on to a database.

Optional

Filename

Location and filename of the template to be used. Can be a local or network location.

• LABEL – Location and filename of the label template to use. The template can be located on a local or network connection, for example, D:\PRINTSYSTEM\TEMPLATES\WAFERLBL.ZPL.
• REPORT – Location and filename of the report template to use. The template can be located on a local or network location, for example, \\ShareServer\Rpttemplates\Traveler.rpt.
• TEXTFILE – Output location and filename of the target text file. This can be located on a local or network connection, for example, D:\PrintSystem\Output\TestText.txt. Additionally, text files can be configured to be dynamically named based on specific formatting, for example, D:PrintSystem\Output\#Container#_File.txt. The configuration of the location and filename of the text file template is maintained using the reserved print parameter name (TEXTFILE_TEMPLATE). Refer to "Print Parameters" for information.

Required

Number Of Copies

Number of copies to be printed. Defaults to 1.

Required

Pre-Transaction SQL

SQL that will execute before any of the printing setup parameters are resolved. It enables the user to execute SQL that produces temporary output, for example, a temporary table to be used during parameter resolution.

Optional

Post-Transaction SQL

SQL that will execute after all of the parameters are resolved, for example, a statement to delete a temporary table.

Optional

Enable Box Count Offset

Check box to determine if the box number parameter will be continuous across multiple print sets instead of being reset.

If Enable Box Count Offset is not selected:

• Printset 01 Boxnumber Parameter Value 1
• Printset 02 Boxnumber Parameter Value 1
• Printset 03 Boxnumber Parameter Value 1

If Enable Box Count Offset is selected:

• Printset 01 Boxnumber Parameter Value 1
• Printset 02 Boxnumber Parameter Value 2
• Printset 03 Boxnumber Parameter Value 3

Refer to "Print Set Calculation" for information.

Optional

Parameters grid

List of parameters used in print execution. Refer to "Print Parameters" for information on how parameters are resolved.

Optional

Param Name

Parameter name that will be used or sent in the output print. Refer to "Print Parameters" for the list of available system parameters.

Note: This field is required if a parameter is added.

Optional

Param Type

Valid values for Parameter Type:

• REQUIRED – A value is required.
• OPTIONAL – A value is not necessary.
• INTERNAL – The value is determined by the system. This parameter will not be displayed to the user.

When using the Ad-Hoc Printing form:

• If Parameter Type = REQUIRED, the parameter will be shown in bold (indicating that it is required field).
• If Parameter Type = OPTIONAL, the parameter will be shown.
• If Parameter Type = INTERNAL, the parameter will not be displayed.

Note: This field is required if a parameter is added.

Optional

Param Value

Default parameter value.

Optional

Param Value Is Dynamic

Check box that denotes if the parameter value is to be resolved internally by the XML server. The parameter value has to be of a valid Designer notation for this check box setting to be effective.

Optional

Send To Printer

The application does not use this field.

 

Display Text

Displays the text for a parameter name. If missing, the parameter name will be used for display.

Optional

Formula Code

String formatting function that can be applied to parameter values. Available functions are:

• RPAD – Right pads the parameter value. Length Value is defined in formula Param01, for example, 10.
• LPAD – Padding character defined in formula Param02, for example X.
• TRIM – Trims down the length of the parameter value. Length value is defined in Formula Param01.
• Substring – Extracts a substring of the parameter value. Length value is defined in Formula Param01. Starting index of string is defined in Formula Param02.

Optional

Formula Param 01

Used in conjunction with the formula codes.

Optional

Formula Param 02

Used in conjunction with the formula codes.

Optional

Formula Param 03

Used in conjunction with the formula codes.

Optional

Queries grid

List of queries used during parameter resolution.

Optional

Query Text

Query text – SQL query that is executed to produce parameter values.

Note: This field is required if a query is added.

Optional

Skip Printing If No Records

Flag to denote whether to skip or drop the print job if there are no records produced by the query.

Optional

Subsets grid

List of any subset printing setups triggered at the print set level.

Optional

Subset Printing Setup

Contains supplementary printing requirements for each print set. For example, a box may only need one label but each item within the box may also need a label. The items within the box would be covered by the Subset Printing Setup. Typically used for labels.

Note: This field is required if a subset is added.

Optional

How to Define a Printing Setup

Follow these steps to define a Printing Setup:

1. Open the Printing Setup page. The Printing Setup page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter a name for the new instance in the Printing Setup field.
4. Enter a Printing Type.
5. Enter the Filename.
6. Enter the Number of Copies.
7. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
8. Click Save. The application saves the modeling object and displays a success message.
