Create Carrier Container with "scsDBLotStartSimple" Service

Carrier Containers can be created using the “scsDBLotStartSimple” service if the Carrier is specified in the Request XML. When the Carrier Container is created using “scsDBLotStartSimple” service, you can optionally assign the Carrier Container its own Start Reason, Owner and Level values by adding the following scripts to the XML request:

<scsCarrierStartReason><__name><![CDATA[Carrier Start Reason]]></__name></scsCarrierStartReason>

<scsCarrierOwner><__name><![CDATA[Carrier Owner]]></__name></scsCarrierOwner>

<scsCarrierLevel><__name><![CDATA[Carrier Level]]></__name></scsCarrierLevel>


If the Start Reason, Owner and Level values are not passed in with the Request XML, the application determines whether there are Shop Floor Integration Settings associated with the carrier's carrier family. If there are Shop Floor Integration Settings associated with the carrier family, the application uses these Start Reason, Owner, and Level values. If the Start Reason, Owner, and Level values are not specified by the Request XML or by any Shop Floor Integration Settings, the application uses the values specified on the Lot Start - Bulk (HPE) page or the Work Order Dispatch (HPE) page.

To summarize the priority, the application will use the Start Reason, Owner and Level fields based on the following precedence:

1. Request XML script,
2. Shop Floor Integration Settings specified in the Carrier Family,
3. If you are using "Lot Start - Bulk (HPE)" page or "Work Order Dispatch (HPE)" page. This is specified at user interface level and not automation.
Note: If you are utilizing Numbering Rules to create containers at the automation layer (using DBLotStartSimple), you must ensure that appropriate Numbering Rule has been configured at either Container Level or PN. The application displays an error message if no numbering rule is detected. The following setups must be applied:
• Numbering Rule must be configured at PN/ Product Family/ Service Setup.
• Numbering Rule must be configured at Child's Container Level if "Generate Child Automatically" was set to true.
• Child's Container Level must be provided if "Generate Child Automatically" was set to true.

Sample of Request XML for Carrier Container Creation with "scsDBLotStartSimple" Service

The request XML below shows a sample of starting carrier container using scsDBLotStartSimple service with the specified Level, Owner and Start Reason values.


<__InSite __version="1.1" __encryption="3">

<__service __serviceType="scsDBLotStartSimple">

<__utcOffset><![CDATA[-05:00:00]]></__utcOffset>

<__inputData>

<Carrier>

<__name><![CDATA[Carrier Name]]></__name>

</Carrier>

<ContainerName><![CDATA[Parent Container Name]]></ContainerName>

<ContainerNamesStr><![CDATA[Child Container Name(s) String with bar(|) separation]]></ContainerNamesStr>

<Factory>

<__name><![CDATA[SGP]]></__name>

</Factory>

<MfgOrder>

<__name><![CDATA[Work Order Name]]></__name>

</MfgOrder>

<Owner __CDOTypeName="Owner">

<__name><![CDATA[PROD]]></__name>

</Owner>

<ProcessSpec>

<__name><![CDATA[ASSYM001]]></__name>

<__rev><![CDATA[1]]></__rev>

<__useROR><![CDATA[false]]></__useROR>

</ProcessSpec>

<Product>

<__name><![CDATA[PA-001]]></__name>

<__useROR><![CDATA[true]]></__useROR>

</Product>

<scsChildCount><![CDATA[3]]></scsChildCount>

<scsDefaultChildLevel>

<__name><![CDATA[LOT]]></__name>

</scsDefaultChildLevel>

<scsDefaultChildQty><![CDATA[1]]></scsDefaultChildQty>

<StartReason __CDOTypeName="StartReason">

<__name><![CDATA[NORMAL]]></__name>

</StartReason>

<Level>

<__name><![CDATA[LOT]]></__name>

</Level>

<scsCarrierStartReason>

<__name><![CDATA[ReqCarrier]]></__name>

</scsCarrierStartReason>

<scsCarrierOwner>

<__name><![CDATA[ReqCarrierOwner]]></__name>

</scsCarrierOwner>

<scsCarrierLevel>

<__name><![CDATA[ReqCarrierLevel]]></__name>

</scsCarrierLevel>

</__inputData>

<__execute>

</__execute>

<__requestData>

<CompletionMsg>

</CompletionMsg>

</__requestData>

</__service>

</__InSite>
