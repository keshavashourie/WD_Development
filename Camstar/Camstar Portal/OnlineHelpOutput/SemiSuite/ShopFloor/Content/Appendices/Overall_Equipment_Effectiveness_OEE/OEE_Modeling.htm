Defining the OEE 

Modeling is the part of Opcenter Execution Semiconductor (Opcenter EX SM) used to define and maintain the elements of a manufacturing facility model. These elements contain data such as products, operations, specifications, and workflows that are used to describe and control processing activities. The main modeling objects for OEE are described in this section.

Defining OEE Settings

The Real Time OEE Duration field on the OEE Settings modeling object enables you to set the time span for which the application calculates real time OEE. Options include:

• Day
• Shift
• Work

You can assign OEE Settings to these modeling objects:

• Factory
• Equipment
• Equipment Family
• Resource Status Codes
• Manufacturing Calendars

Defining a Factory

A Factory is any division, department, or group that is separated for accounting and reporting purposes. An enterprise can contain one or more factories.

Assigning OEE Settings on the Factory

Select the OEE Settings check box in the OEE section if you want to set the time span for which the application calculates Overall Equipment Effectiveness (OEE) for the selected factory. You can also assign OEE Settings on the Equipment and Equipment Family.

These rules apply when assigning OEE Settings:

• The OEE Settings assigned on the Equipment modeling object take precedence over the OEE Settings assigned on the Equipment Family modeling object.
• The OEE Settings assigned on the Equipment Family modeling object take precedence over the OEE Settings assigned on the Factory modeling object.

Defining Equipment and Equipment Families

There are five subclasses of Equipment and Equipment Family in Opcenter Execution Semiconductor. The five subclasses of Equipment and Equipment Family are:

• Assembly Equipment
• Back Grind Equipment
• Test Equipment
• Wafer Equipment
• Wafer Sort Equipment

Equipment modeling objects define the equipment available for manufacturing operations. An Equipment Family provides a way to categorize equipment based on their attributes and according to your business requirements. You can use an equipment family as a filter for various shop floor transactions.

When Defining an Equipment and an Equipment Family for OEE

Select the Include in OEE Data check box if you want the application to accumulate OEE summary data for the resource.

You can use the Ideal Cycle Times grid to define the ideal cycle time for a product or product family. These rules apply when defining an ideal cycle time:

• The ideal cycle time defined on the Equipment page takes precedence over the ideal cycle time defined on the Equipment Family page.
• You must specify a product (PN) or a product family for each ideal cycle time defined in the Ideal Cycle Times grid.
• You can specify a product (PN) or product family only once in the Ideal Cycle Times grid. The product (PN) or product family must be unique for each ideal cycle time.
• The ideal cycle time defined for a product (PN) takes precedence over the ideal cycle time defined for a product family.

Defining Resource Status Codes

A Resource Status Code describes the status that can be assigned to an equipment, both initially at setup and later for each status change. Some examples could be Available, Reserved, and Stored.

When Defining a Resource Status Code for OEE

The application must summarize resource status code data for each shift to perform OEE calculations. The application summarizes the data at the end of each shift using a stored procedure to calculate the time the equipment was in each status.

You can use the OEE Loss Category field on the Resource Status Code page to indicate the type of loss for each scheduled downtime. Options include:

• Availability - Indicates the time in this resource status code counts as availability loss for a resource.
• Performance - Indicates the time in this resource status code counts as performance loss for an equipment.
• Schedule - Indicates the time in this resource status code counts as schedule loss for a resource.

Defining Manufacturing Calendars

A Manufacturing Calendar translates the timestamp for a transaction into a specific manufacturing date and shift.

When Defining a Manufacturing Calendar for OEE

You can use the Non-scheduled Time field on the Calendar Shift grid to enter the time resources are not scheduled during a shift. Non-scheduled time cannot exceed the shift's duration.
