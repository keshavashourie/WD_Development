Process Timers in Opcenter Execution Semiconductor

Process Time Enforcement is implemented with process timers. All process timers are configured with a minimum time, a maximum time, or both. A process timer can be configured with disposition actions that are executed automatically by the application when a process timer violation occurs.

Opcenter Execution Semiconductor uses the standard Opcenter Execution Core Process Time Enforcement feature with minor modifications.

Changes for Opcenter Execution Semiconductor
1. Future Hold has been added as a disposition action. For Opcenter Execution Semiconductor, the disposition actions include:
a. Business Rule
b. Production Event
c. Rework
d. Move Non-Std
e. Hold
f. Future Hold
2. Track In, Track Out, and Check Sheets were added to the list of transactions that support process timers. For Opcenter Execution Semiconductor, the transactions that support process timers by default include:
a. Move In
b. Move Out
c. Track In
d. Track Out
e. E-Procedure (tasks)
f. Check Sheets (tasks)
3. The WIP Main Lots tab grid displays any process timers for the selected lot.
4. The Dispatch List Lot(s) grid and the Lot tab grid on the Equipment WIP Dispatch page contain a column for process timer display.

Process Timer Search Page

The Process Timers Search page is an Opcenter Execution Core feature that enables you to search for and view all current and historical process timers. It also enables you to stop a process timer. Opcenter Execution Semiconductor uses this page as is, without any modifications. Process Timer Search is available under the Opcenter Execution Semiconductor main menu Search option. Refer to the Opcenter Execution Semiconductor Shop Floor Guide for information on the Process Timer Search page.

When a Process Timer Prevents Track In

Within standard Opcenter Execution Semiconductor processing, a lot cannot be processed via a Move Non Std or Rework transaction while the lot is tracked into an equipment resource. It is possible for a lot to be at a Track In transaction when a timer is stopped and the timer has failed to meet its time limits. This would be a problem if the process timer is configured to complete the transaction at which it is stopped and then Track In to a Rework or Move Non-Std step. To avoid this problem, the application under these circumstances is designed to bypass the Track In at which the process timer stopped and complete the disposition actions (Rework or Move Non-Std, for example) specified in the process timer.
