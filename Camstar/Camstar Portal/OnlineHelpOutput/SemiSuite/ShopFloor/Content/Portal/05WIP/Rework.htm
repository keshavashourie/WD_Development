Rework

The Rework transaction enables you to move a container from the current workflow step to another workflow step so that certain procedures can be repeated or additional work can be completed. Rework includes the options of bypassing or skipping Lot Move Out logic such as Yield Off Rejects and Split Bins.

Before Using Rework

Rework reason codes should be configured before performing a rework transaction. The application prevents you from executing the rework transaction if you enter a rework reason not associated with the container's current operation.

When Using Rework

The following rules apply when using the Rework transaction:

• The lot must be in a WIP step.
• The lot must not be processing in the equipment.
• You must select the Cancel WIP Tracking check box before proceeding to the next step if an insertion has been created but is not completed or canceled.
• The process spec’s object type will be verified against the service’s object type. This is to ensure the right service is used to transact the lot.

Rework Maximums and Automatic Holds

A step can be configured with a Max Rework Count. A Max Rework Count is the maximum number of times a lot may be reworked and transacted through the step before being automatically placed on hold. These things happen when a Max Rework Count is exceeded:

• The application places the lot on hold.
• The application moves the configured Rework Hold Reason to the hold reason.
• The application resets the rework counter if the Reset Rework Count check box was selected during configuration.
Note: Refer to the Opcenter Execution Semiconductor Modeling Guide for information.

Rework Page Field Definitions

This table defines the fields on the Rework page.

Field

Definition

Selection Id

ID for a lot, carrier, batch, or piece of equipment.

Employee

Employee performing this transaction if different than the user currently logged in.

Lots grid

Display-only grid that displays the details of the lot.

Trigger Move In

Flag indicating whether to trigger Move In. Move In is required if the lot’s current Operation’s Use Queue flag is set to true and a Move In transaction has not been carried out.

Cancel WIP Tracking

Flag used as an acknowledgment that the lot’s insertion is required to be canceled before moving out.

This flag must be true if the lot has an insertion and has yet to be completed with at least one required process. It must be false for all other scenarios.

Yield Off Rejects

Flag indicating whether to yield off the rejects collected at the step plus defects if the Spec’s Yield Off Defects flag is set to true.

This flag can only be set to true if the insertion has been completed.

Rework Step Type

Field used to filter down the To Workflow Step selection list. Valid values include:

• NEXTSTEPS – Returns the steps ahead of the current step. For WIP Move Non Standard, the standard paths will be used to determine the next steps whereas for Lot Rework the rework paths will be used.
• PREVIOUSMOVES – Returns to the steps the lot previously moved out from.
• PREVIOUSSTEPS – Returns the steps before and including the current step.
• WIPSTEPS – Returns all the WIP steps within the lot’s current WIP Workflow.

Rework Step

(To Workflow Step)

Required field to specify the WIP step to which the lot should move. This value must not be the same as the lot’s current step. Valid steps are taken from the lot’s current workflow.

The application selects a rework path If a value is not entered. It raises an error if no rework path is found. This allows path selectors to be used to select the rework step.

Rework Path

Optional field to specify the path to which the lot should move. This field will overwrite the To Workflow Step.

Rework Reason

Required field to specify the reason for rework.

Note: The list of available rework reasons is based on the Rework Reason Group assigned to the operation where the lot resides.

Rework End Step

Step at which the current rework ends. When a lot passes the last Rework End step with no active rework left, it will no longer be marked as In Rework. It will only be submitted to the Rework Re-Entry step if no valid next step is found in the workflow. Additionally, when the lot reaches the inventory step, it will no longer be marked as In Rework.

Rework Re-Entry Step

Step to which the lot will return. The lot will only be returned to the Rework Re-Entry step if no valid next step is found in the workflow.

Note: This step is only used if the Move transaction cannot determine the next step.

Show/Hide additional fields

Comments

Additional information or instructions. The field accepts a maximum of 255 characters. The application truncates the data if the comments exceed 255 characters.
