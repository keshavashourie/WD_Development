Lot Start - Bulk (HPE)

The Lot Start - Bulk (HPE) page offers functionality to start a parent with child containers, a carrier with child containers, or to start individual containers without any parent or carrier.

Note: Lot Start - Bulk (HPE) is empowered by High Performance Engine (HPE) to increase larger transaction efficiency as the application processes transactions on the database rather than the application server. Refer to Opcenter™ Execution Core Technical Reference: High Performance Engine for information.
When Naming Parent and Child Containers

A unique name must be provided for the Parent and all Child containers. By default, the application utilizes the parent container name to name the child containers. The default method is to append – 01, - 02, and so on. to the parent name for each child container. However, additional naming options are available.

When Generating a Parent Container Name

Leaving the Lot ID field empty, or entering a unique value, the application will search for an appropriate Numbering Rule to use for the parent and children. The application uses the numbering rules associated with the parent container to generate the container name. Numbering rules may be specified for multiple modeling object instances associated with the container. Numbering rules follow this default precedence:

1. Product
2. Product Family
3. Service Setup

Refer to the Opcenter Semiconductor Modeling User Guide or the Opcenter Execution Core Modeling User Guide for information on defining numbering rules.

When Generating Child Container Names

You must associate a numbering rule with the container level you want to use when generating child container names automatically. The application displays a warning message when you perform the following steps:

• You select a container level that does not have an associated numbering rule
• You select the Generate Child Names Automatically check box
• Click Add.

The application uses multiple criteria to determine child container names. There are four possible scenarios:

• When both the Generate Names Automatically and Generate Child Names Automatically check boxes are cleared (the default setting), the application assigns each child container the name specified in the Container field and appends -01, -02, etc. to the end. Example:
• MyContainer – 01
• MyContainer – 02
• MyContainer – 03
• When the Generate Names Automatically check box is selected and the Generate Child Names Automatically check box is cleared, the application assigns each child container name the parent container name generated by the associated numbering rule and appends -01, -02, and so on to the end. Example:
• c_0001 – 01
• c_0001 – 02
• c_0001 – 03
• When the Generate Names Automatically check box is cleared and the Generate Child Names Automatically check box is selected, the application assigns each child container the name specified in the Container field and appends the numbering rule associated with the child container Level to the end. Example:
• MyContainersCC0001
• MyContainersCC0002
• MyContainersCC0003
• When both the Generate Names Automatically and Generate Child Names Automatically check boxes are selected, the application assigns each child container a concatenation of the generated parent and child numbering rules. Example:
• c_0002CC0003
• c_0002CC0004
• c_0002CC0005
Lot Start - Bulk (HPE) Page Field Definitions

This table defines the fields on the Lot Start - Bulk (HPE) page.

Field

Definition

Type

Lot Id

Lot identifier. The application generates a lot ID if it is left blank. The child container or container names displayed in the Child Container/Container grid on this page will be generated to follow this default name or entered name based on the resolved numbering rule.

Optional

Start Reason

Indicates the reason a lot is being created for example, Engineering, Order and Reclaim.

Required

Owner

Person or team responsible for the lot. The application uses the product’s Default Start Owner if the owner field is left blank. Typical values include Manufacturing, Engineering, and Research and Development

Required

Factory

Division, department, or group within an Enterprise that is separated for accounting and reporting purposes. The Factory field on the Lot Start and Lot Create pages represents the factory in which the lot is started. The Lot Start and Lot Create pages use the factory associated with the login user if Factory is left blank.

Required

Product

Product used to start the containers.

Required

Workflow (Inventory Area)

Inventory workflow used to begin processing the lot. The application uses the product's Default Start Location if Inventory in Workflow Area is left blank. Object Category and Object Type on the selected workflow must match those on the transaction to ensure that the correct transaction and start location are used.

Required

Workflow Step (Inventory Location)

Inventory step in which to start processing the lot. The application uses the product’s Default Start Location to retrieve the step if it is left blank. The step's underlying spec Object Category and Object Type must match the transaction's Spec Object Category and Spec Object Type. This is to ensure that the right service is used to start the lot in the right location.

Required

Work Order

Work order used to start the container or child container. Work Orders usually consist of a product manufacturing request that is typically originated to fulfill a sales or inventory requirement.

Optional

Process Spec

Field to select a Process Spec with which to schedule a lot. A process spec is used to track lots after they move out of Inventory and into WIP processing. It specifies the workflow steps to execute and any parameters and variations on workflow steps. The Work Order’s process spec will be used if a process spec value is not entered.

Note: You must select the specific revision configured in Process Spec List of the product.

Optional

First WIP Step Workflow

Workflow or sub-workflow step in which the lot should begin WIP processing. Selection of the step results in population of both the First WIP Step Workflow and the First WIP Step fields.

Optional

First WIP Step

First step within the selected First WIP Step Workflow where lot begins processing after Lot Schedule Preparation or Lot Schedule Release.

Display Only

You are able to add child containers if the quantity is equal or less than the number of slots or positions on the carrier. Refer to the Opcenter Execution Semiconductor Execution Modeling Guide for information on carriers, carrier families, and carrier positions.

You can optionally select a Carrier that has Carrier Family configured with Shop Floor Integration Settings. This will allow the Carrier to inherit the Start Reason, Level and Owner fields.

Level

Required

Auto Prepare

Check box indicating whether to automatically prepare the submitted container for scheduling. Selecting this check box calls the appropriate HPE Lot Schedule Preparation service.

Optional

Individual Containers Only

Check box to start individual containers without any parent or carrier. Selecting this check box will allow you to create a high-volume of individual containers without parent or carrier. Carrier field will be disabled once the check box is selected. The Child Count field will automatically be renamed to Container Count and Child Containers grid will automatically renamed to Containers grid. Refer to the " How to a Start Parent or Carrier with Children Containers" for steps to create individual containers only.

How to a Start Parent or Carrier with Children Containers

Follow these steps to start a parent or carrier with child containers:

1. Open the Lot Start - Bulk (HPE) page from the Inventory menu.
2. Enter a name for the container in the Lot Id field. You may specify a unique container name manually, or a numbering rule can be configured in lieu of entering a value.
3. Select the Start Reason field. The selected reason appears in the Start Reason field.
4. Select the Owner field. The selected owner appears in the Owner field.
5. Select the Factory field.
6. Select the Product field.
7. Select the Workflow (Inventory Area).
8. Select the Workflow Step (Inventory Location).
9. Select the Process Spec field.
10. Select the Level field. The selected level appears in the Level field.
11. If you want to start child containers with Carrier, select carrier in Carrier field. You can optionally select a Carrier that has Carrier Family configured with Shop Floor Integration Settings. This will allow the Carrier to inherit the Start Reason, Level and Owner fields.
12. In the Child Container Info section, enter a Qty for the child containers.
13. Enter the number of child containers to create in the Child Count field and click the Add button. The application loads child containers based on the entered number into the Child Containers grid.
14. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
15. Click Submit. The application displays a status message confirming the container started successfully.
How to Start Individual Containers in Bulk

Follow these steps to start individual containers in bulk:

1. Open the Lot Start - Bulk (HPE) page from the Inventory menu.
2. Follow steps 2 -10 from the " How to a Start Parent or Carrier with Children Containers".
3. Checked the Individual Containers Only check box.
4. Enter a Qty for the child containers.
5. Enter the number of containers to create in the Container Count field and click the Add button. The application loads containers based on the entered number into the Containers grid.
6. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
7. Click Submit. The application displays a status message confirming the container started successfully.
