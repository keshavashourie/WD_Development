Work Order Dispatch (HPE)

The Work Order Dispatch (HPE) page offers functionality to start a parent with child containers, a carrier with child containers or to only start high-volume of individual containers against a selected work order. The page displays a grid of work orders based on priority and the process allow two types of parent containers to be created. The typical parent container is based on the selected Work Order. Additionally, the parent will be based on the selected carrier. The selected carrier takes precedence over the selected Work Order when naming the parent. The Work Order Dispatch process is intended to provide additional functionality related to "Single Wafer (Item) Tracking ".

Note: Work Order Dispatch is empowered by High Performance Engine (HPE) to increase larger transaction efficiency as the application processes transactions on the database rather than the application server. Refer to Opcenter™ Execution Core Technical Reference: High Performance Engine for information.

Hybrid HPE Enabled

In order to support large volumes of child containers at the WIP Main level, you have the option to allow the application to utilize hybrid High Performance Engine (HPE). You may enable the "Hybrid HPE Enabled" check box within the Factory modeling page. Checking this box will allow the WIP Main processes (Move In, Track In, Track Out, Move Out) to utilize available HPE sub-service transactions (if any) together with the standard transactions. Refer to Opcenter™ Execution Core Technical Reference: High Performance Engine for information.

When Using Opcenter Semiconductor Work Order Dispatch (HPE)

You must first define a work order using the Work Order modeling page before it can be populated in the Work Order grid in Work Order Dispatch (HPE) page. Refer to the Opcenter Execution Semiconductor Modeling Guide for information on defining Work Order modeling object.

Only work orders defined with a quantity will appear in the Work Order grid. If a work order is defined with a quantity of zero, the application assumes the order has been fulfilled and will not be displayed in the order. You must enter a quantity to the work order, save, and refresh the Work Order grid to view the updated list.

Refreshing the Work Orders Grid

The Work Orders grid will automatically refreshed when the page is loaded and after each submission. You must refresh the Work Order grid to view the updated or modified work orders and to get any recently added work orders. Refreshing the grid is especially important when someone else is entering work orders from a different location.

When Naming Parent and Child Containers

A unique name must be provided for the Parent and all Child containers. By default, the Parent container will be named the same as the selected Work Order. This value may be changed manually by the user.

By default, the application utilizes the parent container name to name the child containers. The default method is to append – 01, - 02, and so on to the parent name for each child container. However, additional naming options are available.

When Generating a Parent Container Name

Leaving the Lot ID field empty, or entering a unique value, the application will search for an appropriate Numbering Rule to use for the parent and children. The application uses the numbering rules associated with the parent container to generate the container name. Numbering rules may be specified for multiple modeling object instances associated with the container. Numbering rules follow this default precedence:

1. Product
2. Product Family
3. Service Setup

Refer to the Opcenter Semiconductor Modeling User Guide or the Opcenter Execution Core Modeling User Guide for information on defining numbering rules.

When Generating Child Container Names

You must associate a numbering rule with the container level you want to use when generating child container names automatically. The application displays a warning message when:

• You select a container level that does not have an associated numbering rule,
• You select the Generate Child Names Automatically check box, and
• Click Add.

The application uses multiple criteria to determine child container names. There are four possible scenarios:

• When both the Generate Names Automatically and Generate Child Names Automatically check boxes are cleared (the default setting), the application assigns each child container the name specified in the Container field and appends -01, -02, and so on to the end. Example:
• MyContainer – 01
• MyContainer – 02
• MyContainer – 03
• When the Generate Names Automatically check box is selected and the Generate Child Names Automatically check box is cleared, the application assigns each child container name the parent container name generated by associated numbering rule and appends -01, -02 and so on to the end. Example:
• c_0001 – 01
• c_0001 – 02
• c_0001 – 03
• When the Generate Names Automatically check box is cleared and the Generate Child Names Automatically check box is selected, the application assigns each child container the name specified in the Container field and appends the numbering rule associated with the child container Level to the end. Example:
• MyContainersCC0001
• MyContainersCC0002
• MyContainersCC0003
• When both the Generate Names Automatically and Generate Child Names Automatically check boxes are selected, the application assigns each child container a concatenation of the generated parent and child numbering rules. Example:
• c_0002CC0003
• c_0002CC0004
• c_0002CC0005

How to Start Parent and Child Containers using Work Order Dispatch (HPE) page

Follow these steps to start Parent and child containers for a selected work order:

1. Open the Work Order Dispatch page from the Inventory menu. The Work Order Dispatch page appears with a list of current work orders displayed in the grid.
2. On the Work Order grid, select the row of work order to start.
3. Enter a name for the container in the Lot Id field. By default, the application populates default name based on the work order selected, you can specify a unique container name manually. Or a numbering rule can be configured in lieu of entering a value.
4. Select the Start Reason field. The selected reason appears in the Start Reason field.
5. Select the Workflow (Inventory Area).
6. Select the Workflow Step (Inventory Location).
7. Select the Owner field. The selected owner appears in the Owner field.
8. Select the Process Spec field.
9. Select the First WIP Step Workflow field.
10. Select the Level field. The selected level appears in the Level field.
11. Select the Factory field.
12. Enter a Qty for the child containers.
13. Enter the number of child containers to be created in the Child Count field and click the Add button. The application loads child containers based on the number entered into the Child Containers grid.
14. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
15. Click Submit. The application displays a status message confirming the container started successfully. If the all of the order's quantity has been fulfilled, application removes the work orders from the list.
How to Start Carrier and Child Containers using Work Order Dispatch (HPE) page

Follow these steps to start Carrier and child containers for a selected work order:

1. Follow step 1 - 11 from the "How to Start Parent and Child Containers using Work Order Dispatch (HPE) page".
2. Select a Carrier field. Refer to the Carrier field definition for more information on the field. You can optionally select a Carrier that has Carrier Family configured with Shop Floor Integration Settings. This will allow the Carrier to inherit the Start Reason, Level and Owner fields.
3. Enter a Qty for the child containers.
4. Enter the number of child containers to be created in the Child Count field and click the Add button. The number of the Child Count entered must be equal or less than number of slots or positions on the carrier. The application loads child containers based on the number entered into the Child Containers grid.
5. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
6. Click Submit. The application displays a status message confirming the containers started successfully. If the all of the order's quantity has been fulfilled, the application removes the work orders from the list.
How to Start Individual Containers using Work Order Dispatch (HPE) page

Follow these steps to start individual containers using Work Order Dispatch (HPE) page:

1. Follow step 1 - 11 from the "How to Start Parent and Child Containers using Work Order Dispatch (HPE) page".
2. Check the Individual Container Only check box. Carrier field will automatically be disabled once the check box is selected. The Child Count field will automatically renamed to Container Count and Child Containers grid will automatically renamed to Containers grid.
3. Enter a Qty for the child containers.
4. Enter the number of child containers to be created in the Container Count field and click the Add button. The application loads containers based on the number entered into the Containers grid.
5. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
6. Click Submit. The application displays a status message confirming the containers started successfully. If the all of the order's quantity has been fulfilled, the application removes the work orders from the list.
