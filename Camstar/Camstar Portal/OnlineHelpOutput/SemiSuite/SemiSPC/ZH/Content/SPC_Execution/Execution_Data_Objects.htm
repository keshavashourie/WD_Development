SPC 数据对象

Opcenter Execution Semiconductor 使用双确认循环来执行 SPC。两个已命名数据对象 (NDO) 支持 SPC：

1. SPC 事务数据—对于执行的每个 SPC 设置，系统会在 SPC 事务数据中创建一条记录。每个 SPC 事务数据实例都有两组信息：
a. SPC 前执行数据—与执行内容有关的信息，包含：SPC 设置、用户和事务时间戳、批次、设备、事务名称和已解析参数。
b. SPC 执行后数据 — 已配置的 SPC 引擎在执行 SPC 后返回的信息。此消息包含：错误消息、SPC 结果、SPC 结果文件名及最终失败操作。其他信息可能包含：
• GPC 图表的功能索引信息（例如，Cp、Pp 和 Ppk）。此信息存储在 ss_SPCGPCChartData 中，用于历史目的。
• 使用 SAVE 参数的质量图表的其他图表和数据点信息。此信息存储在 ss_SPCTxnDataPointDetails 中。
2. SPC 事务数据点—SPC 事务数据点中的每条记录与用于排除、添加批注或指定替代值的数据点相对应。随 Opcenter Execution Semiconductor SPC 一同提供的示例 SPC 查询具有到对应 SPC 事务数据点的链接（外部联接）。并非所有绘制的点都需要在 SPC 事务数据点中有记录。仅当数据值需要批注、排除或值替代时，才会创建 SPC 事务数据点。
重要提示: 不应在建模环境中修改 SPC 事务数据或 SPC 事务数据点。

数据流

当用户执行配置为调用 SPC 的事务时，事务会在 SPC 事务数据对象中创建包含 SPC 前执行数据的记录。当事务完成并提交其数据（第一个提交周期）时，它调用“触发 SPC”过程并传入 SPC 事务数据列表。然后，“触发 SPC”在传递 SPC 事务数据列表的同一服务器实例中调用“执行 SPC”事务。

对于 SPC 事务数据列表中的每条记录，“执行 SPC”事务调用名为“执行 SPC”的过程，该过程调用已配置的 SPC 引擎。系统将来自已配置的 SPC 引擎的结果或错误传回 Opcenter Execution Semiconductor 服务器。
