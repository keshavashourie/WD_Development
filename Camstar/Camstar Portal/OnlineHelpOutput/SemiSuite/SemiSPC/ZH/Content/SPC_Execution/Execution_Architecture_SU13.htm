SPC 执行体系结构

可以从车间事件中触发 SPC 处理，例如，操作员将数据输入到 WIP 数据设置中。在调用 SPC 之前，系统将事务数据提交给数据库。

示例用例

制造商希望在生产过程中监视晶元厚度。如果晶片测量值超出既定范围，他们想要在将晶元切成模具之前使批次处于搁置状态。此外，他们需要了解测量是否趋于上限或下限范围，以便可以调查设备，从而确定是否需要维修。

Opcenter Execution Semiconductor 管理员定义 WIP 数据设置以获取厚度测量值，并定义 SPC 设置以在测量值超出范围时执行失败操作。管理员将 SPC 设置与 WIP 数据设置相关联。

在车间转出期间，WIP 数据设置要求提示操作员进行必需的测量。操作员输入测量值，应用程序开始执行在关联的 SPC 设置中配置的 SPC 请求。

Opcenter Execution Semiconductor 创建并临时保存 SPC 前执行数据，将车间事务数据提交给数据库，并执行名为 Trigger_SPC 的过程，传入保存的 SPC 数据。然后，Trigger_SPC 过程执行 SPC 事务。

对于 SPC 事务数据列表中的每条记录，执行 SPC 事务会调用一个自定义过程（也称为执行 SPC），该过程又调用 Statit e-Server 以执行 SPC 设置中定义的 SPC 宏。

Statit e-Server 将厚度测量值标识为超出限制并将结果返回到 Opcenter Execution Semiconductor。执行 SPC 事务提交所有 SPC 后执行数据，将批次置于搁置状态，并向用户显示 SPC 结果（包括图表）。

SPC 数据对象

有两个已命名数据对象 (NDOs) 支持 SPC：

• SPC 事务数据：Opcenter Execution Semiconductor 使用双确认循环来执行 SPC。对于执行的每个 SPC 设置，系统在 SPC 事务数据中创建记录。每个 SPC 事务数据实例都有两组信息：
• SPC 前执行数据 - 这是与执行内容有关的信息。示例包含：SPC 设置、用户和事务时间戳、批次、设备（或使用的批次设备）、事务名称和已解析参数。
• SPC 后执行数据 - 即执行 SPC 后 Statit e-Server 返回的信息。示例包含错误消息、SPC 结果、SPC 结果文件名及最终失败操作。
• SPC 事务数据点：每条记录与用于排除、添加批注和/或指定替代值的数据点相对应。随 Opcenter Execution Semiconductor SPC 一同提供的示例 SPC 查询具有到对应 SPC 事务数据点的链接（外部联接）。注意，并非所有绘制点都需要在 SPC 事务数据点中有记录。仅当数据值需要批注、排除或值替代时，才会创建 SPC 事务数据点。
• ss_SPCGPCChartData：存储具有违规的 GPC 图表的历史数据，例如 cp、cpk、pp 和 ppk 值。
• ss_SPCTxnDataPointDetails：存储绘制数据点所包含的原始数据点。存储具有违规且使用 SAVE 参数进行配置的 X 条形图、R 图表和移动极差图表的数据。此表与 A_SPCTxnDataDetails 表交叉引用。
重要提示: 不应在建模环境中修改 SPC 事务数据或 SPC 事务数据点。

数据流

当用户执行配置为调用 SPC 的事务时，事务会在 SPC 事务数据对象中创建包含 SPC 前执行数据的记录。当事务完成并提交其数据（第一个提交周期）时，它调用“触发 SPC”过程并传入 SPC 事务数据列表。然后，“触发 SPC”在传递 SPC 事务数据列表的同一服务器实例中调用“执行 SPC”事务。

对于 SPC 事务数据列表中的每条记录，“执行 SPC”事务调用名为“执行 SPC”的过程，该过程调用 Statit e-Server 来执行 SPC 宏。系统将来自 Statit e-Server 的结果或错误传回 Opcenter Execution Semiconductor 服务器。
