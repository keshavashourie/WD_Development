SPC Data Objects

Opcenter Execution Semiconductor uses a two-commit cycle to execute SPC. Two named data objects (NDOs) support SPC:

1. SPC Txn Data—For each SPC Setup executed, the system creates a record in SPC Txn Data. Each SPC Txn Data instance has two sets of information:
a. Pre-SPC Execution Data—information pertaining to what to execute including: SPC Setup, user and transaction timestamps, lot, equipment, transaction name, and resolved parameters.
b. Post-SPC Execution Data—information returned by the configured SPC engine after executing SPC. This information includes: error message, SPC results, SPC result filename, and final failure action. Additional information may include:
• Capability index information (for example, Cp, Pp, and Ppk) for GPC charts. This information is stored in ss_SPCGPCChartData and is used for historical purposes.
• Additional chart and data point information for quality charts that use the SAVE parameter. This information is stored in ss_SPCTxnDataPointDetails.
2. SPC Txn Data Point—Each record in SPC Txn Data Point corresponds to a data point that is used to exclude, annotate or specify an override value. The sample SPC Queries that are provided with Opcenter Execution Semiconductor SPC have a link (outer join) to the counterpart SPC Txn Data Point. Not all points plotted require a record in SPC Txn Data Point. SPC Txn Data Point is only created if the data value requires annotation, exclusion or value override.
Important: You should not modify SPC Txn Data or SPC Txn Data Point in the modeling environment.

Data Flow

When a user executes a transaction configured to call SPC, the transaction creates a record containing pre-SPC execution data in the SPC Txn Data object. When the transaction completes and commits its data (first commit cycle), it calls the Trigger SPC procedure and passes in the SPC Txn Data List. Trigger SPC then calls the Execute SPC transaction in the same server instance passing along the SPC Txn Data List.

For each record in SPC Txn Data List, the Execute SPC transaction calls a procedure named Execute SPC which calls theconfigured SPC engine. The results or errors from the configured SPC engine are passed back to the Opcenter Execution Semiconductor server.
