SPC Execution Architecture

SPC processing can be triggered from a shop floor event, for example, an operator entering data into a WIP Data Setup. Transaction data is committed to the database before the call to SPC.

Example Use Case

A manufacturer wants to monitor wafer thickness during the production process. If a wafer measurement falls outside of the established range, they want to place the lot or lots on hold before slicing the wafer into die. Additionally, they need to know if measurements are trending towards the upper or lower range limits so that they can investigate the equipment to determine whether repairs may be needed.

The Opcenter Execution Semiconductor administrator defines a WIP Data Setup to capture thickness measurements and an SPC Setup with failure actions to execute when measurements are out of range. The administrator associates the SPC Setup with the WIP Data Setup.

During shop floor Track Out, the WIP Data Setup requirement prompts the operator for the required measurement. The operator enters the measurement and the application begins the SPC request configured in the associated SPC Setup.

Opcenter Execution Semiconductor creates and temporarily saves the pre-SPC execution data, commits the shop floor transaction data to the database, and executes a procedure named Trigger_SPC passing in the saved SPC data. The Trigger_SPC procedure then executes the Execute SPC Transaction.

For each record in SPC Txn Data List, the Execute SPC transaction calls a custom procedure also called Execute SPC which in turn calls the Statit e-Server to execute the SPC Macro defined in the SPC Setup.

Statit e-Server identifies the thickness measurement to be out of limits and returns the results to Opcenter Execution Semiconductor. The Execute SPC transaction commits all the Post-SPC Execution Data, places the lot on hold, and displays the SPC results including chart or charts to the user.

SPC Data Objects

There are two named data objects (NDOs) that support SPC:

• SPC Txn Data: Opcenter Execution Semiconductor uses a two-commit cycle to execute SPC. For each SPC Setup executed, the system creates a record in SPC Txn Data. Each SPC Txn Data instance has two sets of information:
• Pre-SPC Execution Data – This is information pertaining to what to execute. Examples include: SPC Setup, the user and transaction timestamp, the lot, equipment, or both that were used, the transaction name, and resolved parameters.
• Post-SPC Execution Data – This is information Statit e-Server returns after executing SPC. Examples include error message, SPC result, SPC result filename, and final failure action.
• SPC Txn Data Point: Each record corresponds to a data point that is used to exclude, annotate and/or specify an override value. The sample SPC Queries that are provided with Opcenter Execution Semiconductor SPC have a link (outer join) to the counterpart SPC Txn Data Point. Note that not all points plotted require a record in SPC Txn Data Point. SPC Txn Data Point is only created if the data value requires annotation, exclusion or value override.
• ss_SPCGPCChartData: Stores historical data such as cp, cpk, pp, and ppk values for GPC charts with rule violations.
• ss_SPCTxnDataPointDetails: Stores the raw data points of which plotted data points are comprised. Data is stored for XBar, RChart, and Moving Range charts that have rule violations and are configured with the SAVE parameter. This table cross references with A_SPCTxnDataDetails table.
Important: You should not modify SPC Txn Data or SPC Txn Data Point in the modeling environment.

Data Flow

When a user executes a transaction configured to call SPC, the transaction creates a record containing pre-SPC execution data in the SPC Txn Data object. When the transaction completes and commits its data (first commit cycle), it calls the Trigger SPC procedure and passes in the SPC Txn Data List. Trigger SPC then calls the Execute SPC transaction in the same server instance passing along the SPC Txn Data List.

For each record in SPC Txn Data List, the Execute SPC transaction calls a procedure named Execute SPC which calls the Statit e-Server to execute the SPC Macro. The results or errors from the Statit e-Server are passed back to the Opcenter Execution Semiconductor server.
