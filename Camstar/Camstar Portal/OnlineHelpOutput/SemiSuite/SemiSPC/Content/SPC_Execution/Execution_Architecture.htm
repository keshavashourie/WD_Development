SPC Execution Architecture

This topic explains how the SPC execution architecture work. Inline SPC is using an in-house SPC common component which incorporates two engines; SPC Calculation Engine and SPC Display Engine. These common components allow transactions to provide various calculation and visualization functions for a better shop floor experience.

SPC processing can be triggered from a shop floor event, for example, an operator entering data into a WIP Data Setup. Transaction data is committed to the database before the call to SPC.

Example Use Case

A manufacturer wants to monitor wafer thickness during the production process. If a wafer measurement falls outside of the established range, they want to place the lot or lots on hold before slicing the wafer into die. Additionally, they need to know if measurements are trending towards the upper or lower range limits so that they can investigate the equipment to determine whether repairs may be needed.

The Opcenter Execution Semiconductor administrator defines a WIP Data Setup to capture thickness measurements and an SPC Setup with failure actions to execute when measurements are out of range. The administrator associates the SPC Setup with the WIP Data Setup.

During shop floor Track Out, the WIP Data Setup requirement prompts the operator for the required measurement. The operator enters the measurement and the application begins the SPC request configured in the associated SPC Setup.

Opcenter Execution Semiconductor creates and temporarily saves the pre-SPC execution data, commits the shop floor transaction data to the database, and executes a procedure named Trigger_SPC passing in the saved SPC data. The Trigger_SPC procedure then executes the Execute SPC Transaction.

For each record in SPC Txn Data List, the Execute SPC transaction calls a custom procedure also called Execute SPC which in turn calls the appropriate SPC engine based on the SPC Setup configuration.

The desired SPC engine identifies the thickness measurement to be out of limits and returns the results to Opcenter Execution Semiconductor. The Execute SPC transaction commits all the Post-SPC Execution Data, places the lot on hold, and displays the SPC results including chart or charts to the user.
