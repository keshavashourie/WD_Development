Defining User Queries

A User Query is a predefined query stored as instance data. Note that while the query definition is defined as instance data; the query itself can be used to retrieve information from either instance data tables or metadata tables.

The User Query Parameter grid is implemented as a persistent list so that the parameter sequence is automatically maintained by the corresponding persistent list table.

User Query Requirements

Writing queries in Opcenter EX MDD and Opcenter EX CR requires that you be familiar with the application's Object Model, understand SQL syntax, and have experience writing SQL queries. You must also understand the end user requirements so that your queries will present the right kind of information on the user interface.

After the queries are created and tested, they must be called by the custom application. You can do this through Camstar Services API calls (WSQuery) or through a custom execution.

When Defining User Queries

Make sure you have a reasonable amount of container information in order to test the user query effectively. This means the information model must be configured with products, user codes, workflows, and containers with various attributes.

The query must use a Container ID in the selection criteria, if you are building a query to use in Container Search. Otherwise, the query will not return any results when executed from the User Query tab.

When Using the User Query Test Pop-Up

The User Query Test pop-up appears when you click Save and Test User Query. Any required parameter fields are displayed in the pop-up. A grid with results appears when the parameter fields are populated. The application tests the query and provides results if no parameters are required. An error message will be displayed if the query syntax is invalid and no results are displayed in the grid.

How to Define User Queries

Follow these steps to define a User Query:

1. Open the User Query page. The User Query page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter a name for the query in the User Query field.
4. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
5. Refer to "How to Test a Query that Requires a Parameter" for information on testing a query that requires a parameter.

Or

Refer to "How to Test a Query that Does Not Require a Parameter" for information on testing a query that does not require a parameter.

6. Click Save on the User Query page.
7. Click Save. The application saves the modeling object and displays a success message.

How to Test a Query that Requires a Parameter

Follow these steps to test a query that requires a parameter:

1. Perform the "How to Define User Queries" procedure.

Or

Select an existing User Query instance.

2. Enter a SQL statement in the Query Text field that requires a parameter.
3. Enter the User Query Parameter Name and Data Type in the User Query Parameter grid.
4. Click Save and Test Query. The User Query Text pop-up appears with the required parameters at the top of the pop-up.
5. Enter any parameters required by the query.
6. Click Test Query. Any results matching the query and parameters entered are displayed in the Query Results grid.
7. Click Close. The User Query Test pop-up closes.

How to Test a Query that Does Not Require a Parameter

Follow these steps to test a query that does not require a parameter:

1. Perform the "How to Define User Queries" procedure.

Or

Select an existing User Query instance.

2. Enter a SQL statement in the Query Text field that does not require a parameter.
3. Click Save and Test Query. The User Query Text pop-up appears with results displayed in the Query Results grid.
4. Click Close. The User Query Test pop-up closes.

How to Add Parameters to a User Query

Follow these steps to add parameters to a User Query:

1. Perform the "How to Define User Queries" procedure.

Or

Select an existing User Query instance.

2. Click Add new row in the User Query Parameter grid. A new row appears.
3. Enter a name for the parameter in the User Query Parameter Name field. The name will appear as the caption for the data entry field in which the user types the required input.
4. Select the parameter's data type from the Data Type field.
5. Repeat steps 2-4 to add additional parameters as needed.
6. Click Save on the User Query page.
7. Click Save. The application displays a success message indicating the modeling object was updated.
