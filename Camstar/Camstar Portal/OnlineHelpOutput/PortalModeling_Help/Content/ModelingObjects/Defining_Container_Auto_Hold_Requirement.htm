Defining Container Auto Hold Requirement

Container Auto Hold requirement enables you to automatically put one or multiple containers on hold in a workflow steps for a specific reason (for example, a scheduled inspection or audit). You cannot perform any transactions on the container when the container is placed on hold. The container can be released to resume normal processing when the reason for holding a container has been satisfied or no longer exists.

When Defining a Container Auto Hold Requirement

Container Auto-Hold Requirements can be configured on the following options:

• Mfg Order - All of the containers assigned to the same Mfg Order will automatically be stopped.
• Container List - A list of container names to be stopped.
• Container Identifier range - Start and End text values.
• Lot List - A list of Lot codes which may also represent a Container that has been issued to the container.
• Expression - Allows for defining any additional custom logic that you may want to implement.

The Container Auto Hold Reason must be configured on the Factory modeling page, as you need to provide reasons for holding the containers when the container meets the Container Stop configuration requirements. Refer to the Opcenter Execution Medical Device and Diagnostics Modeling User Guide or the Opcenter Execution Core Modeling User Guide for information on defining hold reasons.

How to Define a Container Auto Hold Requirement

Follow these steps to define a container auto hold requirement:

1. Open the Container Auto Hold Requirement page. The Container Auto Hold Requirement page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter the unique name of this definition in the Container Auto Hold Requirement field.
4. Enter the revision of this object in the Revision field.
5. Enter the container list and lot list information in the Container List and Lot List grid respectively.
6. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
7. Click Save. The application saves the modeling object and displays a success message.
