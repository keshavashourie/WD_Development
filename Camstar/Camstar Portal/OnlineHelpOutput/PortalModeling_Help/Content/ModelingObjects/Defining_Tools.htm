Defining Tools

A tool is a physical resource used on equipment and is a sub-class of the Resource object in the application.

Tool Page Field Definitions

This table defines the fields on the Tool page.

Refer to "Common Fields on Modeling Pages" for information on the fields common to all modeling objects.

Field

Definition

Type

Tool

Name for the tool.

Required

General

Factory

Specifies the factory for the tool.

Optional

Location

Specifies the location for the tool.

Optional

Tool Family

Tool family to which this tool belongs.

Optional

Training Requirement Group

Training group required before a user is authorized to perform a specified task.

Optional

Clearance Level

Level specified to enforce Line Clearance. Line Clearance restricts concurrent processing.

Optional

Print Queue

Name of the network printer used to print container labels that are associated with this resource, if applicable.

Optional

Vendor

Name or specification of the vendor from whom the tool was obtained, or produced.

Optional

Vendor Model

Vendor model for the tool.

Optional

Vendor Serial Number

Vendor serial number for the tool.

Optional

Parent Resource

Name of the parent equipment resource. When you save the equipment, the application lists the child equipment in a read-only list in the Child Equipment grid of the parent equipment.

Optional

Maintenance Class

Defines the relationship between a Maintenance Requirement and a group of resources.

Optional

Smart Scan Rule

List of all the numbering rules defined in the application which can be assigned to the tool for implementing Rule-Based Smart Scanning. Use this field to associate a default numbering rule with the factory for auto numbering when starting lots and containers.

Optional

Resource Type

Identifies a type of equipment, such as Regular Maintenance Equipment, that can be associated with a Resource Status Model.

Optional

Resource Status Model

Defines a set of valid resource status transitions and associated availability states. A resource status model can be configured so that the application will automatically create resource maintenance jobs based on the use of specific reason codes and configurable conditions entered for a status change. Resource Status Models are assigned to resources.

Optional

Nickname

Arbitrary name provided as an alternate way to refer to the resource.

Note: This field is used by Opcenter EX EL IoT and Opcenter EX EL MM.

Optional

Factory Level

Level assigned to the resource within the overall factory hierarchy. Options include:

• Area
• Cell
• Equipment

Note: A parent resource assigned to this resource must be one level above on the hierarchy.

Note: This field is used by Opcenter by IoT and Material Management.

Optional

Recipe Pattern

Expression that resolves to the name of a recipe required for resource setup during shop floor operations. The application uses this field only when no recipe was found using a recipe plan or matrix.

Note: This field must contain a unified expression considered valid in Designer.

Optional

Factory Level Index

Level index defining the order of items displayed in the Factory Hierarchy Page. Items with a higher level index will appear below items with a lower level index within the same group of its parent.

Note: The field accepts values in the form of integers only.

Optional

BOM

Bill of materials or materials list used for this tool or resource.

Optional

Use High Volume Traceability

Check box that enables traceability of resources in high volume, allowing factories with high consumption rate of material component to be able to trace all the material components currently loaded to a machine. If the check box is selected when defining a Resource, the resource will appear in High Volume Resource Setup page and High Volume component Issue page. These pages are used to define a "machine setup" for a resource that can be associated to a container when that container moves through the resource. Optional Recipe Setup requirements for a manufacturing resource.

Optional

Child Resources grid

Grid listing child equipment of the resource.

Optional

How to Define a Tool

Follow these steps to define a Tool:

1. Open the Tool page. The Tool page appears within the Modeling page.
2. Click New. Blank fields appear for you to define a new instance.
3. Enter the name of the tool in the Tool field.
4. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
5. Click Save. The application saves the modeling object and displays a success message.
