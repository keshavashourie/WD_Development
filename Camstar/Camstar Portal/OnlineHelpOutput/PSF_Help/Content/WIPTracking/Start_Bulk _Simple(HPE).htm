Start - Bulk Simple (HPE)

The Start - Bulk Simple (HPE) page allows you to start a parent container with multiple child containers or to start individual containers in bulk. The Start - Bulk Simple (HPE) page works similarly to the "Two-Level Start page when starting a parent container with multiple child containers.

Start - Bulk Simple (HPE) page works similarly to the "Start - Bulk (HPE)" page. However, you do not have the option to modify child containers or individual containers.

The application derives parent container quantity from the (rolled up) child container quantities. The group of parent and child containers are processed and tracked together. Starting containers in a multi-level structure provides the benefit of entering subsequent move-type transactions at the top-level container only while the transaction is carried out through all the child containers.

This page also allow you to start individual containers in a large volume or in bulk. You must check the "Individual Container Only" check box to start the individual containers transaction. The Child Containers Info section will automatically be renamed to "Individual Container Info" once the check box is checked.

Note: A High-Performance Engine (HPE) version for Start - Bulk (HPE) is available to enhance the efficiency of transaction execution for large number of containers as the application processes the transaction on the database rather than the application server. Refer to Technical Reference: High Performance Engine for more information.

When Using Start - Bulk Simple (HPE)

Container names must be unique regardless of container level.

You can enforce a hierarchy of valid level relationships. For example, you can allow a batch to have cassettes as children, but disallow a cassette to have batches as children.

When starting a group of containers, the children inherit the attributes defined at the parent level. You can modify child container attributes later using the Container Maintenance transaction.

Factory is not a required field; however, a factory must either be assigned to the employee starting the container, or be specified on the Start - Bulk (HPE) Simple page when you start the container. Otherwise, other transactions such as Move will not process the container.

Note: The application displays a value in the Factory field automatically if a factory was specified for the logged in employee. You can select a different factory, if necessary.

All display fields are empty on the Start - Bulk Simple (HPE) page until a container is selected. Display fields are populated automatically on the Child Container Info pop-up. Refer to "Using Transaction Pages and Pop-ups" for information on performing a transaction from a page or pop-up.

When Naming Parent and Child Containers

You must specify a unique container name when creating new parent containers. You can either enter a container name manually or have the application generate a container name automatically. The application considers closed containers when validating a unique name.

The application uses the parent container name to name child containers regardless of the method used to name the parent. The default method is to append – 01, - 02, etc. to the parent name for each child container. However, additional naming options are available. Refer to "When Generating Child Container Names” for information.

Note: The application displays the parent container in the success message when the transaction executes successfully. The application does not include child container names in the success message.

When Generating a Parent Container Name

You cannot change the method for generating the parent name after creating one or more child containers. The application clears the Child Containers grid and displays a warning message if you change the method after creating child containers.

Select the Generate Names Automatically check box to have the application generate the parent container name using defined numbering rules. The application clears and disables the Container field when you select this check box.

The application uses the numbering rules associated with the parent container to generate the container name. Numbering rules may be specified for multiple modeling object instances associated with the container. Numbering rules follow this default precedence:

1. Container Level
2. MfgOrder
3. Product
4. Product Family
5. Factory

Refer to the Opcenter Execution Medical Device and Diagnostics Modeling User Guide or the Opcenter Execution Core Modeling User Guide for information on defining numbering rules.

When Generating Child Container Names

You must associate a numbering rule with the container level you want to use when generating child container names automatically. The application displays a warning message when:

• You select a container level that does not have an associated numbering rule,
• You select the Generate Child Names Automatically check box, and
• Click Add.

The application uses multiple criteria to determine child container names. There are four possible scenarios:

• When both the Generate Names Automatically and Generate Child Names Automatically check boxes are cleared (the default setting), the application assigns each child container the name specified in the Container field and appends -01, -02, etc. to the end.

Example:

MyContainer – 01

MyContainer – 02

MyContainer – 03

• When the Generate Names Automatically check box is selected and the Generate Child Names Automatically check box is cleared, the application assigns each child container name the parent container name generated by associated numbering rule and appends -01, -02, etc. to the end.

Example:

c_0001 – 01

c_0001 – 02

c_0001 – 03

• When the Generate Names Automatically check box is cleared and the Generate Child Names Automatically check box is selected, the application assigns each child container the name specified in the Container field and appends the numbering rule associated with the child container Level to the end.

Example:

MyContainersCC0001

MyContainersCC0002

MyContainersCC0003

• When both the Generate Names Automatically and Generate Child Names Automatically check boxes are selected, the application assigns each child container a concatenation of the generated parent and child numbering rules.

Example:

c_0002CC0003

c_0002CC0004

c_0002CC0005

How to Start a Parent with Child Containers

Follow these steps to start aparent with child containers:

1. Open the Start - Bulk Simple (HPE) page from the Container menu. The Start - Bulk Simple (HPE) page appears.
2. Enter a name for the parent container in the Container field.

Or

Select the Generate Names Automatically check box.

3. Select a Level. The selected level appears in the Level field.
4. Select an Owner. The selected owner appears in the Owner field.
5. Select a Start Reason. The selected reason appears in the Start Reason field.
6. In the Child Container Info section, enter a Level for the child containers. The application enables the Add button.
7. Enter a Qty for the child containers.
8. Enter an UOM for the quantity.
9. Enter the number of child containers to create in the Child Count field.
10. Click the Add button. Child containers added to the Child Containers grid.
11. Repeat steps 2-10 to start additional child containers, or click Add new row button in the grid to display the Child Container Info pop-up.
12. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
13. Click the Submit button on the right command bar. A status message appears confirming that the containers have been started.
Note: When you select Generate Child Names Automatically for the first child container, you must select the same for all subsequent child containers.
Note: A warning message appears when Generate Names Automatically is selected but there is no auto numbering rule defined.

How to Start Individual Containers Only

Follow these steps to start individual containers only:

1. Open the Start - Bulk Simple (HPE) page from the Container menu. The Start - Bulk Simple (HPE) page appears.
2. Check the Individual Containers Only check box in the Child Container Info. The section automatically rename to "Individual Container Info."
3. Follow steps 2 - 5 from the previous "How to Start a Parent with Child Containers."
4. In the Container Info section, enter a Level for the containers.The application enables the Add button.
5. Enter a Qty for the containers.
6. Enter an UOM for the container's quantity.
7. Enter the number of containers to create in the Container Count field.
8. Click the Add button. Containers added to the Containers grid.
9. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
10. Click the Submit button on the right command bar. A status message appears confirming that the containers have been started.
