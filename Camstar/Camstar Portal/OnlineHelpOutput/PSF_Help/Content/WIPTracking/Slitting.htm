Slitting

The Slitting transaction enables the creation of one or more target containers from an existing source container, inheriting Qty1 and Qty2. A source container is slit into a number of containers specified in the Slit Count field while retaining the characteristics and history of the source container. This activity is commonly employed in the Battery Slitting transaction process, where a single roll is produced with a quantity of 1 and may have a specified length (e.g., Qty2: 100).

If the Slit Product field is configured, the target container will adopt the specified product. Slit Product and Slit Count can be defined on the Product Modeling page. The automatic generation of target container names can be achieved by defining the Slit Numbering Rule on the Factory Modeling page. After slitting transactions are executed, the source container will be automatically closed.

When using the Slitting page

The added target container (rows added on the To Container Details grid) must match the quantity displayed in the Slit Count field. Ensure a unique child container name is specified in the To Container Details grid, either entered manually or generated automatically by the application. Slitting a container or quantity does not relocate either the source or target containers, nor does it imply any processing activity (throughput) on either container.

Enable the "Generate Names Automatically" check box to have the application create the container name using defined numbering rules. Note that selecting this check box clears and disables the To Container field. An error will occur if the container uses the same name as an existing container, even with a different container level.

Adding Affected Containers to Events

The application can add containers to quality events automatically when you execute the slitting transaction on a container associated with one or more quality events. For example, if the source container is associated with an event, the application adds any new containers slit from that source container to the quality event automatically. A system administrator configures the Slit transaction to add containers to events in Modeling. Refer to the Opcenter Execution Medical Device and Diagnostics Event Management User Guide or the Opcenter Execution Core Event Management User Guide and the Opcenter Execution Medical Device and Diagnostics Nonconformance Management User Guide or the Opcenter Execution Core Nonconformance Management User Guide for information on adding affected containers to quality events automatically.

Slitting Page

You can access the page by selecting "Slitting" from the Container menu.

How to Slit a Container

Follow these steps to slit a container:

1. Open the Sliting page from the Container menu. The Sliting page appears.
2. Select or enter a container in the Container field. The application updates the container header and selection fields to display information for the specified container. Values appear only if they were entered for the container.
3. Select the Generate Names Automatically check box. Click Add new row or select a row to start a new container. The application populates target containers to the To Container Details grid.

Or

Enter a name for the new container in the To Container field. The application populates Quantity field. Number of rows entered must equals to the Slit Count entered.

4. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
5. Click Submit on the command bar.The source containers are slit into the target containers, the application clears the fields, and then displays a confirmation message.
