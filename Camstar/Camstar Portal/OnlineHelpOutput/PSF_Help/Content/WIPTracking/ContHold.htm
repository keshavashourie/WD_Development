Container Hold

The Hold transaction enables you to put a container on hold for a specific reason (for example, a scheduled inspection or audit). Placing a container on hold prevents users from performing transactions on the container. The container can be released to resume normal processing when the reason for holding a container no longer exists.

Note: Refer to "Hold Multiple Containers" if you want to place multiple containers on hold simultaneously.

When Placing a Container on Hold

All display fields are empty on the Hold page until a container is selected. The Container drop-down field contains applicable containers to be selected to perform container hold. If Line Assignment Setting is configured, displayed list will include containers based on the selected Work Center, Operation, or Spec value. You may check the Container header located at top of the page for current line assignment status. Refer to "Line Assignment Settings" for more information. Display fields are populated automatically on the Hold pop-up. Refer to "Using Transaction Pages and Pop-ups" for information on performing a transaction from a page or pop-up.

Only one container can be placed on hold per transaction. You must select a hold reason to place a container on hold. Hold reasons are defined in Modeling by a system administrator. The application displays an error message if you click the Hold button without selecting a hold reason. Refer to the Opcenter Execution Medical Device and Diagnostics Modeling User Guide or the Opcenter Execution Core Modeling User Guide for information on defining hold reasons.

Additionally, you can add a message to be displayed if users attempt to perform transactions on the container currently on hold in the Hold Message field. If the field is left empty, a default hold message will be displayed when a transaction against container on hold is attempted.

The application validates that the specified container is active and is not on hold already. You cannot place a closed container on hold.

Placing a container on hold does not place its children on hold. However, placing a child container on hold places the parent container on an implicit hold. You can resume processing on the parent container only after you release the held child container.

Hold Page

You can access the Hold page from the Container menu. The Hold page allows you to scan or enter a container and place that container on hold.

Note: The Hold page may be available as a pop-up also if the container hold transaction has been configured as an available action on another page (for example, Container Search).

How to Place a Container on Hold

Follow these steps to place a container on hold:

1. Open the Hold page from the Container menu. The Hold page appears.
2. Select or enter a container in the Container field. The application updates the container header and selection fields to display information for the specified container.Values appear only if they were entered for the container.
Note: The application populates the Container field and the container header automatically when you access the Hold pop-up from another shop floor page.
3. Select a Hold Reason.
4. Enter optional information according to your business requirements. Refer to the field definitions table for information on the optional fields.
5. Click Hold or Submit on the command bar to place the container on hold. The application displays a status message confirming the container is being held.
