Before Viewing the Manufacturing Audit Trail or Resource Audit Trail

Before viewing container, carrier, event information in the manufacturing audit trail or resource information in the resource audit trail, a system administrator must perform these tasks:

• Define one or more UI preferences in Modeling. A UI preference sets the order of the fields displayed on the Status tab of the Mfg Audit Trail page for a container, carrier, or event. It also sets the order of the fields displayed on the Status tab of the Resource Audit Trail page for a resource. Your organization may consider defining three UI preferences: one for containers and carriers, one for events, and one for resources.
• Associate a UI Preference to:
• A container level for containers and carriers.
• An organization for events.
• A resource type or resource family for a resource
• Configure any custom views for the History Mainline grid using the Audit Trail Configurator. Siemens provides a default view.
Or,
Configure custom views for the History Mainline grid and the transaction details in the Summary/Details grid from the Audit Trail Configuration page. Refer to the Opcenter Execution Medical Device and Diagnostics Designer Portal Modeling Guide or the Opcenter Execution Core Designer Portal Modeling Guide for information on the Audit Trail Configuration page.

Date and Time Considerations

The date and time fields in the audit trail display a history of transactions based on the current offset of the user's selected time zone.

Note: Some time zones have two offsets in a year. For example, Eastern Time (US and Canada) has UTC-05:00 and UTC-04:00.

The system includes dates in GMT format from the database and applies the current offset for date time controls. In addition to the transaction date and time recorded, the audit trail also shows the GMT date and time plus the current offset for the selected time zone.

Important: You will only see the time zone with the GMT date and the offsets on the History Mainline Grid in the audit trail. On container pages, the date and time fields are displayed without any adjustment. The system simply loads the value from the Local Date column in the database. The current offset of the user's selected time zone is not applied.

Example

A transaction is executed in Eastern Time (US and Canada) time zone on 2024-08-20 14:00:00.

Local Time

GMT

 

2024-08-20 14:00:00

2024-08-20 18:00:00

UTC -04:00

In this case (Eastern Time (US and Canada) time zone on 2024-08-20, during Daylight Saving Time), the TxnDate column in the HistoryMainline grid will contain the value 2024-08-20 14:00:00. However, in the Eastern Time (US and Canada) time zone on 2024-12-20, during Standard Time, the TxnDate column will contain the value 2024-12-20 13:00:00.

If you log into the Portal with the Pacific Time (US and Canada) time zone on the date 2024-08-20, you will see the value of the TxnDate column as 2024-08-20 11:00:00. However, in the Pacific Time (US and Canada) time zone on the date 2024-12-20, the TxnDate column will contain the value 2024-12-20 10:00:00.
