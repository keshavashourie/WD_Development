Import Document Structure

This section describes the structure of the XML import document. Do not edit any document provided by Siemens unless directed to do so by Product Support.

The document has the following two sections:

• Header: used to provide general information about the document such as version and import processing defaults.
• Import: contains all of the definitions that are to be added or changed in the target metadata configuration.

Import Section

The Import section describes metadata to be included in the target metadata configuration. This section also follows the Standard Section Format for grouping information.

Standard Section Format

The Import section describes metadata and uses a standard format that starts with grouping object types that can be defined outside the context of another object at the highest level. For example, CLF Definitions are defined without the need for a context. In contrast, Function parameters are only defined within the context of the associated Function.

Import Document Attributes

Because it is not practical to require that the author of an import document know the complete content of all possible target metadata configurations, it is not necessary to differentiate between adding object definitions and updating existing definitions. That is determined automatically by the import processing logic. There is, however, an optional Action attribute in the identification node that makes the import document more readable. The values of the Action attribute can be Create or Import and indicate whether metadata is being added to the target configuration or updated.

The imported data can be anything from a single attribute, such as changing the description of an existing object definition, to a complete object definition or structure of object definitions such as a Function and all of its associated Parameters. The XML format for each object definition consists of the Identification, Attribute data, and groups of other object definitions if necessary such as Events and Methods within a CDO Definition, Parameters within a Function Definition, and so on.

The Attribute data includes simple data types such as the description, which is a string, and compound data types, meaning references to other object definitions. If an attribute is specified with no name, the value is explicitly set to nothing in contrast to other attributes that are omitted from the import document. Any attribute that is omitted will be left unchanged.

Renaming

An Action attribute is used to rename an existing object definition.

Object References

The majority of the attribute data are references to other object definitions, which require a compound structure in the Import document. For most object types, only the Name is required. For certain object types, such as CDO Fields or DB Columns, additional information is required to define the context. For CDO Fields, the CDO Definition is the context. For DBColumns, the context is the DBTable.

Expected Value Processing

The purpose of expected value processing is to avoid accidentally overriding user changes to the target metadata. This is done by optionally specifying an expected value for any attribute that is to be changed. The import processing will compare the value found in the target metadata with the expected value and take the appropriate action. The possible actions are:

• Accept the change and continue processing.
• Leave the value unchanged and continue processing.
• Leave the value unchanged and discontinue processing.
• Prompt the user to determine which of the above actions to take.

Regardless of the action taken, there is an entry written to the log identifying the difference that was found.

The action to take can be specified at three different levels, each one taking precedence over the next. The three levels are:

• Globally. This is the default action if nothing else is specified.
• Globally for a specific group of attributes such as descriptions, label text, and so on. This is the default action to take for any attribute of the specific type.
• Specific for an attribute. This is the action to take for the specific attribute.

The global actions are specified in the Header Section of the document. The specific action is specified as a subnode of the attribute with which it is associated.
