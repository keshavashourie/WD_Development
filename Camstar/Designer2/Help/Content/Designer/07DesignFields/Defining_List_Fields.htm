Defining List Fields

A field is defined as a list field when you check Field is a list on the Add a New CDO Field window. Storing a list of objects can be done either statically or dynamically for a list of objects within data CDOs.

Setting Values

A list of objects is represented by a list of object instance IDs. This list can either be stored in a separate table or dynamically built if the relationship between the objects already exists.

Dynamic Retrieval

Ideally, you want to use dynamic retrieval because this list does not require a separate table for the list. The advantage of not having a separate table is to save database space.

The object containing the list field references an object that contains a list of objects. There is a single field on which to sort for this type of retrieval.

How to View the Settings for Dynamic Retrieval

Follow these steps to view the settings for dynamic retrieval:

Important: The list field must be of data type Object.
1. Select a CDO in the CDO Definition window, and then select the Fields tab.
2. Select the list field for which you need to retrieve entries dynamically.

This example uses the Products field for the ProductFamily CDO.

3. Click Properties at the bottom of the Fields tab. The CDO Field Properties window appears.
4. Click the General tab. The General tab appears.
Note: Field is a list is selected and cannot be changed. This is appropriate for fields configured for dynamic list retrieval. List entries are retrieved dynamically is selected. Again, this is required.

The tab has three fields with lists at the bottom:

• Field from <CDO> to match when building list
This is the name of the field in the CDO (Product in this case, because that is the field type) that is the basis for building a list field. In this example, the ProductFamily field of the Product CDO is displayed.
• Field from <CDO> to match when building list
This is the field that resides within the base object (ProductFamily in this case) that you want to match with the field in the list object. This is the matching criterion and the criterion defines the relationship between the two objects. In this example, InstanceID of ProductFamily from is displayed.
• Field from <CDO> to use when sequencing list
This is the field that resides within the base object (Product in this case) that you want to use for sorting purposes. In this example, ProductBase.Name of Product is displayed. Product is a revisioned object and this is its Base is used. If this were a list for named data objects, it is instance ID.
Note: The <CDO> in the captions for the three list boxes change, depending on the selection.
5. Click OK.

Static List Retrieval

A static retrieval of the list entry requires a new table. The new table is used to maintain and store the list entries that either must be managed or maintained (for example, to preserve the order in a list). This might be necessary if:

• You need a list to manage the order of objects.
• A list has a many-to-many relationship.
• A list contains a list of data values (as opposed to a list of references to existing objects).

How to Set the Values for Static Retrieval

Follow these steps to set the values for static retrieval:

1. Select a CDO in the CDO Definition window, and then select the Fields tab.
2. Select the list field for which you need to retrieve entries statically.
3. Click Properties to display the CDO Field Properties window.
4. Click the General tab. The option Field is a list is selected.
5. Click Create a New Table. A default table name and a default column name appear.
6. Rename the table and column to something meaningful.
7. Click OK.
8. Select Save from the File menu. The application saves your changes.
