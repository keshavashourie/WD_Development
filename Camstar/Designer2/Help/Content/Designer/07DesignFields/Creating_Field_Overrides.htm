Creating Field Overrides

Typically, a CDO subclass uses the inherited fields of its superclass. Overriding customizes a specific property of the inherited field within the CDO subclass. Overrides can be done only on inherited fields. Changes that are made in the override apply only to the selected CDO and any subclasses of the selected CDO. An overridden field value can range from a change in description to a change in object references and value expressions.

The following guidelines apply to overrides:

• You can change the data type in Designer. Your changes will not affect the database.
• If the data type is a CDO, you can override it by selecting a different CDO to reference. Note that the field type becomes the name of the referenced CDO but the field Name is not affected.
• A field with an overridden value has a background color in the Designer window to indicate the color associated with the workspace in which it was overridden.
• Making changes to field properties does not update the associated column in the Opcenter EX MDD or Opcenter EX CR table that stores that field. You must select the field’s Where Used tab to view the tables that use this field. Then make the same property change to all the affected tables. Refer to "Tables" for information on accessing the tables.
• If the field has a corresponding field in a maintenance transaction, you are given a default option to make the same changes in the corresponding field in the associated maintenance transaction.
• Using a larger number of overrides can result in the allocation of more GDI objects than the Windows operating system allows by default per process. You can edit the value of the following registry key to increase the maximum value in order to handle the required GDI objects:

HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\
CurrentVersion\Windows\GDIProcessHandleQuota

The default value is 10,000. The accepted range is 256 to 65,536.

How to Create a Field Override

Follow these steps to create a field override:

1. Open the Designer toolbar.
2. Click CDOs. The CDO Definition window appears.
3. Select a CDO in the CDO Definition window and click the Fields tab.
4. Select Include inherited fields.
5. Select the field for which you will create an override.
6. Click Properties. A dialog box prompts you to confirm the creation of an override.
7. Click Yes. The CDO Field Properties window appears.
Note: If you click No, you will override the field in the ancestor CDO where the field was originally defined, and that override will be inherited by all subclasses of the ancestor CDO.
8. Change any field properties you want to modify according to your business requirements. The background color of overridden fields turns to the color associated with the workspace in which it was overridden.
9. Click OK.
10. Select Save from the File menu. The application saves your changes.
