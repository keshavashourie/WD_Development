CDO Fields

The field types and data types found in the Fields window are used as attributes of CDO fields. CDO fields are found in the Fields tab on the CDO Definition window. This topic discusses:

• Adding a CDO Field
• Selecting the Correct Data Type and Field Type
• Removing Fields

When Adding a CDO Field

Adding a field to a CDO is necessary when customizing Opcenter EX MDD or Opcenter EX CR. Adding a CDO field is different than adding a field type.

When you add a CDO field, specify the field’s singular data type and field type. Once the field is added, it becomes very specific to the CDO to which it is added.

Do not name two services with the same caption when adding a CDO field. Designer allows you to name two services with the same caption, however you cannot indicate which service you are executing.

Adding a CDO field does not affect field type definitions. However, when a CDO is added to the class library, it is added as a Data Type Object field.

Workspace prefixes are automatically inserted before the name of an item when adding a new item, if a prefix has been assigned to the highest active workspace. Workspace prefixes indicate which workspace Designer is applying changes to. For example, the prefix "C200" would be associated to the workspace with a prefix set as "C200" in Management Studio. It is recommended you use the prefix supplied by Designer when adding new items.

You can assign or modify workspace prefixes in Management Studio. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for information.

Note: The base application workspace (csi) cannot have a workspace prefix assigned to it.

Rules

These are the user-defined field rules:

• Fields added to CDOs are inherited by all its subclasses. The more subclasses an object has, the longer the process can take.
• You can drop default and user-defined CDO fields as controls on Portal forms.
• If you add fields to your ParametricData subclass, drop the fields as controls onto the Parametric Data Control form in the Portal.
• If you add user-defined fields in a Service CDO, the fields are loaded on the UserDefined control of the Portal.
• Lists, subentities, and subentity lists need a custom UI. This is done with the Portal.
• Do not assign the same field usage to two object fields in the same CDO.
• Refer to "Valid Characters and Reserved Words" for additional restrictions on field naming.

Selecting the Correct Data Type and Field Type

Choosing the correct data type and field type for a field is important to match the needs of your data element. Use the following guidelines when choosing a data type and field type:

• Base your selection of a data type and field type on the description and intended use. The descriptions of the data types are shown in the Data Type and Field Type table. The descriptions of the field types are provided in the Field Type Properties table.
• Review the properties of the field type to ensure that the properties match your data element requirements.

How to Add a CDO Field

Follow these steps to add a CDO field in Designer:

1. Click CDOs. The CDO Definition window appears.
2. Select the user-defined CDO subclass that you are adding the fields to.
3. Select the Fields tab.
4. Click Add at the bottom of the Fields tab. The Add a New CDO Field window appears.
5. Select a data type from the Data Type list. Refer to "Selecting the Correct Data Type and Field Type" for information on selecting data types and field types.
Note: For persistent objects, a table is created for the list field in the database if you select the Field is a list check box.
6. Select a field type from Field Type.
7. Enter a name for the new field, avoiding illegal characters and reserved words.
Important: The name of the CDO can be up to 30 characters in length, and cannot contain spaces, illegal characters, or reserved words. Refer to "Valid Characters and Reserved Words."
8. Select an existing label to use as a caption from the Caption list.

Or

Enter a label. If you add your own, the new label is added to the user labels library under the OtherField category.

9. Enter a description in the Description field.
10. Select the Add Field to Associated Service Objects check box. This step adds the same field to associated service objects. For example, if you are adding a field to an Employee subclass, the same field is added to the corresponding EmployeeChanges subclass.
11. Click Create. The CDO Field Properties window appears.
12. Confirm or modify the field properties.
13. Click OK.
14. Select Save from the File menu. The application saves your changes.

How to Remove Fields

You can remove user-defined fields, but not default fields. Follow these steps to remove CDO fields in Designer:

1. Click CDOs. The CDO Definition window appears.
2. Select the CDO subclass to remove a field.
3. Select the Fields tab.
4. Select the user-defined field to be deleted.

The Remove button is disabled if you selected a default field, or a user-defined field that is mapped or has overrides.

5. Clear any field overrides and remove field maps. Refer to "Creating Field Overrides" and "Viewing Field Maps."
6. Click Remove. A dialog box prompts you to confirm the deletion of the CDO field.
7. Click Yes. The field is removed. If the field has a database column, that column is also deleted.
8. Select Save from the File menu. The application saves your changes.
