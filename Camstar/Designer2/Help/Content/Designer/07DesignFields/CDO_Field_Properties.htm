CDO Field Properties

A field is defined by its properties. Select a CDO field and click the Properties button to access the CDO Field Properties window. The properties available are specific to the CDO field you select. The Field Properties window has six tabs:

• General
• Options
• Advanced Options
• Expressions
• Selection Values
• Events

Common to all the tabs is the "Apply the same changes to the corresponding field in the associated Maintenance transaction" check box. If this check box is selected, the same changes are made to the associated Maintenance object.

Note: The application does not save any information to the associated Maintenance object when the “Apply the same changes to the corresponding field in the associated Maintenance transaction” check box is selected if no changes have been made to the CDO field's properties.

Options Tab

Various processing options for fields are listed on the Options and Advanced Options tabs.

In the Options tab, specify:

• Constraints
• Accessibility
• Uniqueness
• Value Traits
• Field Usage

Advanced Options Tab Field Definitions

This table defines the fields on the Advanced Options tab.

Field

Definition

Ownership

None

If this option is selected, the object this field references is not owned. It represents an association.

Strong

If this option is selected, the object this field references is a subentity; it is exclusively owned by this CDO (called the parent) and shares the parent’s life span. Deleting a parent instance will also delete the subentity instance referred to in this field. The relationship represents a composition.

Serialization

None

If this option is selected, this field will be excluded from an XML transmission document.

Default

Shallow

If this option is selected, the value of the object reference will be included in an XML transmission document. This will generally include the instance ID as well as the appropriate alternative reference for the object.

Deep

Option is enabled only when the field is an object reference. If this option is selected, the referenced object will be included in an XML transmission document.

Special Processing

Substitute text variables

Option is enabled only when the field is of type String. If this option is selected, text variables in the string will be resolved; the attribute scans the string looking for any special syntax. An example is CompareValue.

Create on Initialize

Attribute used for object field types. When an instance of the CDO containing this field is created (initialized), an instance of another (a second) CDO (of the data type and field type of this field) is also created, and the instance ID of that second CDO is put in this field.

Transaction Reversal

Reverse

If this option is selected, the value before the execution of the last transaction will be restored when the transaction is reversed.

Compensate

Option is enabled only if the field is of type fixed, decimal, float, or integer. If this option is selected and the transaction is reversed, the sign of the value of this field will be switched in the reversal record to ensure quantity balancing.

Visibility in Designer

Basic

If this option is selected, the field is visible in Designer for both user and system mode in both Basic and Advanced views.

Advanced

Expressions Tab

In the Expressions tab, specify:

• Current value expression (CVE)
• Default value (DV)
• Default value expression (DVE)

Expressions Tab Field Definitions

This table defines the fields on the Expressions tab.

Field

Definition

Current Value Expression (CVE)

Current Value Expressions are used to dynamically determine the value of a field in a CDO. The intent of a CVE is to allow the field to determine a value at run time.

Default Value (DV)

Default value is the value that you designate the field will take in the absence of any other specified value.

Note: Siemens recommends that you used default values only for shop floor transactions.

Default Value Expression (DVE)

Default value expression is used to dynamically determine the default value.

Note: Siemens recommends that you used default value expressions only for shop floor transactions.

Supported expressions

Only CVEs and DVEs support expressions; the DV does not. When initializing an object, the system attempts to get a field’s value, if persistent, from the database.

Note: CVE is not evaluated at the time of initialization. CVE is evaluated only at the time field value is requested.

On a request to get the field value, one of the following values is returned. These are executed in the following order:

1. Instance data, the value that was set
2. Value returned by OnGetValue event, if present
3. Value returned by the CVE, if present

The result of this processing, which can still be empty, is set to the field if it evaluated to some value. Getting the value returns whatever value the field is set to.

There is a call that allows to get the default value, csigetdefaultvalue.

Expressions are used to dynamically determine the value of a field in a CDO, whether it is a Current Value Expression or a Default Value Expression. The syntax is similar; the difference is that the current value expression can contain a reference to the current instance data value of a field.

A field expression-a CVE or a DVE-refers to more than one expression listed in sequence, separated by semicolons. The evaluation sequence of a field expression starts with the first expression, proceeding to the last. The evaluation stops when a field expression produces a value. The reserved word is entered first, followed by a semicolon. The current reserved word for a field expression is:

This_Value;

This_Value uses the value that the user has entered in the field.

An expression represents one value but might have more than one field name separated by periods within the expression. The convention for entering a field expression for a field is:

FieldName(ObjectReference).FieldName(ObjectReference).FieldName(any type)

Where:

FieldName(ObjectReference) is a field in a CDO of type OID, where the field refers to a CDO.

and:

FieldName(type any) is a field in a CDO of any type.

Example 1

This_Value;Container.Workflow.FirstStep

This expression instructs the application to use the value the user has entered; if nothing was entered, this expression returns the Instance ID in the FirstStep field contained in the Workflow belonging to the Container.

Example 2

This_Value;Details.Container.Operation;0;

The evaluation for this field expression is as follows:

1. This_Value retrieves the value entered by the user. If this does not yield a value, then;
2. Details.Container.Operation retrieves the value from the Operation field in the Container CDO within the Details CDO. If that CVE does not yield a value, then;
3. The value is set to 0, NULL, or an empty string, depending upon the field type.

Example 3

This_Value;ProductFamily.Workflow

The evaluation for this field expression is as follows:

1. This_Value is used in the CVE to refer to the current instance data value of a field.
2. ProductFamily.Workflow retrieves the value from the Workflow field in the Product Family CDO.

Using the Expression Builder

The Expression Builder relieves you of having to type your CVEs or DVEs by displaying a list of CDOs and fields in a window. You select the CDO and field, and the Builder automatically enters the appropriate delimiters.

Modifying Expressions

You can use the same procedure as How to Enter a CVE or DVE Field Expression to modify current or default value expressions, or you can use the following alternative procedure to edit current or default value strings. This alternative is useful when you have created your own fields and would like to edit multiple expressions to use your fields.

Selection Values Tab

The Selection Values tab of the CDO Field Properties window enables you to specify how to generate selection values for a field in an end-user’s graphical user interface. You can use them for a new field, or you can change the methods already assigned to an existing field.

Refer to "Viewing Field Selection Values" for information on how to work with field selection values.

How to Enter a CVE or DVE Field Expression

Follow these steps to enter a CVE or DVE field expression:

1. Open the Designer toolbar.
2. Click CDOs. The CDO Definition window appears.
3. Select the CDO that contains the field to which you are adding a CVE or a DVE.
4. Select the Fields tab.
5. Select the desired field and click Properties.
6. Select the Expression tab on the CDO Field Properties window.
7. Set a value for the CVE or DVE:
• Type an expression in the Current Value Expression or Default Value Expression field.

Or

• Click Build and use the Expression Builder to set your CVE or DVE.
8. Click OK or select another tab for more options. Refer to "Unified Expressions."
9. Select Save from the File menu. The application saves your changes.

How to Use the Expression Builder

Follow these steps to use the Expression Builder:

1. Click Build next to the Current Value Expression or Default Value Expression field. The Build Expression window appears.
2. Double-click the CDO in the CDO Definition list. The CDO fields appear in the Field list.
3. Double-click the desired field to be listed in the expression. The selected field appears under Expression.
4. Repeat steps 2-3 until the expression is complete.
Note: A period (.) is automatically inserted between each field you add to the expression.
5. Click Save and Close.
6. To add additional expressions in a series that will resolve from left to right, insert a semicolon at the end of a complete expression, and start at step 2 in this list.
7. Select Save from the File menu. The application saves your changes.

How to Edit Current or Default Value Strings

Follow these steps to edit current of default value strings:

1. Right-click on a selected CDO field and select Expressions. The following window appears:

This example is for the Detail field of Container. Default value and current value expressions are displayed in two separate columns. By default, the window enters the current field in both Find what and Replace with fields.

2. Type a string to be replaced in Find what.
3. Type the replacement string in Replace with.
4. Click Find to find an instance of the string you want to replace.
Important: At step 5, the change immediately takes effect without your confirmation.
5. Click Find and Replace to replace the string.
6. Click the X at the upper right corner of the window to close it.
7. Select Save from the File menu. The application saves your changes.
