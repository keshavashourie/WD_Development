Adding and Removing a Table

You have the option of adding a new table to the database or modifying properties of an existing table. When you create a table through Designer, you are actually creating a table definition that will become a table in the transaction database. Refer to “How to Create New Tables” for information on creating tables from the table definitions.

When Adding and Removing a Table

Two ways to create a table are:

• Adding a table when you add a CDO subclass (from within the New CDO Definition window)
• Adding a table using the Tables button on the Designer main window (this option of adding tables is rarely used)
Note: You will never create a table for container CDO subclasses because your container CDO subclass will use the same table (Container) as the superclass from which your container CDO subclass was derived.

Workspace prefixes are automatically inserted before the name of an item when adding a new item, . Workspace prefixes indicate which workspace Designer is applying changes to. For example, the prefix "C200" would be associated to the workspace with a prefix set as "C200" in Management Studio. It is recommended you use the prefix supplied by Designer when adding new items.

You can assign or modify workspace prefixes in Management Studio. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for information.

Note: The base application workspace (csi) cannot have a workspace prefix assigned to it.

How to Create a Table Definition During CDO Subclass Creation

Follow these steps to create a table during CDO subclass creation:

1. Open Designer.
2. Click CDOs.
3. Select the type of object you want to add from the list of objects on the left and click Add. The Create a new CDO Definition window appears.
4. Enter a name and description for the new object.
Important: The name must not contain spaces, illegal characters, or reserved words. Refer to “Valid Characters and Reserved Words.”
5. Select a Storage Category.

Select a category that is also a Table Category. If you select Modeling, an IsFrozen field is automatically added to the subclass if the field does not already exist through inheritance.

6. Select Create a new Table. The table name and description are filled in from the CDO information.
Note: If the check box Create a new Table is disabled, you cannot create a new table for the category of CDO you have selected. Most likely, the particular CDO is not persistent, such as Service CDOs, or you are creating a Container CDO.
7. Click Create.

To view the new table definition, click Tables on the toolbar, expand the category in which you created the new table, and select the name of the table you created. You can modify properties of the table in this window. Refer to “Modifying a Table” for information.

8. Select Save from the File menu. The application saves your changes.

How to Create a Table Definition Using the Tables Button

Follow these steps to create a table from the tables button:

1. Open Designer.
2. Click Tables. The Table Definitions window appears.
3. Select a table category from the pane on the left.
4. Click Add located at the bottom of the pane. A new table name appears, ready to be renamed.
Note: You can also right-click in the selection tree area to open the shortcut menu and select Add a Table Definition.
5. Rename the new table and click away from the new entry to save it.

Refer to "Valid Characters and Reserved Words" for a list of illegal characters and reserved words to avoid.

6. Click the General tab and enter a meaningful description.
7. Select a table category and table type.
8. Add columns according to your business requirements. Refer to “How to Add Table Columns” for information.
Important: If you created a CDO subclass earlier that will use this table, you must have a table column for each of the inherited fields in the derived CDO table. If you do not do this, you will get an ODBC error stating that Opcenter EX MDD or Opcenter EX CR could not find the columns for the inherited fields.
9. Click away to save your changes.
10. Select Save from the File menu. The application saves your changes.

How to Define an Existing CDO to Use the New Table

Follow these steps to define an existing CDO to use the new table:

1. Open Designer.
2. Click CDOs.
3. Select the CDO to be configured.
4. Click the CDO’s General tab.
5. Select the appropriate category in the Storage Category field.
6. In the Persist Data to Table field, click the browse button to find and select the desired table.
7. Click the Fields tab.
8. For each field, open the Properties window (click Yes to override) and:
a. Click the General tab.
b. In the Column name field, select an existing column; or if none exist and you want the application to create one, click Create a new column.
Note: This button is enabled if you are assigning a table for the first time or if you are changing a CDO’s assigned table.
c. Click OK to close the field properties window.
9. Select Save from the File menu. The application saves your changes.

How to Remove a Table

Removing a table in the Designer will not delete the corresponding entity in the production database. This prevents loss of historical data.

Follow these steps to remove a table from the table library:

1. Open Designer.
2. Click Tables. The Table Definitions window appears.
3. Click on the table category where the table resides.
4. Select the table you want removed.
5. If the Remove button is disabled, click the Where Used tab and note the CDOs that are using the table.
6. Use one of these methods to make the table available for removal,
• Remove the CDOs that use the table
• Specify another table for the CDOs to use
Note: Refer to “Finding and Removing CDOs” for information.
7. Click Remove.
8. Select Save from the File menu. The application saves your changes.

How to Create New Tables

Follow these steps to create the new tables in your transaction database:

1. Open Management Studio.
2. Expand the <sitename> node.
3. Expand the Databases folder.
4. Right-click the transaction database and select Create New Database Tables from the menu that appears. The Create Tables For <database> window appears.
5. Leave all check boxes selected.
6. Click OK. The application creates the new tables, closes the Create Tables for <database> window, and displays a message that the new database was created successfully.
