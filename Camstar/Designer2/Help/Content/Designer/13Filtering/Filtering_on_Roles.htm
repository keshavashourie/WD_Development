Filtering on Roles

This section provides guidance for retrieving a list of roles to which an employee has access. When filtering on roles, use the csiAuthGetUsersRoles database function and one parameter for Employee ID to return a table of organization and role combinations (OrganizationId / RoleId).

Example Query

SELECT e.EventName

,o.OrganizationName

,r.RoleName

,emp.EmployeeName

FROM Event e

JOIN (SELECT OrganizationId, RoleId FROM csiAuthGetUsersRoles((SELECT EmployeeId from Employee where EmployeeName = 'CamstarAdmin'))) AS OwnerRoles

ON e.RoleId = OwnerRoles.RoleId AND e.OrganizationId = OwnerRoles.OrganizationId

JOIN RoleDef r ON e.RoleId = r.RoleId

JOIN Employee emp ON e.OwnerId = emp.EmployeeId

JOIN Organization o ON e.OrganizationId = o.OrganizationId

Use

I want to return Concierge messages for all of the Roles in all of the Organizations to which the logged in user has access. I can join to the csiAuthGetUsersRoles function in order to get the Role/Organization combinations for the user.

Default Implementation

The csiAuthGetUsersRoles function is used in logic in the GetToDoList service. The Designer query using the function is GetToDoListEntries.
