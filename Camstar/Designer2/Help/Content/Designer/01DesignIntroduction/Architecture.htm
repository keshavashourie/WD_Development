Architecture

The pillars of the model-driven architecture are the entities and behaviors. The entities define business objects, and the behaviors that define business logic are referred to as:

• Configurable Data Objects (CDOs)
• Configurable Logic Flows (CLFs)

The CDOs and CLFs build the Opcenter EX MDD or Opcenter EX CR object model.

Object Model and the Factory Model

The object model defines the attributes of an object, for example, the data elements of a product. The factory model defines the values of the data elements, for example, the instance of a particular product type. Refer to the Opcenter Execution Medical Device and Diagnostics Modeling User Guide or the Opcenter Execution Core Modeling User Guide for information about the factory model.

Designer

The base product includes definitions to meet the general requirements for any manufacturing business. Siemens provides additional products to extend the object model by incorporating domain-specific CDOs and CLFs.

The extensions to the model-driven architecture are implemented in Designer, an integral part of the base product. This allows you and Siemens’s services and development teams to adapt the object model to the specific needs of your business. Refer to the Opcenter Execution Medical Device and Diagnostics Installation Guide or the Opcenter Execution Core Installation Guide for information on Designer.

Designer Databases

The object model definitions are in the Microsoft Access databases (InSite.mdb and SiteInfo.mdb), also referred to as the metadata databases. Most of the configurations are written to InSite.mdb, while a small portion devoted to site-specific definitions are stored in SiteInfo.mdb. These databases are portable and can be maintained in Designer on any machine running the Microsoft Windows operating system. The definitions are released to the production database and activated using Management Studio.

Metadata Reports

You can generate Metadata reports using a batch file that is provided with Designer:

C:\Program Files (x86)\Camstar\InSite Administration

The first step in extending the object model is to understand the CDOs and CLFs included with your Opcenter EX MDD or Opcenter EX CR version and edition. Then you are able to identify the additional entities required to run your business requirements.

Upon completion of designing and activating your object model, you are be able to use the Portal to define your factory model.

Configurable Data Objects

The business objects are referred to as Configurable Data Objects (CDOs). Opcenter EX MDD or Opcenter EX CR distinguishes two types of CDOs:

• Data CDOs
• Service CDOs

Data CDOs and Service CDOs consist of a set of data elements called fields. A field is of a specific data type defined in the system and can be:

• a simple data type like string, integer, decimal
• a complex data type like object

Furthermore, a field can be scalar or a list.

Data CDOs

Data CDOs define the entities in your system and their behavior in the form of CLFs. The entities in the system represent business objects such as:

• Product
• Workflow
• Equipment
• Material

The Data CDOs are persistent objects in the system. Their data is non-volatile and lives beyond system restarts. The entirety of Data CDOs define the state of the system. Service CDOs and CLFs are used to alter the state of an object.

Service CDOs

Service CDOs define the tasks or units of work you can perform on Data CDOs. The Service CDOs include objects like:

• Product Maintenance (to add product definition)
• Move (to move a part to a downstream workflow step)
• Collect Data (to capture quality and parametric data)

The behavior of these services is defined in the form of CLFs. In contrast to Data CDOs, Service CDOs are not persistent, but alter the persistent state of the system by operating on Data CDOs.

The unit of work performed by a Service CDO will always be executed as a transaction under the ACID principle (atomicity, consistency, isolation, and durability). This means that either all alterations to the system state will get committed as a whole or no alterations will be committed.

Fields

A field, whether it belongs to a Data CDO or Service CDO, is of a data type predefined in Opcenter EX MDD or Opcenter EX CR. Opcenter EX MDD and Opcenter EX CR support the following field data types:

• Boolean (true or false)
• Decimal (fixed point number type with precision and scale)
• Fixed (fixed point number type)
• Float (approximate number type)
• Integer (whole number type)
• String (text)
• Timestamp (date and time)
• Object (CDO)

Opcenter EX MDD and Opcenter EX CR support scalar fields and list fields. Following the model-driven architecture of Opcenter EX MDD and Opcenter EX CR, a field can have CLFs attached to define custom behavior in response to events in the system, like retrieving the field's value.

Logic

Opcenter EX MDD and Opcenter EX CR logic are defined by CLFs. A CLF consists of functions and defines the sequence in which these functions are executed at system runtime. A CLF can be attached to a Service CDO, Data CDO, and CDO field.

A CLF definition can perform many different actions in the system, such as:

• Determine the next workflow step
• Validate the user input to a field
• Calculate the quantity of a container

The role of functions in the system is to provide sufficiently granular, reusable components to build various types of CLFs.
