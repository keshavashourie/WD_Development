Adding High Performance CLFs

High Performance CLFs are a category of CLFs that are processed on the database rather than the application server. A High Performance CLF is defined as part of a transaction and is sent to the database in the form of one or more database statements (INSERT, UPDATE, DELETE). Executing SQL statements on the database makes processing more efficient.

High Performance Engine is a separately licensed feature. The High Performance CLF category does not appear if you are not licensed for this feature.

Refer to the Opcenter Execution Core Technical Reference: High Performance Engine or the Opcenter Execution Medical Device and Diagnostics Technical Reference: High Performance Engine for information on High Performance Engine.

When Adding High Performance CLFs

The application displays standard functions and database-specific functions in the list of Available Functions. You can add, rename, and remove High Performance CLFs like other CLFs.

When you add a function to a High Performance CLF, parameters are available for the life of the High Performance CLF and are prefixed with DBCLF::. DBCLF:: variables are created by the database stored procedures. DBCLF:: variable references are used only on the database. The application server ignores the DBCLF:: prefix and passes it to the database.

When you select some database functions such as ExecuteSingleSQL in the Available Functions list and drag it to the Logic Flow area, the application populates the Parameter Name in the Function Parameters area with SQLStatementName. Other database functions do not have the SQLStatementName parameter; for example, SQLParameter has the Value parameter with a data type of Any and Multiplicity set to 0..1

SQLStatementName uses Special Processing. The Select a Query pop-up appears when you click the ellipsis for this field. You can select an existing query, edit an existing query, or create a new query using this pop-up. Only Advanced Query and NonQuery SQL types of queries are available. The Include all Workspaces check box is not selected by default, indicating that only queries within your workspace are available for selection. Selecting this check box enables you to select a query from other workspaces.

The Query Definitions pop-up appears if you select to edit a query. You can edit only queries defined in the same workspace in which you are working.

Any parameters associated with the query are returned to the High Performance CLF after you select or edit a query. The application populates the Value column for the SQLStatementName parameter with the query name. The list of all query parameters displays in the Logic Flow area. This enables you to populate the parameters associated with the query.

If you try to change the query to a new query, a warning appears asking if you want to reset the SQL parameter list for the current SQL statement. If yes, the application resets the query name and the parameters. If not, the application preserves the existing parameters .

You can click the New button in the Select a Query pop-up to create a new query. An empty Query Definitions pop-up appears.

How to Add a High Performance CLF

Follow theses steps to add a High Performance CLF:

1. Open Designer.
2. Click CLFs.
3. Select the HighPerformance category.
4. Click the Add button located below the CLF list box. The application adds a new CLF with a default name assigned to it.
Note: You can also right-click in the selection tree area and select Add CLF Definition.

When a CLF is first added, it is in Rename mode.

5. Enter a name for this new CLF.
6. Enter a description for this CLF in the General tab.
7. Change the setting for Visibility in Designer if needed.
8. Click the Functions tab.

 

9. Do you want to add standard functions or database functions to the High Performance CLF?

If you want to add . . .

Then . . .

Standard functions

Complete steps 6-9 of "How to Add Functions to a User CLF."

Database functions

Go to step 10.
10. Drag a database function from the Available Functions list to the Logic Flow area.
11. Does the database function have the SQLStatementName parameter?

If . . .

Then . . .

Yes
a. Go to step 12.

No
a. Modify the function parameters as required.
b. Go to step 14.
12. Click the ellipsis on the SQLStatementName row in the Function Parameters area. The Select a Query pop-up appears.
13. Do you want to select or edit a query, or create a new one?

If you want to . . .

Then . . .

Select a query
a. Select a query from the list and click Select. The application populates the Value column for the SQLStatementName parameter with the query name.

Edit a query
a. Select a query from the list and click Edit. The Query Definitions pop-up appears.
b. Edit the definition of the query and click OK. The Select a Query pop-up appears.
c. Ensure the edited query is selected and click Select. The application populates the Value column for the SQLStatementName parameter with the query name.

Create a new query

a. Click New. The Query Definitions pop-up appears.
b. Define the query and click OK. The Select a Query pop-up appears.
c. Ensure the new query is selected and click Select. The application populates the Value column for the SQLStatementName parameter with the query name.
14. Select Save from the File menu. The application saves your changes.
