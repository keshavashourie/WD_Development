Defining a RevisionedObject Subclass

The RevisionedObject class in Opcenter EX MDD and Opcenter EX CR is used for objects that have a name and a revision. The RevisionedObject class supports a revision-of-record feature that allows you to specify one version as the default version, allowing other objects to reference an instance of a RevisionedObject (RO) without specifying a revision. Examples of ROs are Document, Product, Workflow, and Spec (specification).

Role of the RevisionBase CDO

RevisionBase is an NDO that provides the Revision of Record and revisions. The RevOfRcd attribute provides the ID of the current Revision of Record. The Revisions attribute provides a list of revision instances associated with the revisioned object. For each RevisionBase, there is at least one RO.

Overview of Tasks

The overall steps to define a RO are similar to those used to define a NamedDataObject CDO. The only additional steps address the addition of a RevisionBase CDO and changing the CDO associations for the RO and the RevisionBase CDOs. These are performed automatically if you select the Create & Configure a Maintenance Service option.

Add a RevisionedObject CDO Subclass and Add Fields

Add a RevisionedObject CDO to represent your revisioned object. If you add a CDO, it is derived from the previously existing CDO. This makes the one you add a CDO subclass, inheriting all the fields and properties of the CDO from which it is derived. After the CDO is added, you can override field properties, add new fields, or delete fields to create a unique CDO that fits your business model. Add fields to the newly added RevisionedObject (RO) as needed. Refer to “Defining List Fields” for information about adding list fields to a CDO.

Workspace prefixes are automatically inserted before the name of an item when adding a new item, if a prefix has been assigned to the highest active workspace. Workspace prefixes indicate which workspace Designer is applying changes to. For example, the prefix "C200" would be associated to the workspace with a prefix set as "C200" the highest active workspace in Management Studio. It is recommended you use the prefix supplied by Designer when adding new items.

You can assign or modify workspace prefixes in Management Studio. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for information.

Note: The base application workspace (csi) cannot have a workspace prefix assigned to it.

Add a Subentity to an RO

There are many circumstances that are best managed by adding subentities to ROs. You may want to add several subentities to a single RO to group discrete types of information, with the advantage of connecting the grouped information to the RO. For example, to group resource information about an RO, such as a spec, you will maintain the resource information on a subentity under the RO Specification.

Refer to “Defining a Subentity CDO Subclass” for information on adding subentities.

How to Add a RevisionedObject CDO Subclass

This procedure guides you through an exercise that defines a RevisionedObject CDO. The example uses Product.

Follow these steps to add a RevisionedObject CDO subclass:

1. Open Designer.
2. Click CDOs on the toolbar. The CDO Definition window appears.
3. Select Advanced from the View menu.
4. Click CDOs. The CDO Definition window appears.
5. Select RevisionedObject>Product from the list of default classes. The definition window for Product appears.

 

6. Click Add (below the CDO list). The Create a new CDO Definition window appears.
7. Enter MyProduct in the New CDO Name field.
Important: The name of the CDO can be up to 30 characters in length, and cannot contain spaces, illegal characters, or reserved words. Refer to "Valid Characters and Reserved Words” for information.
8. Enter a Description. (The Create button is not enabled until you enter a description.)

 

9. Ensure Modeling is selected for Storage Category.
10. Ensure Create & Configure a Maintenance Service is selected.

The CDOs required for maintenance and the associated required field overrides are automatically created for this RO if this is selected.

11. Click Create. MyProduct is added under RevisionedObject>Product.
12. Click Update DB. A dialog box appears asking you to confirm you want to save the current MDB file and update the database according to the settings in the Preferences dialog box.
13. Click Yes. A status bar appears at the bottom of the window to indicate the update is in progress. The application saves and updates the database.

Automated steps

The following associated CDOs were automatically defined:

• MyProductMaint is added under Service>Update>Maintenance>ProductMaint
• MyProductBase is added under RevisionBase>ProductBase.
• MyProductChanges is added under RevisionedObjectChanges>ProductChanges.
• MyProduct references MyProductBase through the Base field.
• MyProductBase references MyProduct through the Revisions and RevOfRcd fields.
• MyProductChanges references MyProduct through the ObjectToChange field and references MyProductBase through the Base field.

Refer to "Automated Steps in Defining a CDO Subclass" for information.

Note: Refer to "Preferences Dialog Box, DB Update Tab" for information on the settings available in the Preferences dialog box. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for more detailed information on updating the database.

How to Add Fields to the RevisionedObject CDO

In this procedure, you add two fields: a string type and an object type.

1. Select the revisioned object you have just defined. In this case, it is MyProduct. The CDO Definition window for MyProduct opens at the Fields tab.
2. Click Add under the Fields tab. The Add a New CDO Field window appears. The Data Type defaults to String.
3. Configure the field as follows:
a. Select _String as the Field Type.
b. Enter Parm1 in the Name field.
Important: The name must not contain spaces, illegal characters, or reserved words.
c. Enter Parameter 1 in the Caption field.
Note: This value will appear as the field’s caption if using Portal Studio, Modeler, or Visual Controls. For easy reading, use spaces.
d. Enter a description for the field.
e. Keep Add Field to Associated Service Objects selected.
f. Click Create. The CDO Field Properties window appears.
Note: In the General tab, the Field name and Column name fields display the name of the new field.
g. Click OK.
4. Click Add again to add the second field.
5. Configure the field as follows:
a. Select Object data type from the Data Type list.
b. Select Owner as the Field Type.
Note: Keep the field name as Owner.
c. Optionally, change the description to suit your business requirements.
d. Keep Add Field to Associated Service Objects selected.
e. Click Create. The CDO Field Properties window appears.
f. Click OK. The fields Parm1 and Owner are added to MyProduct and to MyProductChanges.
6. Click Update DB. A dialog box appears asking you to confirm you want to save the current MDB file and update the database according to the settings in the Preferences dialog box.
7. Click Yes. A status bar appears at the bottom of the window to indicate the update is in progress. The application saves and updates the database.
Note: Refer to "Preferences Dialog Box, DB Update Tab" for information on the settings available in the Preferences dialog box. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for more detailed information on updating the database.

This completes the exercise of creating a RevisionedObject subclass and all related configurations.

How to Remove a RevisionedObject CDO

If you need to delete the RevisionedObject subclass that you created, you must remove the associated CDOs in the reverse order that the associations were created. This topic explains the process, using MyProduct as an example.

Follow these steps to remove a RevisionedObject CDO:

1. Open Designer.
2. Click CDOs on the toolbar. The CDO Definition window appears.
3. Select Advanced from the View menu.
4. Clear the overrides in the Revisions and RevOfRcd fields of MyProductBase.
5. Clear the overrides in the Base and ObjectToChange fields of MyProductChanges.
6. Clear the overrides in the Base field of MyProduct.
7. Remove MyProductMaint.
8. Remove MyProductBase.
9. Remove MyProductChanges.
10. Remove MyProduct.
11. Select Save from the File menu. The application saves your changes.
Note: Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for more detailed information on updating the database.
