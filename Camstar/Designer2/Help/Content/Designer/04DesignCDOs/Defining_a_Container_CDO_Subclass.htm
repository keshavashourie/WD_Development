Defining a Container CDO Subclass

Container CDO subclasses contain the definition for the Container, the basic tracking unit. It refers to the lot or batch of products in your factory model. The Container is identified by a name and a level. This topic explains the steps required to define a Container CDO subclass. Most of the steps are automated.

When Defining a Container CDO Subclass

You can also extend the Container CDO that has a more sophisticated data structure, such as a subentity CDO.

Workspace prefixes are automatically inserted before the name of an item when adding a new item, if a prefix has been assigned to the highest active workspace. Workspace prefixes indicate which workspace Designer is applying changes to. For example, the prefix "C200" would be associated to the workspace with a prefix set as "C200" in Management Studio. It is recommended you use the prefix supplied by Designer when adding new items.

You can assign or modify workspace prefixes in Management Studio. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for information.

Note: The base application workspace (csi) cannot have a workspace prefix assigned to it.

Automatically Generated Associated CDOs and References

When you add a Container CDO, if you click the check box on the Create a new CDO Definition window to Create & Configure a Start Service, these required tasks are performed automatically. This table defines the required tasks.

Task

Definition

Add a Start Service Subclass

A subclass of the Start Service CDO is added to handle the Start service for the new Container CDO, and the container reference in the Start Service CDO is changed to reference the new Container CDO.

Add a StartDetails Subentity Subclass

ServiceDetails CDOs contain the change data about the Container transactions performed by its StartService, so every StartService CDO needs its own StartDetails CDO. A new StartDetails subentity CDO is added under the new StartService subclass.

Add a StartHistoryDetail Subclass

A subclass of the StartHistoryDetail CDO is created for the new container CDO. This new CDO will be used to track changes to your Container as it is involved in transactions.

Change CDO References

If the Service CDO uses a ServiceDetails CDO, the Service CDO must reference its ServiceDetails subentity through the Details field on the Service CDO. If a ServiceDetails subentity exists for a Container, then the Container field in the ServiceDetails subentity is consulted, so the subentity must reference the correct Container CDO. If you click the check box on the Create a new CDO Definition window to Create & Configure a Start Service, this task is performed automatically for you. Refer to “Creating Field Overrides” for details on overriding CDO references.

Adding Fields

Add fields to the new Container subclass to give this CDO the properties required by your business. This is demonstrated in the exercise that follows. Refer to “Defining List Fields” for information on adding list fields to a CDO.

When you add fields to a Container CDO, if you click the check box on the Add Fields to the Associated Service Objects, the required tasks listed below are performed automatically:

• Add Fields to the Service CDO Subclass
• Add Fields to the ServiceDetails CDO Subclass
• Add Fields to the ServiceHistoryDetails CDO Subclass
• Map Fields Between CDOs

How to Add a Container CDO Subclass

Follow these steps to add a container CDO subclass:

1. Open Designer.
2. Click CDOs on the toolbar. The CDO Definition window appears.
3. Select Container.
4. Click Add below the selection tree. You can also right-click on Container and select Add Subclass. The Create a new CDO Definition window opens.
5. Enter the new object (CDO) name in the New CDO Name field.
Important: The name of the CDO can be up to 30 characters in length, and cannot contain spaces, illegal characters, or reserved words. Refer to "Valid Characters and Reserved Words" for information.
6. Enter a Description.
Note: The Create button is not enabled until you enter a description.
7. Keep the default values in other fields.
8. Click Create. The new CDO appears in the list of CDOs.
9. Click Update DB. A dialog box appears asking you to confirm you want to save the current MDB file and update the database according to the settings in the Preferences dialog box.
10. Click Yes. A status bar appears at the bottom of the window to indicate the update is in progress. The application saves and updates the database.

Automated steps

The following associated CDOs were automatically defined:

• MyContainerStart is added under Service>Update>Shopfloor>Container Txn>Start
• MyContainerStartDetails is added under Subentity>ServiceData>ServiceDetails>StartDetails
• MyContainerHistoryDetail is added under Subentity>HistoryDetails>StartHistoryDetail
• MyContainerStart references MyContainerStartDetails through the Details field.
• MyContainerStart references MyContainerHistoryDetail through the HistorySummary field.
• MyContainerStartDetails references MyContainerStartDetails in the ChildContainers field and references MyContainer in the Container field.
• MyContainerStartDetails references MyContainerStart in the Parent field.

Refer to "Automated Steps in Defining a CDO Subclass" for a detailed discussion of the automated steps.

Note: Refer to "Preferences Dialog Box, DB Update Tab" for information on the settings available in the Preferences dialog box. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for more detailed information on updating the database.

How to Add Fields to the MyContainer CDO

Follow these steps to add fields to the MyContainer subclass:

1. Open Designer.
2. Click CDOs on the toolbar. The CDO Definition window appears.
3. Select MyContainer and then click the Fields tab.
4. Click Add at the bottom of the Fields tab, or right-click on the pane and select Add field. The Add a new CDO Field window appears.
5. Keep the default value on the Data Type field, String.
6. Select [String] in the Field type list.
7. Enter MyField1 in the Name field. The Create button is enabled.
Important: Field names must not contain spaces, illegal characters, or reserved words. Refer to "Valid Characters and Reserved Words" for information.
8. Enter a Caption for the field, or click the ... button to select a caption.
9. Enter a description in the Description field.
10. Keep Add Fields to Associated Service Objects checked.
11. Click Create. The CDO Field Properties window appears.
12. Select the Options tab.
13. Select User required in the Constraints area.
14. Select Read/Write in the Accessibility area.
15. Ensure the Apply the same changes to the corresponding fields in the associated Service and History objects field is selected.
16. Click OK.
17. Repeat step 4 through step 16 to add a field MyField2 to MyContainer.
18. Select Save from the File menu. The application saves your changes.

MyField1 and MyField2 are added to the MyContainer CDO. The following were also defined automatically:

• MyField1 and MyField2 in the MyContainerStartDetails CDO are mapped to MyField1 and MyField2 in the MyContainer CDO. Mapping propagates field values from one CDO to other CDOs when the values are changed by services. This procedure is explained in Viewing Field Maps.
• MyField1 and MyField2 are also added to the History Details CDO, MyContainerHistoryDetail, to capture history data from MyField1 and MyField2 that you added to MyContainer.

How to Remove a Container CDO Subclass

If you need to delete the Container CDO subclass that you created, you must remove the changes in the reverse order that you entered them. Generally, if a CDO has fields referencing its parent or child CDOs, you must remove those reference fields before you can remove the CDO.

Follow these steps to remove a Container CDO subclass:

1. Clear overrides in fields containing references to parent and child CDOs for each CDO created.

For example, the new service details subentity CDO (MyContainerStartDetails) has a Container field referencing the Container subclass CDO (MyContainer), and a Parent field referencing the subentity’s parent CDO. Clear the overrides for both of those fields. Do this in the Fields tab for the subentity CDO. Refer to “Creating Field Overrides” for details on overriding fields.

2. In the service CDO subclass (MyContainerStart), clear the override in the Details field referencing the service details subentity (MyContainerStartDetails) and in the HistorySummary field referencing MyContainerHistoryDetail.
3. In the service details subentity (MyContainerStartDetails), clear the overrides for the ChildContainers field.
4. Remove the new Service CDO subclass (MyContainerStart) by selecting it in the CDO selection tree, and clicking on the Remove button.
5. Remove the new Container subclass CDO (MyContainer).
6. Remove the new Service subentity CDO (MyContainerStartDetails).
7. Remove the new HistoryDetails subentity CDO (MyContainerHistoryDetail).
8. Click Update DB. A dialog box appears asking you to confirm you want to save the current MDB file and update the database according to the settings in the Preferences dialog box.
9. Click Yes. A status bar appears at the bottom of the window to indicate the update is in progress. The application saves and updates the database.
Note: Refer to "Preferences Dialog Box, DB Update Tab" for information on the settings available in the Preferences dialog box. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for more detailed information on updating the database.
