Events and Methods

A CDO initiates a CLF using either an event or a method. Events and methods act as pointers from CDOs to a CLF. Events and methods are defined as follows:

• Event

An event is a delegate that may contain a reference to a CLF.

CDOs and Fields have a predefined set of events that are automatically triggered by the system. For example, when a client application sets a value on a CDO field, the system triggers the Validate event, among others. The set of events cannot be extended by the user.

The system behavior can be modified by attaching CLFs to events, modifying function parameter values of associated CLFs, or detaching CLFs from events.

• Method

A method is a delegate that contains a reference to a CLF.

CDOs defined by Siemens commonly have methods attached. These methods are triggered by the logic flow of a service, a CLF, an event, or directly from a client application. The set of methods attached to a CDO can be extended by the user. A method is created by attaching a CLF, removed by detaching a CLF, and altered by modifying function parameter values. The creation of methods is a common means to partition complex CLFs into reusable components that are executed sequentially.

Refer to the Opcenter Execution Medical Device and Diagnostics Technical Reference: Client APIs or the Opcenter Execution Core Technical Reference: Client APIs for information on using Siemens' .NET Client APIs.

Note: An event or method on a CDO can only be associated with one CLF. This allows each type of CDO to respond to the same event in a unique way.

If a CLF is called or triggered, each function is called in order, one at a time.
