CDO Tabs

Detailed information about a selected CDO is displayed in tabs in the rightmost pane of the CDO Definition window. The following tabs are provided on the CDO Definition window:

• General Tab
• Fields Tab
• Maps Tab
• Advanced Options Tab
• Selection Values Tab
• Events Tab
• Where Used Tab
• Feature Entitlement Tab

Selection Values Tab

The Selection Values tab shows what Selection Values Query, if any, is used by the selected object. The queries are based on the CDO type, such as NDO and RO, and return specific object instances or all object instances in a table.

When you set a Selection Value for the CDO in the CDO Definition window, it is this selection value that becomes the selection value of that field type. When a field references this CDO, the Static selection values option uses the Selection Values Query defined in this tab.

If there are selection values, clicking the Details button opens the Queries window for a selected query. Refer to “Queries” for information.

Events Tab

The Events tab shows the events attached to the selected CDO.

Details for an Event or Method

If you check Details and select an event or method, the list of associated access modes is displayed. The checked access modes indicates authorized user access to the event or method, and requires that the associated permission be granted to the user.

For example, when the system receives a request to execute a service associated with the CDO, the system checks for the access mode associated with the method to determine whether it exists in the service permissions on any role that the user is granted. If it has not been granted, the service will fail.

Permissions are specified through security administration. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for information.

Abstract and Client UI Attributes

CDOs have three attributes that affect how you see NDOs and ROs on the Portal:

• The Abstract check box found on the CDO’s General tab, which impacts application server processing and the UI (the UI can be a customer’s UI or Portal).
• The Client UI check box found on the CDO’s Advanced Options tab, which impacts the UI only.

Abstract Flag

If a CDO is flagged as Abstract, the application server enforces this by not allowing the creation of an instance, even if the client UI requests that an instance be created. The Portal also understands this setting.

Some base classes are defined as abstract in Opcenter EX MDD and Opcenter EX CR, but this setting is overridden in the subclasses

Client UI Flag

The Client UI setting exposes or hides the services under Maintenance. You can use the default modeling menu initially for the Portal. If you decide you do not need some of the objects on the menu, you can change the Client UI setting. You do not make the change directly to the object, however; you change the object’s corresponding Maint object.

Affect on Inheritance

The inheritance of Abstract and Client UI settings affects the client application as follows:

• Using the example of NamedDataObjectMaint, while you cannot instantiate it because it is abstract, it needs to be exposed; otherwise, you will not see its subclasses and therefore cannot maintain any named data objects.
• Not exposing a class to the UI means you cannot access it, even if that class is not abstract.
