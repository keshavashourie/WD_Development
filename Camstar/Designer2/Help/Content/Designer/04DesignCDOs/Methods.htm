Methods

Users can create methods by calling out a CLF and attaching it to a new event. Siemens attached five methods without any preexisting logic to some events in shop floor transactions to make it easier for users to customize these transactions. The methods, also called user exits, are:

1. PreValidate_User

This method is called by the BeforeValidate event. You can insert additional processing logic that occurs after default execution logic.

2. Validate_User

This method is called by the AfterValidate event. You can insert additional processing logic that occurs after the required value validations.

3. PreExecute_User

This method is called by the BeforeExecute event. You can insert additional processing logic that occurs before default transaction execution logic.

4. Execute_User

This method is called by the BeforeExecute event. You can insert additional processing logic that occurs after default transaction execution logic.

5. ExportInfo_Initialize_User

This method inherited and is called by the BeforeExecute event. You can insert logic related to the creation or initialization of additional ExportInfo objects.

6. ProcessAfterCommit_User

This method is called by the AfterCommit event. You can insert additional processing logic that occurs after default transaction post-commit logic.

Custom Logic Examples

You will most likely customize a transaction under ShopFloor by first adding a subclass and then some user-defined fields. Your subclass will then inherit ShopFloor events. Some examples of how you can customize logic are:

• You can attach a CLF to the Validate_User event to validate the new fields or you can attach a CLF and map the new fields in some CDOs to the Execute_User event.
• You can also make calls to your COM-compliant custom executions.

Limitation

There is a possibility that the transaction you are extending might fail. For example, you might be using a variable in the Transaction scope that is already in use by Opcenter EX MDD or Opcenter EX CR.

How to View the User Exits

Follow these steps to view user exits:

1. Click CDOs on the Designer toolbar.
2. Select the ShopFloor CDO.
3. Go to the Events tab and click Include inherited. Inherited events and methods are added to the display.
4. Scroll down to the methods section, and locate the five user exits.
5. View an example of a system event calling one of the methods as follows:
a. Expand the BeforeValidate event.
b. Expand the attached CLF, ShopFloor::Call.
c. Expand the Call function.

The function is calling the PreValidate method. If you want to add your own logic to the BeforeValidate event, select the PreValidate method. This method calls three more methods: PreValidate_User, PreValidate_Specific, and PreValidate_Generic.

The call tree further leads to more methods being called, each one becoming specific. The last method being called provides a placeholder function, _Comments, to which you insert your logic.
