Defining a Container CDO Subclass

The following tasks are performed automatically if you click the check box on the Create a new CDO Definition window to Create & Configure a Start Service when you add a Container CDO.

• Add a StartService CDO Subclass
• Add a StartDetails Subentity Subclass
• Add a StartHistoryDetail Subclass
• Adding Container Fields to the Service History Details CDO

If the Service CDO uses a ServiceDetails CDO, the Service CDO must reference its ServiceDetails subentity through the Details field on the Service CDO. If a ServiceDetails subentity exists for a Container, then the Container field in the ServiceDetails subentity is consulted, so the subentity must reference the correct Container CDO. If you click the check box on the Create a new CDO Definition window to Create & Configure a Start Service, this task is performed automatically for you. Refer to "Creating Field Overrides" for information on overriding CDO references.

When you add fields to a Container CDO, if you click the check box on the Add Fields to the Associated Service Objects, the required tasks listed below are performed automatically:

• Add fields to the StartDetails CDO subclass
• Add fields to the StartHistoryDetails CDO subclass
• Map fields between CDOs

Mapping fields updates fields in your specified CDO destinations from the CDO sources you identify. Fields added to the new Container subclass, to the StartServiceDetails, and to the StartHistoryDetails CDOs are mapped from the new fields in the StartDetails CDO to the new Container fields, and then mapped from the new Container CDO to the new StartHistoryDetails CDO. Mapping is done in this sequence because the end-user’s changes will go from the User Interface to the Start Details CDO first. Refer to "Viewing Field Maps" for information.

Add a StartService CDO Subclass

Every Container CDO has to have its own StartService CDO. The procedure to create a StartService CDO for the new Container has been automated for you if you click Create & Configure a Start Service when creating the new Container CDO. A subclass of the Start Service CDO is added to handle the start service for the new Container CDO, and the container reference in the Start Service CDO is changed to reference the new Container CDO.

Refer to "How to Add a Service CDO" for information.

Add a StartDetails Subentity Subclass

ServiceDetails CDOs contain the change data (details) about the Container transactions performed by its StartService, so every StartService CDO needs its own StartDetails CDO. A new StartDetails subentity CDO is added under the new StartService subclass. This procedure is automated for you if you click Create & Configure a Start Service when creating a Container CDO.

Refer to "Creating the Service Subclass Using the Wizard" for information.

Add a StartHistoryDetail Subclass

A subclass of the StartHistoryDetail CDO is created for the new container CDO. This new CDO will be used to track changes to your Container as it is involved in transactions. This CDO is automatically created for you if you click Create & Configure a Start Service when creating a Container CDO.

Adding Container Fields to the Service History Details CDO

In this exercise, you are adding fields to the History Details CDO to capture history data from MyField1 and MyField2 that you added to MyContainer for historical recording purposes. If you click Add Fields to Associated Service Objects when adding the fields, this step is automated for you.

How to Add Fields

Follow these steps to add fields:

1. Open Designer.
2. Locate the following CDO in the CDO class library:

Subentity>HistoryDetails>StartHistoryDetail>MyContainerHistory Detail

3. With MyContainerHistoryDetail selected, select the Fields tab.
4. Add the same fields MyField1 and MyField2 to MyContainerHistoryDetail, in the same way you added them to MyContainer.
Note: This adds fields to the StartHistoryDetail CDO subclass, but it does not ensure that the fields are updated when the Container CDO is updated. To connect them properly, you must map the fields. Mapping is explained in "Viewing Field Maps." If you click Add Fields to Associated Service Objects when adding the fields, this step is automated for you.
5. Select Save from the File menu. The application saves your changes.
