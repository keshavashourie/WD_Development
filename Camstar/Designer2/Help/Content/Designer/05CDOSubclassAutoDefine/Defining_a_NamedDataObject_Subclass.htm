Defining a NamedDataObject Subclass

A NamedDataObject is a class of objects that is identified by a unique name. It represents static entities that are not revisioned. When you add named data objects, follow the structure in the class library by relating your new CDOs to one another in the same way that the default named data objects relate to one another. Instances of named data objects are persistent; that is, information about them is written to the database.

When you add a NamedDataObject CDO, if you select the check box on the Create a new CDO Definition window to Create a Maintenance Service, the required tasks (listed immediately below) are performed automatically:

• Add an ObjectChanges CDO for the NDO.
• Reference the new NDO from new ObjectChanges CDO.
• Add a Maintenance CDO for the NDO.
• Reference the new NDO from the new Maintenance CDO

ObjectChanges CDO for the NDO

ObjectChanges CDOs are visible in the Advanced view. The purpose of adding an ObjectChanges CDO is to provide a scratch area to store the changes before committing them to the NamedDataObject CDO. The ObjectChanges CDO is exposed to the Client. This means that if changes are made to the ObjectChanges CDO, the changes are validated before they are written to the NamedDataObject CDO. This feature provides a layer of protection from accidental changes. The validated changes to the NamedDataObject CDO are in turn written to the database.

Reference the new NDO from new ObjectChanges CDO

The reference is made with a field override. Linking these objects together through a field changes its field type on the ObjectChanges CDO to the name of the NDO to which it is being linked. Moving CDO object references into fields enables CDOs to reference each other. The key field that contains this link on the ObjectChanges CDO is called ObjectToChange. Refer to "Creating Field Overrides" for information on the process of overriding.

Maintenance CDO for the NDO

The purpose of adding a Maintenance CDO is to maintain the new NamedDataObject CDO. Maintenance includes loading, adding, copying, changing, and deleting instances of the object from a Client application, such as the Portal.

Reference the new NDO from the new Maintenance CDO

With this step, you link the Maintenance CDO to the new NamedDataObject CDO and to the new ObjectChanges CDO.
