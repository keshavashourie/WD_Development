Creating the Service Subclass Using the Wizard

Create your own ChgContainerAttribute service so that you can specify the attributes you want to change based on your business rules. The Designer provides a wizard to create the ChgContainerAttribute subclass, its corresponding history objects, and the field mapping definitions.

When Creating the Service Subclass Using the Wizard

Workspace prefixes are automatically inserted before the name of an item when adding a new item, if a prefix has been assigned to the highest active workspace. Workspace prefixes indicate which workspace Designer is applying changes to. For example, the prefix "C200" would be associated to the workspace with a prefix set as "C200" in Management Studio. Siemens recommends you use the prefix supplied by Designer when adding new items.

You can assign or modify workspace prefixes in Management Studio. Refer to the Opcenter Execution Medical Device and Diagnostics System Administration Guide or the Opcenter Execution Core System Administration Guide for information.

Note: The base application workspace (csi) cannot have a workspace prefix assigned to it.
Change Attributes Services Wizard

Changing the service involves adding, removing, and renaming fields. Instead of making the changes to the CDOs directly, Siemens recommends making the changes through the Change Attribute Services Wizard to ensure that the changes are propagated through the associated history objects and that mapping information is also updated.

The ChgContainerAttribute Service Wizard:

• Is enabled for multi-level sub classes of ChgContainerAttribute service
• Disabled updates to inherited field maps, displayed in light green color
• Includes a Sub-class wizard to display subtypes of the Container type defined in the parent service instead of displaying all the Container subtypes
Note: The Change Attribute Services wizard is available through the CDO shortcut menu for any ChgContainerAttribute subclass. In our example, the wizard is called out through the MyContainerMaint subclass.

How to Create the ChgContainerAttribute Service

Follow these steps to create the ChgContainerAttribute service:

1. Log in to Designer.
2. Click CDOs on the toolbar.
3. Locate and select the ChgContainerAttribute CDO.
4. Right-click to open the CDO shortcut menu and select Add Subclass.
5. Enter a name for the subclass (for example, MyContainerMaint) and enter a description.
6. Select the container type for which you are creating this service from the Change Attribute Target Container Type list.

For example, if you are creating the service for your own container subclass called MyContainer, select that from the list. Do not use GroupContainer and UnitContainer. These are provided for backward compatibility only.

7. Click Create. The Change Attributes Service Wizard window appears, displaying a list of fields representing the attributes you can change.
8. Select the check boxes next to the fields (including user-defined fields) you want to add to your service.

The fields you select represent the container attributes you want to change through this service. For example, if your service will be used to change the Customer, DueDate, Level, MfgOrder, Owner, Priority, and any user-defined fields, click only those fields.

9. Click Validate to ensure there are no duplicate field names in your service.

If this is the first time you are creating the service, you are not expected to find any duplicates. But if this is an existing service to which you have added your own fields, and the wizard finds duplicate names, rename one of the fields by double-clicking the field name and typing a unique name.

10. Click OK to complete the creation of your service and wait a few moments for the process to complete.

Note that if you click Cancel instead, the service subclass is still added to the CDO library.

Two fields are created for the service:

• HistorySummary that references MyContainerMaintHistory
• ServiceDetail that has a subentity, MyContainerMaintDetail
11. Go to the subentity, MyContainerMaintDetail, and view the fields.
12. Select Save from the File menu. The application saves your changes.

The following maps from MyContainerMaintDetail are created:

• MyContainerMaintDetailTo<YourContainer>
In this map, the Customer, DueDate, Level, MfgOrder, Owner, and Priority are mapped.
• MyContainerMaintDetailToCurrentStatus
• MyContainerMaintDetailToContainerDetail

For the next two maps, if you added fields to CurrentStatus and ContainerDetail, these are not mapped automatically. You need to copy the user fields to MyContainerDetail and then map those fields.

Important: After the service is created, do not change the container type because redoing the maps is a manual and complex process.

How to Change Your ChgContainerAttribute Service

Follow theses steps to change your ChgContainerAttribute service:

1. Select the service subclass you created previously (in this case, MyContainerMaint) and right-click to open the CDO shortcut menu.
2. Select Change Attribute Service Wizard. The Wizard opens, displaying the fields you added to the service.
3. Change according to your business requirements, as follows:
• To add fields, click the box next to the field you want to add.
• To rename a field that was added to the service, double-click the name; or select the field and click the Rename button. Then enter the new name in the dialog box.
Note: You can choose to rename the field that is in the corresponding service detail and history detail CDOs.
• To remove a previously added field, clear the check mark from the check box.
4. Click OK.
5. Select Save from the File menu. The application saves your changes.
