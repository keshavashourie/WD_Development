本节介绍 XML 导入文档的结构。不要编辑 Siemens 提供的任何文档，除非产品支持指示这样做。

该文档包含以下两部分：

• 标头：用于提供有关文档的常规信息（如版本和导入处理默认设置）。
• 导入：包含要在目标元数据配置中添加或更改的所有定义。

导入部分

“导入”部分介绍要加入目标元数据配置中的元数据。此部分也按标准部分格式对信息进行分组。

标准部分格式

“导入”部分介绍元数据，并使用一种标准格式，这种格式首先对最高级别无需定义在另一对象关联内的对象类型进行分组。例如，定义 CLF 定义时不需要关联，但函数参数只能在相关函数关联中定义。

导入文档属性

鉴于对导入文档的作者提出完整知道所有可能目标元数据配置内容的要求并不现实，所以不必区分添加对象定义和更新现有定义。导入处理逻辑会自动确定此问题。但是，标识节点中有一个可选的“操作”属性，使导入文档更加便于阅读。“操作”属性的值可以是“创建”或“导入”，并指示是将元数据添加到还是更新到目标配置。

导入的数据可以是单个属性中的任何内容，例如将现有对象定义的描述更改为完整的对象定义或对象定义的结构（如函数及其所有关联参数）。每个对象定义的 XML 格式由标识、属性数据构成，必要时还包含其他对象定义的组合，如 CDO 定义中的事件和方法、函数定义中的参数等。

“属性”数据包括一些简单的数据类型，如描述（字符串）和复合数据类型（即对其他对象定义的引用）。如果指定属性时未指定名称，则将值显式设为空值，这与导入文档中省略的其他属性不同。省略的属性将保持不变。

重命名

此操作属性用于对现有对象定义重命名。

对象引用

大多数属性数据都是对其他对象定义的引用，需要在导入文档中使用复合结构。对于大多数对象类型，只需要名称。对于某些对象类型（如 CDO 字段或 DB 列），需要提供附加信息来定义关联。对于 CDO 字段，CDO 定义是关联。对于 DBColumns，关联是 DBTable。

预期值处理

预期值处理的目的是避免意外替代用户对目标元数据的更改。此目的通过为要更改的属性指定可选的预期值来实现。导入处理将对目标元数据中的值与预期值进行比较，并采取适当的操作。以下是可能采取的操作：

• 接受更改并继续处理。
• 保留值不变并继续处理。
• 保留值不变并停止处理。
• 提示用户确定要采取上述哪项操作。

无论采取哪项操作，都向日志中写入一个条目，用于标识找到的差异。

可以在三个不同的级别指定要采取的操作，每一个级别都优先于下一个级别。三个级别分别是：

• 全局。这是未指定其他任何值时的默认操作。
• 对特定属性组（如描述、标签文本等）全局。这是针对特定类型的属性采取的默认操作。
• 特定于属性。这是针对特定属性采取的操作。

全局操作在文档的页眉部分指定。特定操作指定为与其关联的属性的一个子节点。
