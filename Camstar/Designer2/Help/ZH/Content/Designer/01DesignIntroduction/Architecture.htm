体系结构

模型驱动的体系结构以实体和行为作为支柱。实体用于定义业务对象，而用于定义业务逻辑的行为则称为：

• 可配置数据对象 (CDO)
• 可配置逻辑流 (CLF)

CDO 和 CLF 构成了 Opcenter EX MDD 对象模型或 Opcenter EX CR 对象模型。

对象模型和工厂模型

对象模型定义对象的属性，例如，产品的数据元素。工厂模型定义数据元素的值，例如，特定产品类型的实例。有关工厂模型的信息，请参考《Opcenter Execution Medical Device and Diagnostics Modeling 用户指南》或《Opcenter Execution Core Modeling 用户指南》。

Designer

基本产品包含许多定义，可满足任何制造企业的常规要求。Siemens 还提供其他产品，用于通过纳入特定于域的 CDO 和 CLF 来扩展对象模型。

模型驱动体系结构的扩展在 Designer 中实施，这是基础产品的一个组成部分。这有助于用户和 Siemens 服务开发团队均可调整对象模型，以满足业务的特定需求。有关 Designer 的信息，请参考《Opcenter Execution Medical Device and Diagnostics 安装指南》或《Opcenter Execution Core 安装指南》。

Designer 数据库

对象模型在 Microsoft Access 数据库（InSite.mdb 和 SiteInfo.mdb），即元数据数据库中定义。大多数配置都写入 InSite.mdb，而专门用于特定于站点定义的一小部分配置存储在 SiteInfo.mdb 中。这些数据库具有可移植性，且可以在运行 Microsoft Windows 操作系统的任何计算机上的 Designer 中予以维护。此类定义将发布到生产数据库中，并使用以下模块予以激活： Management Studio。

元数据报告

可以通过使用 Designer 随附的批文件来生成元数据报告：

C:\Program Files (x86)\Camstar\InSite Administration

扩展对象模型的第一步是了解您所用 Opcenter EX MDD 或 Opcenter EX CR 版本附带的 CDO 和 CLF。然后，可以标识运行业务要求所需的其他实体。

完成对象模型的设计和激活之后，可以使用 Portal 定义工厂模型。

可配置数据对象

业务对象称为可配置数据对象 (CDO)。Opcenter EX MDD 和 Opcenter EX CR 区分两种类型的 CDO：

• 数据 CDO
• 服务 CDO

数据 CDO 和服务 CDO 由一组称为字段的数据元素组成。字段是在系统中定义的特定数据类型，它可以是：

• 简单的数据类型，如字符串、整数、十进制
• 复杂的数据类型，如对象

此外，字段也可以是标量或列表。

数据 CDO

数据 CDO 以 CLF 的形式定义系统中的实体及其行为。系统中的实体表示业务对象，例如：

• 产品
• 工作流程
• 设备
• 物料

数据 CDO 是系统中的持久对象。其数据具有非易失性，在系统重新启动之后仍然存在。全部数据 CDO 定义系统的状态。服务 CDO 和 CLF 用于更改对象的状态。

服务 CDO

服务 CDO 定义可以在数据 CDO 上执行的任务或工作单元。服务 CDO 包括以下对象：

• 产品维护（用于添加产品定义）
• 移动（用于将零件移动到下游工作流程工步）
• 收集数据（用于捕获质量和参数数据）

这些服务的行为以 CLF 形式予以定义。与数据 CDO 相反，服务 CDO 不具有持久性，而是通过操作数据 CDO 来改变系统的持续状态。

服务 CDO 执行的工作单元始终根据 ACID 原则（原子性、一致性、隔离性和耐久性）作为事务予以执行。这意味着要么系统状态的所有改变作为一个整体进行提交，要么不提交任何更改。

字段

无论属于数据 CDO 还是服务 CDO，字段都具有 Opcenter EX MDD 或 Opcenter EX CR 中预定义的数据类型。Opcenter EX MDD 和 Opcenter EX CR 支持以下字段数据类型：

• 布尔型（true 或 false）
• 十进制（具有整数位数和小数位数的定点数值类型）
• 固定（定点数值类型）
• 浮点（近似数值类型）
• 整数（整数值类型）
• 字符串（文本）
• 时间戳（日期和时间）
• 对象 (CDO)

Opcenter EX MDD 和 Opcenter EX CR 支持标量字段以及列表字段。根据 Opcenter EX MDD 和 Opcenter EX CR 的模型驱动的体系结构，字段可以附加 CLF 以定义自定义行为来响应系统中的事件，例如检索字段的值。

逻辑

Opcenter EX MDD 和 Opcenter EX CR 逻辑由 CLF 定义。 CLF 由函数组成，且定义系统运行时执行这些函数的顺序。CLF 可以附加到服务 CDO、数据 CDO 和 CDO 字段。

CLF 定义可以在系统中执行多种不同的操作，例如：

• 确定下一工作流程工步
• 验证用户的字段输入
• 计算容器数量

函数在系统中的作用是提供足够的粒度以及可重用的组件来构建各种类型的 CLF。
