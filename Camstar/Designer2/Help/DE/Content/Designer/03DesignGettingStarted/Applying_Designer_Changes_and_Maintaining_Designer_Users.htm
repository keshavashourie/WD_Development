Anwenden von Designer-Änderungen und Warten von Designer-Benutzern

Änderungen, die mithilfe von Designer am Fabrikmodell vorgenommen wurden, werden in der Microsoft Access-Datei InSite.mdb gespeichert. Entsprechend diesem Prozess müssen Sie die Änderungen an die Transaktionsdatenbank, "SiteInfo.mdb", und ggf. an die DataStore-Datenbank weiterleiten.

Anwenden von Designer-Änderungen

Wenn Sie Änderungen mithilfe von Designer vornehmen, müssen Sie diese auf Ihre Transaktions- und DataStore-Datenbanken anwenden. Gehen Sie dazu folgendermaßen vor:

• Klicken Sie in der Symbolleiste auf die Schaltfläche "DB aktualisieren".

Oder

• Führen Sie die Aufgabe "Datenbank aktualisieren" in Management Studio aus.

Die Änderungen werden auf den höchsten aktiven Arbeitsbereich angewendet, der in Management Studio festgelegt wurde. Im Designer-Kopf werden ein Arbeitsbereichscode und eine Beschreibung angezeigt, die angeben, welche Arbeitsbereichsänderungen angewendet werden. Weitere Informationen finden Sie unter "Designer-Kopf".

Nutzen von Massenaktualisierungen

Sie können eine Massenaktualisierungseinrichtung nutzen, um Transaktionen für umfangreiche Daten durchzuführen, wenn z. B. eine Vielzahl von Containern oder eine große Batch-Transaktion verarbeitet wird. Wenn Sie Unterstützung benötigen, um Designer so zu konfigurieren, dass Massenaktualisierungen genutzt werden, wenden Sie sich über das Support Center an den Produktsupport.

Weitere Informationen

Ausführlichere Informationen finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration und in der Opcenter Execution Core-Anleitung zur Systemadministration.

Dialogfeld "Voreinstellungen" (Preferences), Registerkarte "DB-Aktualisierung" (DB Update)

Die Anwendung speichert die aktuelle MDB-Datei und aktualisiert die Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences), wenn Sie auf die Schaltfläche "DB aktualisieren" klicken. Es wird ein Bestätigungsdialogfeld angezeigt, in dem darauf hingewiesen wird, dass die Anwendung die aktuelle MDB-Datei speichert und die Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) aktualisiert. Sie rufen das Dialogfeld "Voreinstellungen" (Preferences) im Menü "Datei" auf.

Option

Definition

Typ

Metadaten und Schema aktualisieren

Deaktiviert, aber ausgewählt, wenn eine Datenbankaktualisierung ausgeführt wird.

Nur Anzeige

Gespeicherte Prozeduren aktualisieren (Update Stored Procedures)

Führt die Datei "InstallProcedures.bat" aus. Die gespeicherten Prozeduren sind eine Sammlung von SQL-Anweisungen und logischen Steuerelementen, die in der Datenbank definiert und gespeichert sind und von Programmen aufgerufen werden. Diese gespeicherte Prozeduren enthalten plattformspezifische Regeln, verbessern die Leistung und verringern den Netzwerkverkehr. Da Datenobjekte einen gemeinsamen Satz an Regeln verwenden, ist die Logik zentralisiert.

Wählen Sie diese Option aus, wenn Sie eine der gespeicherten Standardprozeduren ändern oder hinzufügen.

Optional

Indizes erstellen

Löst die Erstellung neuer oder geänderter Indizes aus.

Hinweis: Alle Änderungen, die an Indizes vorgenommen werden, werden in der Protokolldatei des Dienstprogramms zum Ersetzen von Arbeitsbereichsdaten protokolliert. Weitere Informationen zum Hilfsprogramm zum Ersetzen von Arbeitsbereichsdaten finden Sie in der Opcenter Execution Medical Device and Diagnostics-Installationsanleitung oder in der Opcenter Execution Core-Installationsanleitung.

Optional

Menüs neu laden

Stellt die Standard-Portalmenüs wieder her. Jegliche Änderungen an den Standardmenüs werden überschrieben. Benutzerdefinierte Menüs werden nicht überschrieben oder gelöscht. Benutzerdefinierte Menüs bleiben in Portal Studio verfügbar.

Optional

Verwaiste Berechtigungen bereinigen

Bereinigt verwaiste Berechtigungen.

Optional

Portal-Objekte laden (Load Portal Objects)

Füllt das Portal mit Objekten, die in der Modellierung erstellt wurden. Legt alle Portal-Seiten und -Seitenabläufe wieder auf ihre ursprüngliche Konfiguration fest. Weitere Informationen zum Erstellen und Ändern von Definitionen für die Portalmodellierung finden Sie im Opcenter Execution Medical Device and Diagnostics Modeling-Benutzerhandbuch oder im Opcenter Execution Core Modeling-Benutzerhandbuch.

Optional

Wörterbücher laden (Load Dictionaries)

Füllt das Portal mit Wörterbuchbeschriftungen aus CSV-Dateien, die sich im Ordner "Insite Administration\Dictionaries" befinden. Durch das Platzieren benutzerdefinierter CSV-Dateien mit benutzerdefinierten oder übersetzten Beschriftungen können die Beschriftungen im Portal angezeigt werden. Weitere Informationen zum Erstellen und Ändern von Wörterbuchdefinitionen finden Sie im Opcenter Execution Medical Device and Diagnostics Modeling-Benutzerhandbuch oder im Opcenter Execution Core Modeling-Benutzerhandbuch.

Optional

WCF-Dienste erstellen

Erstellt die DLL, die die bereitgestellten Dienste und Datenverträge enthält, indem deren Definitionen aus der MDB extrahiert werden. Sie sollten diese Option aktivieren, wenn Sie Arbeitsbereiche aktivieren oder deaktivieren. Weitere Informationen zum Erstellen von WCF-Diensten finden Sie in der Opcenter Execution Medical Device and Diagnostics-Installationsanleitung oder in der Opcenter Execution Core-Installationsanleitung.

Optional

Web-Datenverkehr verschlüsseln

Ermöglicht das Generieren von WCF-Diensten mit SSL-Sicherheit. "Web-Datenverkehr verschlüsseln" ist standardmäßig ausgewählt.

Optional

Erstellen von REST-API-Diensten

Erzeugt das gesamte REST-API-Modell und startet die REST-API-Dienste, sofern ausgewählt. Diese Option ist nur gültig, wenn Sie statische DLLs verwenden, wie standardmäßig in der Datei "appsettings.json" festgelegt. Weitere Informationen zu REST-API-Einstellungen finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration oder in der Opcenter Execution Core-Anleitung zur Systemadministration. Wenn ein Fehler auftritt, finden Sie Informationen zu Fehlerantworten in Opcenter Execution Medical Device and Diagnostics – Technische Referenz: REST API oder in Opcenter Execution Core – Technische Referenz: REST API.

Optional

Hinzufügen und Löschen von Designer-Benutzern

Sie können das Fenster "Designer-Benutzeradministration" zum Warten der Designer-Benutzer verwenden. Weitere Informationen zum Hinzufügen und Löschen von Designer-Benutzern finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration und der Opcenter Execution Core-Anleitung zur Systemadministration.
