Parameter

Parameter sind Platzhalter für Werte, die während der Laufzeit für Funktionen und CLFs erforderlich sind. Ein Parameter hat neben anderen Attributen einen eindeutigen Namen, eine Eingabe-/Ausgaberichtung, eine Multiplizität, einen Datentyp, einen Standardwert und eine Beschreibung. Der Satz von Parameterspezifikationen für eine bestimmte Funktion oder einen bestimmten CLF definiert die entsprechende Schnittstelle in Opcenter EX MDD oder Opcenter EX CR oder das Kommunikationsprotokoll.

Definieren von Funktionsparametern

CLFs und Funktionen greifen auf Eingabeparameter über deren eindeutigen Parameternamen zu. Ein Parameterwert kann während der Erstellung der Funktion oder des CLFs festgelegt werden und gilt dann als Standardwert für den Parameter. Alternativ kann er während der Laufzeit durch eine andere Funktion oder einen anderen CLF festgelegt werden. Parameter können einfach durch Bereitstellen eines Feldnamens oder etwas komplizierter durch Erweiterung des Parameters in einen komplexen Ausdruck angegeben werden. Parameter können wie folgt definiert werden:

• Als numerische oder Zeichenkettenkonstante
• Als Feldname
• Als Feldausdruck
• Als Variable
• Als Feldausdruck, der mit einer Variablen beginnt
• Als integrierte Variable
• Als Beschriftung oder Beschriftungs-ID-Bezeichner

Wenn Sie einen Ausdruck zur Darstellung Ihres Parameters verwenden möchten, finden Sie weitere Informationen zur korrekten Syntax unter "Vereinheitlichte Ausdrücke".

Parameterdatentypen

Wenn das Flag "Erzwingen von Parametertypen" (Enforce Parameter Types) einer Funktion auf der Registerkarte "Allgemein" der Funktion festgelegt ist, können Sie den Parameter gemäß der folgenden vier Klassen von Parameterdatentypen näher definieren:

1. Einfach

Ein Parameter der Typklasse "Einfach" kann einen der folgenden Typen aufweisen: "Zeichenkette", "Boolesch", "Zeitstempel" sowie die numerischen Typen "Integer", "Festkomma", "Gleitkomma", "Dezimal"

2. Grundlegend

Diese Typklasse besteht aus den grundlegenden Parameterdatentypen. Zu diesen gehören die Datentypen "Einfach", "Objekt" und "Numerisch".

3. Objekt

Eine Referenz auf ein CDO. Wenn der Parameter den Typ "Objekt" aufweist, wird auch der Objektname angegeben.

4. Numerisch

Ein Parameter der Typklasse "Numerisch" kann einen der folgenden Typen aufweisen:

a. Integer: 32-Bit-Integer
b. Gleitkomma: Gleitkommazahl
c. Festkomma: Festkommazahl einer Dezimalzahl und Ganzzahlenstellen. Der feste Datentyp wird verwendet, um eine Festkommazahl als Gleitkommazahl in der Datenbank zu speichern. Ein Gleitkommawert ist die Annäherung eines Festkommawerts. Beachten Sie, dass ein Dezimaltyp verfügbar ist und zum Speichern eines exakten numerischen Werts verwendet werden sollte.
d. Dezimal: Ein Festkommatyp, ein exakter numerischer Wert im Gegensatz zu einem ungefähren numerischen Typ wie z. B. "Gleitkomma".
e. Beliebig: Ein Parameter der Typklasse "Beliebig" kann beliebige andere Datentypen und Typklassen aufweisen. Beispiele:
• Ergebnisgruppe: Parameter, die Eintragsgruppen (Recordsets) sind. Z. B. Parameter, die Ergebnisse einer erweiterten Abfrage sind.
• Parameter: Parameter, die Name/Wert-Paare übergeben, z. B. Parameter, die an Abfragen übergeben werden.

Typmultiplizität

Parameterdatentypen werden durch Typmultiplizität näher gekennzeichnet. Dies bedeutet, dass Sie angeben können, ob der Parameter skalar oder eine Liste oder beides (ListOrScalar) ist.

Multiplizität

Dieses Attribut gibt die Anzahl der Werte an, die der Parameter übernehmen kann oder muss. Die Auswahlmöglichkeiten sind "0...*" (null oder mehr, daher eine optionale Liste), "0...1" (null oder eins, daher optional), "1...1" (eins, daher erforderlich), "1...*" (eins oder mehr, daher eine erforderliche Liste).

Parameter- und Variablenkontext

CLF-Writer können Variablen jederzeit einsetzen. Die Lebensdauer einer Variablen beginnt, wenn der Wert zum ersten Mal festgelegt wird. Parameter- und Variablenkontext bezieht sich auf den Kontext, in dem sich die Variable befindet. Abhängig vom Bereich oder Kontext, zu dem eine Variable gehört, kann sich die Lebensdauer der Variablen ändern.

Drei Bereiche oder Kontexte zum Ausdrücken dieser Parametervariablen:

• Transaktion

Der Transaktionskontext ist Teil des Kontextes des Dienst-CDOs und ist während der gesamten Lebensdauer der Instanz des CDOs vorhanden. Wenn Sie Daten zwischen CLFs beibehalten oder übergeben müssen, verwenden Sie Transaktionsbereichsvariablen. Transaktionskontexte werden für jede Instanz eines bestimmten Dienstes erstellt und sind für jeden Dienst eindeutig. Sobald der Wert der Transaktionsumfangsvariablen festgelegt ist, bleibt er unverändert, bis er z. B. durch einen CLF geändert wird. Alle Transaktionskontextvariablen werden verworfen, sobald der Dienst, zu dem sie gehören, entfernt wird.

• CLF (CLF::)

Der CLF-Kontext wird nur für die Zeit erstellt, während der der CLF ausgeführt wird. Die CLF-Bereichsvariablen dienen in der Regel dazu, Zwischendaten zwischen den Ausführungen innerhalb eines CLFs zu übergeben. Wenn Sie Daten beibehalten oder zwischen den Ausführungen übergeben müssen, verwenden Sie CLF-Bereichsvariablen. Vermeiden Sie die Verwendung von Variablen, die im Transaktionskontextbereich eigentlich zum CLF-Kontext gehören. CLF-Kontextvariablen werden auch zum Übergeben von Parametern an CLFs verwendet. Auf die Parameter wird von innerhalb der CLFs über den CLF-Bereich zugegriffen.

Hinweis: CLF:: Variablen werden vom Anwendungsserver erstellt, können aber von Datenbankfunktionen referenziert werden. High Performance-CLF-Parameter werden mit dem Präfix DBCLF:: versehen, und DBCLF::-Variablen werden durch die in der Datenbank gespeicherten Prozeduren erstellt. DBCLF:: Variable Referenzen werden nur in der Datenbank verwendet. Der Anwendungsserver ignoriert das DBCLF::-Präfix und leitet es an die Datenbank weiter. Weitere Informationen zu High Performance-CLFs finden Sie unter "Hinzufügen von High Performance-CLFs".
• Funktion (Exe::)

Der Funktionskontext ist für Funktionsparameter vorgesehen. Auf die Funktionsparameter kann von innerhalb der Funktionen über den Ausführungsbereich (Exe) zugegriffen werden. Der Funktionskontext wird für die Zeit erstellt, während der die Funktion ausgeführt wird. Funktionen können auch lokale Kontexte mit Variablen einsetzen, auf die über den lokalen Bereich zugegriffen werden kann. Lokale Kontextvariablen werden derzeit für die Verarbeitung von Fehlermeldungen verwendet.

Ein CLF-Kontext wird für die Parameter für die Funktionen 1 und 2 verwendet. Dies liegt daran, dass die Parameterwerte zwischen den Funktionen übergeben werden können. Ein Transaktionskontext hätte ausgewählt werden können, doch der Wert wäre länger gültig gewesen als die Lebensdauer des CLFs. Das war jedoch nicht erforderlich. Analog dazu könnte ein Funktionskontext den Parameterwert nicht zwischen den Funktionen übergeben haben, da der Parameter nach dem Ausführen von Funktion 1 nicht mehr vorhanden ist.

Integrierte Variablen

Integrierte Variablen werden vom Anwendungsserver vor den CLFs-Aufrufen auf bestimmte Werte festgelegt oder vom Anwendungsserver verwendet, um zu bestimmen, was der CLF zurückgegeben hat.

CLF::__CDOID

Typ:Objektreferenz

Wird vom Anwendungsserver vor dem Aufrufen eines CLFs (CDO und CLFs auf Feldebene) auf das aktuelle CDO festgelegt

Verwendung: Wird in CLFs verwendet, um auf das aktuelle CDO zu verweisen (an das der CLF angehängt ist)

Transaction::__Return

Typ: Wird vom Benutzer festgelegt

Der Anwendungsserver erwartet, dass CLFs als Antwort auf bestimmte CDO- oder Feldereignisse einen Wert in dieser Variablen zurückgeben.

Wichtig: Im Abschnitt "Ereignisse" dieses Kapitels wird die integrierte Variable "Transaction::__Return" ausführlicher beschrieben. Weitere Informationen finden Sie unter "Bearbeiten von Parameterwerten für eine Funktion".

Verwendung: Wird in CLFs verwendet, um einen vom Benutzer festgelegten Wert zurückzugeben

Transaction::__CurrentService

Typ: Objektreferenz

Wird zu Beginn der Ausführung oder Validierung des Dienstes vom Anwendungsserver auf den aktuellen Dienst festgelegt

Die Variable kann von CLFs verwendet werden, die an "BeforeValidate", "AfterValidate", "BeforeExecute" und "AfterExecute" angehängt sind.

Hinweis: Diese Variable wird erst festgelegt, wenn der Client-Code Service.Execute aufruft. Diese Variable wird für jeden Unterdienst festgelegt, während eine Verbundtransaktion (CompoundTxn) ausgeführt wird.

Verwendung: Wird in CLFs verwendet, um auf den aktuellen Dienst zu verweisen (unabhängig davon an welches CDO der CLF angehängt ist)

CLF::__FieldValue

Typ: Identisch mit dem Feldtyp

Wird vom Anwendungsserver vor dem Aufrufen eines CLFs für ein skalares Feld auf den aktuellen Feldwert festgelegt

Verwendung: Wird für CLFs verwendet, die an Feldereignisse von skalaren Feldern angehängt sind

CLF::__Index

Typ: Ganzzahl

Wird vom Anwendungsserver vor dem Aufrufen eines CLFs für ein Listenfeldereignis auf den aktuellen Index des Listenfeldelements festgelegt

Im Folgenden sind die möglichen Werte der Variablen abhängig vom Feldereignis aufgeführt:

• Wert = neuer Elementindex für das Ereignis "AddItem"
• Wert = aktueller Elementindex für die Ereignisse "ChangeItem" und "GetItem"
• Wert = aktueller Elementindex für das Ereignis "RemoveItem"
Oder
-1 für "RemoveItem", wenn das Element durch den Wert entfernt wird
• Wert = Quellenelementindex für das Ereignis "MoveItem"

(Die Variablen "CLF::__FromIndex" und "CLF::__ToIndex" werden ebenfalls vor "MoveItem" festgelegt)

• Wert = -1 für alle anderen Listenfeldereignisse

Verwendung: (Selten verwendet) Für CLFs, die an Feldereignisse von Listenfeldern angehängt sind

CLF::__ItemValue

Typ: Identisch mit dem Feldtyp

Wird vom Anwendungsserver vor dem Aufrufen eines CLFs für ein Listenfeld auf den aktuellen Wert des Listenfeldelements festgelegt

Verwendung: (Selten verwendet) Für CLFs, die an Feldereignisse von Listenfeldern angehängt sind

CLF::SessionValues

Typ: Objekt

Erlaubt den Zugriff auf das SessionValues-CDO, das dem angemeldeten Benutzer zugeordnet ist

Wird vom System festgelegt

Verwendung: Nur in CVEs verfügbar und verwendet

Bearbeiten von Parameterwerten für eine Funktion

Sie können Parameter nur für benutzerdefinierte Funktionen ändern.

Vorgehensweise zum Bearbeiten von Parameterwerten für eine Funktion

Gehen Sie folgendermaßen vor, um Parameterwerte für eine Funktion zu bearbeiten:

1. Öffnen Sie Designer.
2. Klicken Sie auf Funktionen. Das Fenster "Funktionsdefinitionen" wird angezeigt.
3. Wählen Sie die Benutzerfunktion aus, für die Sie die Parameter bearbeiten möchten.
4. Klicken Sie auf die Registerkarte Parameter.

 

5. Wählen Sie den zu ändernden Parameter aus.
6. Passen Sie den Parameter an die Anforderungen Ihres Unternehmens an.
Hinweis: Die Änderungen werden in der Funktionsbibliothek vorgenommen. Wenn Sie den Wert in "Standardwert" geändert haben, wirkt sich diese Änderung nicht auf die CLFs aus, die diese geänderte Funktion verwenden. Sie müssen den CLF öffnen, die Funktion entfernen und wieder hinzufügen.
7. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.

Vorgehensweise zum Hinzufügen von Funktionsparametern

Sie können Funktionsparameter nur zu benutzerdefinierten Funktionen hinzufügen. Beachten Sie, dass beim Hinzufügen von Parameterwerten zu Funktionen, die an ein CDO-Ereignis oder eine CDO-Methode angehängt wurden, nur die Vorlagenversion des CLFs betroffen sein wird. Wenn Sie die neuen Parameter für den CLF verwenden möchten, der zuvor an ein CDO-Ereignis oder eine CDO-Methode angehängt wurde, trennen Sie den CLF von diesem CDO ab und hängen Sie die geänderte CLF-Definition an.

Gehen Sie folgendermaßen vor, um Funktionsparameter hinzuzufügen:

1. Öffnen Sie Designer.
2. Klicken Sie auf Funktionen. Das Fenster "Funktionsdefinitionen" wird angezeigt.
3. Wählen Sie die benutzerdefinierte Funktion aus, der Sie Parameter hinzufügen möchten.
4. Klicken Sie auf die Registerkarte Parameter.
5. Klicken Sie auf der Registerkarte "Parameter" auf Hinzufügen. Ein generischer Parameter wird in der Liste mit einem Standardnamen angezeigt.

 

6. Geben Sie einen neuen Namen in das Feld Parametername ein.
7. Klicken Sie im Bereich mit der Parameterliste auf den generischen Parameter, um den Namen zu speichern. Der neue Name ersetzt den generischen Namen.
8. Wählen Sie eine Eingabe für Spezielle Verarbeitung aus.
9. Wählen Sie eine Richtung für den Funktionsparameter aus.
10. Wählen Sie einen Wert für Multiplizität aus.
11. Geben Sie eine Beschreibung Ihres Funktionsparameters ein.
12. Wählen Sie einen Datentyp und die Typmultiplizität aus den Listen Datentyp und Typmultiplizität aus.
13. Geben Sie einen Standardwert für den Parameter ein, falls zutreffend.
14. Geben Sie in das Feld Hinweise abhängig von den Anforderungen Ihres Unternehmens Hinweise und Kommentare für den neuen Funktionsparameter ein.
15. Zum Speichern klicken Sie auf eine andere Registerkarte oder wählen Sie eine andere Funktion aus.
16. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.

Vorgehensweise zum Entfernen von Funktionsparametern

Sie können Parameter nur aus benutzerdefinierten Funktionen entfernen.

Gehen Sie folgendermaßen Sie vor, um Funktionsparameter zu entfernen:

1. Öffnen Sie Designer.
2. Klicken Sie auf Funktionen. Das Fenster "Funktionsdefinitionen" wird angezeigt.
3. Wählen Sie die Benutzerfunktion aus, aus der Sie Parameter entfernen möchten.
4. Klicken Sie auf die Registerkarte Parameter.
5. Wählen Sie den zu entfernenden Parameter aus.
6. Klicken Sie mit der rechten Maustaste auf den Parameter und wählen Sie anschließend im Kontextmenü die Option "Parameter entfernen" aus oder klicken Sie auf der Registerkarte "Parameter" auf Entfernen. In einem Bestätigungsdialogfeld werden Sie aufgefordert, das Entfernen des Parameters zu bestätigen.
7. Klicken Sie auf Ja. Der Parameter wird aus der Liste entfernt.
8. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.

Vorgehensweise zum Ändern der Standardparameter in einer CLF-Funktion

Wenn Sie einen neuen CLF zu einem CDO hinzufügen, sind viele der Parameterwerte für die Funktionen bereits vorhanden. Diese werden auch als CLF-Standardparameter bezeichnet. Zum Ändern dieser Standardwerte muss die Definition des CLFs geändert werden. Beachten Sie, dass sich das Ändern der Standardparameterwerte nur auf die Vorlagenversion des CLFs auswirkt. Daher sind die Parameterwerte eines CLFs und seine Funktionen, die bereits an ein Ereignis oder eine Methode angehängt sind, nicht betroffen. Wenn Sie die geänderten Parameterwerte für den CLF verwenden möchten, der zuvor an ein Ereignis oder eine Methode angehängt wurde, trennen Sie den CLF dort ab und hängen Sie die geänderte CLF-Definition an.

Diese Änderungen wirken sich nur auf die Funktion des ausgewählten CLFs aus. Weitere Informationen zum Ändern der Funktionsparameter finden Sie unter "Bearbeiten von Parameterwerten für eine Funktion".

Gehen Sie folgendermaßen vor, um Standardparameter in einer CLF-Funktion zu ändern:

1. Öffnen Sie Designer.
2. Klicken Sie auf CLFs. Das Fenster "Definition des logischen Ablaufs" wird auf der Registerkarte "Funktionen" geöffnet.
3. Wählen Sie den CLF im Auswahlfenster aus. Im Beispiel befindet sich "MoveIn_Execute" unter "ServiceProcessing".
4. Wählen Sie im Bereich Logischer Ablauf die zu ändernde Funktion aus. Die Standardparameterwerte für die ausgewählte Funktion werden im Funktionsparameterblock angezeigt:

Die verfügbaren Funktionen werden im Bereich Verfügbare Funktionen angezeigt.

5. Ändern Sie die Standardparameterwerte wie gewünscht.
6. Aktivieren Sie optional das Kontrollkästchen Dynamisch, damit der Parameter als dynamischer Wert mithilfe von Suchausdrücken übergeben werden kann. Lassen Sie es deaktiviert, wenn der Parameter als tatsächlicher Wert übergeben werden soll.
Hinweis: Wenn die Funktion Parametertypen erzwingt (festgelegt durch ein Flag im Fenster "Funktionen"), wird das Kontrollkästchen "Dynamisch" (Dynamic) ausgeblendet und die Spalten "Multiplizität" (Multiplicity) und "Datentyp" (Data Type) werden angezeigt. "Multiplizität" und "Datentyp" sind in diesem Fenster schreibgeschützt. Zum Ändern der Werte für diese Spalten wechseln Sie in das Fenster "Funktionsdefinition", in dem Sie benutzerdefinierte Funktionen ändern können.
7. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.
