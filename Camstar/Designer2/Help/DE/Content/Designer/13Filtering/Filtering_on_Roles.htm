Filterung nach Rollen

Dieser Abschnitt enthält Anleitungen zum Abrufen einer Liste von Rollen, auf die ein Mitarbeiter zugreifen kann. Verwenden Sie beim Filtern nach Rollen die Datenbankfunktion "csiAuthGetUsersRoles" und einen Parameter für die Mitarbeiter-ID, damit eine Tabelle für Kombinationen aus Organisation und Rolle zurückgegeben wird (Organisations-ID/Rollen-ID).

Beispiel Abfrage

SELECT e.EventName

,o.OrganizationName

,r.RoleName

,emp.EmployeeName

FROM Event e

JOIN (SELECT OrganizationId, RoleId FROM csiAuthGetUsersRoles((SELECT EmployeeId from Employee where EmployeeName = 'CamstarAdmin'))) AS OwnerRoles

ON e.RoleId = OwnerRoles.RoleId AND e.OrganizationId = OwnerRoles.OrganizationId

JOIN RoleDef r ON e.RoleId = r.RoleId

JOIN Employee emp ON e.OwnerId = emp.EmployeeId

JOIN Organization o ON e.OrganizationId = o.OrganizationId

Verwendung

Es sollen Concierge-Nachrichten für alle Rollen in allen Organisationen zurückgegeben werden, auf die der angemeldete Benutzer Zugriff hat. Mögliche Verknüpfung mit der Funktion "csiAuthGetUsersRoles", um die Kombinationen aus Rolle und Organisation für den Benutzer zu erhalten.

Standardimplementierung

Die Funktion "csiAuthGetUsersRoles" wird in der Logik im GetToDoList-Dienst verwendet. Die Funktion wird in der Designer-Abfrage "GetToDoListEntries" verwendet.
