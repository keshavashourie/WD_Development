Wann Tabellen erstellt werden müssen

Wenn Sie eine Unterklasse eines CDOs erstellen, das bereits eine bestimmte Tabelle oder Tabellen aufweist (z. B. erstellen Sie eine Produkt-Unterklasse und das Produkt-CDO verfügt über die Tabellen "Product" und "ProductBase"), dann werden Sie im Allgemeinen keine neue Tabelle bzw. keine neuen Tabellen erstellen. Wenn Sie in diesem Fall eine neue Tabelle oder mehrere Tabellen erstellen, hat dies Auswirkungen auf die Berichterstattung (es sei denn, diese Tabellen werden von keinem Bericht verwendet).

Wenn Sie eine Unterklasse in eine neue Tabelle einfügen, müssen Sie stets explizit auf sie verweisen. Sie können z. B. eine MyEmployee-Unterklasse und -Tabelle erstellen. Anschließend müssen Sie neue Unterklassen jeder von Ihnen verwendeten Fertigungstransaktion erstellen und diese Unterklasse muss ihr Mitarbeiter-Feld an die MyEmployee-Unterklasse umleiten (überschreiben). Das ist nicht möglich.

Sie können eine Unterklasse nur dann in eine andere Tabelle verschieben, in der sich ihre übergeordnete Klasse nicht befindet, wenn Sie stets explizit auf sie verweisen. Dies ist z. B. mit Objektgruppen möglich. In der Regel werden Sie, wenn Sie eine neue Unterklasse einer Objektgruppe erstellen, auf diese explizit verweisen. Sie können z. B. eine CustomerGroup-Objektgruppe erstellen und diese in eine bestimmte Tabelle einfügen, anstatt sie in der Tabelle "NamedObjectGroup" zu belassen, da Sie normalerweise stets explizit auf "CustomerGroup" verweisen (z. B. in einem bestimmten Kunden-Feld in der Produktfamilie).

Wenn Sie eine Unterklasse eines CDOs erstellen, die keine bestimmte Tabelle oder bestimmten Tabellen aufweist (z. B. wenn Sie eine NamedDataObject-, RevisionedObject-, UserCode- oder Subentity-Unterklasse erstellen), müssen Sie eine neue Tabelle erstellen. Andernfalls gibt es keine Datenbanktabelle, in der Instanzdaten für diese neue Unterklasse gespeichert werden können.
