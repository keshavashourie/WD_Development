Definieren einer NamedDataObject-Unterklasse

Ein NamedDataObject-CDO ist eine Klasse von Objekten, die durch einen eindeutigen Namen identifiziert wird. Es stellt statische Objekte dar, die keine Revisionen aufweisen. Benannte Datenobjekte weisen zugehörige Wartungsobjekte auf. Wenn Sie NDOs hinzufügen, halten Sie sich an die Struktur in der Klassenbibliothek, indem Sie Ihre neuen CDOs miteinander verbinden. Gehen Sie dabei genauso vor wie beim Verbinden der benannten Standarddatenobjekte.

Beim Definieren einer NamedDataObject-Unterklasse

Instanzen benannter Datenobjekte sind persistent, d. h. die zugehörigen Informationen werden in die Datenbank geschrieben.

Arbeitsbereichspräfixe werden beim Hinzufügen eines neuen Elements automatisch vor dem Namen des Elements eingefügt, sofern dem höchsten aktiven Arbeitsbereich ein Präfix zugewiesen wurde. Arbeitsbereichspräfixe geben an, auf welchen Arbeitsbereich Designer Änderungen anwendet. Dem Arbeitsbereich würde z. B. das Präfix "C200" zugeordnet werden, wenn für diesen in Management Studio das Präfix "C200" festgelegt wurde. Es wird empfohlen, beim Hinzufügen neuer Elemente die von Designer bereitgestellten Präfixe zu verwenden.

Sie können Arbeitsbereichspräfixe in Management Studio zuweisen oder ändern. Weitere Informationen finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration und der Opcenter Execution Core-Anleitung zur Systemadministration.

Hinweis: Dem Basisarbeitsbereich der Anwendung (csi) kann kein Arbeitsbereichspräfix zugewiesen sein.

Aufgabenübersicht

Der allgemeine Prozess zum Definieren eines NamedDataObject-CDOs ähnelt dem zum Definieren eines Container-CDOs. Die einzigen zusätzlichen Konzepte fügen ein ObjectChanges-CDO und ein Wartungsdienst-CDO für das NDO hinzu. Diese Schritte werden beim Erstellen des NDOs automatisch ausgeführt, wenn das Kontrollkästchen "Wartungsdienst erstellen & konfigurieren" aktiviert ist. Weitere Informationen finden Sie unter "Automatisierte Schritte beim Definieren einer CDO-Unterklasse".

Vorgehensweise zum Hinzufügen eines NamedDataObject-CDOs CDO-Unterklasse

Gehen Sie folgendermaßen vor, um eine NamedDataObject-CDO-Unterklasse hinzuzufügen:

1. Öffnen Sie Designer.
2. Klicken Sie in der Symbolleiste auf CDOs. Das Fenster "CDO-Definition" wird angezeigt.
3. Wählen Sie Erweitert im Menü Ansicht aus.
4. Erweitern Sie die Klasse NamedDataObject.
5. Wählen Sie die Unterklasse NamedDataObject aus. In diesem Beispiel wird Fabrik verwendet.
6. Klicken Sie unter der CDO-Liste auf die Schaltfläche Hinzufügen oder klicken Sie mit der rechten Maustaste auf Fabrik und wählen Sie Unterklasse hinzufügen aus. Das Fenster "Neue CDO-Definition erstellen" wird angezeigt.
Hinweis: Im Feld "Ableiten von" wird die Basisklasse für Ihr neues CDO angegeben.
7. Geben Sie den Namen MyFactory in das Feld Neuer CDO-Name ein.
Wichtig: Der Name des CDOs kann bis zu 30 Zeichen lang sein und darf keine Leerzeichen, unzulässigen Zeichen oder reservierten Wörter enthalten. Weitere Informationen finden Sie unter "Gültige Zeichen und reservierte Wörter".
8. Geben Sie eine Beschreibung ein.
Hinweis: Die Schaltfläche "Erstellen" wird erst aktiviert, wenn die Felder "Neuer CDO-Name" und "Beschreibung" ausgefüllt sind.
9. Behalten Sie die Standardwerte für CDO-Verwendung und Speicherkategorie bei.
10. Wählen Sie nicht die Option Neue Tabelle erstellen aus.
Hinweis: Dem Objekt "Fabrik" ist bereits eine Tabelle zugeordnet. Weitere Informationen finden Sie unter "Wann Tabellen erstellt werden müssen".
11. Gewährleisten Sie, dass Wartungsdienst erstellen & konfigurieren aktiviert ist.
12. Klicken Sie auf Erstellen. Das neue NDO "MyFactory" wird im Auswahlbaum angezeigt und "MyFactory" ist ausgewählt.

Die für die Wartung erforderlichen CDOs und die zugehörigen erforderlichen Feldüberschreibungen werden für dieses NDO automatisch erstellt.

a. Wählen Sie die Registerkarte Allgemein für "MyFactory" aus, sofern sie noch nicht angezeigt wird.
Wichtig: Achten Sie darauf, nicht den Wert im Feld "Abstrakt" zu ändern. Beachten Sie, dass die Überschrift den CDO-Namen übernommen hat. Fügen Sie jedoch nach jedem Großbuchstaben ein Leerzeichen ein.
b. Passen Sie Überschrift an die Anforderungen Ihres Unternehmens an.
13. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.

Automatisierte Schritte

Die folgenden zugehörigen CDOs wurden automatisch definiert:

• "MyFactoryMaint" wird unter "Dienst > Wartung > NamedDataObjectMaint > FactoryMaint" hinzugefügt
• "MyFactoryMaint" referenziert "MyFactoryChanges" über das Feld "ObjectChanges".
• "MyFactoryMaint" referenziert "MyFactory" über das Feld "ObjectListInquiry".
• "MyFactoryMaint" referenziert "MyFactory" über die Felder "ObjectToChange" und "ObjectListInquiry".
• "MyFactoryChanges" wird unter "NamedDataObjectChanges > FactoryChanges" hinzugefügt.
• "MyFactoryChanges" referenziert "MyFactory" über das Feld "ObjectToChange".

Weitere Informationen finden Sie unter "Automatisierte Schritte beim Definieren einer CDO-Unterklasse".

Vorgehensweise zum Hinzufügen von Feldern zum benutzerdefinierten NDO

In dieser Übung fügen Sie zwei Felder hinzu: ein Zeichenketten- und ein Objektfeld. Auf der Benutzeroberfläche werden beide Felder optional sein (Benutzereinträge sind nicht erforderlich). Weitere Informationen finden Sie unter "CDO-Felder".

Gehen Sie folgendermaßen vor, um der Unterklasse für benutzerdefinierte NDOs Felder hinzuzufügen:

1. Wählen Sie das eben definierte CDO aus. In diesem Fall ist es MyFactory.
2. Wählen Sie die Registerkarte Felder aus.
3. Klicken Sie auf Hinzufügen auf der Registerkarte Felder (Fields) (oder klicken Sie mit der rechten Maustaste in den Bereich und wählen Sie Feld hinzufügen (Add field) aus), um ein Feld hinzuzufügen.
4. Konfigurieren Sie das neue Feld wie folgt:
a. Wählen Sie Zeichenkette als Datentyp aus.
b. Wählen Sie [Zeichenkette] als Feldtyp aus.
c. Geben Sie Parm1 für den Feldnamen ein.
Hinweis: Feldnamen dürfen keine Leerzeichen, unzulässigen Zeichen oder reservierte Wörter enthalten. Weitere Informationen finden Sie unter "Gültige Zeichen und reservierte Wörter".
d. Geben Sie die Parameter 1 für die Überschrift ein.
Hinweis: Dieser Wert wird als Überschrift des Felds angezeigt, wenn Sie Portal Studio, Modeler oder Visual Controls verwenden. Überschriften können Leerzeichen enthalten, um sie lesbarer zu machen.
e. Geben Sie eine Beschreibung ein.
f. Lassen Sie Feld zu zugehörigen Dienstobjekten hinzufügen ausgewählt. Dadurch wird das Feld zum MyFactoryChanges-CDO hinzugefügt.
g. Klicken Sie auf Erstellen. Das Fenster "CDO-Feldeigenschaften" wird auf der Registerkarte "Optionen" geöffnet.
h. Klicken Sie unter "Zugänglichkeit" auf Lesen/Schreiben.
i. Behalten Sie die anderen Standardwerte bei.
j. Klicken Sie auf OK.
5. Klicken Sie auf Hinzufügen, um ein zweites Feld hinzuzufügen.
6. Konfigurieren Sie das zweite Feld wie folgt:
a. Wählen Sie Objekt (Object) aus der Liste "Datentyp" (Data Type) aus.
b. Wählen Sie Eigentümer als Feldtyp aus und behalten Sie den Feldnamen Eigentümer bei.
c. Optional können Sie die Beschreibung an die Anforderungen Ihres Unternehmens anpassen oder die Standardbeschreibung beibehalten.
d. Klicken Sie auf Erstellen. Das Fenster "CDO-Feldeigenschaften" wird auf der Registerkarte "Optionen" geöffnet.
Hinweis: Auf der Registerkarte "Allgemein" wird der Spaltenname für dieses Feld als "OwnerID" angegeben.
e. Klicken Sie auf OK.
7. Klicken Sie auf DB aktualisieren. In einem Dialogfeld werden Sie aufgefordert, das Speichern der aktuellen MDB-Datei und die Aktualisierung der Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) zu bestätigen.
8. Klicken Sie auf Ja. Eine Statusleiste wird am unteren Rand des Fensters angezeigt, um darauf hinzuweisen, dass die Aktualisierung ausgeführt wird. Die Anwendung speichert und aktualisiert die Datenbank.
Hinweis: Weitere Informationen zu den im Dialogfeld "Voreinstellungen" (Preferences) verfügbaren Einstellungen finden Sie unter "Dialogfeld "Voreinstellungen" (Preferences), Registerkarte "DB-Aktualisierung" (DB Update)". Weitere Informationen zum Aktualisieren der Datenbank finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration oder der Opcenter Execution Core-Anleitung zur Systemadministration.

Damit ist die Übung zum Erstellen eines benannten Datenobjekts (NamedDataObject) abgeschlossen.

Vorgehensweise zum Entfernen eines NDOs

Soll die von Ihnen erstellte NDO-Unterklasse gelöscht werden, müssen Sie ihre Zuordnungen zu anderen CDOs entfernen, und zwar in der umgekehrten Reihenfolge, in der die Zuordnungen erstellt wurden. Im folgenden Beispiel wird "MyFactory" entfernt.

Gehen Sie folgendermaßen vor, um eine NDO-Unterklasse zu entfernen:

1. Öffnen Sie Designer.
2. Klicken Sie in der Symbolleiste auf CDOs. Das Fenster "CDO-Definition" wird angezeigt.
3. Wählen Sie Erweitert aus dem Menü Ansicht aus.
4. Wählen Sie das Objekt "Änderungen" aus, in diesem Beispiel MyFactoryChanges, und deaktivieren Sie die Überschreibung für das Feld ObjectToChange.
5. Wählen Sie das Wartungsobjekt (in diesem Beispiel MyFactoryMaint) aus und deaktivieren Sie die Überschreibung für das Feld ObjectChange.
6. Entfernen Sie das Änderungs-CDO (in diesem Beispiel MyFactoryChanges).
7. Entfernen Sie das NDO-Wartungs-CDO (in diesem Beispiel MyFactoryMaint).
8. Entfernen Sie MyFactory.
9. Klicken Sie auf DB aktualisieren. In einem Dialogfeld werden Sie aufgefordert, das Speichern der aktuellen MDB-Datei und die Aktualisierung der Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) zu bestätigen.
10. Klicken Sie auf Ja. Eine Statusleiste wird am unteren Rand des Fensters angezeigt, um darauf hinzuweisen, dass die Aktualisierung ausgeführt wird. Die Anwendung speichert und aktualisiert die Datenbank.
Hinweis: Weitere Informationen zu den im Dialogfeld "Voreinstellungen" (Preferences) verfügbaren Einstellungen finden Sie unter "Dialogfeld "Voreinstellungen" (Preferences), Registerkarte "DB-Aktualisierung" (DB Update)". Weitere Informationen zum Aktualisieren der Datenbank finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration oder der Opcenter Execution Core-Anleitung zur Systemadministration.
