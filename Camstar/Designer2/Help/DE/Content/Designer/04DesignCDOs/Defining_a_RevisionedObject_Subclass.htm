Definieren einer RevisionedObject-Unterklasse

Die Klasse RevisionedObject wird in Opcenter EX MDD und Opcenter EX CR für Objekte verwendet, die einen Namen und einen Änderungsstand aufweisen. Die RevisionedObject-Klasse unterstützt eine Standardrevisionsfunktion, mit der Sie eine Version als Standardversion angeben können. So können Sie anderen Objekten erlauben, die Instanz eines revisionierten Objekts (RevisionedObject, RO) ohne Angabe einer Revision zu referenzieren. Beispiele für ROs sind "Dokument", "Produkt", "Arbeitsplan" und "Spezifikation".

Rolle des RevisionBase-CDOs

RevisionBase ist ein NDO, das die Standardrevision und die Revisionen bereitstellt. Das Attribut RevOfRcd stellt die ID der aktuellen Standardrevision zur Verfügung. Das Attribut Revisions stellt eine Liste der Revisionsinstanzen zur Verfügung, die dem revisionierten Objekt zugeordnet sind. Für jede Revisionsbasis (RevisionBase) gibt es mindestens ein RO.

Aufgabenübersicht

Die allgemeinen Schritte zum Definieren eines ROs ähneln denen zum Definieren eines NamedDataObject-CDOs. Die einzigen zusätzlichen Schritte dienen zum Hinzufügen eines RevisionBase-CDOs und zum Ändern der CDO-Zuordnungen für die RO- und RevisionBase-CDOs. Diese werden automatisch ausgeführt, wenn das Kontrollkästchen "Wartungsdienst erstellen & konfigurieren" (Create & Configure a Maintenance Service) aktiviert ist.

Hinzufügen einer RevisionedObject-CDO-Unterklasse und Hinzufügen von Feldern

Hinzufügen eines RevisionedObject-CDOs zur Darstellung Ihres revisionierten Objekts. Wenn Sie ein CDO hinzufügen, wird es vom bereits vorhandenen CDO abgeleitet. Dadurch erbt das CDO, dem Sie eine CDO-Unterklasse hinzufügen, alle Felder und Eigenschaften des CDOs, von dem es abgeleitet wurde. Nach dem Hinzufügen des CDOs können Sie Feldeigenschaften überschreiben, neue Felder hinzufügen oder löschen, um ein eindeutiges CDO zu erstellen, das an Ihr Geschäftsmodell angepasst ist. Fügen Sie nach Bedarf Felder zum neu hinzugefügten RevisionedObject (RO) hinzu. Weitere Informationen zum Hinzufügen von Listenfeldern zu einem CDO finden Sie unter "Definieren von Listenfeldern.

Arbeitsbereichspräfixe werden beim Hinzufügen eines neuen Elements automatisch vor dem Namen des Elements eingefügt, sofern dem höchsten aktiven Arbeitsbereich ein Präfix zugewiesen wurde. Arbeitsbereichspräfixe geben an, auf welchen Arbeitsbereich Designer Änderungen anwendet. Dem Arbeitsbereich würde z. B. das Präfix "C200" zugeordnet werden, wenn für diesen das Präfix "C200" festgelegt wurde und er der höchste aktive Arbeitsbereich in Management Studio ist. Es wird empfohlen, beim Hinzufügen neuer Elemente die von Designer bereitgestellten Präfixe zu verwenden.

Sie können Arbeitsbereichspräfixe in Management Studio zuweisen oder ändern. Weitere Informationen finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration und der Opcenter Execution Core-Anleitung zur Systemadministration.

Hinweis: Dem Basisarbeitsbereich der Anwendung (csi) kann kein Arbeitsbereichspräfix zugewiesen sein.

Hinzufügen eines Unterobjekts zu einem RO

Es gibt viele Umstände, unter denen das Hinzufügen von Unterobjekten zu ROs sinnvoll ist. Möglicherweise möchten Sie mehrere Unterobjekte zu einem einzelnen RO hinzufügen, um diskrete Informationstypen zu gruppieren. Dies hat den Vorteil, dass die gruppierten Informationen mit dem RO verbunden werden. Wenn Sie Ressourceninformationen zu einem RO gruppieren möchten, z. B. eine Spezifikation, warten Sie die Ressourceninformationen in einem Unterobjekt unter der RO-Spezifikation.

Weitere Informationen zum Hinzufügen von Unterobjekten finden Sie unter "Definieren einer Unterobjekt-CDO-Unterklasse".

Vorgehensweise zum Hinzufügen einer RevisionedObject-CDO-Unterklasse

Diese Vorgehensweise führt Sie durch eine Übung zum Definieren eines RevisionedObject-CDOs. Im Beispiel wird Produkt (Product) verwendet.

Gehen Sie folgendermaßen vor, um eine RevisionedObject-CDO-Unterklasse hinzuzufügen:

1. Öffnen Sie Designer.
2. Klicken Sie in der Symbolleiste auf CDOs. Das Fenster "CDO-Definition" (CDO Definition) wird angezeigt.
3. Wählen Sie Erweitert (Advanced) aus dem Menü Ansicht (View) aus.
4. Klicken Sie auf CDOs. Das Fenster "CDO-Definition" (CDO Definition) wird angezeigt.
5. Wählen Sie in der Liste der Standardklassen die Optionen RevisionedObject > Produkt aus. Das Definitionsfenster für "Produkt" wird angezeigt.

 

6. Klicken Sie unter der CDO-Liste auf Hinzufügen. Das Fenster "Neue CDO-Definition erstellen" wird angezeigt.
7. Geben Sie MyProduct in das Feld "Neuer CDO-Name" ein.
Wichtig: Der Name des CDOs kann bis zu 30 Zeichen lang sein und darf keine Leerzeichen, unzulässigen Zeichen oder reservierten Wörter enthalten. Weitere Informationen finden Sie unter "Gültige Zeichen und reservierte Wörter".
8. Geben Sie eine Beschreibung ein. (Die Schaltfläche "Erstellen" wird erst aktiviert, wenn Sie eine Beschreibung eingeben.)

 

9. Gewährleisten Sie, dass für "Speicherkategorie" (Storage Category) Modellierung ausgewählt ist.
10. Gewährleisten Sie, dass Wartungsdienst erstellen & konfigurieren (Create & Configure a Maintenance Service) aktiviert ist.

Die für die Wartung erforderlichen CDOs und die zugehörigen erforderlichen Feldüberschreibungen für dieses RO werden automatisch erstellt, wenn dieses Kontrollkästchen aktiviert ist.

11. Klicken Sie auf Erstellen. "MyProduct" wird unter "RevisionedObject > Produkt" (RevisionedObject > Produkt) hinzugefügt.
12. Klicken Sie auf DB aktualisieren. In einem Dialogfeld werden Sie aufgefordert, das Speichern der aktuellen MDB-Datei und die Aktualisierung der Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) zu bestätigen.
13. Klicken Sie auf Ja. Eine Statusleiste wird am unteren Rand des Fensters angezeigt, um darauf hinzuweisen, dass die Aktualisierung ausgeführt wird. Die Anwendung speichert und aktualisiert die Datenbank.

Automatisierte Schritte

Die folgenden zugehörigen CDOs wurden automatisch definiert:

• "MyProductMaint" wird unter "Dienst > Update > Wartung > ProductMaint" (Service > Update > Maintenance > ProductMaint) hinzugefügt
• "MyProductBase" wird unter "RevisionBase > ProductBase" hinzugefügt.
• "MyProductChanges" wird unter "RevisionedObjectChanges > ProductChanges" hinzugefügt.
• "MyProduct" referenziert "MyProductBase" über das Feld "Base".
• "MyProductBase" referenziert "MyProduct" über die Felder "Revisions" und "RevOfRcd".
• "MyProductChanges" referenziert "MyProduct" über das Feld "ObjectToChange" und referenziert "MyProductBase" über das Feld "Base".

Weitere Informationen finden Sie unter "Automatisierte Schritte beim Definieren einer CDO-Unterklasse".

Hinweis: Weitere Informationen zu den im Dialogfeld "Voreinstellungen" (Preferences) verfügbaren Einstellungen finden Sie unter "Dialogfeld "Voreinstellungen" (Preferences), Registerkarte "DB-Aktualisierung" (DB Update)". Weitere Informationen zum Aktualisieren der Datenbank finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration oder der Opcenter Execution Core-Anleitung zur Systemadministration.

Vorgehensweise zum Hinzufügen von Feldern zum RevisionedObject-CDO

Bei dieser Vorgehensweise fügen Sie zwei Felder hinzu: ein Feld vom Typ "Zeichenkette" und ein Feld vom Typ "Objekt" (Object).

1. Wählen Sie das revisionierte Objekt aus, das Sie soeben definiert haben. In diesem Fall ist es MyProduct. Das Fenster "CDO-Definition für MyProduct" (CDO Definition for MyProduct) wird auf der Registerkarte "Felder" (Fields) geöffnet.
2. Klicken Sie auf Hinzufügen auf der Registerkarte Felder (Fields). Das Fenster "Neues CDO-Feld hinzufügen" (Add a New CDO Field) wird angezeigt. Der Standarddatentyp ist "Zeichenkette".
3. Konfigurieren Sie das Feld wie folgt:
a. Wählen Sie _Zeichenkette (_String) als Feldtyp aus.
b. Geben Sie Parm1 in das Feld "Name" ein.
Wichtig: Der Name darf keine Leerzeichen, unzulässigen Zeichen oder reservierten Wörter enthalten.
c. Geben Sie in das Feld "Überschrift" die Zeichenkette Parameter 1 ein.
Hinweis: Dieser Wert wird als Überschrift des Felds angezeigt, wenn Sie Portal Studio, Modeler oder Visual Controls verwenden. Verwenden Sie Leerzeichen, um die Überschrift lesbarer zu gestalten.
d. Geben Sie eine Beschreibung für das Feld ein.
e. Lassen Sie Feld zu zugehörigen Dienstobjekten hinzufügen (Add Field to Associated Service Objects) ausgewählt.
f. Klicken Sie auf Erstellen. Das Fenster "CDO-Feldeigenschaften" (CDO Field Properties) wird angezeigt.
Hinweis: Auf der Registerkarte Allgemein wird in den Feldern Feldname (Field name) und Spaltenname (Column name) der Name des neuen Felds angezeigt.
g. Klicken Sie auf OK.
4. Klicken Sie erneut auf Hinzufügen, um das zweite Feld hinzuzufügen.
5. Konfigurieren Sie das Feld wie folgt:
a. Wählen Sie den Datentyp Objekt (Object) aus der Liste Datentyp (Data Type) aus.
b. Wählen Sie Eigentümer als Feldtyp (Field Type) aus.
Hinweis: Behalten Sie den Feldnamen als Eigentümer bei.
c. Optional: Passen Sie die Beschreibung an die Anforderungen Ihres Unternehmens an.
d. Lassen Sie Feld zu zugehörigen Dienstobjekten hinzufügen (Add Field to Associated Service Objects) ausgewählt.
e. Klicken Sie auf Erstellen. Das Fenster "CDO-Feldeigenschaften" (CDO Field Properties) wird angezeigt.
f. Klicken Sie auf OK. Die Felder "Parm1" und "Eigentümer" werden zu "MyProduct" und "MyProductChanges" hinzugefügt.
6. Klicken Sie auf DB aktualisieren. In einem Dialogfeld werden Sie aufgefordert, das Speichern der aktuellen MDB-Datei und die Aktualisierung der Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) zu bestätigen.
7. Klicken Sie auf Ja. Eine Statusleiste wird am unteren Rand des Fensters angezeigt, um darauf hinzuweisen, dass die Aktualisierung ausgeführt wird. Die Anwendung speichert und aktualisiert die Datenbank.
Hinweis: Weitere Informationen zu den im Dialogfeld "Voreinstellungen" (Preferences) verfügbaren Einstellungen finden Sie unter "Dialogfeld "Voreinstellungen" (Preferences), Registerkarte "DB-Aktualisierung" (DB Update)". Weitere Informationen zum Aktualisieren der Datenbank finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration oder der Opcenter Execution Core-Anleitung zur Systemadministration.

Damit ist die Übung zum Erstellen einer RevisionedObject-Unterklasse mit allen zugehörigen Konfigurationen abgeschlossen.

Vorgehensweise zum Entfernen eines RevisionedObject-CDOs

Soll die von Ihnen erstellte RevisionedObject-Unterklasse gelöscht werden, müssen Sie die zugehörigen CDOs in der umgekehrten Reihenfolge ihrer Erstellung entfernen. Im folgenden Thema wird der Prozess am Beispiel von MyProduct erläutert.

Gehen Sie folgendermaßen vor, um ein RevisionedObject-CDO zu entfernen:

1. Öffnen Sie Designer.
2. Klicken Sie in der Symbolleiste auf CDOs. Das Fenster "CDO-Definition" (CDO Definition) wird angezeigt.
3. Wählen Sie Erweitert (Advanced) aus dem Menü Ansicht (View) aus.
4. Löschen Sie die Überschreibungen in den Feldern Revisions und RevOfRcd von "MyProductBase".
5. Löschen Sie die Überschreibungen in den Feldern Base und ObjectToChange von "MyProductChanges".
6. Löschen Sie die Überschreibungen im Feld Base von "MyProduct".
7. Entfernen Sie MyProductMaint.
8. Entfernen Sie MyProductBase.
9. Entfernen Sie MyProductChanges.
10. Entfernen Sie MyProduct.
11. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.
Hinweis: Weitere Informationen zum Aktualisieren der Datenbank finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration oder der Opcenter Execution Core-Anleitung zur Systemadministration.
