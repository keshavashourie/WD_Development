Hinzufügen von CDOs

Erstellen Sie ein CDO oder fügen Sie ein CDO hinzu, indem Sie unter dem Auswahlbaum auf die Schaltfläche "Hinzufügen" klicken oder indem Sie mit der rechten Maustaste in den Bereich des Auswahlbaums klicken und "Unterklasse hinzufügen" auswählen.

Beim Hinzufügen von CDOs

Arbeitsbereichspräfixe werden beim Hinzufügen eines neuen Elements automatisch vor dem Namen des Elements eingefügt, sofern dem höchsten aktiven Arbeitsbereich ein Präfix zugewiesen wurde. Arbeitsbereichspräfixe geben an, auf welchen Arbeitsbereich Designer Änderungen anwendet. Dem Arbeitsbereich würde z. B. das Präfix "C200" zugeordnet werden, wenn für diesen das Präfix "C200" festgelegt wurde und er der höchste aktive Arbeitsbereich in Management Studio ist. Siemens empfiehlt die Verwendung der von Designer bereitgestellten Präfixe, wenn Sie neue Elemente hinzufügen.

Sie können Arbeitsbereichspräfixe in Management Studio zuweisen oder ändern. Weitere Informationen finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration und der Opcenter Execution Core-Anleitung zur Systemadministration.

Hinweis: Dem Basisarbeitsbereich der Anwendung (csi) kann kein Arbeitsbereichspräfix zugewiesen sein.
Beim Hinzufügen einer Unterklasse

Siemens empfiehlt beim Hinzufügen einer CDO-Unterklasse die Verwendung eines eindeutigen Namens. Wenn das CDO und die CDO-Unterklasse den gleichen Namen verwenden und die Instanzen des CDOs mit Unterklasse in der Datenbank in der Tabelle des Eltern-CDOs gespeichert sind, werden während des Modellierungsexports keine Instanzen zur Auswahl angezeigt (selbst wenn sie für die Eltern- und Kind-CDOs definiert sind).

Wenn das CDO und die CDO-Unterklasse verschiedene Namen haben, jedoch in derselben Tabelle gespeichert sind, werden alle Instanzen zurückgegeben, die für die Eltern- und Kind-CDOs definiert sind. Dabei spielt es keine Rolle, ob Sie während des Modellierungsexports das Eltern- oder das Kind-CDO auswählen. Der Name des CDOs mit Unterklasse wird während des Modellierungsexports als Objekttyp angezeigt.

Felddefinitionen

Diese Tabelle definiert die Felder im Fenster "Neue CDO-Definition erstellen".

Feld

Definition

Neuer CDO-Name

Der eindeutige Name für das CDO. Meistens werden CDOs bei der Programmierung nach Name referenziert.

Beschreibung

Beschreibung zur Aktivierung der Schaltfläche "Erstellen" (sofern zusätzlich zum Namen eingegeben).

CDO-Verwendung (CDO Usage)

Auswahl bestimmt die vordefinierten Attributeinstellungen, die dem CDO zugeordnet sind.

Details

Schaltfläche, die Ihnen die Anzeige und Aktivierung von Verwendungsattributen für das ausgewählte CDO erlaubt, z. B. ob es sich bei dem CDO um einen Container oder ein benanntes Datenobjekt handelt.

Speicherkategorie

Referenz auf eine Tabellenkategorie, die für dieses CDO verwendet wird. Wenn die Kategorie "Modellierung" ausgewählt ist, wird dem CDO automatisch ein IsFrozen-Feld hinzugefügt, falls noch keines vorhanden ist. Wählen Sie "Kein" aus, wenn das CDO nicht persistent ist und keinen Speicher erfordert. Wählen Sie "Nicht definiert" aus, wenn die Speicherkategorie später festgelegt werden soll.

Neue Tabelle erstellen (Create a New Table)

Kontrollkästchen, das für Container-Unterklassen deaktiviert ist, da die Container-Tabelle der Anwendung verwendet wird. Andernfalls aktivieren Sie dieses Kontrollkästchen, um eine neue Tabelle für die CDO-Unterklasse zu erstellen. Wenn einer Klasse bereits eine Tabelle zugeordnet ist, möchten Sie meistens dieselbe Tabelle für die Unterklasse verwenden, um die Eindeutigkeit der CDO-Typen zu erzwingen (z. B. wenn Sie eine Unterklasse des Produkts erstellen). Wenn jedoch die Eindeutigkeit keine Rolle spielt und eine separate Tabelle erwünscht ist, erstellen Sie eine neue Tabelle. Neben dem Feld wird eine Nachricht angezeigt, die darauf hinweist, dass die Tabelle bereits dem Objekt zugeordnet ist. Die gleiche Nachricht wird angezeigt, wenn Sie auf "Erstellen" klicken. Klicken Sie zu diesem Zeitpunkt auf "Ja", um mit dem Erstellen der CDO-Unterklasse fortzufahren.

Tabellenname

Eindeutiger Name, mit dem die Tabelle für dieses CDO identifiziert wird.

Beschreibung

Dient zur Dokumentation des Zwecks der Tabelle.

Wartungsdienst erstellen & konfigurieren (Create & Configure a Maintenance Service)

Kontrollkästchen, das nur für die NamedDataObject- und RevisionedObject-CDOs aktiviert ist. Wenn Sie dieses Kontrollkästchen aktivieren, werden weitere zu erstellende Objekte erstellt. Referenzen, die erstellt werden müssen, damit dieses CDO ordnungsgemäß funktioniert, werden für Sie referenziert.

Berechtigungen

Wenn Sie einen neuen Dienst oder einen zusammengesetzten Dienst in Designer erstellen, müssen Sie den Zugang zu diesem erlauben, indem Sie den Dienstmethoden den Zugriffsmodus zuweisen.

Die Methode "Neu" wird ausgelöst, wenn Sie versuchen, ein neues Modellierungsobjekt zu erstellen. Sie müssen den Zugriffsmodus "Erstellen" für diese Methode aktivieren. So erkennt das System, dass es für die Methode "Neu" prüfen muss, ob der Zugriffsmodus "Erstellen" einer Rolle erteilt wurde, zu der der Benutzer gehört.

Rollen und Rollenmitgliedschaften werden in den Modellierungsobjekten "Rolle", "Mitarbeiter" und "Organisation" des Portals verwaltet. Weitere Informationen finden Sie im Opcenter Execution Medical Device and Diagnostics Modeling-Benutzerhandbuch und im Opcenter Execution Core Modeling-Benutzerhandbuch.

Informationen zu zusammengesetzten Diensten

Ein zusammengesetzter Dienst führt mehrere Unterdienste aus. Prüfung der Autorisierung und Validierung des organisatorischen Kontextes hängen von der jeweiligen Konfiguration des zusammengesetzten Dienstes in Designer und von den Parametern ab, die von einer aufrufenden Anwendung übergeben werden.
