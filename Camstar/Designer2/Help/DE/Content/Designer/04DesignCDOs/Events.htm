Geschehen

Wichtig: Dieses Thema bezieht sich auf die Verwendung der integrierten Variablen "Transaction::__Return".

Ereignisse werden vom System für ein CDO oder ein Feld ausgelöst und können entweder durch Zuordnung zu einem CLF oder durch Änderung der Parameter der Funktionen innerhalb des CLFs geändert werden.

In diesem Thema werden Ereignisse in CDO-Ereignissen, Feldereignissen und Listenfeldereignissen gruppiert. Weitere Informationen finden Sie unter "Allgemeine Szenarien".

CDO Geschehen

Für alle Ereignisse wird ein beliebiger zurückgegebener Wert in der Variablen "Transaction::__Return" festgelegt. Diese Tabelle beschreibt CDO-Ereignisse und deren Details.

BeforeValidate

Ja

Beim Ausführen eines Dienstes, bevor die Felder validiert wurden.

Gibt "Wahr" oder "Falsch" zurück. Wenn der CLF "Falsch" zurückgibt, wird die Ausführung abgebrochen.

BeforeExecute

Ja

Beim Ausführen eines Dienstes, nachdem "Cdo_validate" erfolgreich war.

Gibt "Wahr" oder "Falsch" zurück. Wenn der CLF "Falsch" zurückgibt, wird die Ausführung abgebrochen.

AfterExecute

Ja

Beim Ausführen eines Dienstes, nachdem "BeforeExecute" erfolgreich war.

Keine.

Hinweis: "AfterExecute" wird aufgerufen, bevor die Transaktion tatsächlich in der Datenbank festgeschrieben wird.

AfterCommit

Ja

Nachdem die Transaktion erfolgreich in der Datenbank festgeschrieben wurde.

Durch Fehler, die in diesem Ereignis auftreten, wird der Dienst nicht rückgängig gemacht.

Hinweis: Wenn in diesem Ereignis unbehandelte Fehler auftreten, werden die Felder "ACEStatus" und "ACEMessage" mit der entsprechenden Fehlermeldung aktualisiert, bevor das Ereignis "AfterCommitEventFailure" ausgelöst wird.

AfterCommitEvent

Ja

Wenn eine unbehandelte Ausnahme in der Logik auftritt, die an das Ereignis "AfterCommit" angehängt ist.

Fehler können mit einem try-catch-Block erfasst werden. Fehler, die mit "catch" erfasst wurden, lösen das Ereignis "AfterCommitEventFailure" nicht aus.

Hinweis: Wenn in diesem Ereignis unbehandelte Fehler auftreten, werden die Felder "ACEStatus" und "ACEMessage" mit der entsprechenden Fehlermeldung aktualisiert, bevor das Ereignis "AfterCommitEventFailure" ausgelöst wird.

Listenfeld Geschehen

Diese Tabelle beschreibt die Listenfeldereignisse und deren Details.

Event

Implementiert

Ausgelöst

Nebeneffekt

AddItem

Ja

Beim Hinzufügen eines Elements zu einem Listenfeld.

Gibt "Wahr" oder "Falsch" zurück. Wenn der CLF "Falsch" zurückgibt, wird das Element nicht hinzugefügt.

RemoveItem

Ja

Beim Entfernen eines Elements aus einem Listenfeld.

Gibt "Wahr" oder "Falsch" zurück. Wenn der CLF "Falsch" zurückgibt, wird das Element nicht entfernt.

DeleteItem

Ja

Wenn ein Unterobjekt aus einem Listenfeld gelöscht wird.

Gibt "Wahr" oder "Falsch" zurück. Wenn der CLF "Falsch" zurückgibt, wird das Element nicht gelöscht.

Hinweis: "RemoveItem" wird zuerst ausgelöst, anschließend, sofern dadurch "Wahr" zurückgegeben wird, wird "DeleteItem" ausgelöst.

MoveItem

Ja

Beim Verschieben eines Elements in einem Listenfeld.

Gibt "Wahr" oder "Falsch" zurück. Wenn der CLF "Falsch" zurückgibt, wird das Element nicht verschoben.

ChangeItem

Ja

Beim Aktualisieren eines Elements in einem Listenfeld.

Gibt "Wahr" oder "Falsch" zurück. Wenn der CLF "Falsch" zurückgibt, wird das Element nicht festgelegt.

GetItem

Ja

Beim Anfordern eines Elements in einem Listenfeld.

Gibt einen Wert zurück. Der CLF kann den Elementwert überschreiben und einen anderen Wert zurückgeben, sofern erforderlich.

InitializeList

Nein
