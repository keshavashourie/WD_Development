Definieren einer Dienst-CDO-Unterklasse

Dienstobjekte stellen die Arbeit dar, die an Containerobjekten ausgeführt wurde. Bei der Definition einer Container-CDO-Unterklasse wird die Startdienst-Unterklasse automatisch erstellt. Beim Definieren einer NamedDataObject-Unterklasse und beim Definieren einer RevisionedObject-Unterklasse wird automatisch eine Wartungsdienst-Unterklasse erstellt. Es stehen weitere Dienste, z. B. Abfragen und Transaktionen, zur Verfügung. Die meisten täglichen Aufgaben, die von Mitarbeitern ausgeführt werden, sind Fertigungstransaktionen an Containern.

Beim Definieren einer Dienst-CDO-Unterklasse

Arbeitsbereichspräfixe werden beim Hinzufügen eines neuen Elements automatisch vor dem Namen des Elements eingefügt, sofern dem höchsten aktiven Arbeitsbereich ein Präfix zugewiesen wurde. Arbeitsbereichspräfixe geben an, auf welchen Arbeitsbereich Designer Änderungen anwendet. Dem Arbeitsbereich würde z. B. das Präfix "C200" zugeordnet werden, wenn für diesen in Management Studio das Präfix "C200" festgelegt wurde. Es wird empfohlen, beim Hinzufügen neuer Elemente die von Designer bereitgestellten Präfixe zu verwenden.

Sie können Arbeitsbereichspräfixe in Management Studio zuweisen oder ändern. Weitere Informationen finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration und der Opcenter Execution Core-Anleitung zur Systemadministration.

Hinweis: Dem Basisarbeitsbereich der Anwendung (csi) kann kein Arbeitsbereichspräfix zugewiesen sein.
Aufgabenübersicht

Die Dienstklasse enthält Unterklassen, die die Containertransaktionen darstellen, die in der Fertigung ausgeführt werden, z. B. "Start", "MoveTxn" und das Zuordnen von CDOs (Associate CDOs), um nur einige zu nennen. Im Anschluss an diese allgemeinen Erläuterungen folgt eine Übung mit schrittweisen Anleitungen.

Hinzufügen einer Dienst-CDO-Unterklasse

Fügen Sie Ihre Dienstunterklasse unter dem entsprechenden, von Siemens bereitgestellten Dienst-CDO hinzu.

Beim Definieren eines Dienstobjekts, z. B. der Transaktion "MoveStd" unter "ContainerTxn", wird die gleiche Vorgehensweise verwendet wie für CDOs im Allgemeinen. Den Transaktionen sind keine Datenbanktabellen zugeordnet, obwohl Historieninformationen gesammelt und gespeichert werden, um die für einen Container verwendeten Transaktionen zu verfolgen. Dies beinhaltet auch Informationen dazu, wann und durch wen die Transaktionen ausgeführt wurden.

Erstellen eines ServiceDetails-Unterobjekts

Einige Dienste umfassen ein ServiceDetails-Unterobjekt, das Informationen enthält, die für den Dienst erforderlich sind. Die einfachen Dienste erfordern kein ServiceDetails-Unterobjekt, da alle für den Dienst erforderlichen Informationen im Dienst selbst vorhanden sind. Für Dienste mit einem ServiceDetails-Unterobjekt werden Sie eine ServiceDetails-Unterobjekt-Unterklasse für die neue Dienst-CDO-Unterklasse erstellen. Konzepte und Anweisungen wurden unter "Definieren einer Unterobjekt-CDO-Unterklasse" erläutert und in der Übung zum Hinzufügen eines Unterobjekts über ein Feld veranschaulicht.

Hinzufügen von Feldern zur Service- oder ServiceDetails-CDO-Unterklasse

Für Dienst-CDOs mit einem Feld "ServiceDetails" werden Sie die Felder zum ServiceDetails-Unterobjekt hinzufügen. Für Dienst-CDOs ohne das Feld "ServiceDetails" (oder einem gleichwertigen Feld, z. B. "ToContainerDetails" für den Dienst "Aufteilen"), werden Sie die Felder direkt zum Dienst-CDO hinzufügen.

Überschreiben von CDO-Referenzen

Wenn das neue Dienst-CDO das Feld "Details" erbt, zeigt das Feld auf das ServiceDetails-Unterobjekt seines übergeordneten CDOs und nicht auf das ServiceDetails-Unterobjekt, das zum neu erstellten Dienst-CDO gehört. In diesem Fall ändern Sie die Referenz im Feld "Details" des neuen Dienst-CDOs so, dass es auf das neue ServiceDetails-Unterobjekt-CDO zeigt.

Das neue Dienst-CDO muss auf das richtige Container-CDO zeigen. Für Dienste mit einem ServiceDetails-Unterobjekt werden Sie das Feld "Container" im Unterobjekt so überschreiben, dass es auf das richtige Container-CDO zeigt. Für Dienste ohne das ServiceDetails-Unterobjekt werden Sie das Feld "Container" im Dienst-CDO so überschreiben, dass es auf das richtige Container-CDO zeigt.

Hinzufügen von Feldern zum Historien-CDO

Wenn Sie einen Dienst durch Erstellen einer Unterklasse und Hinzufügen Ihrer eigenen Felder erweitern, und diese neuen Felder in die Historieneinträge des Dienstes geschrieben werden sollen, werden Sie die gleichen Felder dem entsprechenden Typ der Historien-CDO-Unterklasse hinzufügen und anschließend diese zusätzlichen Felder vom erweiterten Dienst-CDO der neuen Historien-CDO-Unterklasse zuordnen. Sie können drei Typen von Historien-CDOs verwenden:

• ServiceHistoryDetail (für Dienste mit ServiceDetails).
• ServiceHistorySummary (für Dienste ohne ServiceDetails).
• StartHistoryDetail (nur für Startdienste, zusätzlich zu ServiceHistoryDetail).

Hinzufügen von Feldern zum HistoryDetails-Unterobjekt-CDO

Alle Felder, die Sie aufzeichnen möchten, müssen vom Dienst-CDO in das HistoryDetails-CDO kopiert werden. Die Daten werden ordnungsgemäß aufgezeichnet, wenn Sie die Felder vom Quellen-CDO dem Ziel-CDO zuordnen.

Zunächst werden Sie dem entsprechenden HistoryDetails-Unterobjekt eine Unterklasse hinzufügen und anschließend die neuen Felder diesem Historien-CDO hinzufügen. Dies ermöglicht es Ihnen, Historieninformationen für die neuen Felder "Container" immer dann aufzuzeichnen, wenn der Dienst für den Container ausgeführt wird.

Vorgehensweise zum Hinzufügen eines Dienst-CDOs

Der Startdienst und alle zugehörigen CDOs und Referenzen werden automatisch erstellt, wenn Sie eine Unterklasse des Container-CDOs erstellen und "Startdienst erstellen & konfigurieren" (Create & Configure a Start Service) auswählen. Wartungsdienste werden beim Hinzufügen der Unterklasse eines NamedDataObject- oder RevisionedObject-CDOs automatisch erstellt, wenn das Kontrollkästchen "Wartungsdienst erstellen & konfigurieren" (Create & Configure a Maintenance Service) aktiviert wurde. Für alle anderen Containerdienste müssen Sie eine Unterklasse für den erforderlichen Dienst erstellen.

In den folgenden Schritten wird erläutert, wie Sie eine Unterklasse für den Durchsatz-Dienst erstellen. Gehen Sie folgendermaßen vor, um ein Dienst-CDO hinzuzufügen:

1. Öffnen Sie Designer.
2. Wählen Sie das Durchsatz-Dienst-CDO in der Klassenliste aus:

Service>Update>ShopFloor>ContainerTxn>Thruput

 

3. Klicken Sie unter dem CDO-Auswahlbereich auf Hinzufügen. Das Fenster "Neue CDO-Definition erstellen" wird angezeigt.

In diesem Fenster können Sie diesem Dienst-CDO eine neue Unterklasse hinzufügen.

4. Geben Sie den Namen dieser neuen Dienstunterklasse, MyThruput, in das Feld Neuer CDO-Name ein.
Wichtig: Der Name des CDOs kann bis zu 30 Zeichen lang sein und darf keine Leerzeichen, unzulässigen Zeichen oder reservierten Wörter enthalten. Weitere Informationen finden Sie unter "Gültige Zeichen und reservierte Wörter".
5. Geben Sie eine Beschreibung in das Feld Beschreibung (Description) ein. Die Schaltfläche "Erstellen" ist aktiviert, wenn die Felder "Name" und "Beschreibung" ausgefüllt sind.
6. Lassen Sie die Standardwerte CDO-Verwendung (CDO Usage) = Service Shopfloor Reversible und Speicherkategorie (Storage Category) = Keine unverändert.
Dienst-CDOs sind nicht persistent und erfordern keine Speicherung.
7. Klicken Sie auf Erstellen. MyThruput ist jetzt eine Unterklasse von "Durchsatz".
8. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.

Hinzufügen eines ServiceDetails-CDOs

Zur Fortsetzung des Beispiels erstellen Sie das MyThruputDetail-Unterobjekt-CDO als Unterklasse von "ThruputDetail" (gemäß der Klassenstruktur von "Thruput").

Vorgehensweise zum Hinzufügen von "MyThruputDetail"

Gehen Sie folgendermaßen vor, um die MyThruputDetail-Unterklasse hinzuzufügen:

1. Wählen Sie das Thruput-CDO aus.
2. Klicken Sie mit der rechten Maustaste auf das Feld ServiceDetails.
3. Wählen Sie An CDO-Definition positionieren (Position to CDO Definition) aus, um zum ThruputDetails-Unterobjekt zu wechseln.
4. Leiten Sie die Unterklasse, MyThruputDetail, ab (bzw. fügen Sie sie hinzu) und geben Sie eine Beschreibung ein. Behalten Sie die anderen Standardwerte bei. Das Unterobjekt wird wie folgt zur Klassenstruktur hinzugefügt:

Subentity>ServiceData>ServiceDetails>ThruputDetails>MyThruputDetail

5. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.

Service-CDOs und ihre Unterobjekte erfordern keine Speicherkategoriedefinitionen. Prüfen Sie bei Bedarf, wie die Unterklasse eines Unterobjekt-CDOs definiert wird. Mit den folgenden Schritten werden Sie diesem Unterobjekt Felder hinzufügen.

Hinzufügen von Feldern zum Dienst- oder ServiceDetails-CDO

Sie können Felder zum ServiceDetails-CDO (oder zum Dienst-CDO, falls kein ServiceDetails-CDO vorhanden ist) hinzufügen, wenn dies für die Anforderungen Ihres Unternehmens erforderlich ist.

Vorgehensweise zum Hinzufügen eines Felds zu "MyThruputDetail"

Gehen Sie folgendermaßen vor, um das Feld zur MyThruputDetail-Unterklasse hinzuzufügen:

1. Wählen Sie die die soeben erstellte MyThruputDetail-Unterklasse aus.

Die Registerkarte Felder (Fields) wird angezeigt.

2. Klicken Sie unter dem Felderbereich auf Hinzufügen.
3. Behalten Sie den Datentyp "Zeichenkette" bei. Geben Sie in das Feld Name die Zeichenkette MyThruputField1 ein.
Hinweis: Feldnamen müssen nur innerhalb des CDOs eindeutig sein.
4. Klicken Sie auf Erstellen.
5. Wählen Sie Speichern im Menü Datei aus. Die Anwendung speichert Ihre Änderungen.

Erstellen der HistoryDetails-CDO-Unterklasse

Anstatt das vorhandene Standard-HistoryDetails-CDO für "Thruput" zu verwenden, fügen Sie eine neue Unterklasse zum entsprechenden HistoryDetails-CDO und anschließend Felder zur Unterklasse hinzu.

Vorgehensweise zum Hinzufügen von "MyThruputHistoryDetail"

Gehen Sie folgendermaßen vor, um die MyThruputHistoryDetail-Unterklasse hinzuzufügen:

1. Gehen Sie zu

 

Subentity>HistoryDetails>ServiceHistoryDetail>ThruputHistoryDetail

Hinweis: Sie können auch auf "Geerbte Felder einschließen" (Include inherited fields) klicken, um diese verfügbar zu machen. Klicken Sie anschließend mit der rechten Maustaste auf das Feld "HistoryDetail" und wählen Sie "An CDO-Definition positionieren" (Position to CDO Definition) aus, um zu "ThruputHistoryDetail" zu wechseln.
2. Wählen Sie ThruputHistoryDetail aus und klicken Sie unter dem Auswahlbereich auf Hinzufügen. Das Fenster "Neue CDO-Definition erstellen" wird angezeigt.
3. Geben Sie MyThruputHistoryDetail in das Feld Neuer CDO-Name ein.
4. Geben Sie eine Beschreibung ein, die den Anforderungen Ihres Unternehmens entspricht.
5. Klicken Sie auf Erstellen.
6. Klicken Sie auf DB aktualisieren. In einem Dialogfeld werden Sie aufgefordert, das Speichern der aktuellen MDB-Datei und die Aktualisierung der Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) zu bestätigen.
7. Klicken Sie auf Ja. Eine Statusleiste wird am unteren Rand des Fensters angezeigt, um darauf hinzuweisen, dass die Aktualisierung ausgeführt wird. Die Anwendung speichert und aktualisiert die Datenbank.

Hinzufügen von Feldern zum HistoryDetails-CDO

Fügen Sie diesem CDO (in diesem Fall MyThruputField1) die gleichen Felder hinzu, die Sie dem Service- oder ServiceDetails-CDO hinzugefügt haben.

Hinweis: Fügen Sie das Feld "MyThruputField1" entweder manuell hinzu oder kopieren Sie es aus "MyThruputDetails" und fügen Sie es in "MyThruputHistoryDetail" ein. Wenn Sie sich für das Kopieren und Einfügen entscheiden, verwenden Sie das Kontextmenü des Felds "CDO" und nicht die Windows-Tastaturkürzel.

Im nächsten Schritt werden Sie die Felder zuordnen wie unter "Anzeigen von Feldzuordnungen" erläutert.
