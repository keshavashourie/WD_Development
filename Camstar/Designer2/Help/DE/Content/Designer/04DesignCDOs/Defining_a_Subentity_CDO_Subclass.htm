Definieren einer Unterobjekt-CDO-Unterklasse

Ein Unterobjekt ist ein Objekt, dessen Eigentümer ein anderes Objekt ist. (Dieser eigentümerbezogene Beziehungstyp wird in der Regel als Zusammensetzung bezeichnet.) Ein Objekt vom Typ Unterobjekt gehört ausschließlich zu einem Eltern-Objekt. Das Vorhandensein von Unterobjekten ist normalerweise vom Vorhandensein ihrer Eltern abhängig. Wenn die Instanz eines Elternobjekts gelöscht wird, werden auch die Instanzen seiner Unterobjekte gelöscht.

Beim Definieren einer Unterobjekt-CDO-Unterklasse

Wenn eine Liste mit Elementen erforderlich ist, wird ein Design mit Unterobjekten benötigt, wobei jedes Element mehrere Attribute aufweist. Soll z. B. ein Arbeitsplan im Opcenter EX MDD- oder Opcenter EX CR-Objektmodell modelliert werden, müssen Sie "Schritt" als Unterobjekt definieren und als Listenfeld im Arbeitsplan markieren.

Zudem sollten Sie ein Unterobjekt verwenden, anstatt mehrere einzelne Felder zum Elternobjekt hinzuzufügen, wenn Sie eine Reihe zusammenhängender Felder für die Wiederverwendung, Kapselung oder aus sonstigen Gründen gruppieren möchten. Zum Beispiel enthält entweder Opcenter EX MDD oder Opcenter EX CR ein SchedulingDetail-Objekt mit Feldern wie "SetupTime", "RunRate" usw. Diese Unterobjektdefinition wird in den Objekten "Operation", "Spezifikation" (Spec) und "WorkflowStep" verwendet.

Während nur ein bestimmtes Elternobjekt ein bestimmtes Unterobjekt besitzt, kann das Unterobjekt durch andere Objekte referenziert werden. Ein Arbeitsplan besitzt z. B. seine Schritte, doch andere Objekte wie z. B. ein Container können einen bestimmten Arbeitsplanschritt referenzieren. Zum Referenzieren des Unterobjekts eines anderen Objekts müssen Sie in der Regel das Elternobjekt des Unterobjekts als Teil der Referenzinformationen angeben.

Beispiele für die Funktionen eines Unterobjekt-CDOs:

• Das Elternobjekt enthält Referenzen auf seine Unterobjekte und jedes Unterobjekt enthält Referenzen auf sein Elternobjekt.
• Wenn die Instanz eines Elternobjekts gelöscht wird, werden alle Instanzen seiner Unterobjekte automatisch gelöscht.
• Opcenter EX MDD oder Opcenter EX CR enthält eine spezielle Klasse von Unterobjekten mit der Bezeichnung NamedSubentity. Benannte Unterobjekte sind hilfreich, wenn Sie ein Unterobjekt-Listenfeld erstellen müssen. Zudem müssen Sie jedem Unterobjektelement einen Namen zuweisen, der innerhalb des Elternobjekts eindeutig ist. Das VendorItem-Unterobjekt, das als Liste innerhalb eines Anbieters (Vendor) verwendet wird, verfügt über ein benanntes Unterobjekt. Das System erfordert, dass jedes Element einen Namen aufweist, der innerhalb des Anbieters eindeutig ist, und das VendorItem-Unterobjekt kann referenziert werden, indem der Anbieter und der Name des Elements angegeben werden.
• Jedes Objekt kann Unterobjekte enthalten. Selbst Unterobjekte können andere Unterobjekte enthalten.

Arbeitsbereichspräfixe werden beim Hinzufügen eines neuen Elements automatisch vor dem Namen des Elements eingefügt, sofern dem höchsten aktiven Arbeitsbereich ein Präfix zugewiesen wurde. Arbeitsbereichspräfixe geben an, auf welchen Arbeitsbereich Designer Änderungen anwendet. Dem Arbeitsbereich würde z. B. das Präfix "C200" zugeordnet werden, wenn für diesen das Präfix "C200" festgelegt wurde und er der höchste aktive Arbeitsbereich in Management Studio ist. Es wird empfohlen, beim Hinzufügen neuer Elemente die von Designer bereitgestellten Präfixe zu verwenden.

Sie können Arbeitsbereichspräfixe in Management Studio zuweisen oder ändern. Weitere Informationen finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration und der Opcenter Execution Core-Anleitung zur Systemadministration.

Hinweis: Dem Basisarbeitsbereich der Anwendung (csi) kann kein Arbeitsbereichspräfix zugewiesen sein.

Unterobjekte von NDOs und ROs

Durch Opcenter EX MDD und Opcenter EX CR wurde der Prozess zum Erstellen von Unterobjekten für NDOs und ROs stark automatisiert. Es sind lediglich die folgenden Schritte erforderlich:

• Erstellen Sie das Unterobjekt, indem Sie dem Elternobjekt ein Feld hinzufügen.

Wählen Sie beim Hinzufügen des Felds den Datentyp "[Erstellen eines neuen Unterobjekts]" (Create a new subentity) aus. Anschließend können Sie auswählen, welche Art von Unterobjekt Sie erstellen möchten (z. B. ein benanntes Unterobjekt oder die Unterklasse eines bestimmten, bereits vorhandenen Unterobjekts).

• Geben Sie die Attribute des Unterobjekts an, z. B. Name, Beschreibung, Speicherkategorie und Tabellenname (falls erforderlich). Geben Sie auch an, ob das Unterobjekt als Liste im aktuellen Elternobjekt verwendet werden soll.
• Nachdem Sie das Unterobjekt erstellt haben, indem Sie es dem Elternobjekt als Feld hinzugefügt haben, navigieren Sie zum neuen Unterobjekt, indem Sie mit der rechten Maustaste auf das Feld des Unterobjekts klicken und die Option "Position to CDO" (Position zu CDO) im Kontextmenü verwenden.
• Fügen Sie dem Unterobjekt alle erforderlichen Felder hinzu.

Der Designer wartet alle anderen Arbeitsschritte zur Aktualisierung des neuen Unterobjekts mit dem entsprechenden Wartungsdienst automatisch.

Ergebnisse des Hinzufügens eines neuen Unterobjekts mithilfe der automatisierten Funktion:

• Es wird ein neues Unterobjekt erstellt, das den Typ aufweist, den Sie für die Vererbung ausgewählt haben.
• Das neue Unterobjekt enthält ein Feld, das es mit dem Eltern-CDO verbindet, für das Sie dieses Unterobjekt erstellt haben. Der Name des Felds ist "Eltern" (Parent) und sein Typ entspricht dem Namen des Eltern-CDOs.
• Das Eltern-CDO (das CDO, für das Sie das neue Unterobjekt erstellt haben) weist ein neues Feld auf, das eine Referenz auf sein neues Unterobjekt enthält. Der Feldtyp ist der Name des neuen Unterobjekts.

Unterobjekte für Container

Das Container-CDO verfügt über ein Unterobjekt, "ContainerDetails", das durch das Feld "Details" referenziert wird. In bestimmten Fällen müssen Sie Felder hinzufügen, um das Container-CDO anzupassen. Sie können diese zum ContainerDetails-Unterobjekt hinzufügen. "ContainerDetails" ist ein Unterobjekt ohne Liste. Informationen zu Unterobjektlisten finden Sie unter "Unterobjekte anderer Objekte".

Unterobjekte anderer Objekte

Wenn das Unterobjekt eines anderen Unterobjekts, das Unterobjekt eines Fertigungsdienstes, eine Unterobjektliste für einen Container oder andere anspruchsvolle Unterobjekte erforderlich sind, müssen Sie Designer umfassender konfigurieren. Die dazu erforderlichen Schritte hängen von der jeweiligen Aufgabe ab, können jedoch Folgendes umfassen:

• Generieren des neuen Unterobjekts entweder beim Hinzufügen des Felds zum Elternobjekt oder vorab durch Erstellen einer neuen Unterklasse eines Unterobjekts.
• Erstellen paralleler Historienunterobjekte oder Erweitern eines vorhandenen Historienobjekts, um Felder einzuschließen, die im Dienst- oder Containerunterobjekt vorhanden sind.
• Erweitern oder Aktualisieren vorhandener Zuordnungen zum Kopieren der Daten nach Bedarf, z. B. zwischen einem Dienstunterobjekt und einem Historienunterobjekt.
• Aktualisieren von CLFs, um neue Zuordnungen oder andere Mechanismen zum Kopieren von Daten hinzuzufügen.
• Aktualisieren Sie bei Bedarf das Feld "Eltern" (Parent) des neuen Unterobjekts so, dass es einem bestimmten Objekttyp entspricht.

Hinzufügen eines vorhandenen Unterobjekts zu einem Parent-CDO

Ein vorhandenes Unterobjekt kann problemlos einem Objekt hinzugefügt werden, indem Sie seinen Objekttyp auswählen. Wählen Sie im Fenster "Neues CDO-Feld hinzufügen" (Add a new CDO field) das Datentypobjekt und danach den Namen des vorhandenen Unterobjekts in der Auswahlliste "Feldtyp" (Field type) aus. Anschließend können Sie dieses Feld als Liste markieren und nach Bedarf entsprechende Felddefinitionen zu dienstbezogenen Objekten hinzufügen.

Abhängig vom Typ des Objekts, zu dem Sie dieses Unterobjektfeld hinzugefügt haben, sind möglicherweise weitere Schritte erforderlich, z. B. das Erweitern von Zuordnungen usw. Diese Schritte wurden bereits weiter oben beschrieben.

Übung zum Hinzufügen eines Unterobjekts über ein Feld

In diesem Beispiel werden Sie eine Unterobjekt-Unterklasse hinzufügen, die Daten zu Kontakten gruppiert, die Sie für jeden Ihrer Kunden warten möchten. Dieses Unterobjekt ermöglicht Ihnen das Definieren und Sammeln von Informationen in einem Unterobjekt für jede Instanz des Kunden und das bidirektionale Referenzieren zwischen den einzelnen Kunden und deren Contacts-Unterobjekt.

Wichtig: Das Hinzufügen von Unterobjekten wurde durch die Option "Hinzufügen" auf der Registerkarte "Felder" für CDOs automatisiert. Dies bedeutet, dass Sie in einem ersten Schritt das CDO festlegen und auswählen müssen, das Sie um ein neues Unterobjekt erweitern möchten.

Referenzieren eines benannten Unterobjekts nach Name

Benannte Unterobjekte können entweder nach Name oder nach Index referenziert werden. Wenn ein benanntes Unterobjekt für ein Objekt vorliegt (z. B. ein Produkt), können eindeutige Einträge nach Name mit einem entsprechenden Wert hinzugefügt werden.

Daher erlaubt Ihnen Designer die Referenzierung des Unterobjekts entweder nach Index oder durch gezielte Eingabe in einen Pfadselektor nach Name anstatt nach Index.

Gehen Sie folgendermaßen vor, um Folgendes nach Name zu suchen:

Container.Product.Attributes("Color").Value.

Sie können Folgendes verwenden:

FindListItem (Container.Product.Attributes, Name, "Color").Value

Vorgehensweise zum Hinzufügen von Feldern zum ContainerDetails-Unterobjekt

Gehen Sie folgendermaßen vor, um dem ContainerDetails-Unterobjekt Felder hinzuzufügen:

1. Wählen Sie die Unterklasse Container aus, die Sie anpassen möchten.
2. Klicken Sie auf die Registerkarte Felder (Fields).
3. Wählen Sie An CDO-Definition positionieren (Position to CDO Definition) aus dem Kontextmenü des Felds Detail aus, um auf das ContainerDetail-CDO zuzugreifen.
4. Fügen Sie abhängig von den Anforderungen Ihres Unternehmens Felder zum ContainerDetail-CDO hinzu.
5. Wenn für die Felder "ContainerDetail" während des Startdienstes der Container-Unterklasse Werte bereitgestellt werden sollen (in der Regel müssen Werte für die Felder "ContainerDetail" bei der Containerverarbeitung erst später festgelegt werden):
a. Wählen Sie den zugehörigen Startdienst für den Container aus.
b. Wählen Sie aus dem Kontextmenü des Felds "Details" die Option An CDO-Definition positionieren (Position to CDO Definition) aus, um auf das entsprechende StartDetails-CDO zuzugreifen. Fügen Sie anschließend die entsprechenden Felder hinzu.
c. Fügen Sie der Zuordnung StartDetails_to_ContainerDetail einen Zuordnungseintrag für die Felder hinzu, die dem StartDetails-CDO hinzugefügt wurden.
Hinweis: Weitere Informationen zu dieser Vorgehensweise finden Sie unter "Vorgehensweise zum Zuordnen eines Felds durch Erweitern einer vorhandenen Zuordnung".
d. Gehen Sie folgendermaßen vor, um die Historie zu konfigurieren (falls gewünscht):
1) Wählen Sie das StartHistoryDetail-CDO aus und fügen Sie die entsprechenden Felder hinzu.
Hinweis: Dieser Schritt ist erforderlich, wenn ein Historieneintrag erforderlich ist.
2) Fügen Sie einen Zuordnungseintrag in die Zuordnung ContainerDetail_to_StartHistoryDetail für die Felder hinzu, die dem StartHistoryDetail-CDO hinzugefügt wurden.
Wichtig: Dieser Schritt ist erforderlich, wenn der Historieneintrag erweitert wird.
6. Erweitern Sie ContainerTxn, um die Felder bei Bedarf zu aktualisieren:
a. Fügen Sie die entsprechenden Felder der jeweiligen Unterklasse von ContainerTxn hinzu und stellen Sie "CVE" in einem Format zur Verfügung, das in etwa wie folgt aussieht This_Value;Container.Detail.MyField.
Wichtig: Dieser Schritt ist erforderlich, wenn "ContainerTxn" und die entsprechenden Unterklassen in der Lage sein sollten, diese Detailfeldwerte zu aktualisieren.
b. Fügen Sie einen Zuordnungseintrag in der Zuordnung ContainerTxn_to_ContainerDetail für die Felder hinzu, die zu ContainerTxn hinzugefügt wurden.
Wichtig: Dieser Schritt ist erforderlich, wenn ContainerTxn und die entsprechenden Unterklassen in der Lage sein sollen, diese Detailfeldwerte zu aktualisieren.
7. Fügen Sie entsprechende Felder zum HistorySummary-CDO hinzu, wenn Historieneinträge erforderlich sind.
8. Fügen Sie einen Zuordnungseintrag für die Felder hinzu, die dem HistorySummary-CDO hinzugefügt wurden:
a. Fügen Sie der Zuordnung SummaryContainerDetailPreHistory einen Zuordnungseintrag für die Felder hinzu, die dem HistorySummary-CDO hinzugefügt wurden.
Wichtig: Dieser Schritt ist erforderlich, wenn Sie Felder für die alten Werte hinzugefügt haben, um Vorhistorieneinträge beizubehalten.
b. Fügen Sie der Zuordnung SummaryContainerDetailPostHistory einen Zuordnungseintrag für die Felder hinzu, die dem HistorySummary-CDO hinzugefügt wurden.
Wichtig: Dieser Schritt ist erforderlich, wenn Sie Felder für die neuen Werte hinzufügen, um Nachhistorieneinträge beizubehalten.
9. Fügen Sie Logik zum Dienst Starten hinzu, sodass beim Erstellen dieses Containertyps auch das entsprechende ContainerDetail-Unterobjekt erstellt wird. Weitere Informationen finden Sie unter "Konfigurierbare logische Abläufe":
a. Erstellen eines Benutzer-CLFs
In diesem Fall fügen Sie Ihren eigenen CLF unter der Kategorie UserFunctions hinzu.
b. Hinzufügen einer Funktion zu Ihrem Benutzer-CLF
In diesem Fall werden Sie die Funktion CreateCDO aus der Kategorie ObjectProcessing hinzufügen. Sie werden die Parameter exakt wie angegeben festlegen (nur Text in Fettschrift):
CreateOnlyIfNotExists = Transaction::__Const.BooleanTrue
Location = Container.Detail
c. Hinzufügen des Benutzer-CLFs zur Registerkarte "Ereignisse" eines CDOs durch Überschreiben einer vorhandenen Methode
In diesem Fall wählen Sie das dem Container zugeordnete StartDetails-CDO aus und überschreiben die Methode CreateContainer_User mit Ihrem Benutzer-CLF.
10. Klicken Sie auf DB aktualisieren. In einem Dialogfeld werden Sie aufgefordert, das Speichern der aktuellen MDB-Datei und die Aktualisierung der Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) zu bestätigen.
11. Klicken Sie auf Ja. Eine Statusleiste wird am unteren Rand des Fensters angezeigt, um darauf hinzuweisen, dass die Aktualisierung ausgeführt wird. Die Anwendung speichert und aktualisiert die Datenbank.
Hinweis: Weitere Informationen zu den im Dialogfeld "Voreinstellungen" (Preferences) verfügbaren Einstellungen finden Sie unter "Dialogfeld "Voreinstellungen" (Preferences), Registerkarte "DB-Aktualisierung" (DB Update)". Vorgehensweise zum Hinzufügen eines Unterobjekts CDO zu einem CDO

Gehen Sie folgendermaßen vor, um ein Unterobjekt-CDO zum Customers-CDO hinzuzufügen:

1. Öffnen Sie Designer.
2. Klicken Sie in der Symbolleiste auf CDOs. Das Fenster "CDO-Definition" wird angezeigt.
3. Wählen Sie Erweitert (Advanced) aus dem Menü Ansicht (View) aus.
4. Suchen Sie die folgende Klasse:

NamedDataObject>Customer

5. Wählen Sie Customer aus. Das CDO wird auf der Registerkarte "Felder" (Fields) geöffnet.
6. Klicken Sie unter der Registerkarte "Feld" (Field) auf Hinzufügen. Das Fenster "Neues CDO-Feld hinzufügen" (Add a new CDO Field) wird angezeigt.
7. Wählen Sie die Option Neues Unterobjekt erstellen (Create a new Subentity) aus der Liste Datentyp (Data Type) aus. Das Feld "Feldtyp" (Field Type) ändert sich in die CDO-Definition, von der geerbt werden soll.
8. Wählen Sie aus der Liste der Objekte, von denen das neue Unterobjekt erbt, die Option Unterobjekt (Subentity) aus.
9. Legen Sie für die neue Unterklasse des Customer-Unterobjekts den Namen CustomerContacts fest.
10. Geben Sie ggf. eine Überschrift ein, z. B. Customer Contacts.
11. Geben Sie eine aussagekräftige Beschreibung ein.
12. Wählen Sie Modellierung aus der Liste Speicherkategorie (Storage Category) aus.
13. Geben Sie einen Tabellennamen für die Tabelle ein, in der Sie Ihre CustomerContacts-Daten speichern möchten. Geben Sie für dieses Beispiel CustomerContacts ein.
14. Klicken Sie auf Erstellen. Das Fenster "CDO-Feldeigenschaften" (CDO Field Properties) für "CustomerContacts" wird geöffnet.
15. Überprüfen Sie die Eigenschaften und ändern Sie sie, falls erforderlich.
16. Klicken Sie auf OK. Das Customer-CDO enthält jetzt ein Feld, das es mit dem neuen Unterobjekt verknüpft, und der Name des Felds entspricht dem Namen des neuen Unterobjekts, "CustomerContacts".
17. Sie können das neue Unterobjekt wie folgt anzeigen:
a. Klicken Sie mit der rechten Maustaste auf das Feld CustomerContacts, um das Kontextmenü anzuzeigen.
b. Wählen Sie An CDO-Definition positionieren (Position to CDO Definition) aus. Das neue Unterobjekt ist ausgewählt und seine Registerkarte "Felder" (Fields) wird angezeigt.
Hinweis: Später können Sie diesem neuen Unterobjekt Felder hinzufügen, damit es in seinem Kontext zum Erweitern seines Eltern-CDOs verwendet werden kann.
18. Klicken Sie auf DB aktualisieren. In einem Dialogfeld werden Sie aufgefordert, das Speichern der aktuellen MDB-Datei und die Aktualisierung der Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) zu bestätigen.
19. Klicken Sie auf Ja. Eine Statusleiste wird am unteren Rand des Fensters angezeigt, um darauf hinzuweisen, dass die Aktualisierung ausgeführt wird. Die Anwendung speichert und aktualisiert die Datenbank.

Automatisierte Schritte

Die folgenden Definitionen werden erstellt:

• Das CustomerContactsChanges-CDO wird unter "SubentityChanges" hinzugefügt.

Vorgehensweise zum Entfernen eines Unterobjekts

Wenn Sie das Feld im Eltern-CDO entfernen, das Eigentümer des Unterobjekts ist, wird das Unterobjekt nicht entfernt, wenn andere CDOs Referenzen auf dieses Unterobjekt enthalten. Zum Entfernen eines Unterobjekts müssen Sie alle Referenzen darauf entfernen.

Gehen Sie wie in diesem Beispiel beschrieben vor, um das Kundenkontakt-Unterobjekt zu entfernen:

1. Wählen Sie das Customer-CDO aus.
2. Wählen Sie das Feld CustomerContacts aus.
3. Klicken Sie unter dem Feldbereich auf Entfernen (Remove), um das Feld CustomerContacts zu entfernen. Das Feld wird entfernt.
4. Wählen Sie das CustomerContacts-CDO aus.
5. Wählen Sie die Registerkarte Wo genutzt (Where Used) aus.
6. Doppelklicken Sie in der Liste auf CustomerContactsChanges. Der Fokus wird zum CustomerContactsChanges-CDO verschoben.
7. Wählen Sie die Registerkarte Felder (Fields) aus.
8. Wählen Sie das Feld ListItemToChange aus.
9. Klicken Sie auf Überschreibung löschen (Clear Override). Die Referenz auf "CustomerContactsChanges" wird entfernt.
10. Wählen Sie das Feld ObjectToChange aus.
11. Klicken Sie auf Überschreibung löschen (Clear Override). Die Referenz auf "CustomerContacts" wird entfernt.
12. Wählen Sie das CustomerContactsChanges-CDO aus.
13. Klicken Sie unter dem Auswahlbaum auf Entfernen, um das CustomerContactsChanges-CDO zu entfernen.
14. Wählen Sie das CustomerContacts-CDO aus.
15. Klicken Sie unter dem Auswahlbaum auf Entfernen, um das CustomerContacts-CDO zu entfernen. Dadurch werden das CustomerContacts-CDO und die entsprechende Tabelle aus der Tabellendefinition gelöscht.
16. Klicken Sie auf DB aktualisieren. In einem Dialogfeld werden Sie aufgefordert, das Speichern der aktuellen MDB-Datei und die Aktualisierung der Datenbank gemäß den Einstellungen im Dialogfeld "Voreinstellungen" (Preferences) zu bestätigen.
17. Klicken Sie auf Ja. Eine Statusleiste wird am unteren Rand des Fensters angezeigt, um darauf hinzuweisen, dass die Aktualisierung ausgeführt wird. Die Anwendung speichert und aktualisiert die Datenbank.
Hinweis: Weitere Informationen zu den im Dialogfeld "Voreinstellungen" (Preferences) verfügbaren Einstellungen finden Sie unter "Dialogfeld "Voreinstellungen" (Preferences), Registerkarte "DB-Aktualisierung" (DB Update)". Weitere Informationen zum Aktualisieren der Datenbank finden Sie in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration oder der Opcenter Execution Core-Anleitung zur Systemadministration.
