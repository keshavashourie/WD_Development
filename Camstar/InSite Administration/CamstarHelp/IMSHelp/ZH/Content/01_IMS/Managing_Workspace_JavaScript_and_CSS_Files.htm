管理工作区 JavaScript 和 CSS 文件

可以为每个活动工作区存储自定义 JavaScript 和 CSS 文件，这允许将自定义代码扩展到顺序较高的工作区。应用程序通过每个活动工作区（不包括基础 csi 工作区）进行工作，并在绑定更高的活动工作区功能之前在代码文件中搜索重复函数的文件。

管理工作区 JavaScript 和 CSS 文件

在存储自定义工作区 JavaScript 和 CSS 文件时，必须在预期的文件路径中添加工作区子文件夹。工作区子文件夹必须命名为关联工作区的代码。 例如，与工作区 200 关联的子文件夹必须命名为“200”。

工作区子文件夹的预期文件路径为：

• Camstar\Camstar Portal\Scripts\User for JavaScript files。
• Camstar\Camstar Portal\Themes\User for CSS files。

每个工作区子文件夹中只能存在一个用户代码文件。您必须遵循命名约定“WorkspaceCode.js”和“WorkspaceCode.css”，其中“WorkspaceCode”是工作区的代码，例如“180”或“190”。例如，“200.css”是 CSS 文件的接受文件名，必须放在 Camstar\Camstar Portal\Themes\User 文件夹的“200”子文件夹中。

服务器启动时将发生自定义代码文件的绑定。Siemens 建议在添加或更新工作区代码文件时停止然后重新启动服务器。

管理工作区 JavaScript 和 CSS 文件示例

在此示例中，工作区 190 和 200 当前处于活动状态。您有这两个工作区的 JavaScript 文件和 200 工作区的 CSS 文件。以下步骤概述了存储这些文件的正确方法：

1. 导航至文件路径 Camstar\Camstar Portal\Scripts\User。
2. 创建一个名为 190 的新文件夹。
3. 创建另一个名为 200 的新文件夹。
4. 将工作区 190 的 JavaScript 文件重命名为 190.js，然后将其复制到新创建的 190 文件夹中。
5. 将工作区 200 的 JavaScript 文件重命名为 200.js，然后将其复制到新创建的 200 文件夹中。
6. 导航至文件路径 Camstar\Camstar Portal\Themes\User。
7. 创建一个名为 200 的新文件夹。
8. 将工作区 200 的 CSS 文件重命名为 200.css，然后将其复制到新创建的 200 文件夹中。

应用程序在服务器启动时捆绑存储文件。在此示例中，应用程序捆绑 200.css 文件，并在 190.js 和 200.js 文件夹中查找重复功能，然后在 190.js 文件上捆绑在 200.js 文件中找到的重复功能，因为 200.js 文件与最高的活动工作区相关联。
