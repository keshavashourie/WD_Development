Konfigurieren von Opcenter EX MDD oder Opcenter EX CR

Der Konfigurationsbereich wird verwendet, um verschiedene Systemparameter anzugeben.

Beim Konfigurieren von Opcenter EX MDD oder Opcenter EX CR

Voraussetzungen

Dies sind Voraussetzungen zum Konfigurieren von Opcenter EX MDD oder Opcenter EX CR:

• Sie müssen die Metadaten-Datenbank festlegen, bevor Sie die Standardsicherheitsdomäne angeben können.
• Sie müssen eine Standardsicherheitsdomäne im Konfigurationsbereich festlegen, bevor Sie den Anwendungsserver starten können.
• Sie müssen auf der Registerkarte "SSO" eine Single Sign-On-Methode für die Anmeldung angeben.
• Sie müssen einen Benutzernamen und ein Kennwort für REST API angeben, wenn Sie die REST APIs verwenden.

Datenbankverbindungen

Datenbankverbindungen werden im Anwendungsserver zwischengespeichert. Die Verbindungen im Verbindungspool werden nicht zurück in den Pool freigegeben, solange der Server die Verbindungen aktiv nutzt. Die einzige Möglichkeit zum Bereinigen der Verbindungen besteht darin, die Anwendungsserver anzuhalten und wieder zu starten.

Die Bereinigung von nicht genutzten Datenbankverbindungen wird über zwei Felder in der InSite-SiteInfo-Tabelle und in SiteInfo.mdb gesteuert. Informationen zu diesen Feldern werden im Konfigurationsbereich eingegeben:

• Bereinigen von nicht genutzten Verbindungen aktivieren

Dieses Kontrollkästchen ermöglicht ein Protokollieren der Verbindungsbereinigung im Ereignisprotokoll.

• Verbindungen schließen, die nicht genutzt wurden seit

Das Feld füllt den Wert für LogDBConnectionCleanup in der Tabelle. Der Wert wird in Sekunden angegeben und bestimmt die Zeit, die eine Verbindung im Leerlauf sein muss, bevor sie geschlossen wird.

Hinweis: Möglicherweise möchten Sie von Anfang an die Protokollierung aktivieren, um sicherzugehen, dass Verbindungen bereinigt werden. Sie sollten diesen Wert löschen, um die Protokollierung zu deaktivieren, sobald die Datenbank in Produktion geht.

Benachrichtigungsserver

Der Benachrichtigungsserver ist ein eigenständiger .NET-basierter Dienst. Er verwendet seine eigene Konfigurationsdatei, um eine Verbindung mit der Datenbank herzustellen, aus der E-Mails abgefragt werden.

Erstellte E-Mail-Nachrichten werden in einer Tabelle der Datenbank mit den SMTP-Server-Verbindungsinformationen gespeichert. Der Benachrichtigungsserver ruft neue E-Mail-Nachrichten aus dieser Tabelle ab und sendet sie anschließend an den SMTP-Server, der sie dann versendet.

Der Benachrichtigungsserver hat auch einen Wiederholungsmechanismus für Nachrichten, die nicht erfolgreich gesendet werden konnten. Wenn mehrere Benachrichtigungsserver auf dieselbe Datenbank zugreifen, ist ein Zeilensperrmechanismus verfügbar, der gewährleistet, dass die E-Mail-Nachricht nur von einem einzigen Server bearbeitet wird.

Der E-Mail-Benachrichtigungsdienst verwendet den Benachrichtigungsserver, um die E-Mails an den SMTP-Server zu senden. Die Konfigurationseinstellungen in Management Studio enthalten die Einstellungen für den Benachrichtigungsserver. Sie können die Konfigurationseinstellungen ändern, um die Funktionsweise des Benachrichtigungsservers zu ändern.

Hinweis: Wenn Sie den Parameter "Sessions" in Ihrer Oracle-Datenbank einstellen, sollten Sie daran denken, dass der Benachrichtigungsserver etwa 100 Verbindungen zur Datenbank benötigt. Weitere Informationen zum Sitzungswert finden Sie unter "Beispielparameter für die Datenbankerstellung" in der Opcenter Execution Medical Device and Diagnostics-Anleitung zur Systemadministration oder Opcenter Execution Core-Anleitung zur Systemadministration.

Notwendige Berechtigungen für ein lokales Konto, um den Benachrichtigungsserverdienst auszuführen

Wenn der Benachrichtigungsserver unter einem bestimmten Benutzerkonto ausgeführt wird, muss dieser Benutzer normalerweise ein Mitglied der lokalen Gruppe der Administratoren sein. Wird an Ihrem Standort aber ein lokales Konto eines Nicht-Administrators verwendet, um den Benachrichtigungsserverdienst auszuführen, muss ein Systemadministrator folgende Berechtigungen gewähren:

• Für das lokale Konto, das kein Administratorkonto ist, Lese-/Schreibzugriff auf die .config-Dateien in dem Verzeichnis, in dem sich die Anwendungen befinden.
• Für die IIS-Benutzergruppe Lesezugriff auf dieselben .config-Dateien.

Dies gilt auch für den Sicherheitsserver.

Application Server in einem NLB-Cluster

Wenn sich Ihre Anwendungsserver in einem NLB-Cluster(Netzwerklastenausgleich) befinden und Sie mehr als zwei Knoten haben, ist es ratsam, den Benachrichtigungsserver auf genau zwei dieser Knoten auszuführen. Der Dienst fragt die Datenbank standardmäßig jede Sekunde auf neue E-Mails ab, die gesendet werden müssen. Konflikte können entstehen, wenn mehrere Server dieselbe Tabelle häufig abfragen. Zusätzlich erstellt jede Benachrichtigungsserverinstanz etwa 100 Verbindungen zur Datenbank.

Konfigurieren der E-Mail-Benachrichtigungseinstellungen für Qualitätsdatensätze

Im Thema "Konfigurieren von Umlaufbestands-E-Mails" in der Anleitung zur Systemadministration wird erläutert, wie Opcenter EX MDD oder Opcenter EX CR so konfiguriert wird, dass Wartungs- und Umlaufbestands-E-Mails gesendet werden, wenn ein Bediener eine Transaktion für eine Ressource durchgeführt hat. Dies ist eine gesonderte Funktion von der E-Mail-Benachrichtigungsfunktion für Qualitätsdatensätze.

Konfigurieren von Lizenzablaufbenachrichtigungen

Opcenter EX MDD und Opcenter EX CR bieten die Möglichkeit, bestimmte Empfänger automatisch zu benachrichtigen, wenn ihre Lizenz abläuft. Sie können auch Management Studio verwenden, um Einstellungen so zu konfigurieren, dass in regelmäßigen Abständen E-Mail-Nachrichten gesendet werden, bevor die Lizenz abläuft. Es gibt zwei Intervalle, die Sie einstellen können:

• Warnungszeitraum
• Kritischer Zeitraum

Die Anwendung sendet eine E-Mail-Benachrichtigung für einen Zeitraum: einmal für den Warnungszeitraum und einmal für den kritischen Zeitraum. Sollten Sie z. B. den Warnungszeitraum auf 30 Tage und den kritischen Zeitraum auf 15 Tage einstellen, erhalten Sie 30 Tage vor Ablauf Ihrer Lizenz eine Warnung und 15 Tage vor Ablauf Ihrer Lizenz eine kritische Benachrichtigung. Sie erhalten auch eine E-Mail, wenn die Lizenz abläuft.

Beim Konfigurieren von Inline SPC

Rufen Sie die Registerkarte "Lizenz" auf und klicken Sie auf Speichern, um die Inline SPC-Lizenz zu aktivieren und den Flexlm-Lizenzserver mit dem Inline SPC-Wert in der Appsettings-Datei zu aktualisieren. Inline SPC bietet die Möglichkeit, angezeigte Charts automatisch in einem Dateipfad auf Ihrem Server zu speichern. Greifen Sie auf die Registerkarte "Inline SPC" zu, um den Standarddateipfad zu konfigurieren.

Hinweis: Die Registerkarte "Inline SPC" wird nur angezeigt, wenn Inline SPC installiert ist. Weitere Informationen finden Sie in der Opcenter Execution Medical Device and Diagnostics-Installationsanleitung und der Opcenter Execution Core-Installationsanleitung.

Beim Konfigurieren von Lizenzablaufbenachrichtigungen

Sie können den Warnungszeitraum auf null festlegen, um E-Mail-Benachrichtigungen für den Warnungszeitraum zu deaktivieren.

Sie können den kritischen Zeitraum auf null festlegen, um E-Mail-Benachrichtigungen für den kritischen Zeitraum zu deaktivieren.

Hinweis: Die höchste Anzahl an Tagen, die Sie in die Felder "Warnungszeitraum" und "Kritischer Zeitraum" eingeben können, ist 365.

Trennen Sie die E-Mail-Adressen der Empfänger mit einem Semikolon. Es ist mindestens eine Adresse erforderlich.

Das Ablaufdatum des Lizenzzeitraums wird zurückgesetzt, wenn die Lizenz erneuert wird.

Die Betreff-Zeile und der Text der E-Mail-Benachrichtigungen sind systemdefiniert.

Sie müssen einen SMTP-Transport für den Exchange-Server und einen neuen Standort festlegen, der den SMTP-Transport verwendet. Der Standortname muss identisch mit dem Standortnamen sein, der in Management Studio verwendet wird. SMTP-Transporte und Standorte werden in der Modellierung definiert.

Zeitlich begrenzte Lizenzen werden im Notfall durch den Produkt-Support ausgegeben. Wenn Sie z. B. zusätzliche Lizenzen bestellen, kann Siemens Ihnen zeitlich begrenzte Lizenzen zur Verfügung stellen, bis Ihre Bestellung bearbeitet wurde.

Hinweis: Die Anwendung fügt die Lizenzserver-Portnummer (28000/29000) als Präfix zu den Lizenzserverfeldern hinzu, nachdem die Konfigurationsinformationen gespeichert wurden.

Lizenzierungsfehler

Bestimmte An- und Abmeldeverfahren können die Anzahl verfügbarer Lizenzen beeinflussen. Befolgen Sie bei der Anmeldung beim Portal im Webbrowser diese grundlegende Vorgehensweise, um Fehler zu vermeiden:

1. Starten Sie eine neue Sitzung Ihres Webbrowsers.
2. Anmelden im Portal.

Weitere Informationen zum Anmelden finden Sie im Opcenter Execution Medical Device and Diagnostics-Benutzerhandbuch – Erste Schritte oder im Opcenter Execution Core-Benutzerhandbuch – Erste Schritte.

Das Starten des Browsers mit einer dieser Methoden führt zu einem Lizenzfehler. Starten Sie Ihren Browser nicht mit einer der folgenden Vorgehensweisen:

• Starten einer neuen Browsersitzung über die EXE-Datei (z. B. Auswahl im Startmenü)
• Öffnen eines neuen Fensters in einer bestehenden Browsersitzung
• Öffnen einer neuen Registerkarte in einer vorhandenen Browsersitzung

Siemens unterstützt nicht mehrere Instanzen der Anwendung im selben Browser.

Die Installation einer neuen Lizenz ohne Neustart der produktbezogenen Anwendungspools und Dienste kann die in Management Studio angezeigten Lizenzinformationen beeinflussen. Weitere Informationen zum Installieren neuer Lizenzdateien finden Sie in der Opcenter Execution Medical Device and Diagnostics-Installationsanleitung oder in der Opcenter Execution Core-Installationsanleitung.

Single Sign-On

Durch Verwenden des Single Sign-On- Authentifizierungsansatzes können Benutzer auf mehrere lokale oder cloudbasierte Anwendungen von Siemens zugreifen, indem sie sich bei einer der Anwendungen anmelden. Der Single Sign-On-Ansatz bietet eine einzige Identitäts- und Zugriffsverwaltungslösung für das gesamte Ökosystem der Siemens-Anwendungen und -Dienste.

Sie müssen diese Aufgaben ausführen, um Single Sign-On zu aktivieren:

• Konfigurieren Sie Single Sign-On in Management Studio,
• legen Sie den Single Sign-On-Proxydienst auf "Automatisch" fest und
• starten Sie den Single Sign-On-Proxydienst.

Single Sign-On ist im Desktopmodus verfügbar und wird im mobilen Modus nicht unterstützt.

Folgende Anmeldeoptionen stehen zur Verfügung:

• Standard – Die Standardanmeldung bei der Implementierung ist die Anmeldung ohne Single Sign-On. Sie können die vorhandene Anmeldefunktion weiterhin verwenden, indem Sie Ihren Benutzernamen und Ihr Kennwort eingeben.
• SAM – Der Authentifizierungsmechanismus der Sicherheits- und Zugriffsverwaltung (SAM) überprüft die Autorisierung, die von Siemens-Diensten für den Zugriff auf andere Dienste und Ressourcen von Siemens erforderlich ist. Für alle Konto-IDs und -dienste wird ein eindeutiger Zugriffsschlüssel (Webkey) erstellt und der SAM-Dienst überprüft gegebenenfalls die Autorisierung für den Zugriff auf die anderen Dienste.
• SAML – Die Authentifizierung über den SAML-Adapter wird auf die Azure Active Directory (Azure AD) ausgeweitet.
Weitere Informationen finden Sie unter "Vorgehensweise zum Erstellen einer SAML-Anwendung im ID-Portal (Azure AD)".
Weitere Informationen zu dieser Option finden Sie in der Dokumentation zu Azure AD.
• Windows-Authentifizierung – Authentifizierung mit Ihren Windows-Anmeldeinformationen.
• Smartcard – Authentifizierung mit Smartcards.
Hinweis: Die Authentifizierung der Sicherheits- und Zugriffsverwaltung (SAM) ist die einzige Single Sign-On-Authentifizierungsmethode, die für cloudbasierte Dienste von Siemens verfügbar ist.

Cross-Origin Resource Sharing (CORS)

CORS ist ein durch die Fetch-API-Spezifikation definierter Mechanismus, mit dem die REST API angeben kann, welche Ursprünge auf ihre Ressourcen zugreifen dürfen. Dies ist für die Websicherheit unerlässlich, da Browser aus Sicherheitsgründen standardmäßig Anforderungen von verschiedenen Quellen blockieren.

Nur Anforderungen von Ursprüngen, die Sie angeben (z. B. https://example.com), dürfen auf die API zugreifen. Wenn Sie versuchen, von einem anderen Ursprung aus auf die API zuzugreifen, wird die Anforderung aufgrund der CORS-Richtlinie abgelehnt. Wenn eine Anwendung von einem nicht genehmigten Ursprung versucht, auf die API zuzugreifen, erhält sie eine CORS-Fehlerantwort. Dadurch wird verhindert, dass nicht autorisierte Domänen Ihre API verwenden.

Wenn Sie auf der Registerkarte CORS einen Ursprung angeben und auf "Speichern" klicken, aktualisiert die Anwendung die appsettings.json Datei für jeden REST-API-Dienst (Modellierung, Fertigung, Abfrage und Beschriftungen). Die Anwendung schreibt die Informationen in den Abschnitt "AllowedOrigins":

"AllowedOrigins": [

"https://example.com"

]

Hinweis: Wenn Sie Informationen manuell in den Abschnitt "AllowedOrigins" einer der appsettings.json-Dateien eingegeben haben, werden diese durch alle Ursprünge überschrieben, die Sie in Management Studio angegeben haben.

Von einer Webanwendung aus, die in https://example.com gehostet wird, ist z. B. eine GET-Anforderung an https://{server}/modeling erfolgreich, wenn Sie den Ursprung in der Liste der zulässigen Elemente (Whitelist) auf der Registerkarte CORS angegeben haben. Eine Anforderung von einem nicht autorisierten Ursprung, z. B. https://unauthorized.com, wird standardmäßig entsprechend der CORS-Richtlinie blockiert.

Beispiel: Konfigurieren von Single Sign-On für eine SAML-Anwendung, die in Azure AD erstellt wurde

Gehen Sie folgendermaßen vor, um Single Sign-On für eine SAML-Anwendung in Azure AD zu konfigurieren.

Hinweis: Beachten Sie, dass die Konfiguration von Single Sign-On bestimmte URLs und SAML-spezifische Überlegungen erfordert, die in den Metadaten der von Ihnen erstellten SAML-Anwendung verfügbar sind. Für bestimmte Schritte wurden die erforderlichen URL-Details hartcodiert und müssen wie in diesem Dokument im Abschnitt Felddefinitionen der Registerkarte "SSO" angegeben eingegeben werden.

1. Wählen Sie Single Sign-On auf der Übersichtsseite der SAML-Anwendung aus.
2. Klicken Sie in der Tabelle "SAML-Basiskonfiguration" auf "Bearbeiten" . Die folgenden beiden Details müssen manuell eingegeben werden
1) Entity-ID – Die SAML-Entity-ID ist ein eindeutiger Name. Geben Sie dieselben Entity-ID-Details ein, die in Management Studio > Enitity-ID/Aussteller in der Tabelle "SAML-Basiskonfiguration" bereitgestellt wurden.
2) Assert-URL – Geben Sie den Domänennamen und den Servernamen im Standardformat dieses Dokuments an: https://{{mydomain}}/IDPAgent/api/v1/sso-service-provider/saml-assert-consumer-service in Management Studio > URL voraussetzen und in der Tabelle "SAML-Basiskonfiguration" unter "Antwort-URL" (Assertionsverbraucherdienst-URL).

Die in der SAML-Anwendung und im Management Studio-Portal bereitgestellte Assert-URL sollte identisch sein.

3) Anmelde-URL (optional) – Obwohl dies ein optionales Feld ist, ist dieses Detail erforderlich, um Single Sign-On ordnungsgemäß zu konfigurieren. Geben Sie den Domänennamen zusammen mit "4040" in diesem Format ein: https://mydomain:4040
4) Abmelde-URL (optional) – Dies ist die URL für die Abmeldeantwort. Verwenden Sie die in diesem Dokument angegebene URL https://<mydomain>/IDPAgent/api/v1/sso-service-provider/saml-logout-response.
3. Sobald die Konfigurationen unter "Basis-SAML" abgeschlossen sind, können Sie mit den Konfigurationen unter "Einrichten" (SAML-Anwendung) fortfahren
1) Anmelde-URL – Geben Sie die Anmelde-URL ein, die in der Tabelle "Einrichtung" der SAML-Anwendung in Management Studio > Endpunkt-URL bereitgestellt wird.
2) Abmelde-URL – Geben Sie die Abmelde-URL ein, die in der Tabelle "Einrichten" der SAML-Anwendung in Management Studio > Abmelde-URL angegeben ist.
4. Laden Sie das SAML-Zertifikat von der Azure AD-Website herunter, um das Zertifikat zu überprüfen. Speichern Sie das Zertifikat im bereitgestellten Ordner, z. B. im Pfad: C:\Programme (x86)\Camstar\SSO\IDPAgent\app_data\Certificates. Wenn der Pfad "\app_data\Certificates" nicht vorhanden ist, erstellen Sie den Ordner und speichern Sie das Zertifikat in diesem Ordner.
Der anzugebende Wert "Öffentlicher Schlüssel externer IDP" sollte der relative Pfad sein, z. B.: \app_data\Certificates\name_des_zertifikats.

Nach Abschluss sollten die Konfigurationen in der SAML-Anwendung, die in Azure AD erstellt wurde, wie in der folgenden Abbildung aussehen.

Erstellen der server.key- und server.pem-Dateien

Wenn Sie nicht über gültige Zertifikate verfügen, treten möglicherweise Fehler wie in der folgenden Abbildung angezeigt auf.

Um die server.key-Dateien und die server.pem-Datei zu erstellen, folgen Sie den Anweisungen in den Abschnitten Erstellen der server.key- und server.pem-Dateien und Definieren der server.key- und server.pem-Dateien in camstarproxy.com

1. Öffnen Sie die Eingabeaufforderung.
3) Suchen Sie in der Windows-Suche nach der Eingabeaufforderung.
4) Geben Sie "OpenSSL" ein, um zu überprüfen, ob OpenSSL installiert ist oder nicht.
2. Wenn der Befehl "OpenSSL" nicht funktioniert, müssen Sie OpenSSL installieren.
3. Rufen Sie die PFX-Datei ab:
1) Sie benötigen die PFX-Datei vom Servercomputer. Jeder Servercomputer muss über eine PFX für HTTPS-Kommunikation verfügen. google.com verfügt z. B. über eine eigene PFX (wobei google.com der Servername oder der vollqualifizierte Domänenname ist).
2) In Ihrem Fall lautet der Servername <Vollqualifizierter Domänen-/Servername>, und Sie sollten über eine PFX-Datei von Ihrer Zertifizierungsstelle verfügen.
4. Konvertieren von PFX-Dateien in PEM- und KEY-Dateien:
1) Nachdem Sie die PFX-Datei erhalten haben, geben Sie das Kennwort für die Datei ein, um die server.key- und server.pem-Dateien zu erstellen.
2) Navigieren Sie über die Eingabeaufforderung zum folgenden Ordner:
C:\Programme (x86)\Camstar\SSO\SSOProxy

Definieren der server.key- und server.pem-Dateien in camstarproxy.com

1. Suchen Sie in der Windows-Suche nach CMD.
1) Führen Sie den folgenden Befehl aus: CD C:\Programme (x86)\Camstar\SSO\SSOProxy.
2) Kopieren Sie die PFX-Datei und fügen Sie sie in diesen Ordner ein.
2. Führen Sie die OpenSSL-Befehle aus:
1) Führen Sie in der Eingabeaufforderung die folgenden Befehle aus:
a) Zum Erstellen der server.key-Datei (ersetzen Sie "your_server_certificate_name.pfx" durch Ihren tatsächlichen PFX-Dateinamen) - openssl pkcs12 -in your_server_certificate_name.pfx -nocerts -out server.key -nodes.
b) Zum Erstellen der Datei server.pem (ersetzen Sie "your_server_certificate_name.pfx" durch Ihren tatsächlichen PFX-Dateinamen) - openssl pkcs12 -in your_server_certificate_name.pfx -clcerts -nokeys -out server.pem.
2) Sie werden jedes Mal aufgefordert, das Kennwort für die PFX-Datei einzugeben.
3. Sichern und ersetzen Sie Dateien:
1) Nachdem Sie die server.key- und server.pem-Dateien erstellt haben, kopieren Sie sie in C:\Programme (x86)\Camstar\SSO\SSOProxy\server.
2) Sichern Sie die älteren Dateien, bevor Sie sie ersetzen.
4. Starten Sie den Dienst neu.
1) Schließen Sie alle Browserfenster.
2) Starten Sie den Single Sign-On-Proxydienst über die Windows-Dienste neu.
3) Öffnen Sie ein Inkognito-Browserfenster und dann die URL "https://<vollqualifizierter Domänenname/Servername>".

Felddefinitionen der Registerkarte "REST API"

Diese Tabelle definiert die Felder der Registerkarte "REST API".

Feld

Definition

Typ

Systemanmeldeinformationen

Benutzername

Benutzername, der mit allen REST API-Diensten verwendet werden soll.

Erforderlich

Kennwort

Kennwort, das mit allen REST API-Diensten verwendet werden soll.

Erforderlich

Protokollkonfiguration

Protokollpfad

Gibt den Ordner an, in dem Protokolldateien gespeichert werden. Er ist standardmäßig auf "C:\Temp\" festgelegt.

Erforderlich

XML-Protokolle

Kontrollkästchen, das angibt, ob grundlegende XML-Protokolle der verarbeiteten Daten, die erfolgreich an den Anwendungsserver gesendet wurden, und ihrer Antworten erstellt werden. Wenn dieses Kontrollkästchen aktiviert ist, werden für jede verarbeitete Anforderung zwei XML-Dateien im angegebenen Verzeichnis erstellt: eine für die ausgehende XML-Anforderung und eine für die eingehende XML-Antwort. Ist standardmäßig nicht aktiviert.

Optional

Transaktionsprotokolle

Kontrollkästchen, das angibt, ob detaillierte Informationen zu allen einzelnen API-Transaktionen (Erfolg und Ausnahme) protokolliert werden. Die Informationen umfassen Zeitstempel sowie Anforderungs- und Antwortdaten. Diese Informationen sind nützlich, um Ausführungsschritte zu verfolgen und auf REST-API-Anforderungsebene zu debuggen. Ist standardmäßig nicht aktiviert.

Optional

Fehlerprotokolle

Kontrollkästchen, das angibt, ob Protokolle von Transaktionsdaten für fehlgeschlagene API-Anforderungen aktiviert sind. Dieses Feld ist standardmäßig aktiviert.

Optional
Hinweis: REST API-Anmeldeinformationen sind erforderlich, wenn Sie die REST API-Dienste verwenden, jedoch nicht für andere Management Studio-Konfigurationen.
Hinweis: Weitere Informationen zum Aktivieren von Protokollen in der Datei "appsettings.json" finden Sie in der Opcenter Execution Medical Device and Diagnostics Technical Reference: REST API oder der Opcenter Execution Core Technical Reference: REST API.

Vorgehensweise zum Konfigurieren von Opcenter EX MDD oder Opcenter EX CR

Gehen Sie folgendermaßen vor, um Opcenter EX MDD oder Opcenter EX CR zu konfigurieren:

1. Klicken Sie auf Start > Opcenter Execution MDD > Management Studio. Das Fenster "Management Studio" wird angezeigt.

Oder

Klicken Sie auf Start > Opcenter Execution Core > Management Studio. Das Fenster "Management Studio" wird angezeigt.

2. Erweitern Sie den Ordner Konfiguration in der Struktur "Standorte" und wählen Sie den Knoten Konfiguration aus. Die Standortkonfigurationsinformationen werden im rechten Bereich angezeigt.
3. Klicken Sie auf die Registerkarte Sicherheit.
4. Geben Sie die Standarddomäne ein.
5. Klicken Sie auf Registerkarte "SSO".
6. Wählen Sie die Authentifizierungsmethode aus den Optionen in der Liste Anmelden über aus.
7. Geben Sie die Details basierend auf der ausgewählten SSO-Methode ein.
Hinweis: Sie können Konfigurationsdetails für alle vier Single Sign-On-Authentifizierungsmodi hinzufügen und speichern. Als Authentifizierungsmethode angewendet wird aber die ausgewählte und gespeicherte Option (Anmelden über).
8. Klicken Sie auf die Registerkarte REST API, wenn Sie die REST APIs verwenden.
9. Geben Sie den Benutzernamen und das Kennwort ein, die mit REST API verwendet werden sollen. Management Studio verschlüsselt das eingegebene Kennwort und übergibt dann beim Speichern den Benutzernamen und das verschlüsselte Kennwort an jede der Dateien appsettings.json.
10. Klicken Sie auf die Registerkarte CORS, wenn Sie zulässige Ursprünge festlegen müssen.
11. Klicken Sie in eine neue Zeile in der Liste "Ursprung" und geben Sie die HTTP-Adresse eines Ursprungs ein, den Sie zulassen möchten.
12. Wiederholen Sie Schritt 11, um bei Bedarf einen weiteren Ursprung hinzuzufügen.
13. Geben Sie entsprechend Ihren Geschäftsanforderungen optionale Informationen ein. Informationen zu den optionalen Feldern finden Sie in der Tabelle mit den Felddefinition.
14. Klicken Sie auf Speichern. Management Studio zeigt eine Erfolgsmeldung an.
