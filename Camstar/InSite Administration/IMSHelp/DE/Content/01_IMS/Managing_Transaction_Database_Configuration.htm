Verwalten der Konfiguration der Transaktionsdatenbank

Die Transaktionsdatenbank ist erforderlich. Sie können die Transaktionsdatenbank nach der Metadaten-Datenbank erstellen.

Konfigurationsinformationen der Transaktionsdatenbank

Konfigurationsinformationen für die Transaktionsdatenbank werden im rechten Bereich des Management Studio-Fensters angezeigt, wenn Sie die Transaktionsdatenbank hinzufügen oder auswählen.

Im Management Studio-Fenster wird ein Menü "Datenbanken" angezeigt, wenn der Ordner "Datenbanken" oder ein Datenbankknoten ausgewählt wird. Weitere Informationen zum Menü für Datenbanken finden Sie unter "Menü "Datenbanken"".

Schema

Der Anmeldename für ihre Transaktionsdatenbank. Für diesen Eintrag wird zwischen Groß- und Kleinschreibung unterschieden. Ihr Eintrag muss mit dem Wert identisch sein, den Sie im DBMS eingegeben haben.

Kennwort

Das Kennwort für Ihren Transaktionsdatenbankbenutzer. Für diesen Wert wird zwischen Groß- und Kleinschreibung unterschieden.

Der Wert, den Sie eingeben, wird aus Sicherheitsgründen verschlüsselt. Ihr Eintrag muss mit dem Wert identisch sein, den Sie im DBMS eingegeben haben.

Erforderlich

Datenbankverkehr verschlüsseln

Verschlüsselt den Datenverkehr zwischen der Datenbank und dem Opcenter-Anwendungsserver, Security Service, Notification Service und Opcenter Management Studio.

Hinweis: Wenn das Kontrollkästchen aktiviert ist, müssen Sie den Port für den Transaktionsdatenbankport in den verschlüsselten Port ändern, den Sie für verschlüsselten Datenverkehr konfiguriert haben. Der Standard-Port für die Verschlüsselung ist 2484 für Oracle und 1433 für SQL Server.

Optional

Serverzertifikat überprüfen

Kontrollkästchen, das angibt, ob das Serverzertifikat überprüft werden soll. Wenn Sie das Kontrollkästchen "Serverzertifikat überprüfen" aktivieren, führt der Datenbankserver während des TLS-Handshakes eine Überprüfung durch. Die Angabe von "Hostname in Zertifikat überprüfen" und "Hostname in Zertifikat" ist optional, wenn "Serverzertifikat überprüfen" ausgewählt ist. Wenn "Serverzertifikat überprüfen" nicht ausgewählt ist, sind alle Verschlüsselungseinstellungen (Zertifikatspeicherdatei, Hostname in Zertifikat überprüfen und Hostname in Zertifikat) deaktiviert. Das Aktivieren von "Serverzertifikat überprüfen" wird als beste Vorgehensweise betrachtet.

Optional

Verschlüsselungseinstellungen

Zertifikatspeicherdatei

Für SQL Server ist die Zertifikatspeicherdatei nicht mehr erforderlich. Der Wert für die Zertifikatspeicherdatei wird ignoriert, da der Microsoft-Zertifikatspeicher auf dem Opcenter EX MDD- oder CR-Client verwendet wird, um die vertrauenswürdigen Zertifikate der Zertifizierungsstellenkette zu lokalisieren. Weitere Informationen finden Sie unter "Opcenter Execution MDD- oder CR-Clientkonfiguration für SQL Server" im Opcenter Execution Medical Device and Diagnostics-Sicherheitshandbuch und im Opcenter Execution Core-Sicherheitshandbuch.

Für Oracle ist die Zertifikatspeicherdatei nur erforderlich, wenn Sie sich für die Verwendung eines Oracle-Client-Wallets auf dem Opcenter EX MDD- oder CR-Client entschieden haben, der die vertrauenswürdigen Zertifikate der Zertifizierungsstellenkette enthält. In diesem Fall entspricht der Wert für die Zertifikatspeicherdatei dem Pfad und der Datei "cwallet.sso". Andernfalls wird der Microsoft-Zertifikatspeicher auf dem Opcenter EX MDD- oder CR-Client verwendet, um die vertrauenswürdigen Zertifikate der Zertifizierungsstellenkette zu lokalisieren. Weitere Informationen finden Sie unter "Opcenter Execution MDD- oder CR-Clientkonfiguration für Oracle" im Opcenter Execution Medical Device and Diagnostics-Sicherheitshandbuch und im Opcenter Execution Core-Sicherheitshandbuch.

Optional

Hostname in Zertifikat überprüfen

Wenn Sie dieses Kontrollkästchen aktivieren, müssen Sie auch einen Wert für das Feld "Hostname in Zertifikat" angeben. Während des TLS-Handshakes wird das Common Name (CN)-Attribut des Distinguished Name im Datenbankzertifikat mit dem im Feld "Hostname in Zertifikat" angegebenen Wert geprüft, um festzustellen, ob eine Übereinstimmung vorliegt. Bei Oracle werden zusätzliche Zertifikatattribute im Distinguished Name des Datenbankzertifikats auch mit den Zertifikatattributen geprüft, die im Wert für "Hostname in Zertifikat" angegeben sind.

Optional

Hostname in Zertifikat

Legen Sie das Attribut und die Attributwerte im Feld "Hostname in Zertifikat" fest, die mit dem Attribut und den Attributwerten im elektronischen Zertifikat der Datenbank abgeglichen werden sollen, um den Hostnamen im Zertifikat zu validieren.

• Oracle. Bei Oracle muss "Hostname in Zertifikat" mit dem Common Name-Attribut (CN) des Distinguished Name des Datenbankserverzertifikats übereinstimmen. Im Wert "Hostname in Zertifikat" sind möglicherweise zusätzliche Zertifikatattribute erforderlich, wenn der Distinguished Name des Datenbankzertifikats mit zusätzlichen Zertifikatattributen wie Organisation, Organisationseinheit, Ort, Bundesland/Kanton erstellt wurde. Sie müssen diese zusätzlichen Zertifikatattribute zusätzlich zum Attribut für den Common Name im Wert "Hostname in Zertifikat" angeben, wenn diese Attribute im Distinguished Name des Datenbankzertifikats definiert sind. Für jedes Attribut muss die Attributabkürzung, gefolgt von einem Gleichheitszeichen und dem Attributwert im Wert "Hostname in Zertifikat" angegeben sein. Jedes Attribut muss durch ein Komma getrennt werden.

Beispiel für Hostname in Zertifikatwerten in Opcenter EX MDD oder CR Management Studio.
Im Datenbankzertifikat ist nur das Attribut CN definiert:
CN=oramachine12.opac.local


Attribute zusätzlich zum CN-Attribut werden im Datenbankzertifikat definiert:
CN=oramachine12.opac.local, C=US
CN=oramachine12.opac.local, O=APAC, OU=IT,
L = Charlotte, S = North Carolina, C = US


• SQL Server. Bei SQL Server muss "Hostname in Zertifikat" nur mit dem Common Name (CN)-Teil im Distinguished Name des Zertifikats übereinstimmen. Beim Erstellen des Distinguished Name des Datenbankserverzertifikats wurden möglicherweise andere Zertifikatattribute wie Organisation, Organisationseinheit, Ort, Bundesland/Kanton eingegeben. Diese anderen Zertifikatattribute sind nicht erforderlich, wenn Sie den Wert "Hostname im Zertifikat" in Opcenter Management Studio angeben. Sie können jedoch beliebige oder alle Zertifikatattribute angeben.

Beispiel für "Serverzertifikat überprüfen"-Werte in Opcenter Management Studio:

CN=sqlmachine12.opac.local, C=US

CN=sqlmachine12.opac.local

CN=sqlmachine12.opac.local, O=APAC, OU=IT, L=Charlotte, S=North Carolina, C=US

Hinweis: Das Feld ist erforderlich, wenn das Kontrollkästchen "Hostname in Zertifikat" markiert ist.

Erforderlich

Standort-ID

Gesamtzahl der Standorte

Die Anzahl der Standorte, die im Unternehmen enthalten sein sollen. Diese Anzahl bestimmt den Bereich der Identifikatoren (IDs), die Siemens für die Standorte im Unternehmen reserviert.

10 ist ein guter Standardwert für die meisten Siemens-Kunden. Sie sollten die Anzahl von Standorten nach oben abschätzen, um noch Erweiterungsmöglichkeiten zu haben.

Geben Sie z. B. die Anzahl von Standorten + 3 ein, wenn Sie erwarten, mehr als 10 Standorte zu haben.

Wichtig: Diese Anzahl sollte nicht größer als 15 sein. Sollten Sie einen Wert größer als 15 benötigen, wenden Sie sich an den Produkt-Support, um über diesen Wert zu sprechen.

Erforderlich

Standort-ID

Zahl, die einen eindeutigen Identifikator für einen Standort darstellt.

Weisen Sie nicht 0 (Null) zu, weil 0 für die Nutzung durch Siemens reserviert ist. Sobald eine DBID einem Standort zugewiesen wurde, sollten Sie diese nicht erneut verwenden, auch nicht, nachdem der Standort entfernt wurde.

Diese Zahl sollte 15 nicht überschreiten.

Erforderlich

Warnungsschwellenwert

Die Anzahl von verfügbaren Identifikatoren (von über zwei Milliarden möglichen), bei der der Systemadministrator vom System benachrichtigt wird, dass dem System die Identifikatoren ausgehen.

Behalten Sie den Standardwert von 500000 bei.

Vorgehensweise zum Hinzufügen und Konfigurieren einer Transaktionsdatenbank

Gehen Sie folgendermaßen vor, um eine Transaktionsdatenbank hinzuzufügen und zu konfigurieren:

1. Klicken Sie auf Start > Opcenter Execution MDD > Management Studio. Das Fenster "Management Studio" wird angezeigt.

Oder

Klicken Sie auf Start > Opcenter Execution Core > Management Studio. Das Fenster "Management Studio" wird angezeigt.

2. Klicken Sie mit der rechten Maustaste auf den Ordner Datenbanken und wählen Sie Transaktionsdatenbank hinzufügen aus. Ein Transaktionsdatenbanksymbol wird angezeigt und im rechten Bereich werden die Informationen zur Transaktionsdatenbank angezeigt.
3. Informationen, welche Werte Sie in die Felder unter Verbindungsinformationen für Transaktionsdatenbank eingeben müssen, finden Sie in der Tabelle der Felddefinitionen.
4. Klicken Sie auf Verbindung testen. Management Studio zeigt die Meldung "Verbindung hergestellt" an, wenn die Verbindung erfolgreich hergestellt wurde. Andernfalls zeigt die Anwendung eine Fehlermeldung an.
5. Klicken Sie auf OK, um die Meldung zu schließen.
6. Informationen, welche Werte Sie in die Felder unter Standort-ID eingeben müssen, finden Sie in der Tabelle der Felddefinitionen.
7. Klicken Sie auf Speichern. Management Studio zeigt eine Erfolgsmeldung an.
