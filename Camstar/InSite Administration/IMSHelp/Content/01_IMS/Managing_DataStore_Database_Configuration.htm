Managing DataStore Database Configuration

You need to configure a DataStore database only if you will be running DataStore. The Metadata and Transaction databases must be created first. Be sure to add the DataStore Database Configuration to all Application Servers in the environment (Portal and CIO servers).

DataStore Database Configuration Information

Configuration information for the DataStore database appears in the right pane of the Management Studio window when you add or select the DataStore database.

A Databases menu appears on the Management Studio window when the Databases folder or database nodes are selected. Refer to "Databases Menu" for information on the Databases menu.

Note: A warning message pop-up appears when you lower the number of insert tables when the number of insert tables is 3 or greater. Click Yes on the pop-up to close the pop-up and reduce the number of insert tables. Click No to close the pop-up and discard your changes.

A toggle switch appears in the DataStore State field section that displays the current state of your DataStore database and allows you to start and stop your database. The toggle switch has two states:

• Running, where the toggle switch is set to the right option and displays a green circle with the word "on."
• Stopped, where the toggle switch is set to the left option and displays a red circle with the word "off."

A message appears in place of the toggle switch when Management Studio cannot reach the DataStore database. Verify your DataStore database connection information to ensure Management Studio can reach your database.

Note: You can also start and stop your DataStore database from the Databases menu. The toggle switch's state updates to reflect your database's state when you start or stop your database from the Databases menu.

Important Caution

During the Opcenter EX MDD or Opcenter EX CR installation process, several database objects such as tables, links, jobs, and sequences are created. Do not modify any of these objects without first consulting Product Support, as any changes to the configuration of these objects could cause a DataStore failure or data corruption.

Validate Server Certificate

Check box to indicate whether to validate the server certificate. Selecting the Validate Server Certificate check box validates the database server during the TLS handshake. Specifying the option Validate Hostname in Certificate and the option Hostname in Certificate is optional when Validate Server Certificate is selected. If Validate Server Certificate is not selected, all encryption settings (Certificate Store File, Validate Hostname in Certificate, and Hostname in Certificate) are disabled. Selecting the Validate Server Certificate is considered a best practice.

Optional

Encryption Settings

Certificate Store File

For SQL Server, Certificate Store File is no longer required. The Certificate Store File value is ignored as the Microsoft Certificate Store on the Opcenter EX MDD or CR client is used to locate the certificate authority chain trusted certificate or certificates. Refer to the procedure in "Opcenter Execution MDD or CR Client Configuration for SQL Server" in the Opcenter Execution Medical Device and Diagnostics Security Guide or the Opcenter Execution Core Security Guide.

For Oracle, Certificate Store File is only required if you have chosen to use an Oracle Client Wallet on the Opcenter EX MDD or CR client that contains the certificate authority chain trusted certificate or certificates. In this case, the value for Certificate Store File is the path and the cwallet.sso file. Otherwise, the Microsoft Certificate Store on the Opcenter EX MDD or CR client is used to locate the certificate authority chain trusted certificate or certificates. Refer to the procedure in "Opcenter Execution MDD or CR Client Configuration for Oracle" in the Opcenter Execution Medical Device and Diagnostics Security Guide or the Opcenter Execution Core Security Guide. 

Optional

Validate Hostname In Certificate

If you select this check box, you must also specify a value for the Hostname in Certificate field. During the TLS handshake, the common name (CN) attribute of the distinguished name in the database certificate is checked against the value specified in the Hostname in Certificate field to determine if it matches. For Oracle, additional certificate attributes in the database certificate’s distinguished name are also checked against the certificate attributes specified in the value for Hostname in Certificate.

Optional

Hostname in Certificate

Specify attribute and attribute values in the Hostname in Certificate field to be matched against the attribute and attribute values in the database electronic certificate to validate the hostname in certificate.

• Oracle. For Oracle, Hostname in Certificate must match the common name (CN) attribute of the database server certificate distinguished name. Additional certificate attributes may be required in the Hostname in Certificate value if the database certificate distinguished name was generated with additional certificate attributes like Organization, Organizational unit, City/locality, State/province. You must include these additional certificate attributes, in addition to the common name attribute, in the Hostname in Certificate value if these attributes are defined in the database certificate distinguished name. Each attribute must have the attribute abbreviation specified followed by an equal sign and the attribute value in the Hostname in Certificate value. Each attribute must be separated by a comma.

Example of Hostname in Certificate values in Opcenter EX MDD or CR Management Studio:
Only the CN attribute is defined in the database certificate:
CN=oramachine12.opac.local

Attributes in addition to the CN attribute are defined in the database certificate:
CN=oramachine12.opac.local, C=USCN=oramachine12.opac.local, O=APAC, OU=IT,L=Charlotte, S=North Carolina, C=US

Required

• SQL Server. For SQL Server, Hostname in Certificate must match only the common name (CN) portion in the certificate distinguished name. Other certificate attributes like Organization, Organizational unit, City/locality, State/province may have been entered when the database server certificate distinguished name was generated. These other certificate attributes are not required when specifying the Hostname in Certificate value in Management Studio, but you can specify any or all of them if you like.

Example of Validate Server Certificate values in Management Studio:

CN=sqlmachine12.opac.local, C=US

CN=sqlmachine12.opac.local

CN=sqlmachine12.opac.local, O=APAC, OU=IT, L=Charlotte, S=North Carolina, C=US

Note: The field is required if the Hostname in Certificate check box is marked.

 

DataStore State

Contains a toggle switch with green "on" and red "off" options that display the current state of your DataStore database and allow you to start or stop your database.

Note: A message appears in place of the toggle switch when Management Studio cannot reach the DataStore database. Verify your DataStore database connection information to ensure Management Studio can reach your database.

DataStore Configuration

Cleanup Batch Size (1-50000)

Number of Opcenter EX MDD or Opcenter EX CR transactions that are removed in a single database commit cycle if the number of processed Opcenter EX MDD or Opcenter EX CR transactions in the queue tables on the Transaction (Production) database exceeds this number. The default value is 5000.

Required

Number of Insert Tables (2-8)

Number from 2 through 8 for the number of insert tables. The default value is 2.

Required

Commit Batch Size (0-1000)

Number of Opcenter EX MDD or Opcenter EX CR transactions to batch in a single commit cycle while there are Opcenter EX MDD or Opcenter EX CR transactions to be processed. This only applies to Oracle databases. A value of 0 means that everyOpcenter EX MDD or Opcenter EX CR transaction will be committed in a single batch cycle and no batching of Opcenter EX MDD or Opcenter EX CR transactions will be done. The default value is 0 for SQL Server and 100 for Oracle.

Note: This field is disabled and displays a value 0 if your DataStore database type is SQL Server. Switching your server type back to Oracle displays the original value you set.

Required

Log Level Detail

Log Level Detail determines the granularity of log messages logged to the DataStoreLog tables. Valid values are Critical Errors, Min Detail, and Max Detail. The default value is Critical Errors.

Required

Sleep Time Between Polling (2-60)

Number of seconds the DataStore waits between reading the queue tables on the Transaction (Production) database. Valid values are 2-60. The default value is 2.

Required

Log Retention Duration

Amount of time that data is retained in the DataStoreErrors and DataStoreLog tables. The default value is 6 months. Valid values are Indefinite, 1 Month, 3 Months, 6 Months, 9 Months, 1 Year, 2 Years, and 3 Years.

Data is purged from the DataStoreErrors and DataStoreLog table that is older than the value specified as the Log Retention Duration.

Required

Retry Attempts (1-100)

Number of attempts for the DataStore to resolve out of sync conditions such as uncommitted Opcenter EX MDD or Opcenter EX CR transactions in the Transaction (Production) database or transaction sequence gaps in the DataStore database. When the Retry Attempts value is exceeded with the out of sync condition not resolved, the DataStore stops. Valid values are 1-100. The default value is 2.

Required

Verify DB Host

Flag with valid values of Yes or No. The default value is No if the DataStore is on SQL Server and Yes if the DataStore is on Oracle.

This flag determines if a comparison is done to verify that the DataStore metadata in the DataStore instance matches the DataStore executing environment, and that the DataStore and OLTP metadata in the OLTP instance matches DataStore and OLTP metadata in the DataStore instance.

Required

E-mail Management

Recipient E-mail

E-mail address or list of e-mail addresses for the recipients of the DataStore e-mail alerts to notify the recipients if the DataStore is stopped or started. For Oracle, separate e-mail addresses with a comma. For SQL Server, separate e-mail addresses with a semicolon.

Optional

Sender E-mail

E-mail address of the sender of the DataStore e-mail alerts to notify the recipients if the DataStore is stopped or started. This is commonly set to a no reply e-mail address like no-reply_DataStore@domain.com.

Optional

How to Add and Configure a DataStore Database

Follow these steps to add and configure a DataStore database:

1. Click Start > Opcenter Execution MDD > Management Studio. The Management Studio window appears.

Or

Click Start > Opcenter Execution Core > Management Studio. The Management Studio window appears.

2. Right-click the Databases folder and select Add DataStore Database. A DataStore Database icon appears and the DataStore Database Configuration information appears in the right pane.
3. Refer to the field definitions table for field entry information.
4. Click Test Connect. Management Studio displays a “Connection Established” message if the connection is successfully established. Otherwise, the application displays an error message.
5. Click OK to close the message.
6. Click Save. Management Studio displays a success message.
