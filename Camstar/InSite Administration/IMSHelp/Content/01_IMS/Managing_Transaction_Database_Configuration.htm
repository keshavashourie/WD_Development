Managing Transaction Database Configuration

The Transaction database is required. You can create the Transaction database after creating the metadata database.

Transaction Database Configuration Information

Configuration information for the Transaction database appears in the right pane of the Management Studio window when you add or select the Transaction database.

A Databases menu appears on the Management Studio window when the Databases folder or database nodes are selected. Refer to "Databases Menu" for information on the Databases menu.

Encrypt Database Traffic

Validate Server Certificate

Check box to indicate whether to validate the server certificate. Selecting the Validate Server Certificate check box validates the database server during the TLS handshake. Specifying the Validate Hostname in Certificate and the Hostname in Certificate is optional when Validate Server Certificate is selected. If Validate Server Certificate is not selected, all encryption settings (Certificate Store File, Validate Hostname in Certificate, and Hostname in Certificate) are disabled. Selecting the Validate Server Certificate is considered a best practice.

Optional

Encryption Settings

Certificate Store File

For SQL Server, Certificate Store File is no longer required. The Certificate Store File value is ignored as the Microsoft Certificate Store on the Opcenter EX MDD or CR client is used to locate the certificate authority chain trusted certificates. Refer to the procedure in "Opcenter Execution MDD or CR Client Configuration for SQL Server" in the Opcenter Execution Medical Device and Diagnostics Security Guide or the Opcenter Execution Core Security Guide.

For Oracle, Certificate Store File is only required if you have chosen to use an Oracle Client Wallet on the Opcenter EX MDD or CR client that contains the certificate authority chain trusted certificate or certificates. In this case, the value for Certificate Store File is the path and the cwallet.sso file. Otherwise, the Microsoft Certificate Store on the Opcenter EX MDD or CR client is used to locate the certificate authority chain trusted certificates. Refer to the procedure in "Opcenter Execution MDD or CR Client Configuration for Oracle" in the Opcenter Execution Medical Device and Diagnostics Security Guide or the Opcenter Execution Core Security Guide.

Optional

Validate Hostname In Certificate

If you select this check box, you must also specify a value for the Hostname in Certificate field. During the TLS handshake, the common name (CN) attribute of the distinguished name in the database certificate is checked against the value specified in the Hostname in Certificate field to determine if it matches. For Oracle, additional certificate attributes in the database certificate’s distinguished name are also checked against the certificate attributes specified in the value for Hostname in Certificate.

Optional

Hostname in Certificate

Specify attribute and attribute values in the Hostname in Certificate field to be matched against the attribute and attribute values in the database electronic certificate to validate the hostname in certificate.

• Oracle. For Oracle, Hostname in Certificate must match the common name (CN) attribute of the database server certificate distinguished name. Additional certificate attributes may be required in the Hostname in Certificate value if the database certificate distinguished name was generated with additional certificate attributes like Organization, Organizational unit, City/locality, State/province. You must include these additional certificate attributes, in addition to the common name attribute, in the Hostname in Certificate value if these attributes are defined in the database certificate distinguished name. Each attribute must have the attribute abbreviation specified followed by an equal sign and the attribute value in the Hostname in Certificate value. Each attribute must be separated by a comma.

Example of Hostname in Certificate values in Opcenter EX MDD or CR Management Studio.
Only the CN attribute is defined in the database certificate:
CN=oramachine12.opac.local


Attributes in addition to the CN attribute are defined in the database certificate:
CN=oramachine12.opac.local, C=US
CN=oramachine12.opac.local, O=APAC, OU=IT,
L=Charlotte, S=North Carolina, C=US


• SQL Server. For SQL Server, Hostname in Certificate must match only the common name (CN) portion in the certificate distinguished name. Other certificate attributes like Organization, Organizational unit, City/locality, State/province may have been entered when the database server certificate distinguished name was generated. These other certificate attributes are not required when specifying the Hostname in Certificate value in Opcenter Management Studio, but you can specify any or all of them if you like.

Example of Validate Server Certificate values in Opcenter Management Studio:

CN=sqlmachine12.opac.local, C=US

CN=sqlmachine12.opac.local

CN=sqlmachine12.opac.local, O=APAC, OU=IT, L=Charlotte, S=North Carolina, C=US

Note: The field is required if the Hostname in Certificate check box is marked.

Required

Site Identifier

Total Number of Sites

Number of sites that the enterprise will contain. This number determines the range of identifiers Siemens will reserve for sites in the enterprise.

10 is a good default for most Siemens customers. You should overestimate the number of sites to allow for expansion.

For example, enter the number of sites + 3 if you expect to have more than 10 sites.

Important: This number should not exceed 15. If you need a value greater than 15, contact Product Support to discuss this value.

Required

Site Identifier

Number that represents a unique identifier for the site.

Do not assign 0 (zero) because it is reserved for Siemens use. Once a DBID is assigned to a site, do not reuse it even after removing the site.

This number should not exceed 15.

Required

Warning Threshold

Number of identifiers available (out of the more than two thousand million possible) at which point the system administrator is notified that the system is running out of identifiers.

Keep the default value of 500000.

Required

How to Add and Configure a Transaction Database

Follow these steps to add and configure a transaction database:

1. Click Start > Opcenter Execution MDD > Management Studio. The Management Studio window appears.

Or

Click Start > Opcenter Execution Core > Management Studio. The Management Studio window appears.

2. Right-click the Databases folder and select Add Transaction Database. A Transaction Database icon appears and the Transaction Database Configuration information appears in the right pane.
3. Refer to the field definitions table for information on what to enter in the Transaction Database Connection Info fields.
4. Click Test Connect. Management Studio displays a “Connection Established” message if the connection is successfully established. Otherwise, the application displays an error message.
5. Click OK to close the message.
6. Refer to the field definitions table for information on what to enter in the Site Identifier fields.
7. Click Save. Management Studio displays a success message.
