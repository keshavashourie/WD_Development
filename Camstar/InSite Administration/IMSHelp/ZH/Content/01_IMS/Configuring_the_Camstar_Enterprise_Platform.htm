配置 Opcenter EX MDD 或 Opcenter EX CR

先决条件

以下是配置 Opcenter EX MDD 或 Opcenter EX CR 的先决条件：

• 必须先设置元数据数据库，然后才能指定默认安全域。
• 必须先在“配置”窗格中设置默认安全域，然后才能启动应用程序服务器。
• 必须在 SSO 选项卡上指定身份验证的单一登录方法。
• 如果使用 REST API，则必须指定 REST API 用户名和密码。

数据库连接

数据库连接已在应用程序服务器中缓存。只要服务器当前正在使用连接，连接池中的连接就不会释放回到池中。清理连接的仅有方法是停止并启动应用程序服务器。

空闲数据库连接清理由 SiteInfo.mdb 文件中的 InSite SiteInfo 表中的两个字段控制。可以在“配置”窗格中输入这两个字段的信息：

• 启用空闲连接清理

选中此复选框可将连接清理记录到事件日志。

• 空闲后关闭连接

此字段将填充表中的 LogDBConnectionCleanup 值。该值以秒为单位，并指示关闭某个连接之前该连接必须空闲的时间量。

注释: 最初您可能想要启用日志记录以验证是否正在清理连接。数据库在生产环境中运行后，应清除该值以禁用日志记录活动。

Notification Server

通知服务器是基于 .NET 的独立服务。它使用自己的配置文件来与从中轮询电子邮件消息的数据库建立连接。

生成的电子邮件消息与 SMTP 服务器连接信息一起存储在数据库的表中。通知服务器将为要发送的新电子邮件消息轮询此表，然后将消息发送至 SMTP 服务器进行交付。

对于无法成功发送的消息，通知服务器包含重试机制。对于多个访问同一数据库的通知服务器，将提供行锁定机制以确保仅由一个服务器处理电子邮件消息。

电子邮件通知使用 Notification Server 将电子邮件提交到 SMTP 服务器。Management Studio 中的配置设置包含 Notification Server 的设置。可以修改配置设置以更改通知服务器的工作方式。

注释: 在 Oracle 数据库中设置会话参数时，需记住，通知服务器将创建大约 100 个与数据库的连接。有关“会话”值的信息，请参考《Opcenter Execution Medical Device and Diagnostics 系统管理指南》或《Opcenter Execution Core 系统管理指南》中的“示例数据库创建参数”。

使用本地帐户运行通知服务器服务所需的权限

通常，如果以特定用户的身份运行通知服务器帐户，则该用户必须是本地 Administrators 组的成员。但是，如果使用站点的非管理本地帐户来运行通知服务器服务，则系统管理员必须设置以下权限：

• 对于非管理本地帐户，设置对应用程序所在目录中的 .config 文件的读/写访问权限。
• 对于 IIS 用户组，对相同的 .config 文件设置读取访问权限。

这对安全服务器也适用。

网络负载平衡 (NLB) 集群中的应用程序服务器

如果应用程序服务器位于 NLB 集群中并且您有两个以上的节点，则典范做法是让通知服务器在其中两个或更少节点上运行。默认情况下，该服务每秒轮询数据库一次，以搜索要发送的新电子邮件。如果多个服务器频繁轮询同一个表，可能会出现争用问题。此外，每个通知服务器实例将创建大约 100 个与数据库的连接。

为质量记录配置电子邮件通知设置

《系统管理指南》中的“配置 WIP 电子邮件”主题讨论了如何配置 Opcenter EX MDD 或 Opcenter EX CR，以在操作员完成资源上的事务时发送维护和 WIP 消息电子邮件。该功能和质量记录电子邮件通知功能是两个独立功能。

配置许可证到期通知

Opcenter EX MDD 和 Opcenter EX CR 提供了许可证到期时自动通知指定收件人的功能。也可以使用 Management Studio 来配置设置，以在许可证到期之前按间隔发送电子邮件通知。可以设置以下两个间隔：

• 警告期
• 紧急期

应用程序将在每个时期发送一次电子邮件通知：一次表示警告，一次表示紧急。例如，如果将警告期设置为 30 天并将紧急期设置为 15 天，您将在许可证到期前的 30 天之前收到警告通知，接着在许可证到期前的 15 天之前收到紧急通知。您还会在许可证到期时收到电子邮件。

配置 Inline SPC 时

访问“许可证选”项卡，并单击保存以激活 Inline SPC 许可证，然后使用 appsettings 文件中的 Inline SPC 值更新 Flexlm 许可证服务器。 通过 Inline SPC，可以自动将显示的图表保存至位于服务器上的文件路径中。 访问 Inline SPC 选项卡以配置默认文件路径。

注释: Inline SPC 选项卡仅在安装了 Inline SPC 时显示。 请参考《Opcenter Execution Medical Device and Diagnostics 安装指南》或《Opcenter Execution Core 安装指南》。

配置许可证到期通知

可以将警告期设置为零以禁用警告期电子邮件通知。

可以将紧急期设置为零以禁用紧急期电子邮件通知。

注释: 可在“警告期”字段和“紧急期”字段中输入的最大天数为 365。

可以用分号分隔多个电子邮件收件人地址。至少需要一个地址。

颁发新许可证时，将重置许可证到期日期。

每封电子邮件通知的主题和文本由系统定义。

必须为 Exchange 服务器定义 SMTP 传输，并定义使用该 SMTP 传输的新站点。站点名称必须与 Management Studio 中使用的站点名称匹配。SMTP 传输和站点可以在“建模”页面中进行定义。

在紧急情况下，可以通过产品支持获取临时许可证。例如，如果您订购其他许可证，Siemens 可以在处理您的新许可证订单之前提供临时许可证。

注释: 保存配置信息后，应用程序会将许可证服务器端口号 (28000/29000) 作为前缀添加到许可证服务器字段中。

许可错误

某些登录和注销过程会影响可用许可证的数量。从 Web 浏览器登录到门户时，遵循此基本过程以防止发生错误：

1. 启动 Web 浏览器的新会话。
2. 登录到门户。

有关登录的信息，请参考《Opcenter Execution Medical Device and Diagnostics 入门用户指南》或《Opcenter Execution Core 入门用户指南》。

使用以下任意方法启动浏览器将导致发生许可证错误。不要使用以下过程之一启动浏览器：

• 使用 .exe 文件启动新的浏览器会话（例如从“开始”菜单选择该文件）
• 从现有浏览器会话中打开新窗口
• 从现有浏览器会话中启动新选项卡

Siemens 不支持同一浏览器中应用程序的多个实例。

安装新的许可证而不重新启动产品相关应用程序工具和服务会导致许可证未显示在 Management Studio 中。有关安装新许可证文件的信息，请参考 Opcenter Execution Medical Device and Diagnostics 安装指南或 Opcenter Execution Core 安装指南。

单一登录

使用单一登录 身份验证方法，用户可以通过登录任何应用程序来访问多个 Siemens 本地应用程序或基于云的应用程序。单一登录方法在 Siemens 应用程序和服务的完整生态系统中提供了单一的身份和访问管理解决方案。

必须执行以下任务才能启用单一登录：

• 在 Management Studio 中配置单一登录，
• 将单一登录代理服务设为自动，然后
• 启动单一登录代理服务。

单一登录在桌面模式下可用，在移动模式下不受支持。

登录选项包括：

• 默认 - 默认登录实施是在没有单一登录的情况下登录。通过输入用户名和密码，可以继续使用现有登录功能。
• SAM - Security and Access Management (SAM) 身份验证机制可验证 Siemens 服务所需的授权，以访问其他 Siemens 服务和资源。为所有帐户 ID 和服务生成独特访问密钥 (Webkey)，SAM 服务将根据需要验证授权以访问其他服务。
• SAML - 通过 SAML 适配器进行身份验证已扩展至 Azure Active Directory (Azure AD)。
有关更多信息，请参考“如何使用 ID Portal (Azure AD) 构建 SAML 应用程序”。
有关此选项的更多信息，请参考 Azure AD 文档。
• Windows 身份验证 - 使用 Windows 凭证进行身份验证。
• 智能卡 - 使用智能卡进行身份验证。
注释: Security and Access Management (SAM) 身份验证是可用于 Siemens 云服务的仅有单一登录身份验证方法。

跨域资源共享 (CORS)

CORS 是由 Fetch API 规范定义的一种机制，它允许 REST API 指定允许哪些源访问其资源。 这对于 Web 安全至关重要，因为出于安全原因，浏览器默认会阻止来自不同源的请求。

仅允许来自指定源（例如 https://example.com）的请求访问 API。 如果尝试从其他源访问 API，请求将因 CORS 策略而被拒。 如果来自未经批准源的应用程序尝试访问 API，会收到 CORS 错误响应。 这样可以防止未经授权的域使用您的 API。

在 CORS 选项卡上指定源并单击“保存”时，应用程序将更新每个 REST API 服务（建模、车间、查询和标签）的 appsettings.json 文件。应用程序将信息写入 AllowedOrigins 部分：

"AllowedOrigins": [

"https://example.com"

]

注释: 如果在任何 appsettings.json 文件的 AllowedOrigins 部分手动输入了信息，该信息将被 Management Studio 中指定的任何源覆盖。

例如，如果在 CORS 选项卡上的允许列表（白名单）中指定了源，则从 https://example.com 托管的 Web 应用程序向 https://{server}/modeling 发出 GET 请求会成功。 根据 CORS 策略，默认情况下会阻止来自未经授权源（如 https://unauthorized.com）的请求。

示例：在 Azure AD 上创建的 SAML 应用程序上配置单一登录

按照以下步骤在 Azure AD 中为 SAML 应用程序配置单一登录。

注：请注意，配置单一登录需要特定的 URL 和 SAML 特定考虑因素，这些因素在您创建的 SAML 应用程序的元数据中提供。 对于某些步骤，必要的 URL 详细信息已进行硬编码，且必须按照本文档中 SSO 选项卡字段定义部分的指定情况输入。

1. 在 SAML 应用程序的概述页上选择“单一登录”。
2. 单击“基本 SAML 配置”表格中的“编辑”。以下两段详细信息需要手动输入
1) 实体 ID - SAML 实体 ID 是不重复名称。 在 Management Studio > 实体 ID/分发者中输入“基本 SAML 配置”表格中提供的相同实体 ID 详细信息。
2) 断言 URL - 在 Management Studio > 断言 URL 中和在“基本 SAML 配置”表格中的“回复 URL”（断言使用者服务 URL）下以本文档中提供的默认格式提供域名和服务器名称 - https://{{mydomain}}/IDPAgent/api/v1/sso-service-provider/saml-assert-consumer-service。

SAML 应用程序中和 Management Studio 集成接口中提供的断言 URL 应相同。

3) 登录 URL（可选） - 尽管这是选填字段，但必须提供此详细信息才能正确配置单一登录。 以此格式输入域名以及 4040 - https://mydomain:4040
4) 注销 URL（可选） - 这是注销响应 URL。 使用本文档中提供的 URL，https://<mydomain>/IDPAgent/api/v1/sso-service-provider/saml-logout-response。
3. 完成“基本 SAML”下的配置后，可以继续执行“设置”（SAML 应用程序）下的配置
1) 登录 URL - 在 Management Studio > 端点 URL 中输入 SAML 应用程序的“设置”表格中提供的登录 URL。
2) 注销 URL - 在 Management Studio > 注销 URL 中输入 SAML 应用程序的“设置”表格中提供的注销 URL。
4. 从 Azure AD 站点下载 SAML 证书以验证该证书。 将证书保存在已部署的文件夹中。例如 路径 - C:\Program Files (x86)\Camstar\SSO\IDPAgent\app_data\Certificates。 如果 \app_data\Certificates 路径不存在，创建该文件夹，然后将证书保存在该文件夹中。
要提供的外部 Idp 公钥值应为相对路径，例如：\app_data\Certificates\name_of_the_certificate。

如何配置 Opcenter EX MDD 或 Opcenter EX CR

按照以下步骤配置 Opcenter EX MDD 或 Opcenter EX CR：

1. 单击开始 > Opcenter Execution MDD > Management Studio。此时将显示 Management Studio 窗口。

或

单击开始 > Opcenter Execution Core > Management Studio。此时将显示 Management Studio 窗口。

2. 在“站点”树中展开配置文件夹，然后选择配置节点。站点配置信息将显示在右窗格中。
3. 单击安全选项卡。
4. 输入默认域。
5. 单击 SSO 选项卡。
6. 从登录方式列表的选项中选择身份验证方法。
7. 根据选定的 SSO 方法输入详细信息。
注释: 可以添加并保存所有四种单一登录身份验证模式的配置详细信息，但应用的身份验证方法为选定（登录方式）并保存的选项。
8. 如果使用 REST API，则单击 REST API 选项卡。
9. 输入要用于 REST API 的用户名和密码。Management Studio 会加密输入的密码，然后在您保存时将用户名和加密密码传递给每个 appsettings.json 文件。
10. 如果需要指定允许的源，单击 CORS 选项卡。
11. 单击“源”列表中的新行，然后输入要允许的源的 http 地址。
12. 如果需要，重复步骤 11 以添加另一个源。
13. 根据您的业务需求输入可选信息。有关可选字段的信息，请参考字段定义表。
14. 单击保存。 Management Studio 将显示成功消息。
