管理 DataStore 数据库配置

只有在打算运行 DataStore 时才需要配置 DataStore 数据库。必须先创建元数据数据库和事务数据库。务必将 DataStore 数据库配置添加到环境中的所有应用程序服务器（门户和 CIO 服务器）。

DataStore 数据库配置信息

添加或选择 DataStore 数据库时，DataStore 数据库的配置信息将显示在 Management Studio 窗口的右窗格中。

选择“数据库”文件夹或数据库节点时，Management Studio 窗口中将显示“数据库”菜单。有关“数据库”菜单的信息，请参考“数据库菜单”。

注释: 如果插入表数量为 3 或以上，则当减少插入表数量时，将显示警告消息弹出窗口。在弹出窗口上单击“是”可关闭弹出窗口并减少插入表数量。单击“否”可关闭弹出窗口并放弃所做更改。

“DataStore 状态”字段部分中会显示一个切换开关，其中显示 DataStore 数据库的当前状态，使用该切换开关可以启动和停止数据库。该切换开关具有以下两种状态：

• “正在运行”，在此状态下，切换开关置于右侧选项，显示带有“开”字样的绿色圆圈。
• “已停止”，在此状态下，切换开关置于左侧选项，显示带有“关”字样的红色圆圈。

当 Management Studio 无法访问 DataStore 数据库时，将显示一条消息以代替切换开关。验证 DataStore 数据库连接信息以确保 Management Studio 可以访问数据库。

注释: 也可以从“数据库”菜单中启动和停止 DataStore 数据库。从“数据库”菜单中启动或停止数据库时，切换开关的状态会更新以反映数据库的状态。

重要注意事项

在 Opcenter EX MDD 或 Opcenter EX CR 安装过程中，将创建多个数据库对象，如表、链接、作业和序列。不要在未事先咨询产品支持的情况下修改其中任何对象，因为对这些对象配置的任何更改都可能导致 DataStore 失败或数据损坏。

注意：如果选中该复选框，确保将事务数据库端口的端口更改为为加密流量配置的加密端口。Oracle 的默认加密标准端口为 2484，SQL Server 为 1433。

验证服务器证书

此复选框指示是否验证服务器证书。 选中“验证服务器证书”复选框以在 TLS 信号交换期间验证数据库服务器。 选中“验证服务器证书”时，可以选择指定“验证证书中的主机名”选项和“证书中的主机名”选项。 未选中“验证服务器”证书时，将禁用所有加密设置（证书存储文件、验证证书中的主机名和证书中的主机名）。选中“验证服务器证书”复选框被视为典范做法。

可选

加密设置

证书存储文件

对于 SQL Server，不再需要证书存储文件。 由于 Opcenter EX MDD 或 CR 客户端上的 Microsoft 证书存储用于查找证书授权链信任的一个或多个证书，因此将忽略证书存储文件值。 请参考《Opcenter Execution Medical Device and Diagnostics 安全指南》或《Opcenter Execution Core 安全指南》的“针对 SQL Server 的 Opcenter Execution MDD 或 CR 客户端配置”中的过程。

对于 Oracle，仅当已选择在 Opcenter EX MDD 或 CR 客户端上使用包含证书授权链信任的一个或多个证书的 Oracle 客户端钱包时，才需要证书存储文件。 在此情况下，证书存储文件的值是路径和 cwallet.sso 文件。 否则，Opcenter EX MDD 或 CR 客户端上的 Microsoft 证书存储将用于查找证书授权链信任的一个或多个证书。 请参考《Opcenter Execution Medical Device and Diagnostics 安全指南》或《Opcenter Execution Core 安全指南》的“针对 Oracle 的 Opcenter Execution MDD 或 CR 客户端配置”中的过程。

可选

验证证书中的主机名

如果选中此复选框，还必须为“证书中的主机名”字段指定值。 在 TLS 信号交换期间，将根据“证书中的主机名”字段中指定的值检查数据库证书中可分辨名称的公用名 (CN) 属性，以确定它们是否匹配。 对于 Oracle，还会根据“证书中的主机名”的值中指定的证书属性，检查数据库证书可分辨名称中的其他证书属性。

可选

证书中的主机名

在证书中的主机名字段中指定要与数据库电子证书中的属性和属性值匹配的属性和属性值，以验证证书中的主机名。

• Oracle。 对于 Oracle，证书中的主机名必须与数据库服务器证书可分辨名称的公用名 (CN) 属性匹配。 如果数据库证书可分辨名称是使用其他证书属性（如组织、组织单位、城市/地区、省/市/自治区/直辖市）生成的，则“证书中的主机名”值中可能需要其他证书属性。 如果在数据库证书可分辨名称中定义了其他属性，则除了公用名属性外，还必须在“证书中的主机名”值中包含这些证书属性。 每个属性必须具有指定的属性缩写，后跟等号和“证书中的主机名”值中的属性值。 每个属性必须用逗号分隔。

Opcenter EX MDD 或 CR Management Studio 中的“证书中主机名”值的示例：
在数据库证书中仅定义 CN 属性：
CN=oramachine12.opac.local

除 CN 属性外，数据库证书中还定义了其他属性：
CN=oramachine12.opac.local, C=USCN=oramachine12.opac.local, O=APAC, OU=IT,L=Charlotte, S=North Carolina, C=US

必需

• SQL Server。 对于 SQL Server，证书中的主机名必须仅与证书可分辨名称中的公用名 (CN) 部分匹配。 生成数据库服务器证书可分辨名称时，可能输入了组织、组织单位、城市/区域、省/市/自治区/直辖市等其他证书属性。 在 Management Studio 中指定“证书中的主机名”值时，不需要这些其他证书属性，但可以根据需要指定其中任何或全部属性。

Management Studio 中验证服务器证书值的示例：

CN=sqlmachine12.opac.local, C=US

CN=sqlmachine12.opac.local

CN=sqlmachine12.opac.local, O=APAC, OU=IT, L=Charlotte, S=North Carolina, C=US

注意：如果已标记“证书中的主机名”复选框，则此字段为必填字段。

 

DataStore 状态

包含一个带有绿色“开”选项和红色“关”选项的切换开关，其中显示 DataStore 数据库的当前状态，使用该切换开关可以启动或停止数据库。

注意：当 Management Studio 无法访问 DataStore 数据库时，将显示一条消息以代替切换开关。验证 DataStore 数据库连接信息以确保 Management Studio 可以访问数据库。

DataStore 配置

清理批大小 (1-50000)

当事务（生产）数据库中的队列表中已处理的 Opcenter EX MDD 或 Opcenter EX CR 事务的数量超过此数字时，将在单个数据库提交周期中移除的 Opcenter EX MDD 或 Opcenter EX CR 事务的数量。默认值为 5000。

必需

插入表数量 (2-8)

用数字 2 到 8 表示插入表数量。默认值为 2。

必需

提交批大小 (0-1000)

当存在待处理的 Opcenter EX MDD 或 Opcenter EX CR 事务时，将在单个提交周期中进行批处理的 Opcenter EX MDD 或 Opcenter EX CR 事务的数量。此字段仅适用于 Oracle 数据库。值为 0 意味着将在单个批处理周期内提交每个 Opcenter EX MDD 或 Opcenter EX CR 事务，并且不会执行 Opcenter EX MDD 或 Opcenter EX CR 事务的批处理。对于 SQL Server，默认值为 0；对于 Oracle，默认值为 100。

注意：如果 DataStore 数据库类型为 SQL Server，则此字段处于禁用状态并显示值 0。将服务器类型切换回 Oracle 可显示已设置的原始值。

必需

日志级别详细信息

日志级别详细信息决定记录到 DataStoreLog 表的日志消息的粒度。有效值为“严重错误”、“最少详细信息”和“最多详细信息”。默认值为“严重错误”。

必需

两次轮询之间的休眠时间 (2-60)

DataStore 在两次读取事务（生产）数据库中的队列表之间等待的秒数。有效值为 2-60。默认值为 2。

必需

日志保留持续时间

在 DataStoreErrors 表和 DataStoreLog 表中保留数据的时间量。默认值为 6 个月。有效值为“无限期”、“1 个月”、“3 个月”、“6 个月”、“9 个月”、“1 年”、“2 年”和“3 年”。

将从 DataStoreErrors 表和 DataStoreLog 表中清除早于指定为“日志保留持续时间”值的数据。

必需

重试次数 (1-100)

DataStore 为解决不同步状况（例如事务（生产）数据库中有未提交的 Opcenter EX MDD 或 Opcenter EX CR 事务或 DataStore 数据库中存在事务序列空隙）而尝试的次数。当超过“重试次数”值且不同步状况未解决时，DataStore 将停止。有效值为 1-100。默认值为 2。

必需

验证数据库主机

使用有效值“是”或“否”进行标记。如果 DataStore 在 SQL Server 上，则默认值为“否”；如果 DataStore 在 Oracle 上，则默认值“是”。

此标志确定是否执行了比较，以验证 DataStore 实例中的 DataStore 元数据是否与 DataStore 执行环境匹配，以及 OLTP 实例中的 DataStore 和 OLTP 元数据是否与 DataStore 实例中的 DataStore 和 OLTP 元数据匹配。

必需

电子邮件管理

收件人电子邮件

DataStore 电子邮件警报的收件人电子邮件地址或电子邮件地址列表，用于通知收件人 DataStore 已停止还是已启动。对于 Oracle，用逗号分隔电子邮件地址。对于 SQL Server，用分号分隔电子邮件地址。

可选

发件人电子邮件

DataStore 电子邮件警报的发件人电子邮件地址，用于通知收件人 DataStore 已停止还是已启动。这通常设为无回复电子邮件地址，例如 no-reply_DataStore@domain.com。

可选

如何添加和配置 DataStore 数据库

按照以下步骤添加和配置 DataStore 数据库：

1. 单击开始 > Opcenter Execution MDD > Management Studio。此时将显示 Management Studio 窗口。

或

单击开始 > Opcenter Execution Core > Management Studio。此时将显示 Management Studio 窗口。

2. 右键单击数据库文件夹，然后选择添加 DataStore 数据库。此时将显示 DataStore 数据库图标，并且 DataStore 数据库配置信息会显示在右窗格中。
3. 有关字段输入信息，请参考字段定义表。
4. 单击测试连接。 如果已成功建立连接，Management Studio 将显示“已建立连接”消息。 否则，应用程序将显示错误消息。
5. 单击确定以关闭消息。
6. 单击保存。 Management Studio 将显示成功消息。
